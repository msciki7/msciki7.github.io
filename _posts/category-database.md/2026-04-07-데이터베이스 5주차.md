# 정보보안의 가장 기본: CIA

&ensp;정보보안을 처음 배울 때 가장 먼저 나오는 개념이 바로 CIA이다.<br/>
* Confidentiality(기밀성): 허가되지 않은 사용자가 정보에 접근할 수 없도록 보호하는 성질이다.
* Integrity(무결성): 정보가 인가되지 않은 방식으로 변경되거나 훼손되지 않도록 유지하는 성질이다.
* Availability(가용성): 정당한 사용자가 필요할 때 정보나 시스템을 사용할 수 있도록 보장하는 성질이다.

&ensp;이 세 가지는 보안의 핵심 목표이며 데이터베이스 보안을 이해할 때도 가장 기본이 되는 기준이다.<br/>

# 보안 공격 유형

&ensp;1. Interception(갈취)<br/>
&ensp;정보를 몰래 가로채서 확인하는 공격이다.<br/>
&ensp;이는 **기밀성에 대한 공격**이다.<br/>
&ensp;예를 들어 네트워크에서 메시지를 도청하거나 비인가 사용자가 데이터를 몰래 열람하는 경우가 이에 해당한다.<br/>
<p align="center"><img src="/assets/img/database/5주차/5-1.png" width="600"></p>

&ensp;2. Interruption(서비스 거부)<br/>
&ensp;정상적인 서비스 제공을 방해하는 공격이다. 이는 **가용성에 대한 공격**이다.<br/>
&ensp;대표적인 예가 DoS 공격이다. 서버가 감당할 수 없는 수준의 요청을 받아 정상 사용자에게 서비스를 제공하지 못하게 되는 상황을 의미한다.<br/>
<p align="center"><img src="/assets/img/database/5주차/5-2.png" width="600"></p>

&ensp;3. Modification(수정)<br/>
&ensp;전송 중이거나 저장된 데이터를 중간에서 변경하는 공격이다. 이는 **무결성에 대한 공격**이다.<br/>
&ensp;즉 원래 데이터와 도착한 데이터가 달라진다면 해당 정보는 더 이상 신뢰할 수 없게 된다.<br/>
<p align="center"><img src="/assets/img/database/5주차/5-3.png" width="600"></p>

&ensp;4 Fabrication(신분 위장)<br/>
&ensp;정상 사용자인 것처럼 가장하여 가짜 메시지나 정보를 만들어내는 공격이다. 이는 **인증(Authentication)**과 관련된 공격이다.<br/>
&ensp;예를 들어, 공격자가 다른 사용자인 척 시스템에 접속하거나 가짜 요청을 보내는 경우가 이에 해당한다.<br/>
<p align="center"><img src="/assets/img/database/5주차/5-4.png" width="600"></p>

&ensp;추가적인 보안 개념<br/>
&ensp;정보보안은 CIA만으로 끝나지 않는다.<br/>

&ensp;**인증(Authentication)**<br/>
&ensp;사용자가 실제로 누구인지 확인하는 절차이다. 아이디/비밀번호, OTP, 생체인증 등이 대표적인 예이다.<br/>
&ensp;**부인방지(Non-Repudiation)**<br/>
&ensp;어떤 행위를 수행한 사용자가 나중에 그 사실을 부인할 수 없도록 하는 성질이다.
전자서명이나 감사 로그가 대표적인 수단이다. 즉, 현대의 보안은 단순히 정보를 숨기는 수준을 넘어서, 누가 어떤 행위를 했는지 확인하고 추적할 수 있어야 한다는 방향으로 확장된다.<br/>
<p align="center"><img src="/assets/img/database/5주차/5-5.png" width="600"></p>

# 데이터베이스 보안의 개념

&ensp;데이터베이스 보안은 데이터베이스와 그 내부 데이터를 보호하기 위한 다양한 통제 기능과 수단을 의미한다.<br/>
&ensp;보호 대상은 단순히 테이블의 데이터만이 아니다. 다음과 같은 요소 전체가 포함된다.<br/>
* 데이터베이스의 실제 데이터
* DBMS
* 관련 애플리케이션
* 물리적 또는 가상 서버
* 데이터베이스 접근에 사용되는 네트워크 및 컴퓨팅 인프라

&ensp;즉, 데이터베이스 보안은 데이터 자체뿐 아니라, 데이터가 저장·처리·전송되는 전체 환경을 보호하는 개념이다.<br/>

# 정보보호 기술의 적용

&ensp;보안은 단순히 데이터를 숨기는 행위 하나만 의미하지 않는다.<br/>
&ensp;송신자와 수신자가 안전하게 정보를 주고받을 수 있도록 중간 과정 전체를 보호하는 것이 중요하다. 그래서 보안 기술은 메시지 자체뿐 아니라, 키 관리, 인증, 무결성 검증, 중재자 역할까지 포함하는 구조로 이해해야 한다.<br/>

&ensp;즉 보안은 "파일 하나 암호화했다"로 끝나는 것이 아니라 **정보가 생성되고, 전달되고, 사용되는 전 과정에 기술적으로 개입하는 체계라고 보면 된다.<br/>

## 보안 모델과 Trusted Third Party(TTP)

&ensp;TTP는 말 그대로 **신뢰된 제 3자**이다.<br/>
&ensp;송신자와 수신자 사이에서 보안에 필요한 비밀 정보나 키를 중재·분배하는 역할을 한다.<br/>
* 송신자와 수신자가 안전하게 통신하려면 어떤 비밀 정보가 필요하다.
* 그런데 그 비밀 정보를 아무렇게나 주고받으면 중간 공격자에게 노출될 수 있다.
* 그래서 신뢰할 수 있는 제3자가 키나 인증 정보를 관리하고 전달하는 구조가 필요하다.

<p align="center"><img src="/assets/img/database/5주차/5-6.png" width="600"></p>

&ensp;이 보안 모델에서 핵심은 다음 두 가지이다.<br/>
&ensp;1) 송신자와 수신자 사이에는 공격자가 존재할 수 있다.<br/>
&ensp;즉, 통신 채널은 안전하지 않을 수 있다. 중간에서 누군가 메시지를 훔쳐보거나 바꾸거나 위장할 수 있다.<br/>

&ensp;2) 보안 관련 변환이 필요하다.<br/>
&nesp;그냥 평문 메시지를 보내는 것이 아니라, 보안 기술을 적용해 안전한 메시지로 바꾼 뒤 전달해야 한다.<br/>
&ensp;여기서 “보안 관련 변환”은 대표적으로 다음을 떠올리면 된다.<br/>
* 암호화
* 복호화
* 해시
* MAC
* 전자서명
* 인증 처리

&ensp;즉, TTP가 등장하는 이유는 안전하지 않은 통신 환경 속에서 안전한 보안 절차를 가능하게 하기 위해서이다.<br/>

&ensp;기밀성 제공을 위한 암호화 기술<br/>
* 기밀성을 제공하기 위해서는 암호화 기술의 키가 필요하다.
* 공격자가 메시지를 가로채더라도 키가 없으면 내용을 이해할 수 없어야 한다.

&ensp;즉, 기밀성은 “누가 메시지를 못 보게 막는다”가 아니라 보더라도 이해할 수 없게 만든다는 개념에 가깝다.<br/>

&ensp;예를 들면,<br/>
* 평문 메시지: I love you
* 암호화된 메시지: 알 수 없는 암호문

&ensp;공격자가 중간에서 메시지를 가로채더라도, 암호화 키가 없으면 원래 내용을 알 수 없다. 이것이 바로 기밀성 보장의 핵심이다.<br/>
* 기밀성 보장 = 암호화
* 암호화의 핵심 = 키
* 키 관리 실패 = 기밀성 실패

&ensp;무결성 보안 기술의 예시<br/>
&ensp;여기서 중요한 키워드는 Hash, MAC<br/>
* 안전한 데이터 송수신을 위해서는 단순 암호화만으로 부족하다.
* 메시지가 중간에 바뀌지 않았는지 확인하는 기술도 필요하다.
* 이때 사용하는 대표적인 기술이 Hash 와 MAC 이다.

&ensp;Hash<br/>
&ensp;원본 데이터로부터 고정된 길이의 요약값을 만드는 기술이다. 데이터가 조금만 바뀌어도 해시값이 크게 달라진다. 그래서 수신자는 해시값을 비교하여 메시지가 변조되었는지 확인할 수 있다.<br/>

&ensp;MAC<br/>
&ensp;Message Authentication Code의 약자이다. 해시와 비슷하게 무결성 확인에 사용되지만, 비밀키를 함께 사용한다는 점에서 더 강한 인증 성격을 가진다.<br/>

* Hash → 데이터 변조 여부 확인
* MAC → 데이터 변조 여부 + 송신자 정당성 일부 확인

# 데이터베이스 보안 개요

1. 정보에는 기밀성, 무결성, 가용성이 중요하다.
2. 이 목표를 위협하는 다양한 공격이 존재한다.
3. 따라서 이를 막기 위한 관리적·기술적 수단이 필요하다.
4. 그 전체 활동을 정보보호 또는 보안이라고 부른다.

&ensp;데이터베이스 보안: 데이터베이스의 기밀성, 무결성 및 가용성을 설정하고 유지하도록 설계된 다양한 툴 또는 통제기능 및 수단<br/>
* 데이터베이스 보안은 단순히 비밀번호 설정만 의미하지 않는다.
* DB에 저장된 데이터가 유출되지 않게 하고,
* 데이터가 변조되지 않게 하며,
* 필요한 순간 정상적으로 이용 가능하도록 유지하는 모든 장치와 관리 활동을 포함한다.

&ensp;데이터베이스 보안은 DB의 CIA를 실현하기 위한 구체적 수단 전체라고 말할 수 있다.<br/>

&ensp;데이터베이스 보안의 분류<br/>
&ensp;1) 권한 관리를 통한 보안<br/>
* 객체 권한
* 역할(권한 바구니)

&ensp;즉 누가 어떤 데이터나 객체에 접근 가능한지 관리하는 보안이다.<br/>

&ensp;2) 운영 관리를 통한 보안<br/>
* 무결성 제공 기술
* 데이터 암호화
* 보안 정책 관리

&ensp;즉, 시스템을 안전하게 운영하기 위한 기술적·관리적 보호 수단이다.<br/>

&ensp;3) 물리적 환경에 대한 보안<br/>
* 자연재해 등으로부터 보호

&ensp;즉, 서버실, 하드웨어, 물리 장비, 재난 대응도 DB 보안 범위에 포함된다는 뜻이다.<br/>
<p align="center"><img src="/assets/img/database/5주차/5-7.png" width="600"></p>

## 보호 대상

&ensp;보안을 논할 때 제일 먼저 해야 하는 일은 무엇을 보호해야 하는지 정의하는 것이다.<br/>
&ensp;왜냐하면 보호 대상을 잘못 잡으면<br/>
* 중요한 것은 못 지키고
* 덜 중요한 것만 막게 될 수 있기 때문이다

&ensp;그래서 데이터베이스 보안에서도 “테이블만 지키면 끝”이 아니라 DB를 둘러싼 여러 요소를 함께 봐야 한다.<br/>

&ensp;데이터베이스 보안의 보호 대상<br/>
&ensp;1) 데이터베이스의 데이터<br/>
&ensp;가장 기본적 보호 대상이다. 테이블 안의 실제 데이터, 레코드, 민감정보 등이 여기에 포함된다.<br/>

&ensp;2) 데이터베이스 관리시스템(DBMS)<br/>
&ensp;데이터를 저장·조회·수정·삭제하게 해주는 핵심 소프트웨어이다. DBMS가 뚫리면 데이터 전체가 위험해질 수 있다.<br/>

&ensp;3) 연관된 애플리케이션<br/>
&ensp;웹 애플리케이션이나 업무 시스템처럼 DB와 연결된 프로그램도 보호 대상이다. 왜냐하면 많은 공격이 DB 자체가 아니라 애플리케이션을 경유해서 들어오기 때문이다.<br/>

&ensp;4) 물리적/가상 데이터베이스 서버와 기본 하드웨어<br/>
&ensp;실제 서버 장비, 디스크, 가상 서버 환경도 포함된다. 하드웨어 장애나 물리적 침입도 보안 문제이기 때문이다.<br/>

&ensp;5) 데이터베이스에 액세스하는 컴퓨팅/네트워크 인프라<br/>
&ensp;네트워크, 통신 장비, 접속 환경 등도 보호 대상이다. 전송 과정이 취약하면 DB 내용도 쉽게 유출될 수 있다.<br/>


# 데이터베이스 보안 위협

&ensp;데이터베이스 보안에는 여러 가지 위협이 존재한다.<br/>
&ensp;1. 소프트웨어 구성 오류 및 취약점 악용<br/>
&ensp;DBMS 또는 관련 소프트웨어의 설정 오류, 보안 취약점, 패치 미적용 상태를 이용하는 공격이다.
이 때문에 정기적인 패치 적용과 안전한 설정 관리가 중요하다.<br/>

&ensp;2. SQL\NoSQL 인젝션<br/>
&ensp;사용자 입력값 검증이 제대로 이루어지지 않을 때, 공격자가 조작된 질의문을 삽입하여 데이터베이스를 공격하는 방식이다.<br/>
&ensp;이 공격은 다음과 같은 심각한 결과를 초래할 수 있다.<br/>
* 데이터 열람
* 데이터 유출
* 데이터 조작
* 관리자 인증 우회

&ensp;3. 서비스 거부 공격(DoS/DDoS)<br/>
&ensp;과도한 요청을 통해 서버의 정상 동작을 방해하는 공격이다. 목적은 시스템 마비이며 대표적으로 가용성 침해 공격이다.<br/>

&ensp;4. 백업에 대한 공격<br/>
&ensp;백업 데이터 역시 운영 데이터와 동일하게 중요한 자산이다. 백업이 유출되거나 손상되면 데이터 복구 체계 자체가 무너질 수 있으므로, 백업에도 엄격한 보안 통제가 필요하다.<br/>
&ensp;악화 요소<br/>
* 데이터 볼륨 증가
* 복잡해지는 네트워크 환경
* 사이버보안 스킬 부족

&ensp;5. 내부자 위협<br/>
&ensp;조직 내부 사용자에 의한 위협이다. 악의적인 내부자뿐 아니라, 보안 지식 부족이나 실수로 인해 위험을 초래하는 사용자도 포함된다.<br/>

&ensp;6. 데이터 유출 위협<br/>
&ensp;암호화되지 않은 데이터는 네트워크 도청, 파일 유출, 비인가 조회 등의 방식으로 외부에 노출될 수 있다. 또한 안전하지 않은 암호 알고리즘을 사용하면 암호화된 데이터 역시 해독될 위험이 있다.<br/>

<p align="center"><img src="/assets/img/database/5주차/5-8.png" width="600"></p>

# 데이터 유츌 위협

&ensp;1) 데이터 유출 위협<br/>
* 비암호화 데이터는 네트워크 도청, 파일백업, 정당한 사용자 및 비인가 사용자에 의한 데이터베이스 검색을 통한 데이터 유출 가능
* 안정성이 확인되지 않은 암호알고리즘/모듈을 사용하는 경우 악의적인 사용자에 의해 암호문 해독 가능

&ensp;기타 보안 위협<br/>
* 사람(사용자)의 실수
    - 데이터베이스 보안 공역의 거의 절반(49%)의 원인
    - 매우 흔하고 치명적
    - 취약한 암호, 암호 공유 및 무지한 사용자 행동
* 멀웨어(Malware)
    - 취약점을 약용하거나 기타 방식으로 데이터베이스에 손상을 유발하기 위해 특별히 고안된 소프트웨어

# 정보보안과 데이터베이스 보안의 차이

&ensp;정보보안은 정보 전체를 보호하는 넓은 개념이다. 여기에는 네트워크 보안, 시스템 보안, 애플리케이션 보안, 데이터베이스 보안 등이 포함된다.<br/>
&ensp;반면 데이터베이스 보안은 이 중에서도 데이터베이스와 데이터 보호에 특화된 영역이다.<br/>
&ensp;즉, 정보보안이 상위 개념이라면 데이터베이스 보안은 그 하위 영역이라고 볼 수 있다.<br/>

<p align="center"><img src="/assets/img/database/5주차/5-9.png" width="600"></p>

# 데이터베이스 보안 요구사항

&ensp;1. 접근제어와 인증<br/>
&ensp;데이터베이스 보안의 가장 기본이 되는 요소이다. 인가된 사용자만 데이터에 접근할 수 있어야 하며, 사용자별로 수행 가능한 작업도 적절히 제한되어야 한다.<br/>

&ensp;2. 데이터 보호<br/>
&ensp;민감한 정보 유출에 대비하기 위해 데이터 암호화가 필요하다. 전체 테이블을 암호화할 수도 있고, 특정 컬럼만 선택적으로 암호화할 수도 있다.<br/>
&ensp;또한 안전한 암호 알고리즘 사용과 암호키 관리가 매우 중요하다.<br/>
* 중요한 테이블 전체 또는 민감정보를 저장하고 있는 특정 칼럼에 대한 암호화
* 안전하고 권고하는 암호화 알고리즘 및 암호화 모듈 사용
* 암호화 키에 대한 안전한 관리와 운영 중요

&ensp;3. 추론 방지<br/>
&ensp;직접적으로 접근이 허용되지 않은 정보라 하더라도, 공개된 여러 데이터를 조합하여 민감한 정보를 유추할 수 있는 경우가 있다. 이러한 추론 가능성을 줄이는 것도 중요한 보안 요구사항이다.<br/>

<p align="center"><img src="/assets/img/database/5주차/5-10.png" width="600"></p>


&ensp;4. 데이터베이스 무결성 보장<br/>
&ensp;무결성 보장은 크게 두 가지 측면으로 나뉜다.<br/>
* 운영적 무결성: 병행 처리 환경에서 데이터의 논리적 일관성을 유지하는 것
* 의미적 무결성: 데이터가 허용된 값의 범위를 벗어나지 않도록 제약조건으로 통제하는 것

<p align="center"><img src="/assets/img/database/5주차/5-11.png" width="600"></p>
<p align="center"><img src="/assets/img/database/5주차/5-12.png" width="600"></p>

&ensp;5. 감사 및 모니터링<br/>
&ensp;누가 어떤 데이터에 접근했고, 어떤 SQL 문을 실행했으며, 어떤 변경이 발생했는지를 기록하고 추적할 수 있어야 한다. 이러한 감사 기능은 사고 분석과 책임 추적에 필수적이다.<br/>

&ensp;6. 기타 요구사항<br/>
* 백업 보안
    - 데이터베이스의 모든 백업, 사본 또는 이미지는 데이터베이스 자체와 동일한(또는 동일하게 엄격한) 보안 통제 적용
* 애플리케이션 / 웹 서버 보안
    - 데이터베이스와 상호작용하는 모든 애플리케이션 또는 웹 서버는 공격 대상 채널이 될 수 있으므로 지속적인 보안 테스트 및 보안 관리 대상
* 데이터베이스 소프트웨어 보안
    - 항상 최신 버전 데이터베이스 관리 소프트웨어 사용
    - 취약점 관련 패치는 배포되는 즉시 적용
* 물리적 보안
    - 데이터베이스 서버가 안전하고 냉난방이 구비된 환경 내에서 운영
* 네트워크 보안
    - DBMS와 어플리케이션 간 데이터 전송은 안전한 전송채널로 통신

# 보안과 성능의 관계

&ensp;데이터베이스 보안을 강화하면 보통 성능이나 접근성이 저하될 수 있다. 반대로 성능과 편의성만 지나치게 강조하면 보안은 취약해질 수 있다. 즉, 보안성·접근성·성능·가용성은 서로 trade-off 관계에 있다. 따라서 시스템 설계 시 요구사항을 잘 분석하여 균형 있게 반영해야 한다.<br/>

# 데이터베이스 보안 기술

&ensp;데이터베이스 보안 기술은 크게 접근제어 기술과 암호화 기술로 나눌 수 있다.<br/>

## 데이터베이스 접근제어

&ensp;1. DAC(임의적 접근제어)<br/>
&ensp;객체 소유자가 다른 사용자에게 권한을 부여하거나 회수하는 방식이다. 대표적으로 SQL의 `GRANT`, `REVOKE`가 이에 해당한다.<br/>
* 접근 요청하는 사용자의 신분 및 접근 규칙 기반하는 접근제어
    - 신분 기반 접근제어(Identity Based Access Control, IBAC)
* 객체 소유자가 객체 보안 레벨 결정 및 객체 접근제어 설정
* 대표적 접근제어 모델
    - 접근제어행렬(Access Control Matrix, ACM): 가상화 모델
    - 권한목록(Capabiliy, 접근가능목록)
    - 접근제어목록(Access Control List, ACL)
* 객체 소유자가 SQL문(GRANT/REVOKE)을 통하여 다른 사용자에게 객체에 대한 특정 권한 부여 및 삭제 가능

&ensp;2. MAC(강제적 접근제어)<br/>
&ensp;시스템에 있는 주체와 객체의 보안 분류 등급에 따라 시스템이 강제로 접근을 통제하는 방식<br/>

<p align="center"><img src="/assets/img/database/5주차/5-15.png" width="600"></p>

&ensp;높은 수준의 보안이 필요한 환경에서 사용된다.<br/>
* 규칙기반 접근 제어
* 중앙 집권적인 관리로 보안성이 높은 편
* 대표적 모델
    - Bell Lapadula(BLP) 모델
    - Biba 모델

&ensp;RBAC(역할기반 접근제어)<br/>

&ensp;3. RBAC(역할기반 접근제어)<br/>
&ensp;사용자 개인이 아니라 역할(Role)에 따라 권한을 부여하는 방식이다. 대규모 조직 환경에서 효율적인 권한 관리가 가능하다.<br/>
* 객체에 대한 주체의 접근권한을 주체 신분이나 이미 정해진 규칙에 의해 판단하지 않고 주체가 소속된 조직 내 역할에 따라 결정
* 일반적으로 대규모 엔터프라이즈 환경에서 사용
* DBA는 SQL문(CREATE ROLE문)을 통해 ROLE을 생성하고 특정 사용자에게 객체에 대한 권한 부여 및 회수 가능

# 데이터베이스 암호화

&ensp;데이터베이스 암호화는 민감한 정보 유출에 대비하기 위한 핵심 기술이다.<br/>
&ensp;암호화는 평문을 암호문으로 변환하여, 암호키가 없는 사용자는 내용을 확인할 수 없도록 만드는 기술이다. 이는 기밀성 보장에 가장 직접적으로 사용되며, 무결성이나 인증에도 활용될 수 있다.<br/>
&ensp;적용 방식은 다양하다.<br/>
* 응용프로그램 자체 암호화
* DB 서버 암호화
* DBMS 자체 암호화
* 운영체제 수준 암호화

&ensp;중요한 것은 단순히 암호화를 적용하는 것에 그치지 않고, 어떤 알고리즘을 사용하는지, 키를 어떻게 관리하는지, 어느 계층에서 암복호화를 수행하는지까지 함께 고려해야 한다는 점이다.<br/>
