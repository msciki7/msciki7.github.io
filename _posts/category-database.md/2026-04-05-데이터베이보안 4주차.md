# 1. SQL이란?

&ensp;SQL(Structured Query Language)은 관계형 DBMS에서 데이터를 관리하기 위해 사용하는 데이터베이스 표준 질의어이다. 즉 DBMS에게 무슨 데이터를 만들고, 찾고, 바꾸고, 지울지를 말하는 언어라고 보면 된다. 단순 조회만 하는 게 아니라 검색, 삽입, 수정, 삭제, 권한 제어, 복구까지 가능하다.<br/>

&ensp;"SQL은 DBMS에게 원하는 작업을 요청하고 결과를 얻기 위한 데이터베이스 전용 언어이다."<br/>

# 2. SQL과 일반 프로그래밍 언어의 차이

&ensp;SQL은 자바, C처럼 완전한 프로그래밍 언어가 아니다. 그래서 데이터 부속어(Data Sublanguage)라고 부른다.<br/>

&ensp;완전한 프로그래밍 언어가 아닌 이유<br/>
&ensp;SQL은 데이터베이스의 데이터를 다루는 문법에 특화되어 있기 때문이다.<br/>

&ensp;SQL<br/>
* 목적: 데이터베이스에서 데이터 추출, 저장, 변경
* 입력/출력 대상: 테이블
* 실행 주체: DBMS가 해석/번역

&ensp;일반 프로그래밍 언어<br/>
* 목적: 전반적인 문제 해결
* 입력/출력 대상: 파일, 키보드, 네트워크, 화면 등 다양
* 실행 주체: 컴파일러/인터프리터

# 3. SQL의 기능별 분류

&ensp;SQL은 크게 3가지로 나뉜다.<br/>

&ensp;1. DDL (Data Definition Language, 데이터 정의어)<br/>
&ensp;데이터베이스 구조를 정의할 때 사용<br/>
* CREATE
* ALTER
* DROP

&ensp;즉 테이블을 만들고 / 구조를 바꾸고 / 삭제하는 언어<br/>
<p align="center"><img src="/assets/img/database/4주차/4-2.png" width="600"></p>

&ensp;2. DML (Data Manipulation Language, 데이터 조작어)<br/>
&ensp;테이블 안의 실제 데이터를 다룰 때 사용<br/>
* SELECT
* INSERT
* UPDATE
* DELETE

&ensp;즉 데이터를 조회하고 / 넣고 / 고치고 / 지우는 언어<br/>
<p align="center"><img src="/assets/img/database/4주차/4-3.png" width="600"></p>

&ensp;3. DCL (Data Control Language, 데이터 제어어)<br/>
&ensp;권한과 복구를 다룰 때 사용<br/>
* GRANT
* REVOKE
* COMMIT
* ROLLBACK

&ensp;즉 권한을 주고 / 빼고 / 작업을 확정하고 / 되돌리는 언어<br/>
<p align="center"><img src="/assets/img/database/4주차/4-4.png" width="600"></p>

# 4. SQL 표준화

&ensp;흐름<br/>
* 1970년대 후반: IBM의 SEQUEL 이 시초
* 1983년: ANSI가 표준화 시작
* 1986년: SQL-86(SQL1)
* 1987년: ISO 표준 언어 채택
*  1992년: SQL-92(SQL2)
* 1999년: SQL:1999(SQL3)
* 2019년: SQL:2019 발표

&ensp;표준화가 중요한 이유<br/>
&ensp;표준을 정하면 DBMS 종류가 달라도 데이터를 좀 더 쉽게 공유할 수 있게 때문이다. 즉 **호환성**을 높이기 위해서이다.<br/>
&ensp;하지만 현실에서는 완벽히 안 지킨다.<br/>
1. SQL 표준 자체가 너무 방대하고 복잡함
2. 기존 고객과 과거 버전과의 호환성을 유지해야 해서 이 때문에 DBMS마다 문법 차이가 조금씩 생긴다.

# 5. DDL 정리

&ensp;데이터 정의어: CREATE / ALTER / DROP<br/>
&ensp;DDL은 구조를 다루는 언어이다. "데이터 자체"보디 "데이터를 담는 틀"을 다룬다.<br/>

&ensp;1. CREATE<br/>
&ensp;테이블 같은 객체를 생성할 때 사용<br/>
&ensp;기본 구조<br/>
```sql
CREATE TABLE 테이블이름 (
    속성이름 데이터타입 [NOT NULL] [DEFAULT 기본값],
    [PRIMARY KEY (속성리스트)],
    [UNIQUE (속성리스트)],
    [FOREIGN KEY (속성리스트) REFERENCES 테이블이름(속성리스트)],
    [CONSTRAINT 이름 CHECK(조건)]
);
```

&ensp;예<br/>
```sql
CREATE TABLE customer_info (
    ID VARCHAR(20) PRIMARY KEY,
    Name VARCHAR(20),
    Age INT,
    Grade VARCHAR(10),
    Job VARCHAR(20)
);
```

&ensp;2. CREATE 안에서 알아야 하는 핵심 요소<br/>
&ensp;(1) 속성 정의<br/>
&ensp;각 열(column)의 이름과 데이터 타입을 정하는 부분<br/>
&ensp;예<br/>
```sql
나이 INT
이름 VARCHAR(20)
주문일자 DATE
```

&ensp;자주 나오는 데이터 타입<br/>
* INT, INTEGER: 정수
* SMALLINT: 더 작은 정수
* CHAR(n): 고정 길이 문자열
* VARCHAR(n): 가변 길이 문자열
* NUMERIC(p, s) 또는 DECIMAL(p, s): 고정 소수점
* FLOAT, REAL: 실수
* DATE: 날짜
* TIME: 시간
* DATETIME: 날짜+시간

<p align="center"><img src="/assets/img/database/4주차/4-5.png" width="600"></p>

&ensp;문자, 날짜, 시간 값은 작은따옴표로 적는다.<br/>
&ensp;숫자는 보통 그대로 적는다.<br/>
&ensp;예<br/>
```sql
'홍길동'
'2022-05-22'
30
```

&ensp;(2) NOT NULL<br/>
&ensp;해당 속성에 NULL을 허용하지 않겠다는 뜻<br/>
```sql
USER_ID VARCHAR(10) NOT NULL;
```

&ensp;기본적으로 테이블 속성은 NULL을 허용하는데 반드시 값이 있어야 하는 속성은 NOT NULL을 붙어야 한다.<br/>

&ensp;(3) DEFAULT<br/>
&ensp;값을 따로 넣지 않았을 때 자동으로 들어갈 기본값<br/>
```sql
USER_AGE INT DEFAULT 0;
STUDENT_GRADE CHAR(2) DEFAULT 'A0';
```

&ensp;(4) PRIMARY KEY<br/>
&ensp;각 튜플(행)을 유일하게 식별하는 키<br/>
```sql
PRIMARY KEY(USER_ID);
```

&ensp;또는 복합키<br/>
```sql
PRIMARY KEY(CUSTOMER_ID, PRODUCT_ID);
```

&ensp;특징<br/>
* 중복 불가
* NULL 불가
* 가능하면 테이블마다 저장하는 것이 좋음

&ensp;(5) UNIQUE<br/>
&ensp;대체키를 지정할 때 사용<br/>
```sql
UNIQUE(USER_NUM);
```

&ensp;특징<br/>
* 유일성은 보장
* 하지만 PRIMARY KEY 와 달리 NULL 가능

&ensp;PRIMARY KEY와 UNIQUE 차이<br/>
* 둘 다 중복 방지
* 하지만 기본키는 NULL 불가
* UNIQUE는 NULL 허용 가능

&ensp;(6) FOREIGN KEY<br/>
&ensp;다른 테이블의 기본키를 참조하는 키<br/>
```sql
FOREIGN KEY(USER_NUM) REFERENCES USER(NUM);
```

&ensp;의미<br/>
&ensp;내 테이블의 값이 다른 테이블에 실제로 존재하는 값과 연결되어야 한다는 뜻이다.<br/>

&ensp;(7) CONSTRAINT / CHECK<br/>
&ensp;무결성 조건을 주고 싶을 때 사용<br/>
```sql
CHECK(PRICE >= 0)
CONSTRAINT CHK_PRICE CHECK(PRICE >= 0)
```

&ensp;의미<br/>
&ensp;값이 특정 조건을 만족해야만 들어갈 수 있도록 제한하는 것<br/>

&ensp;3. 무결성 제약조건 정리<br/>
&ensp;1) 개체 무결성<br/>
* 기본키는 NULL이면 안 됨
* 기본키 값은 중복되면 안 됨

&ensp;각 행은 분명히 구별되어야 한다.<br/>

&ensp;2) 참조 무결성<br/>
* 외래키는 참조하는 부모 테이블 기본키와 도메인이 같아야 함
* 자식 테이블의 값은 부모 테이블의 제약을 받음

&ensp;즉 존재하지 않는 부모를 참조하면 안 된다.<br/>

&ensp;3) 도메인 무결성<br/>
* 각 속성은 정해진 범위의 값만 가져야 함

```sql
CHECK(PRICE >= 0)
```

&ensp;즉 가격에 음수 같은 이상한 값이 들어가면 안 된다.<br/>

&ensp;4. CREATE 대표 예제<br/>
&ensp;문제<br/>
&ensp;주문 테이블을 만들자<br/>
* 주문번호: 기본키
* 주문고객: 고객 테이블의 고객아이디 참조
* 주문제품: 제품 테이블의 제품번호 참조

&ensp;SQL<br/>
```sql
CREATE TABLE 주문 (
    주문번호 CHAR(3) NOT NULL,
    주문고객 VARCHAR(20),
    주문제품 CHAR(3),
    수량 INT,
    배송지 VARCHAR(30),
    주문일자 DATE,
    PRIMARY KEY(주문번호),
    FOREIGN KEY(주문고객) REFERENCES 고객(고객아이디),
    FOREIGN KEY(주문제품) REFERENCES 제품(제품번호)
);
```

&ensp;해석<br/>
* 주문번호는 주문 하나를 구별하는 대표값
* 주문고객은 고객 테이블과 연결
* 주문제품은 제품 테이블과 연결

&ensp;즉 이 SQL은 단순히 테이블만 만드는 것이 아니라 주문-고객-제품의 관계까지 함께 설정<br/>

&ensp;5. ALTER<br/>
&ensp;이미 만든 테이블 구조를 변경할 때 사용<br/>
&ensp;할 수 있는 일<br/>
* 새로운 속성 추가
* 기존 속성 삭제
* 제약조건 추가
* 제약조건 삭제

&ensp;(1) 속성 추가<br/>
```sql
ALTER TABLE 테이블이름
ADD 속성이름 데이터타입 [NOT NULL] [DEFAULT 기본값];
```

&ensp;(2) 속성 삭제<br/>
```sql
ALTER TABLE 테이블이름
DROP COLUMN 속성이름;
```

&ensp;(3) 제약조건 추가<br/>
```sql
ALTER TABLE 테이블이름
ADD CONSTRAINT 제약조건이름 제약조건내용;
```

&ensp;(4) 제약조건 삭제<br/>
```sql
ALTER TABLE 테이블이름
DROP CONSTRAINT 제약조건이름;
```

&ensp;ALTER 예제<br/>
&ensp;고객 테이블에 20세 이상만 가입 가능 조건 추가:<br/>
```sql
ALTER TABLE 고객
ADD CONSTRAINT CHK_AGE CHECK(나이 >= 20);
```

&ensp;이미 만들어진 고객 테이블에 나이가 20이상이어야 한다는 규칙을 나중에 추가한 것<br/>

&ensp;6. DROP<br/>
&ensp;테이블 자체를 삭제하는 문<br/>
```sql
DROP TABLE 테이블이름;
```

&ensp;예<br/>
```sql
DROP TABLE 배송업체;
```

&ensp;다른 테이블이 그 테이블을 외래키로 참조하고 있으면 바로 삭제할 수 없다. 먼저 외래키 제약조건을 제거해야 한다.<br/>

# 6. DML 정리

&ensp;데이터 조작어: SELECT / INSERT / UPDATE / DELETE<br/>
&ensp;DML은 테이블 안에 저장된 실제 데이터를 다루는 언어이다.<br/>

&ensp;1. SELECT<br/>
&ensp;데이터를 검색할 때 사용하는 가장 기본적인 문장<br/>
&ensp;기본 구조<br/>
```sql
SELECT [ALL | DISTINCT] 속성리스트
FROM 테이블리스트;
```

&ensp;의미<br/>
* `SELECT`: 무엇을 볼지
* `FROM`: 어디서 가져올지

&ensp;ALL과 DISTINCT<br/>
* `ALL`: 중복 허용
* `DISTINCT`: 중복 제거

&ensp;예<br/>
<p align="center"><img src="/assets/img/database/4주차/4-8.png" width="600"></p>

```sql
SELECT 제조업체
FROM 제품;
```

&ensp;→ 같은 제조업체 이름이 여러 번 나올 수 있음<br/>
<p align="center"><img src="/assets/img/database/4주차/4-9.png" width="600"></p>

```sql
SELECT DISTINCT 제조업체
FROM 제품;
```

&ensp;→ 제조업체 이름을 한 번씩만 보여줌<br/>
<p align="center"><img src="/assets/img/database/4주차/4-10.png" width="600"></p>
 
&ensp;SELECT 예제<br/>
```sql
SELECT 고객아이디, 고객이름, 등급
FROM 고객;
```

&ensp;의미: 고객 테이블에서 고객아이디, 이름, 등급만 보여라<br/>
<p align="center"><img src="/assets/img/database/4주차/4-6.png" width="600"></p>
<p align="center"><img src="/assets/img/database/4주차/4-7.png" width="600"></p>

&ensp;2. WHERE<br/>
&ensp;조건을 만족하는 데이터만 검색할 때 사용<br/>
&ensp;기본 구조<br/>
```sql
SELECT 속성리스트
FROM 테이블리스트
WHERE 조건;
```

&ensp;비교 연산자<br/>
* `=` : 같다
* `<>` : 다르다
* `<` : 작다
* `>` : 크다
* `<=` : 작거나 같다
* `>=` : 크거나 같다

&ensp;논리 연산자<br/>
* `AND`: 모두 만족
* `OR`: 하나만 만족해도 됨
* `NOT`: 조건을 만족하지 않는 것

<p align="center"><img src="/assets/img/database/4주차/4-11.png" width="600"></p>

&ensp;WHERE 예제<br/>
&ensp;문제: apple 고객이 주문했거나 수량이 15개 이상인 주문 검색<br/>
<p align="center"><img src="/assets/img/database/4주차/4-12.png" width="600"></p>

```sql
SELECT 주문제품, 수량, 주문일자, 주문고객
FROM 주문
WHERE 주문고객 = 'apple' OR 수량 >= 15;
```

&ensp;주문고객이 apple 이거나 수량이 15 이상이면 결과에 포함<br/>

<p align="center"><img src="/assets/img/database/4주차/4-13.png" width="600"></p>

&ensp;3. LIKE<br/>
&ensp;문자열 조건을 부분적으로만 알고 있을 때 사용<br/>
&ensp;필요한 이유<br/>
&ensp; `=` 는 정확히 일치해야 한다. 그런데 이름 일부만 알거나 길이만 알면 `LIKE`를 쓴다.<br/>

&ensp;LIKE에서 쓰는 기호<br/>
* `%`: 0개 이상의 문자
* `_`: 정확히 1개의 문자

<p align="center"><img src="/assets/img/database/4주차/4-14.png" width="600"></p>

&ensp;예시 해석<br/>
* `LIKE '데이터%'` : 데이터로 시작
* `LIKE '%데이터'` : 데이터로 끝남
* `LIKE '%데이터%'` : 중간에 데이터 포함
* `LIKE '데이터___'` : 데이터로 시작하고 뒤에 3글자
* `LIKE '__한%'` : 세 번째 글자가 한

<p align="center"><img src="/assets/img/database/4주차/4-15.png" width="600"></p>

&ensp;LIKE 대표 예제<br/>
&ensp;문제: 고객 아이디가 5자인 고객 검색<br/>
<p align="center"><img src="/assets/img/database/4주차/4-16.png" width="600"></p>

```sql
SELECT 고객아이디, 고객이름, 등급
FROM 고객
WHERE 고객아이디 LIKE '_____';
```

&ensp;언더바 하나가 한 글자이므로 언더바 5개 = 정확히 5글자<br/>
<p align="center"><img src="/assets/img/database/4주차/4-17.png" width="600"></p>

&ensp;4. 집계 함수<br/>
&ensp;값을 통계적으로 계산할 때 사용<br/>

&ensp;주요 함수<br/>
* COUNT : 개수
* MAX : 최댓값
* MIN : 최솟값
* SUM : 합계
* AVG : 평균

<p align="center"><img src="/assets/img/database/4주차/4-18.png" width="600"></p>

&ensp;주의사항<br/>
1. NULL 값은 제외하고 계산
2. WHERE 조건에는 사용 불가
3. SELECT문이나 HAVING 조건에서 사용 가능

&ensp;WHERE에서는 안 되는 이유<br/>
&ensp;WHERE는 **행을 먼저 거르는 단계**이고 집계 함수는 **여러 행을 모아 계산한 뒤** 나오는 값이기 때문이다. 그래서 그룹 결과 조건은 HAVING에 쓴다.<br/>

&ensp;집계 함수 예제<br/>
&ensp;모든 제품 단가 평균<br/>
<p align="center"><img src="/assets/img/database/4주차/4-19.png" width="600"></p>

```sql
SELECT AVG(단가)
FROM 제품;
```

<p align="center"><img src="/assets/img/database/4주차/4-20.png" width="600"></p>

&ensp;한국제과 제품의 재고량 합계<br/>
```sql
SELECT SUM(재고량) AS 재고량합계
FROM 제품
WHERE 제조업체 = '한국제과';
```

<p align="center"><img src="/assets/img/database/4주차/4-21.png" width="600"></p>

&ensp;AS의 의미<br/>
&ensp;출력 결과 컬럼 이름을 바꾸는 것<br/>

&ensp;예<br/>
* 원래: SUM(재고량)
* 바꾼 후: 재고량합계

&ensp;5. GROUP BY / HAVING<br/>
&ensp;같은 값을 가진 행끼리 묶어서 그룹별로 계산할 때 사용<br/>
&ensp;기본 구조<br/>
```sql
SELECT 속성리스트
FROM 테이블리스트
[WHERE 조건]
[GROUP BY 속성리스트 [HAVING 조건]]
[ORDER BY 속성리스트 [ASC | DESC]];
```

&ensp;핵심 의미<br/>
* `GROUP BY`: 그룹 나누기
* `HAVING`: 그룹에 조건 걸기
* `ORDER BY`: 정렬하기

&ensp;대표 예제<br/>
&ensp;문제: 제품을 3개 이상 제조한 제조업체별로 제품 수와 최고가 검색<br/>
<p align="center"><img src="/assets/img/database/4주차/4-22.png" width="600"></p>

```sql
SELECT 제조업체, COUNT(*) AS 제품수, MAX(단가) AS 최고가
FROM 제품
GROUP BY 제조업체
HAVING COUNT(*) >= 3;
```

&ensp;해석 순서<br/>
1. 제품 테이블을 제조업체별로 묶음
2. 각 그룹마다 제품 수 계산
3. 각 그룹마다 최고 단가 계산
4. 그중 제품 수가 3개 이상인 그룹만 출력


<p align="center"><img src="/assets/img/database/4주차/4-23.png" width="600"></p>

&ensp;6. INSERT<br/>
&ensp;새로운 튜플을 삽입할 때 사용<br/>
&ensp;방식 1: 직접 삽입<br/>
```sql
INSERT INTO 테이블이름[(속성리스트)]
VALUES (속성값리스트);
```

&ensp;중요: 속성리스트와 값의 순서의 일대응 대응해야 한다.<br/>

&ensp;예제<br/>
```sql
INSERT INTO 고객(고객아이디, 고객이름, 나이, 등급, 직업, 적립금)
VALUES ('strawberry', '최유경', 30, 'vip', '공무원', 100);
```

&ensp;해석: 고객 테이블에 새로운 고객 1명을 추가하는 문장<br/>

&ensp;방식 2: SELECT 결과를 이용한 삽입<br/>
```sql
INSERT INTO 테이블이름[(속성리스트)]
SELECT ...
```

&ensp;예<br/>
```sql
INSERT INTO 대한제품(제품명, 재고량, 단가)
SELECT 제품명, 재고량, 단가
FROM 제품
WHERE 제조업체 = '한국제과';
```

&ensp;해석: 제품 테이블에서 한국제과 제품만 골라서 대한 제품 테이블에 복사해 넣는 것<br/>

&ensp;7. UPDATE<br/>
&ensp;저장도니 데이터를 수정할 때 사용<br/>
&ensp;기본 구조<br/>
```sql
UPDATE 테이블이름
SET 속성이름 = 값1, 속성이름 = 값2, ...
[WHERE 조건];
```

&ensp;중요: WHERE가 없으면 모든 행이 수정될 수 있음<br/>

&ensp;예제<br/>
```sql
UPDATE 제품
SET 제품명 = '통큰파이'
WHERE 제품번호 = 'p03';
```

&ensp;제품번호가 p03인 행의 제품명만 통큰파이로 수정<br/>

&ensp;서브쿼리 사용<br/>
```sql
UPDATE 주문
SET 수량 = 5
WHERE 주문고객 IN (
    SELECT 고객아이디
    FROM 고객
    WHERE 고객이름 = '정소화'
);
```

&ensp;해석<br/>
1. 고객 테이블에서 이름이 정소화인 고객의 ID를 찾고
2. 주문 테이블에서 그 고객이 주문한 행을 찾은 뒤
3. 수량을 5로 바꿈

&ensp;8. DELETE<br/>
&ensp;테이블에 저장된 데이터를 삭제할 때 사용<br/>
&ensp;기본 구조<br/>
```sql
DELETE
FROM 테이블이름
[WHERE 조건];
```

&ensp;중요: WHERE가 없으면 테이블의 모든 행이 삭제될 수 있음<br/>

&ensp;예제 1<br/>
```sql
DELETE
FROM 주문
WHERE 주문일자 = '2022-05-22';
```

&ensp;예제 2<br/>
```sql
DELETE
FROM 주문
WHERE 주문고객 IN (
    SELECT 고객아이디
    FROM 고객
    WHERE 고객이름 = '정소화'
);
```

# 7. DCL 정리

&ensp;데이터 제어어: GRANT / REVOKE / COMMIT / ROLLBACK<br/>
&ensp;DCL은 보안과 복구 관련 언어이다. 주로 DBA나 권한을 가진 사용자가 사용한다.<br/>

&ensp;1. 접근 제어 개념<br/>
&ensp;DBMS는 아무나 데이터에 접근하지 못하게 한다.<br/>

&ensp;데이터베이스 접근 과정<br/>
1. 로그인
2. 권한 확인
3. 허가되면 접근 가능

&ensp;계정이 있다고 끝이 아니라 **권한이 있어야 실제 테이블에 접근 가능**하다.<br/>

<p align="center"><img src="/assets/img/database/4주차/4-24.png" width="600"></p>

&ensp;2. GRANT<br/>
&ensp;권한을 부여하는 문<br/>

&ensp;객체 권한 부여<br/>
&ensp;개체(보통 테이블)의 소유자가 다른 사용자에게 그 객체에 대한 권한을 줌<br/>
&ensp;기본 구조<br/>
```sql
GRANT 권한 ON 객체 TO 사용자 [WITH GRANT OPTION];
```

&ensp;부여 가능한 주요 권한<br/>
* INSERT
* DELETE
* UPDATE
* SELECT
* REFERENCES

&ensp;PUBLIC: 모든 사용자에게 같은 권한을 줄 때 사용<br/>
&ensp;WITH GRANT OPTION: 권한을 받은 사용자가 그 권한을 다른 사람에게 다시 줄 수 있게 하는 옵션<br/>

<p align="center"><img src="/assets/img/database/4주차/4-25.png" width="600"></p>

&ensp;예제 1<br/>
&ensp;고객 테이블의 등급, 적립금 수정 권한을 Park에게 부여<br/>
```sql
GRANT UPDATE(등급, 적립금) ON 고객 TO Park;
```

&ensp;예제 2<br/>
&ensp;고객 테이블 조회 권한을 Lee에게, 재부여 가능하게 부여<br/>
```sql
GRANT SELECT ON 고객 TO Lee WITH GRANT OPTION;
```

&ensp;의미: Lee는 고객 테이블 조회 가능 그리고 Lee가 다른 사용자에게도 조회 권한을 줄 수 있음<br/>

&ensp;3. 시스템 권한 부여<br/>
&ensp;특정 테이블이 아니라 DB 전체 관리와 관련된 권한<br/>
<p align="center"><img src="/assets/img/database/4주차/4-26.png" width="600"></p>

&ensp;예<br/>
* CREATE TABLE
* CREATE VIEW

&ensp;특징<br/>
* DBA가 부여
* 객체 지정 필요 없음

&ensp;예<br/>
```sql
GRANT CREATE TABLE TO Song;
```

&ensp;4. RBAC<br/>
&ensp;Role-Based Access Control<br/>
&ensp;사용자에게 직접 권한을 하나하나 주는 대신 역할(Role) 을 만들고, 그 역할에 권한을 묶어서 사용자에게 부여하는 방식이다.<br/>

&ensp;예<br/>
* 교수자
* 학생
* 교직원
* 관리자

<p align="center"><img src="/assets/img/database/4주차/4-27.png" width="600"></p>

&ensp;5. REVOKE<br/>
&ensp;권한을 취소하는 문<br/>
&ensp;기본 구조<br/>
```sql
REVOKE 권한 ON 객체 FROM 사용자 CASCADE | RESTRICT;
```

&ensp;CASCADE와 RESTRICT 차이<br/>
&ensp;CASCADE<br/>
&nesp;연쇄적으로 부여된 권한까지 모두 취소<br/>

&ensp;RESTRICT<br/>
&ensp;직접 부여한 권한만 취소. 연쇄적으로 연결된 권한까지는 건드리지 않음<br/>

&ensp;예시<br/>
* Kim → Hong 에게 권한 부여
* Hong → Park 에게 다시 권한 부여

<p align="center"><img src="/assets/img/database/4주차/4-28.png" width="600"></p>
<p align="center"><img src="/assets/img/database/4주차/4-29.png" width="600"></p>

&ensp;이때 Kim이 Hong 권한을 취소할 때:<br/>
&ensp;1) CASCADE<br/>
```sql
REVOKE SELECT ON 고객 FROM Hong CASCADE;
```

&ensp;→ Hong도 취소, Park도 취소<br/>

&ensp;2) RESTRICT<br/>
```sql
REVOKE SELECT ON 고객 FROM Hong RESTRICT;
```

&ensp;→ 직접적인 취소만 고려<br/>
&ensp;조건에 따라 연쇄 권한이 있으면 제한될 수 있음<br/>

&ensp;시스템 권한 취소<br/>
&ensp;객체 지정 없이 취소 가능<br/>
```sql
REVOKE CREATE TABLE FROM Hong;
```

&ensp;6. COMMIT / ROLLBACK<br/>

&ensp;COMMIT<br/>
&ensp;지금까지 한 작업을 최종 저장<br/>

&ensp;ROLLBACK<br/>
&ensp;작업 중 문제가 생기면 원래 상태로 되돌림<br/>
