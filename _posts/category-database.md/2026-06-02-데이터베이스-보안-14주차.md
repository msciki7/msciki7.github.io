# 빅데이터 수집 단계의 보안 기술

&ensp;1. 빅데이터 수집 단계<br/>
&ensp;빅데이터 생명주기는 보통 다음과 같은 흐름으로 진행된다.<br/>
* 수집 → 저장 → 분석 → 활용 → 폐기

&ensp;수집 단계<br/>
&ensp;빅데이터는 여러 경로를 통해 모인다. 예를 들면 웹사이트 이용 기록, 앱 사용 기록, 위치 정보, 구매 기록, 센서 데이터, SNS 게시글 같은 것들이 있다. 이 데이터들은 형태에 따라 다음처럼 나눌 수 있다.<br/>

| 데이터 종류  | 설명                       | 예시                 |
| ------- | ------------------------ | ------------------ |
| 정형 데이터  | 표처럼 구조가 명확한 데이터          | 회원 정보, 주문 내역       |
| 반정형 데이터 | 구조는 있지만 완전히 표 형태는 아닌 데이터 | JSON, XML, 로그 파일   |
| 비정형 데이터 | 정해진 구조가 없는 데이터           | 이미지, 영상, 음성, SNS 글 |

&ensp;수집 단계가 제대로 안전하게 이루어지지 않으면 이후 분석 결과도 신뢰하기 어렵다.<br/>
&ensp;예를 들어 악의적인 사람이 잘못된 데이터를 섞어 넣거나 사용자의 동의 없이 민감한 정보를 수집하거나 수집 중 데이터가 유출되면 아무리 좋은 분석 기법을 써도 결과가 위험하거나 잘못될 수 있다.<br/>

&ensp;2. 수집 단계의 주요 보안 위협<br/>
&ensp;1) 무분별한 / 과도한 데이터 수집<br/>
&ensp;첫 번째 위협은 **정보 제공자의 명시적 동의와 관계없이 무분별하고 과도하게 수집되는 경우 ** 이다.<br/>
&ensp;= 사용자가 명확하게 동의하지 않았는데도 데이터를 너무 많이 수집하는 경우<br/>

&ensp;2) 옵트인(Opt-In)과 옵트아웃(Opt-Out)<br/>
&ensp;옵트인 방식<br/>
&ensp;옵트인은 **사용자가 먼저 동의해야 데이터를 수집할 수 있는 방식** 이다.<br/>
&ensp;기본값은 “수집하지 않음”이고, 사용자가 체크하거나 동의 버튼을 눌러야 수집이 가능하다.<br/>

&ensp;옵트아웃 방식<br/>
&ensp;옵트아웃은 반대로, **사용자가 거부 의사를 밝히지 않으면 동의한 것으로 보는 방식** 이다.<br/>
&ensp;즉, 기본값은 “수집함”이고, 사용자가 직접 거부해야 수집이 중단된다.<br/>

&ensp;3. 무분별한 데이터 수집의 문제점<br/>
&ensp;첫째, 정보 주권 침해<br/>
&ensp;정보 주권이란 내 정보에 대해 내가 통제할 권리라고 보면 된다.<br/>
&ensp;그런데 기업이나 서비스 제공자가 사용자의 정보를 과도하게 수집하면, 사용자는 자기 정보가 어디에 쓰이는지 통제하기 어려워진다.<br/>
&ensp;예를 들어 내가 단순히 배달 앱을 썼는데, 내 위치 기록, 결제 습관, 자주 먹는 음식, 활동 시간대까지 계속 분석된다면 내 생활 패턴이 노출될 수 있다.<br/>

&ensp;둘째, 민감한 데이터 유출 가능성<br/>
&ensp;사용자의 동의 없이 민감한 데이터가 수집되면, 나중에 그 데이터가 유출되었을 때 피해가 훨씬 크다.<br/>
&ensp;민감한 데이터에는 이런 것들이 포함될 수 있다.<br/>

| 민감한 데이터 예시 |
| ---------- |
| 주민등록번호     |
| 위치 정보      |
| 건강 정보      |
| 금융 정보      |
| 생체 정보      |
| 사생활 관련 정보  |

&ensp;그래서 수집 단계부터 “어떤 데이터를 왜 수집하는지”, “정말 필요한 데이터인지”를 따지는 게 중요하다.<br/>

&ensp;4. 데이터 유출<br/>
&ensp;정보 주체의 명시적 동의에 의해 올바르게 데이터가 수집되었다고 하더라도, 내부자 또는 외부자에 의해 데이터 유출이 발생할 수 있다.<br/>
&ensp;즉, 데이터 수집 자체는 합법적으로 했더라도 그 이후 과정에서 공격자가 데이터를 빼가면 문제가 생긴다.<br/>

&ensp;데이터 유출 공격 예시<br/>

| 공격 유형 | 설명                              |
| ----- | ------------------------------- |
| 피싱    | 가짜 사이트나 메시지로 사용자를 속여 정보를 빼내는 공격 |
| 스패밍   | 대량의 악성 메시지를 보내 사용자를 유도하는 공격     |
| 스푸핑   | 공격자가 정상 사용자나 서버인 것처럼 속이는 공격     |
| 스니핑   | 네트워크 상에서 오가는 데이터를 몰래 훔쳐보는 공격    |

&ensp;예를 들어 공공 와이파이에 접속했는데, 공격자가 같은 네트워크에서 내가 보내는 로그인 정보를 훔쳐본다면 이건 스니핑 공격에 가깝다. 또 가짜 로그인 페이지를 만들어 아이디와 비밀번호를 입력하게 만들면 피싱 공격이다.<br/>

&ensp;5. 데이터 중요성 인식 부족<br/>
&ensp;국내에서는 개인정보 수집 시 옵트인 방식, 즉 사용자의 동의를 받는 방식을 사용하지만, 문제는 사용자가 동의 내용을 자세히 읽지 않는 경우가 많다.<br/>

&ensp;6. 수집 단계 보안 위협 대응 기술<br/>

| 대응 기술               | 대응하는 위협                 |
| ------------------- | ----------------------- |
| 개인정보보호 데이터 수집, PPDC | 무분별한 / 과도한 데이터 수집       |
| 데이터 교란 기법           | 과도한 데이터 수집 방어           |
| 동형 암호               | 데이터 유용성과 프라이버시 보호 동시 달성 |
| 정보보호 교육 및 캠페인       | 인식 부족, 사회공학 공격 대응       |
| 관련 법과 제도 마련         | 불법 수집 및 데이터 주권 침해 방지    |
| 통신 보안               | 데이터 유출 방지               |
| VPN                 | 안전한 통신 경로 제공            |
| SSL/TLS             | 송수신 데이터 암호화             |

&ensp;1) 개인정보보호 데이터 수집, PPDC<br/>
&ensp;PPDC는 **Privacy-Preeserving Data Collection** 이다.<br/>
&ensp;말 그대로 개인정보를 보호하면서 데이터를 수집하는 기술이다.<br/>
> 데이터 수집 단계에서 개인정보보호를 달성하기 위해 사용할 수 있는 모든 기술

* 데이터 수집 단계에서 개인정보보호를 달성하기 위해 사용할 수 있는 모든 기술
* 정보 주체가 자신의 프라이버시 노출을 최소화하기 위해 사용
* 무분별한/과도한 데이터 수집에 대한 대응 보안 기술

&ensp;PPDC의 목적<br/>
1. 데이터 분석에 필요한 정보는 어느 정도 활용할 수 있게 한다.
2. 개인이 누구인지 드러나거나 민감한 정보가 노출되지 않도록 한다.

&ensp;데이터 교란 기법<br/>
&ensp;PPDC의 대표적인 방법 중 하나가 데이터 교란 기법이다.<br/>
&ensp;데이터 교란은 데이터를 교란하여 데이터 수집가가 데이터를 수집하더라도 고품질의 데이터를 확보하지 못하도록 방해하는 것이다.<br/해

&ensp;2) 동형 암호<br/>
&ensp;동형 암호는 데이터를 암호화한 상태에서 데이터에 대해 연산을 수행하면 복호화한 데이터(원본 데이터)를 통해 연산한 값과 동일한 결과가 나오게 하는 차세대 암호 기술<br/>
&ensp;원본 데이터가 공유되지 않아도 데이터의 유용성을 보장받는 점에서 데이터 분석과 프라이버시 보호 모두 달성할 수 있다.<br/>

&ensp;3) 정보보호 교육 및 캠페인<br/>
* 정보 주체의 데이터 중요성 인식 부족 위협과 사회공학 공격으로 인한 데이터 유출에 대응할 수 있는 보안 기술
* 국가 차원의 정보보호 교육 의무화하여 데이터 유츌 및 주권 침해 방지

&ensp;4) 관련 법과 제도 마련<br/>

&ensp;7. 통신 보안<br/>
&ensp;통신 보안은 데이터를 수집하는 과정에서 데이터가 안전하게 송수신되도록 보호하는 기술이다.<br/>

| 통신 보안 기술 | 설명                      |
| -------- | ----------------------- |
| VPN      | 가상의 사설 통신망을 만들어 안전하게 통신 |
| SSL/TLS  | 웹 통신에서 데이터를 암호화하여 전송    |

# 빅데이터 저장 단계의 보안기술

&ensp;1. 빅데이터 저장 단계<br/>
&ensp;저장 단계는 말 그대로 수집된 데이터를 관리하는 단계이다. 단순히 데이터를 DB나 클라우드에 넣어두는 것이 아니라, 데이터를 안전하게 관리하면서 발생할 수 있는 보안 위협을 식별하고 최소화해야 한다.<br/>
&ensp;특히 빅데이터는 한 사람의 데이터만 저장하는 게 아니라, 여러 정보 주체의 데이터가 대량으로 모여 있기 때문에 유출되면 사회적으로 큰 문제가 될 수 있다.<br/>

&ensp;저장 단계에서는 데이터 관리자가 중요하다.<br/>
<p align="center"><img src="/assets/img/database/14주차/14-3.png" width="600"></p>

&ensp;2. 저장 단계의 주요 보안 위협<br/>

| 저장 단계 보안 위협 | 의미                                    |
| ----------- | ------------------------------------- |
| 데이터 무결성 훼손  | 데이터가 허가 없이 변경되거나 손상되는 문제              |
| 데이터 유출      | 저장된 데이터가 내부자 또는 외부자에 의해 외부로 새어 나가는 문제 |
| 시스템 가용성 위협  | 사용자가 필요할 때 시스템을 정상적으로 이용하지 못하는 문제     |

&ensp;앞의 수집 단계에서는 과도한 수집, 데이터 유출, 인식 부족이 핵심이었다면, 저장 단계에서는 무결성, 유출, 가용성이 핵심이다.<br/>

&ensp;1) 데이터 무결성 훼손<br/>
&ensp;무결성은 쉽게 말해 데이터가 원래 상태 그대로 정확하게 유지되는 성질이다.<br/>
* 주로 데이터에 허가를 받지 않은 제 3의 악의적인 공격자나 내부자에 의해 발생
* 데이터 무결성이 훼손되면 데이터 품질 하락 -> 분석 단계에 악영향
* 데이터 품질 저하 문제를 해소하기 위해 매출에 많은 부분을 소비

&ensp;2) 데이터 유출<br/>
* 빅데이터 생명주기의 모든 단계에서 발생할 수 있는 위협
* 내부자에 의해 의도적으로 데이터 유출이 발생할 가능성 높음 -> 탐지가 매우 어렵기 때문에 적극적인 관리 감독 필요

&ensp;3) 시스템 가용성 위협<br/>
* 올바른 사용자가 적절한 때에 시스템을 사용하고 싶으면 언제든지 정상적으로 시스템을 이용할 수 있도록 보장하는 가용성을 보장하는 것이 중요

<p align="center"><img src="/assets/img/database/14주차/14-4.png" width="600"></p>

&ensp;3. 저장 단계 보안 위협 대응 기술<br/>

| 보안 위협      | 대응 보안 기술    |
| ---------- | ----------- |
| 데이터 무결성 훼손 | 접근제어, 보안 감사 |
| 데이터 유출     | 암호화, 보안 감사  |
| 시스템 가용성    | 분산화         |

&ensp;1) 접근제어<br/>
&ensp;접근제어는 데이터 무결성 훼손과 데이터 유출 위협을 최소화할 수 있는 기술이다.<br/>

&ensp;인증과 인가<br/>

| 개념 | 의미                     | 예시            |
| -- | ---------------------- | ------------- |
| 인증 | 사용자가 누구인지 확인           | 아이디/비밀번호 로그인  |
| 인가 | 인증된 사용자가 어떤 권한을 갖는지 확인 | 관리자만 회원 삭제 가능 |

&ensp;접근제어 모델<br/>

| 접근제어 모델   | 영어   | 핵심                          |
| --------- | ---- | --------------------------- |
| 임의적 접근제어  | DAC  | 데이터 소유자가 접근 권한 결정           |
| 강제적 접근제어  | MAC  | 시스템 정책에 따라 접근 결정            |
| 역할기반 접근제어 | RBAC | 사용자의 역할에 따라 접근 결정           |
| 속성기반 접근제어 | ABAC | 사용자, 자원, 환경 등의 속성에 따라 접근 결정 |

&ensp;적합한 모델 선택이 필요하다.<br/>

&ensp;2) 시스템 분산화<br/>
&ensp;스템 분산화는 주로 시스템 가용성을 보장하기 위한 기술이다.<br/>
* 빅데이터는 데이터의 양이 방대하고 관리가 까다롭기 때문에 일반적으로 분산화된 클라우드를 통해 관리

<p align="center"><img src="/assets/img/database/14주차/14-5.png" width="600"></p>

&ensp;3) 보안 감사<br/>
&ensp;시스템을 안전하게 보호하기 위해 시스템 내에 사용자가 수행한 일련의 작업을 로그에 저장하는 방법인 보안감사를 토대로 보안 사고 발생 여부 탐지 또는 모니터하는 방법<br/>
* 데이터가 완전 신뢰할 수 없는 제 3자(클라우드 서비스 제공자)에게 공유되기 때문에 주기적인 보안 감사 수행 필요 

&ensp;4) 암호화<br/>
&ensp;데이터가 유출되더라도 유출된 데이터의 내용을 알아볼 수 없게 하여 기밀성을 보호하는 것<br/>
&ensp;주로 대칭키 기술 사용<br/>
&ensp;대칭키와 공개키<br/>

| 구분     | 대칭키               | 공개키            |
| ------ | ----------------- | -------------- |
| 키 구조   | 암호화와 복호화에 같은 키 사용 | 공개키와 개인키 사용    |
| 속도     | 빠름                | 느림             |
| 적합한 용도 | 대용량 데이터 암호화       | 키 교환, 인증, 전자서명 |
| 예시     | AES               | RSA            |

&ensp;속성기반 암호화(Attribute-Based Encryption), ABE<br/>
&ensp;속성기반 암호화는 단순한 암호화가 아니라 암호화 + 접근제어의 성격을 함께 가진 기술이다.<br/>
> 적합한 속성을 가진 사용자만 데이터를 암호화하도록 하는 기술

&ensp;CP-ABE와 KP-ABE<br/>
&ensp;속성기반 암호화를 두 가지로 나눈다.<br/>
| 구분     | 이름                    | 핵심              |
| ------ | --------------------- | --------------- |
| CP-ABE | Ciphertext-Policy ABE | 암호문에 접근 정책이 포함됨 |
| KP-ABE | Key-Policy ABE        | 키에 접근 정책이 포함됨   |

&ensp;전체 암호화와 일부 컬럼 암호화<br/>
&ensp;암호화는 크게 두 방식으로 생각할 수 있다.<br/>

| 방식         | 설명              | 장점               | 고려할 점         |
| ---------- | --------------- | ---------------- | ------------- |
| 모든 데이터 암호화 | 저장된 모든 데이터를 암호화 | 높은 보안 가능         | 성능, 접근성 저하 가능 |
| 일부 컬럼 암호화  | 민감한 컬럼만 암호화     | 효율성, 가용성, 접근성 확보 | 보호 범위 제한      |

# 빅데이터 분석 단계의 보안기술

&ensp;1. 빅데이터 분석 단계<br/>
&ensp;분석 단계는 저장 단계에서 관리되고 있던 데이터를 이용해서 의미 있는 결과를 찾아내는 단계<br/>
> 개인정보처리자가 데이터를 비식별화 처리한 후, 데이터 분석가가 데이터 분석을 수행하는 단계

&ensp;2. 분석 단계의 주요 보안 위협<br/>

| 분석 단계 보안 위협 | 의미                              |
| ----------- | ------------------------------- |
| 개인 식별 가능성   | 분석 과정에서 특정 개인이 누구인지 드러날 수 있는 문제 |
| 데이터 유출      | 분석 과정에서 데이터가 외부로 새어 나가는 문제      |

&ensp;1) 개인 식별 가능성<br/>
* 분석 단계 보안 위협 = 개인 식별 가능성 + 데이터 유출
* 개인정보 처리자와 데이터 분석가 모두에 의해 발생 가능

&ensp;개인 식별<br/>
&ensp;개인 식별은 말 그대로 특정 개인이 누구인지 알아내는 것이다.<br/>
* 특정 개인을 개인 식별 정보를 통해 식별
* 재식별을 통한 개인 식별: 개인 식별 정보가 제거된 상황에서도 다른 데이터와 결합하여 특정 개인을 식별하는 경우

&ensp;개인 식별 정보, PII<br/>
* PII는 Personal Identifiable Information의 약자
* 정보 주체를 특정하여 식별할 수 있는 모든 정보

&ensp;개인정보처리자와 데이터 분석가 모두 위험 요인이 될 수 있다.<br/>
<p align="center"><img src="/assets/img/database/14주차/14-7.png" width="600"></p>

&ensp;2) 데이터 유출<br/>
* 빅데이터 생명주기 전 주기에서 발생 가능한 위협으로 기존 보유 기술을 동일하게 적용 필요

# 분석 단계 보안 위협 대응 기술

| 보안 위협     | 대응 보안 기술                       |
| --------- | ------------------------------ |
| 개인 식별 가능성 | 비식별화, 프라이버시 보존형 데이터 마이닝, 보안 감사 |
| 데이터 유출    | 보안 감사                          |

&ensp;1. 비식별화, De-Identification<br/>
&ensp;1) 비식별화란?<br/>
&ensp;비식별화는 데이터 집합에서 개인 식별 정보를 제거해서 특정 개인을 식별할 수 없도록 하는 기술이다.<br/>
> 데이터 집합에서 개인 식별 정보를 제거함으로써 특정 개인을 식별할 수 없도록 하는 기술

&ensp;2) 비식별화는 언제 수행되는가?<br/>
&ensp;비식별화가 관점이나 활용 목적에 따라 빅데이터 생명주기의 여러 단계 중 하나에서 수행될 수 있다.<br/>
&ensp;예를 들어 다음 단계에서 수행될 수 있다.<br/>

| 단계     | 비식별화 가능성              |
| ------ | --------------------- |
| 데이터 수집 | 수집할 때부터 식별 정보를 줄여서 수집 |
| 데이터 저장 | 저장 전에 민감 정보를 제거하거나 변환 |
| 데이터 변환 | 분석용 데이터셋으로 바꾸면서 처리    |
| 데이터 활용 | 외부 제공 또는 서비스 활용 전에 처리 |

&ensp;2. 비식별화 데이터 유형<br/>
<p align="center"><img src="/assets/img/database/14주차/14-8.png" width="600"></p>

&ensp;비식별화 과정은 이 위험을 낮추는 방향으로 데이터를 처리하는 과정<br/>

&ensp;3. 비식별화 처리 기법<br/>

| 비식별화 기법 | 의미                              |
| ------- | ------------------------------- |
| 가명처리    | 이름이나 식별자를 다른 값으로 바꾸는 방법         |
| 데이터 마스킹 | 일부 정보를 가리는 방법                   |
| 범주화     | 구체적인 값을 범위나 그룹으로 바꾸는 방법         |
| 삭제      | 식별 정보를 제거하는 방법                  |
| 총계처리    | 개별 데이터 대신 합계, 평균 등 통계값으로 바꾸는 방법 |

<p align="center"><img src="/assets/img/database/14주차/14-9.png" width="600"></p>

&ensp;4. 비식별화의 한계<br/>
&ensp;개인정보처리자가 의도적으로 비식별화를 하지 않거나, 완전하지 않은 비식별화를 한 데이터를 분석가에게 제공할 가능성이 있다.<br/>
&ensp;또한 비식별화된 데이터라도 다른 데이터와 결합하면 재식별될 수 있다.<br/>
<p align="center"><img src="/assets/img/database/14주차/14-10.png" width="600"></p>

&ensp;5. 비식별화 절차<br/>
<p align="center"><img src="/assets/img/database/14주차/14-11.png" width="600"></p>

&ensp;**개인정보 → 비식별 조치 → 비식별 적정성 평가 → 비식별 정보** <br/>

&ensp;K-익명성은 비식별화가 충분한지 평가할 때 사용하는 대표적인 모델이다.<br/>
> 같은 속성을 가진 사람이 최소 K명 이상 존재하도록 만들어 특정 개인을 구분하기 어렵게 하는 것

&ensp;L-다양성<br/>
&ensp;L-다양성은 K-익명성의 한계를 보완하는 모델이다.<br/>
&ensp;K-익명성은 같은 그룹 안에 사람이 여러 명 있으면 안전하다고 보지만, 만약 그 그룹의 민감 정보가 모두 같다면 문제가 생긴다. 그래서 L-다양성은 같은 그룹 안의 민감한 값이 충분히 다양해야 한다는 개념이다.<br/>

&ensp;6. 분석 단계 보안 위협 대응 기술<br/>
&ensp;1) 프라이버시 보존형 데이터 마이닝, PPDM<br/>
&ensp;PPDM은 Privacy Preserving Data Mining의 약자<br/>
> 데이터 분석가가 데이터 분석을 진행하는 과정에서 특정 개인을 식별할 수 없도록 하는 기술

&ensp;분석과정에 데이터 교란(예: 노이즈 추가)를 발생시키는 방법으로 차분 프라이버시 기법 널리 사용<br/>

&ensp;프라이버시와 데이터 효용성의 트레이드오프<br/>

| 프라이버시 보호 수준 | 데이터 효용성  |
| ----------- | -------- |
| 높아짐         | 낮아질 수 있음 |
| 낮아짐         | 높아질 수 있음 |

&ensp;관계 분석을 통해 균형을 적절히 맞추는 것이 중요<br/>

&ensp;2) 보안 감사<br/>
* 내부자에 의한 불법적이고 의도적인 행위를 탐지하는데 확실한 방법으로 보안 사고 발생 시 로그를 통해 행적 분석 가능
*  개인정보처리자의 데이터 유출과 데이터 분석가의 개인 식별 가능성 위협을 최소화하도록 로그를 남겨 주기적 행적 조회 및 악의적인 행동 탐지

&ensp;7. 정리<br/>

| 보안 위협     | 대응 보안 기술                  |
| --------- | ------------------------- |
| 개인 식별 가능성 | 비식별화, 프라이버시 보존 마이닝, 보안 감사 |
| 데이터 유출    | 보안 감사                     |

| 대응 기술        | 예시                          |
| ------------ | --------------------------- |
| 비식별화         | 마스킹, 총계처리, 가명처리, 삭제, 범주화    |

| 보안 감사        | 로그 저장, 주기적 행적 조회, 악의적 행동 탐지 |

# 빅데이터 활용 단계의 보안 기술

&ensp;1. 빅데이터 활용 단계란?<br/>
&ensp;활용 단계는 분석된 데이터를 외부 제3자에게 공개하거나 공유하는 단계<br/>
&ensp;활용 단계는 데이터 공유가 이루어진 뒤에는 위협을 최소화할 방안이 거의 없기 때문에 보안 관리자의 지속적인 감독이 필요하다.<br/>

> 데이터가 외부로 공유되기 전에 재식별 위험을 최대한 줄여야 한다.

&ensp;2. 활용 단계의 핵심 보안 위협<br/>
&ensp;1) 재식별<br/>
&ensp;재식별은 개인 식별 정보가 제거된 상황에서도 다른 데이터와 결합하여 특정 개인을 식별하는 것<br/>

&ensp;3. 활용 단계 대응 기술<br/>
&ensp;1) 비식별화<br/>
&ensp;비식별화는 개인 식별 정보, PII를 제거하거나 변형하여 특정 개인을 식별할 수 없도록 하는 기술이다.<br/>

| 비식별화 방법 | 설명                        |
| ------- | ------------------------- |
| 총계처리    | 개별 데이터 대신 합계, 평균 등 통계값 사용 |
| 데이터 마스킹 | 일부 정보를 `OO`, `****`처럼 가림  |
| 가명화     | 이름이나 식별자를 다른 값으로 대체       |
| 데이터 삭제  | 식별 가능성이 높은 정보를 제거         |
| 데이터 범주화 | 구체적인 값을 범위나 그룹으로 변환       |

&ensp;4. 프라이버시 보호 모델<br/>
&ensp;프라이버시 보호 모델은 비식별화된 데이터를 평가하기 위한 기준이다.<br/>

| 프라이버시 보호 모델 | 영어          | 핵심                                      |
| ----------- | ----------- | --------------------------------------- |
| K-익명성       | K-Anonymity | 같은 준식별자 조합을 가진 사람이 최소 K명 이상 존재          |
| l-다양성       | l-Diversity | 같은 익명 그룹 안에 민감 정보가 최소 l개 이상 다양하게 존재     |
| T-근접성       | T-Closeness | 각 그룹의 민감 정보 분포가 전체 데이터 분포와 너무 다르지 않게 유지 |

> K-익명성 → l-다양성 → T-근접성 뒤로 갈수록 앞 모델의 한계를 보완한다.

&ensp;5. 식별자와 준식별자<br/>
* 식별자: 식별자는 그 자체만으로 개인을 식별할 수 있는 정보
* 준식별자: 준식별자는 혼자서는 개인을 바로 식별하기 어렵지만, 다른 정보와 결합하면 개인을 식별할 수 있는 정보

&ensp;6. K-익명성<br/>
&ensp;K-익명성은 연결 공격으로부터 재식별을 막기 위해 등장한 프라이버시 보호 모델이다.<br/>
*  주어진 데이터 집합에서 동일한 값이 최소 K개 이상 존재하도록 하여 개인을 익명화하는 방식
* 준식별자를 통해 개인 식별을 시도하더라도 K-1명의 데이터 집합과 함께 K개의 집합이 나오도록 하여 추론을 방지

&ensp;겉으로 보면 4명 중 하나라서 정확히 알 수 없어 보이지만, 공격자는 배경지식으로 여성은 전립선염에 걸리지 않는다는 사실을 알고 있다. 이지민 씨는 여성이므로 전립선염 가능성을 제외하면 남는 것은 고혈압이다.<br/>
&ensp;즉, K=4 익명성이 적용되었지만 배경지식을 이용하면 민감 정보가 추론될 수 있다.<br/>

&ensp;8. 동질성 공격<br/>
&ensp;동질성 공격은 같은 익명 그룹 안의 민감 정보가 모두 같거나 거의 같을 때 발생한다.<br/>
&ensp;료의 K-익명성 한계 예시에서 9~12번 그룹을 보면 질병이 모두 위암이다.<br/>

| 지역 코드 | 연령 | 성별 | 질병 |
| ----- | -- | -- | -- |
| 130** | 3* | *  | 위암 |
| 130** | 3* | *  | 위암 |
| 130** | 3* | *  | 위암 |
| 130** | 3* | *  | 위암 |

&ensp;이 경우 K=4라서 한 명을 정확히 특정할 수는 없다. 하지만 해당 그룹에 속한다는 것만 알면 그 사람의 질병이 위암이라는 것을 알 수 있다.<br/>
&ensp;즉, 개인의 이름을 특정하지 못해도 민감 정보가 드러난다.<br/>

&ensp;9. l-다양성<br/>
&ensp;K-익명성의 한계를 보완하기 위해 등장한 것이 l-다양성이다.<br/>
> 데이터 집합에서 함께 익명화되는 레코드들은 적어도 l개 이상 서로 다른 데이터를 가지도록 하는 것

&ensp;l-다양성 예시<br/>
&ensp;l=3<br/>
<p align="center"><img src="/assets/img/database/14주차/14-15.png" width="600"></p>

&ensp;이 그룹에는 적어도 3개의 서로 다른 질병이 있다. 따라서 공격자가 어떤 사람이 이 그룹에 속한다는 것을 알아도, 그 사람의 질병을 하나로 확정하기 어려워진다.<br/>

&ensp;l-다양성의 취약점<br/>

| l-다양성의 취약점 | 설명                             |
| ---------- | ------------------------------ |
| 쏠림 공격      | 전체 데이터 분포가 한쪽으로 치우쳐 있을 때 발생    |
| 유사성 공격     | 민감 정보 값들이 서로 다르지만 의미상 비슷할 때 발생 |

&ensp;쏠림 공격<br/>
&ensp;쏠림 공격은 데이터 집합 내에서 데이터 분포가 한쪽으로 치우쳐 있을 때 발생할 수 있는 공격이다.<br/>
> 쏠림 공격은 전체 데이터의 민감 정보 분포가 한쪽으로 치우쳐 있을 때, 특정 그룹의 분포 차이를 이용해 개인의 민감 정보를 추론하는 공격이다.

<p align="center"><img src="/assets/img/database/14주차/14-16.png" width="600"></p>

&ensp;유사성 공격<br/>
&ensp;유사성 공격은 민감 정보 값들이 서로 다르긴 하지만 의미상 매우 비슷할 때 발생한다.<br/>
> 유사성 공격은 민감 정보 값들이 서로 다르더라도 의미상 유사하여 특정 개인의 민감한 특성을 추론할 수 있는 공격이다.

<p align="center"><img src="/assets/img/database/14주차/14-17.png" width="600"></p>

&ensp;10. T-근접성<br/>
&ensp;l-다양성의 취약점을 해결하기 위해 등장한 것이 T-근접성이다.<br/>
> 데이터 집합에서의 특정 데이터 분포가 전체 데이터 집합에서의 분포와 비교하여 T 이하의 차이가 보이도록 하는 것

&ensp;한 그룹만 지나치게 특이한 분포를 가지면 공격자가 그 특이성을 이용해서 민감 정보를 추론할 수 있으니까, 그룹별 분포를 전체 분포와 비슷하게 맞추는 것이다.<br/>

&ensp;T-근접성 예시<br/>
<p align="center"><img src="/assets/img/database/14주차/14-18.png" width="600"></p>

&ensp;한 그룹에 급여가 30, 50, 90처럼 다양하고, 질병도 위궤양, 만성 위염, 폐렴처럼 다양하게 섞여 있다. 다른 그룹도 급여와 질병이 고르게 분포되도록 구성되어 있다. 이렇게 하면 특정 그룹이 전체 데이터와 지나치게 다른 특징을 갖지 않기 때문에 재식별 위험이 낮아진다.<br/>

# 빅데이터 폐기 단계의 보안기술

&ensp;1. 빅데이터 폐기 단계란?<br/>
&ensp;폐기 단계는 단순히 “파일 삭제 버튼을 누르는 것”이 아니라, 정보 주체가 더 이상 데이터 수집이나 보관을 원하지 않거나, 데이터 보관 목적이 끝났을 때 해당 데이터를 안전하게 제거하는 단계이다.<br/>

&ensp;저장 및 활용 단계와 밀접한 관련<br/>
&ensp;옵트아웃은 사용자가 “내 데이터를 더 이상 수집하지 말라”는 거부 의사를 밝히는 방식이야. 사용자가 데이터 수집 거부 의사를 밝히면 수집을 중단해야 하고, 데이터 삭제를 요구하면 해당 데이터도 삭제해야 한다.<br/>

&ensp;폐기 단계는 정보 주체의 데이터 주권과 직접 연결된다.<br/>

<p align="center"><img src="/assets/img/database/14주차/14-19.png" width="600"></p>

&ensp;2. 폐기 단계에서 발생하는 문제<br/>

| 문제 상황                  | 설명                                      |
| ---------------------- | --------------------------------------- |
| 삭제했다고 알리고 실제로는 삭제하지 않음 | 사용자에게는 삭제 완료라고 하지만 데이터가 여전히 남아 있음       |
| 의도치 않은 이유로 삭제하지 못함     | 시스템 문제, 백업 구조, 분산 저장 구조 때문에 완전히 삭제되지 않음 |

&ensp;3. 데이터 잔존<br/>
&ensp;데이터 잔존이란 폐기되어야 할 데이터가 실제로는 삭제되지 않고 저장소에 그대로 남아 있는 상태를 의미한다.<br/>
&ensp;빅데이터 환경에서는 이 문제가 더 심각해질 수 있다. 데이터가 여러 서버, 백업 저장소, 클라우드, 로그 시스템 등에 분산되어 있기 때문이다.<br/>

&ensp;4. 폐기 단계의 주요 보안 위협<br/>
&ensp;1) 데이터 유출<br/>

| 보안 위협  | 원인     |
| ------ | ------ |
| 데이터 유출 | 데이터 잔존 |

&ensp;폐기 단계에서는 데이터가 제대로 삭제되지 않고 남아 있다가 유출되는 것<br/>
> 폐기되어야 할 데이터가 폐기되지 않고 데이터 저장소에 그대로 유지되면 데이터 유출 위협으로 이어지기 때문에 주요 취약점이 된다.

&ensp;데이터 폐기는 정보 주체의 데이터 주권 보장<br/>
&ensp;데이터 폐기가 정보 주체의 데이터 주권을 보장하기 위한 필수 요구사항이다.<br/>

| 정보 주체의 권리 | 의미                         |
| --------- | -------------------------- |
| 수집 거부     | 더 이상 내 데이터를 수집하지 말라고 요구    |
| 삭제 요구     | 이미 수집된 내 데이터를 삭제해 달라고 요구   |
| 활용 제한     | 내 데이터를 특정 목적으로 사용하지 말라고 요구 |
| 보관 중단     | 더 이상 내 데이터를 보관하지 말라고 요구    |

&ensp;5. 폐기 단계 보안 위협 대응 기술<br/>

| 대응 기술 | 핵심                              |
| ----- | ------------------------------- |
| 오버라이팅 | 기존 데이터가 있던 위치에 다른 데이터를 반복해서 덮어씀 |
| 디가우싱  | 강한 자기장을 이용해 저장매체의 데이터를 파괴함      |

&ensp;1) 오버라이팅<br/>
&ensp;오버라이팅은 기존 데이터가 저장된 위치에 새로운 데이터를 여러 번 덮어써서 원래 데이터를 알아볼 수 없게 만드는 기술이다.<br/>
&ensp;컴퓨터 저장장치에서는 기존 데이터가 있던 공간에 0이나 1 같은 값을 반복적으로 써서 원래 데이터를 복구하기 어렵게 만들다.<br/>

| 방식        | 설명                      |
| --------- | ----------------------- |
| 0으로 덮어쓰기  | 저장 공간을 0으로 채움           |
| 1로 덮어쓰기   | 저장 공간을 1로 채움            |
| 문자열로 덮어쓰기 | 특정 문자열이나 패턴으로 덮어씀       |
| 표준 기반 삭제  | NIST SP 800-88 같은 표준 참조 |

&ensp;오버라이팅의 장점<br/>

| 장점             | 설명                 |
| -------------- | ------------------ |
| 저장장치 재사용 가능    | 디스크 자체를 파괴하지 않음    |
| 소프트웨어적으로 수행 가능 | 별도 장비 없이 프로그램으로 가능 |
| 비용이 상대적으로 낮음   | 물리적 파괴보다 경제적       |

&ensp;오버라이팅의 한계<br/>
&ensp;빅데이터 특성상 클라우드 서비스를 널리 사용하기 때문에 문제가 발생한다.<br/>
&ensp;클라우드 환경에서는 데이터가 한 곳에만 저장되어 있지 않는다. 여러 서버, 여러 디스크, 여러 복제본, 여러 백업에 분산되어 있을 수 있다. 그래서 데이터가 정확히 어느 위치에 저장되어 있는지 파악하기 어렵고, 오버라이팅을 수행해야 할 모든 위치를 찾기 어렵다.<br/>

&ensp;2) 디가우싱<br/>
&ensp;디가우싱은 강한 자기장을 이용해서 디스크의 데이터를 파괴하여 복구 불가능하게 만드는 방법이다.<br/>

&ensp;디가우싱의 특징<br/>
&ensp;디가우싱은 데이터 복구를 어렵게 만드는 강력한 방식이다.<br/>
&ensp;하지만 디가우싱을 하면 디스크를 재사용할 수 없다.<br/>

| 기술    | 디스크 재사용 |
| ----- | ------- |
| 오버라이팅 | 가능      |
| 디가우싱  | 불가능     |

&ensp;디가우싱은 클라우드 서비스를 주로 이용하는 빅데이터 환경에 부적합<br/>
&ensp;-> 클라우드 환경에서는 사용자가 직접 물리적 디스크에 접근할 수 없기 때문<br/>

&ensp;오버라이팅과 디가우싱 비교<br/>

| 구분          | 오버라이팅                  | 디가우싱                     |
| ----------- | ---------------------- | ------------------------ |
| 방식          | 같은 위치에 데이터를 반복해서 덮어씀   | 강한 자기장으로 데이터 파괴          |
| 성격          | 소프트웨어적 방식              | 물리적/장비 기반 방식             |
| 저장매체 재사용    | 가능                     | 불가능                      |
| 장점          | 비용 낮음, 재사용 가능          | 복구 방지 효과 강함              |
| 단점          | 클라우드 분산 환경에서 위치 파악 어려움 | 디스크 재사용 불가, 클라우드 환경에 부적합 |
| 빅데이터 환경 적합성 | 제한적                    | 부적합한 경우 많음               |
