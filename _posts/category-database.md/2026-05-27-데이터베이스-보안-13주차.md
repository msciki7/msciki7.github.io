# 빅데이터 개요

&ensp;1. 빅데이터가 등장한 배경<br/>
&ensp;빅데이터는 **인터넷, 스마트폰, SNS, 인공지능, 사물인터넷 같은 기술 발전 때문에 데이터가 폭발적으로 많아지면서 등장한 개념** 이다.<br/>

| 등장 배경            | 의미                                    |
| ---------------- | ------------------------------------- |
| 인터넷의 확산          | 웹사이트, 검색, 게시글, 댓글 등 데이터가 엄청나게 생성됨     |
| 개인화 서비스와 SNS의 확산 | 사용자의 취향, 행동, 관계, 위치, 게시글 등이 계속 쌓임     |
| 스마트폰의 보급         | 위치 정보, 사진, 영상, 앱 사용 기록 등 데이터가 빠르게 축적됨 |

&ensp;2. ICT 발전에 따른 데이터 변화<br/>
<p align="center"><img src="/assets/img/database/13주차/13-1.png" width="600"></p>

&ensp;예전에는 데이터가 주로 **정형 데이터** 였다. 예를 들면 회사 DB에 저장된 회원 정보, 사무 문서, 숫자 데이터 같은 것들이다. 그런데 인터넷과 모바일이 발전하면서 SNS 글, 사진, 영상, 음성처럼 구조가 딱 정해져 있지 않은 **비정형 데이터** 가 많아졌고 사물인터넷과 센서 기술이 발전하면서  RFID, 센서 데이터 같은 사물 정보·인지 정보도 생겨났다.<br/>

| 시대         | 데이터 특징                       |
| ---------- | ---------------------------- |
| 과거         | 데이터베이스, 사무 정보 중심             |
| 인터넷·모바일 시대 | SNS, 멀티미디어, 웹 데이터 증가         |
| 스마트 시대     | 센서, RFID, 사물 정보, 인공지능 데이터 증가 |

&ensp;3. 빅데이터의 정의<br/>
&ensp;기존 데이터에 비해 너무 커서 기존 방법이나 도구로 수집, 저장, 검색, 분석, 시각화 등이 어려운 정형 또는 비정형 데이터<br/>

&ensp;빅데이터는 단순히 "용량이 큰 데이터"가 아니다.<br/>
&ensp;기존의 엑셀, 일반 DB, 단순 분석 도구만으로는 처리하기 힘들 만큼 데이터가 크고 복잡한 상태를 말한다.<br/>

&ensp;4. 빅데이터는 “데이터 자체”이면서 “기술 분야”이기도 하다.<br/>

| 관점        | 설명                                      |
| --------- | --------------------------------------- |
| 데이터 특성 측면 | 기존 방식으로 처리하기 어려운 방대한 정형·반정형·비정형 데이터의 집합 |
| 기술 분야 측면  | 데이터를 수집, 저장, 관리, 분석, 시각화하는 정보통신 기술 분야   |

&ensp;빅데이터는 **큰 데이터 그 자체** 를 의미하기도 하고 그 데이터를 다루기 위한 기술과 시스템 전체를 의미하기도 한다.<br/>
&ensp;예를 들어 유튜브 영상 시청 기록 수십억 건은 빅데이터이다. 그 데이터를 저장하고 분석해서 추천 알고리즘을 만드는 기술도 빅데이터 기술이다.<br/>

&ensp;5. 빅데이터 유형<br/>

&ensp;1) 정형 데이터<br/>
&ensp;정형 데이터는 **미리 정해진 형식과 구조에 따라 저장되는 데이터** 이다.<br/>

&ensp;대표 예시<br/>

| 예시             | 설명                                  |
| -------------- | ----------------------------------- |
| 관계형 데이터베이스 테이블 | MySQL, Oracle, PostgreSQL 같은 DB 테이블 |
| 스프레드시트         | 엑셀 파일                               |
| CSV 데이터        | 콤마로 구분된 파일                          |

&ensp;이런 데이터는 컬럼이 정해져 있다.<br/>

&ensp;특징<br/>
&ensp;정형 데이터는 구조가 명확하기 때문에 검색, 수정, 삭제, 조회가 쉽다.<br/>

&ensp;2) 반정형 데이터<br/>
&ensp;반정형 데이터는 **완전히 표처럼 정해져 있지는 않지만 데이터 안에 구조 정보가 함께 들어 있는 데이터** 이다.
&ensp;정형 데이터처럼 고정된 행과 열이 있는 건 아니지만 태크나 key-value 구조를 통헤 어느 정도 규칙을 가지고 있다.<br/>

&ensp;대표 예시<br/>

| 예시   | 설명                   |
| ---- | -------------------- |
| HTML | 웹페이지 구조를 표현          |
| XML  | 태그 기반 데이터 표현         |
| RDF  | 자원 간 관계 표현           |
| JSON | key-value 형식의 데이터 표현 |

&ensp;장점<br/>
* 반정형 데이터는 스키마 수정이 쉽다.
* 파일 단위로 구성되어 있어서 전송과 공유가 편하다.

&ensp;단점<br/>
* 반정형 데이터는 정형 데이터보다 질의 처리가 어렵다.
    - 분석할 때는 보통 JSON이나 XML을 바로 분석하기보다 CSV나 테이블 형태로 변환해서 사용하는 경우가 많다. 

> 반정형 데이터 = 정해진 테이블 구조는 없지만, JSON/XML처럼 데이터 안에 구조 정보가 포함된 데이터

&ensp;3) 비정형 데이터<br/>
&ensp;비정형 데이터는 **정의된 구조가 없는 데이터** 이다.<br/>
&ensp;행과 열도 없고 key-value 구조도 명확하지 않은 데이터이다.<br/>

&ensp;대표 예시<br/>
<p align="center"><img src="/assets/img/database/13주차/13-2.png" width="600"></p>

&ensp;비정형 데이터는 구조가 없기 때문에 컴퓨터가 바로 이해하기 어렵다. 그래서 데이터 분석이나 AI 모델에 넣기 전에 **특징을 추출해서 정형 또는 반정형 데이터로 바꾸는 전처리 과정** 이 필요하다.<br/>

| 데이터 종류 | 전처리 예시                |
| ------ | --------------------- |
| 텍스트    | 자연어 처리, 토큰화, 불용어 제거   |
| 이미지    | 픽셀값 변환, 크기 조정, 노이즈 제거 |
| 음성     | 주파수 변환, 노이즈 제거        |
| 영상     | 프레임 추출, 객체 탐지         |

&ensp;6. 정형·반정형·비정형 데이터 비교<br/>

| 구분      | 정형 데이터          | 반정형 데이터         | 비정형 데이터          |
| ------- | --------------- | --------------- | ---------------- |
| 구조      | 고정된 구조 있음       | 어느 정도 구조 있음     | 정해진 구조 없음        |
| 형태      | 행과 열            | 태그, key-value   | 텍스트, 이미지, 영상, 음성 |
| 예시      | DB 테이블, 엑셀, CSV | HTML, XML, JSON | 사진, 동영상, 문서, 메일  |
| 분석 난이도  | 쉬움              | 중간              | 어려움              |
| 전처리 필요성 | 낮음              | 경우에 따라 필요       | 높음               |
| 장점      | 검색·수정·삭제 쉬움     | 유연하고 공유 쉬움      | 현실의 다양한 정보 반영    |
| 단점      | 구조 변경이 불편함      | 질의 처리가 어려울 수 있음 | 바로 분석하기 어려움      |

# 빅데이터 속성

&ensp;1. 공통적 특성 3V<br/>

| 구분    | 영어       | 의미                    |
| ----- | -------- | --------------------- |
| 규모/크기 | Volume   | 데이터의 양이 매우 많음         |
| 속도    | Velocity | 데이터가 빠르게 생성되고 처리되어야 함 |
| 다양성   | Variety  | 데이터 형태가 다양함           |

&ensp;Volume — 데이터의 크기<br/>
&ensp;Volume은 데이터의 양, 크기를 의미한다.<br/>
* 단순 저장되는 물리적인 데이터 양
* 빅데이터의 가장 기본적인 특징
* 테라바이트(TB) 단위 이상의 대량 데이터

&ensp;데이터 단위<br/>

| 단위  | 관계     |
| --- | ------ |
| 1TB | 1024GB |
| 1PB | 1024TB |
| 1EB | 1024PB |
| 1ZB | 1024EB |
| 1YB | 1024ZB |

&ensp;GB → TB → PB → EB → ZB → YB<br/>

&ensp;Velocity — 데이터의 속도<br/>
&ensp;Velocity는 데이터가 얼마나 빠르게 생성되고 얼마나 빠르게 처리되어야 하는지를 의미한다.<br/>
&ensp;수집 → 저장 → 분석 → 시각화.<br/>
&ensp;이 과정이 정해진 시간 안에 빠르게 이루어져야 함<br/>

&ensp;Variety — 데이터의 다양성<br/>
&ensp;Variety는 다양한 형태의 데이터를 포함한다는 뜻이다.<br/>

| 데이터 유형  | 예시                    |
| ------- | --------------------- |
| 정형 데이터  | DB 테이블, CSV, 엑셀       |
| 반정형 데이터 | JSON, XML, HTML       |
| 비정형 데이터 | 사진, 영상, 음성, 문서, SNS 글 |

&ensp;2. 확장된 특성: 4V, 5V, 6V, 7V<br/>

| 확장 속성 | 영어            | 의미                           |
| ----- | ------------- | ---------------------------- |
| 진실성   | Veracity      | 데이터가 정확하고 신뢰할 수 있어야 함        |
| 가치    | Value         | 분석 결과가 실제 의사결정에 도움이 되어야 함    |
| 가변성   | Variability   | 데이터의 의미가 상황과 맥락에 따라 달라질 수 있음 |
| 시각화   | Visualization | 분석 결과를 이해하기 쉽게 보여줘야 함        |

&ensp;Veracity — 데이터의 진실성<br/>
&ensp;Veracity는 데이터가 정확하고 신뢰할 수 있어야 한다.<br/>
&ensp;빅데이터는 양이 많기 때문에 좋은 데이터만 모이는 게 아니다. 잘못된 데이터, 중복 데이터, 의미 없는 데이터, 오류 데이터도 같이 들어올 수 있다.<br/>
&ensp;그래서 분석 전에 이런 작업이 필요하다.<br/>

| 작업     | 의미            |
| ------ | ------------- |
| 데이터 확인 | 이상한 값이 있는지 확인 |
| 데이터 삭제 | 필요 없는 데이터 제거  |
| 전처리    | 분석 가능한 형태로 정리 |
| 신뢰성 확보 | 정확도 높은 데이터 유지 |

&ensp;Value — 데이터의 가치<br/>
&ensp;Value는 빅데이터 분석 결과가 실제로 쓸모 있는 가치를 가져야 한다.<br/>
&ensp;데이터가 아무리 많아도 분석 결과가 의사결정에 도움이 안 되면 의미가 없다.<br/>

> Value는 “이 데이터를 분석해서 실제로 쓸모 있는 결과를 만들 수 있는가?”를 보는 속성이다.

&ensp;Variability — 데이터의 가변성<br/>
&ensp;Variability는 데이터의 의미가 상황이나 맥락에 따라 달라질 수 있다.<br/>

&ensp;Visualization — 데이터의 시각화<br/>
&ensp;Visualization은 분석 결과를 사람들이 이해하기 쉽게 그림, 그래프, 도표로 표현하는 것을 의미한다.<br/>

&ensp;7V<br/>
&ensp;빅데이터는 빠른 속도로 생성되는 대량의 다양한 데이터를 정확성을 유지하도록 가공하고, 맥락에 따른 의미 변화를 고려해 분석한 뒤, 가치 있는 결과를 도출하고, 이를 이해하기 쉽게 시각화해서 제공하는 것이다.<br/>

# 빅데이터 처리 과정

<p align="center"><img src="/assets/img/database/13주차/13-3.png" width="600"></p>

| 단계     | 쉽게 말하면                       |
| ------ | ---------------------------- |
| 데이터 소스 | 데이터가 어디서 생기는가                |
| 수집     | 데이터를 가져오는 단계                 |
| 저장     | 가져온 데이터를 보관하는 단계             |
| 처리     | 분석하기 좋게 정리하는 단계              |
| 분석     | 의미 있는 결과를 뽑아내는 단계            |
| 표현     | 결과를 그래프, 표, 그림으로 보여주는 단계     |
| 활용     | 분석 결과를 의사결정이나 서비스에 사용하는 단계   |
| 폐기     | 더 이상 필요 없는 데이터를 안전하게 삭제하는 단계 |

&ensp;빅데이터는 데이터가 생기고 → 모이고 → 정리되고 → 분석되고 → 보여지고 → 쓰이고 → 삭제되는 전체 생명주기가 있다.<br/>

&ensp;1. 빅데이터 생성과 수집<br/>
&ensp;1) 데이터 생성<br/>
&ensp;빅데이터는 다양한 데이터 소스에서 생성된다.<br/>

| 데이터 소스       | 예시                              |
| ------------ | ------------------------------- |
| 내부 데이터       | 기업 내부 DBMS, 시스템 로그, 내부 파일       |
| 외부 데이터       | SNS, 공공데이터, 웹 데이터               |
| 미디어/디바이스 데이터 | 센서, IoT 기기, 스마트폰, CCTV, 웨어러블 기기 |

&ensp;2) 데이터 수집<br/>
&ensp;수집은 **분석 대상이 되는 데이터를 가져오는 단계** 이다.<br/>

| 구분        | 설명                                            |
| --------- | --------------------------------------------- |
| 내부 데이터 수집 | 자체적으로 보유한 내부 파일, 시스템, DBMS, 센서 등에서 정형 데이터 수집  |
| 외부 데이터 수집 | 인터넷에 연결된 다양한 매체와 디바이스를 통해 정형, 반정형, 비정형 데이터 수집 |

&ensp;내부 데이터는 보통 회사가 이미 가지고 있는 데이터이다.<br/>
&ensp;외부 데이터는 회사 밖에서 가져오는 데이터이다.<br/>

&ensp;2. 대표적인 빅데이터 수집 기술<br/>

| 수집 기술           | 설명                            |
| --------------- | ----------------------------- |
| 크롤링 / 웹 크롤러     | 웹사이트에서 데이터를 자동으로 수집           |
| 로그 수집기          | 서버나 시스템에서 발생하는 로그 데이터를 수집     |
| 센싱              | 센서 장치에서 온도, 위치, 속도 등 데이터를 수집  |
| RSS 리더 / 오픈 API | 외부 서비스가 제공하는 데이터를 정해진 방식으로 수집 |

&ensp;개인정보는 프라이버시와 관련 있으므로 데이터 제공자에게 사전에 데이터 사용 허가가 필요하다.<br/>

&ensp;3. 빅데이터 저장<br/>
&ensp;수집한 데이터는 형태에 따라 적절한 방식으로 저장해야 한다.<br/>

| 저장 방법          | 설명                              |
| -------------- | ------------------------------- |
| 분산 파일 시스템      | 여러 컴퓨터에 데이터를 나누어 저장             |
| NoSQL          | 관계형 DB가 아닌 유연한 데이터 저장 방식        |
| 병렬 DBMS        | 여러 프로세서와 디스크를 이용해 DB 처리를 동시에 수행 |
| 네트워크 구성 저장 시스템 | 여러 저장 장치를 네트워크로 연결해 관리          |

&ensp;1) 분산 파일 시스템<br/>
&ensp;분산 파일 시스템은 데이터를 여러 컴퓨터에 나눠 저장하는 방식이다. 빅데이터는 너무 크기 때문에 한 대의 컴퓨터에 저장하기 어렵다. 그래서 여러 서버에 데이터를 나누어 저장하고 필요할 때 함께 사용한다.<br/>

&ensp;대표 예시<br/>

| 예시        | 설명                             |
| --------- | ------------------------------ |
| GFS       | Google File System             |
| HDFS      | Hadoop Distributed File System |
| Amazon S3 | 클라우드 기반 객체 저장소                 |

&ensp;큰 파일 하나를 여러 조각으로 나눠서 여러 컴퓨터에 저장하는 방식이다.<br/>

&ensp;2) NoSQL<br/>
&ensp;데이터 모델을 단순화해서 관계형 데이터 모델과 SQL을 사용하지 않는 모든 DBMS 또는 데이터 저장 장치<br/>

&ensp;대표 예시<br/>

| NoSQL 예시  |
| --------- |
| Cloudata  |
| HBase     |
| Cassandra |

&ensp;3) 병렬 DBMS<br/>
&ensp;병렬 DBMS는 여 마이크로프로세서를 사용하여 여러 디스크의 질의, 갱신, 입출력 등 데이터베이스 처리를 동시에 수행하는 데이터베이스 시스템이다.<br/>

| 병렬 DBMS 예시 |
| ---------- |
| SAP HANA   |
| Vertica    |
| VoltDB     |
| Greenplum  |
| Netezza    |

&ensp;혼자 하면 오래 걸리는 DB 작업을 여러 명이 나눠서 동시에 처리하는 방식<br/>

&ensp;4) 네트워크 구성 저장 시스템<br/>
&ensp;서로 다른 종류의 데이터 저장 장치를 하나의 데이터 서버에 연결하여 총괄적으로 데이터를 저장 및 관리하는 방식이다.<br/>

&ensp;대표 예시<br/>

| 예시  | 의미                       |
| --- | ------------------------ |
| SAN | Storage Area Network     |
| NAS | Network Attached Storage |

&ensp;저장 장치들을 네트워크로 묶어서 하나의 저장 공간처럼 사용한다.<br/>

&ensp;4. 빅데이터 처리<br/>
&ensp;분석하기 전에 데이터를 정리하고 가공하는 단계이다.<br/>
> 수집한 데이터들을 실시간으로 또는 일관 처리하는 일종의 데이터 정제/전처리 과정

&ensp;1) 일괄 처리와 실시간 처리<br/>

| 처리 방식    | 설명                   | 예시           |
| -------- | -------------------- | ------------ |
| 일괄 처리    | 데이터를 일정량 모아서 한 번에 처리 | 하루 매출 집계     |
| 실시간 처리   | 데이터가 들어오는 즉시 처리      | 실시간 이상 거래 탐지 |
| 분산 병렬 처리 | 여러 서버가 나눠서 동시에 처리    | 대규모 로그 분석    |

&ensp;5. 대표적인 빅데이터 처리 기술<br/>

| 처리 기술 | 설명                          |
| ----- | --------------------------- |
| 맵리듀스  | 대규모 데이터를 분산 처리하는 프로그래밍 모델   |
| 하둡    | 분산 저장과 분산 처리를 지원하는 빅데이터 플랫폼 |
| R     | 통계 분석과 데이터 처리에 사용되는 언어      |

&ensp;6. 빅데이터 분석<br/>
&ensp;분석은 데이터 안에 숨겨진 유용한 정보나 지식을 찾아내는 단계이다.<br/>
> 수학적인 기법을 적용하여 통계 분석 또는 딥러닝, 머신러닝 등 AI 기술을 통해 분석 결과 생성

&ensp;분석은 단순히 데이터를 보는 게 아니라 의미 있는 패턴을 찾아내는 과정<br/>

# 빅데이터 처리 과정별 기술

<p align="center"><img src="/assets/img/database/13주차/13-5.png" width="600"></p>

&ensp;1. 빅데이터 수집 기술<br/>
&ensp;1) 수집 기술 개요<br/>
&ensp;빅데이터 분석에서 데이터의 양은 매우 중요하다. 데이터가 충분해야 의미 있는 분석 결과를 얻을 수 있기 때문이다.<br/>

&ensp;대표적인 자동 수집 기술<br/>

| 수집 기술           | 핵심                    |
| --------------- | --------------------- |
| 로그 수집기          | 서버, DB, 방화벽 등의 로그 수집  |
| 크롤링 / 웹 크롤러     | 웹페이지나 소셜 데이터를 자동 수집   |
| 센싱              | 센서로 데이터 수집            |
| RSS 리더 / 오픈 API | 외부 데이터를 프로그래밍 방식으로 수집 |
| ETL             | 데이터를 추출, 변환, 적재       |

<p align="center"><img src="/assets/img/database/13주차/13-6.png" width="600"></p>

&ensp;2. 빅데이터 저장 기술<br/>
&ensp;1) 저장 기술 개요<br/>
* 대용량 데이터베이스 저장, 관리 기술이 발전되어 기존 데이터베이스 시스템에서도 빅데이터 저장, 관리 가능
* 기존 RDBMS만으로는 처리하기 어려운 대규모 비정형 데이터가 많아졌고, 새로운 저장 기술이 필요

&ensp;대표적인 저장 기술<br/>

| 저장 기술     | 핵심                   |
| --------- | -------------------- |
| 하둡 에코 시스템 | 대용량 데이터를 분산 저장하고 처리  |
| NoSQL     | 비정형/반정형 데이터를 유연하게 저장 |

&ensp;2) 하둡<br/>
&ensp;하둡은 대용량 데이터를 분산 처리할 수 있는 자바 기반의 오픈소스 프레임워크<br/>
&ensp;하둡은 크게 두 가지 핵심 구성<br/>

| 구성        | 역할                  |
| --------- | ------------------- |
| HDFS      | 데이터를 여러 서버에 나누어 저장  |
| MapReduce | 여러 서버에서 데이터를 나누어 처리 |

&ensp;분산 파일 시스템인 HDFS에 데이터를 저장하고, 분산 처리 시스템인 MapReduce를 이용해 데이터를 처리한다.<br/>

&ensp;HDFS<br/>
* HDFS는 Hadoop Distributed File System의 약자
* 하나의 큰 데이터를 여러 조각으로 나눠 여러 서버에 저장

&ensp;MapReduce<br/>
* MapReduce는 나눠진 데이터를 각 서버에서 처리하고, 그 결과를 모아서 최종 결과를 만드는 방식

&ensp;하둡의 장점<br/>

| 장점       | 설명                            |
| -------- | ----------------------------- |
| 낮은 비용    | 기존 데이터베이스 시스템보다 적은 비용         |
| 빠른 처리 속도 | 여러 서버에 데이터가 분산 저장되어 빠르게 처리 가능 |

> 하둡은 HDFS로 데이터를 나누어 저장하고, MapReduce로 나누어 처리하는 빅데이터 프레임워크이다.

&ensp;3) NoSQL<br/>
&ensp;NoSQL은 관계 데이터 모델과 SQL을 사용하지 않는 데이터베이스 시스템<br/>
> NoSQL은 일관성보다 가용성과 확장성에 중점을 둔다.

&ensp;대표적인 NoSQL<br/>

| NoSQL 예시  |
| --------- |
| HBase     |
| Cassandra |
| MongoDB   |
| CouchDB   |

&ensp;NoSQL의 장점<br/>

| 장점         | 설명                          |
| ---------- | --------------------------- |
| 유연한 데이터 모델 | 비정형 데이터 저장에 유리              |
| 저렴한 분산 처리  | RDBMS보다 낮은 비용으로 분산/병렬 처리 가능 |
| 확장성        | 서버를 늘려 대량 데이터 처리 가능         |

> NoSQL은 SQL 중심의 관계형 DB가 아니라, 대량의 반정형·비정형 데이터를 유연하게 저장하기 위한 데이터베이스 시스템이다.

&ensp;3. 빅데이터 처리 기술<br/>
&ensp;1) 처리 기술 개요<br/>
&ensp;빅데이터 처리 기술은 수집한 데이터를 분석할 수 있도록 정제하고 전처리하는 기술이다.<br/>

> 수집한 데이터들을 실시간으로 일괄 처리하는 일종의 데이터 정제/전처리 과정

&ensp;데이터셋에서 원하는 부분을 추출하거나 전체 데이터를 선택하여 분석을 위해 데이터 재배치 등의 작업 수행<br/>

&ensp;2) 빅데이터 일괄 처리 기술<br/>
&ensp;일괄 처리는 데이터를 일정량 모아서 한 번에 처리하는 방식이다.<br/>

> 빅데이터를 여러 서버로 분산하여 각 서버에서 나누어 처리하고, 이를 다시 모아서 결과를 정리하는 분산·병렬 기술 방식

&ensp;대표적인 솔루션<br/>

| 대표 솔루션         |
| -------------- |
| 구글의 맵리듀스       |
| 하둡의 맵리듀스       |
| 마이크로소프트의 드라이애드 |

&ensp;3) 빅데이터 실시간 처리 기술<br/>
&ensp;실시간 처리 기술은 데이터가 들어오는 즉시 처리하는 방식이다.<br/>

&ensp;대표적인 솔루션<br/>

| 대표 솔루션                 | 설명                        |
| ---------------------- | ------------------------- |
| IBM InfoSphere Streams | 스트림 처리 기술로 강화된 스트림 컴퓨팅 지원 |
| 트위터 Storm              | 분산 환경에서 스트리밍 데이터 분석 지원    |

&ensp;스트림 데이터: 스트림 데이터는 계속 흘러들어오는 데이터.<br/>

&ensp;4) 빅데이터 처리 프로그래밍 지원 기술<br/>
&ensp;빅데이터를 처리하려면 사람이 직접 MapReduce 코드를 복잡하게 작성해야 할 때가 있다. 이를 쉽게 하기 위해 빅데이터 처리 언어나 프레임워크가 사용된다.<br/>

&ensp;대표적인 솔루션<br/>

| 기술         | 설명                                 |
| ---------- | ---------------------------------- |
| 구글 Sawzall | 분산 데이터를 처리하는 프로그래밍 언어              |
| 하둡 Pig     | 병렬 처리를 위한 고성능 데이터 플로우 언어와 실행 프레임워크 |

&ensp;4. 빅데이터 분석 기술<br/>
&ensp;1) 분석 기술 개요<br/>
&ensp;분석 기술은 처리된 데이터에서 의미 있는 지식이나 정보를 도출하는 기술이다.<br/>

&ensp;대표적인 기술<br/>

| 분석 기술   |
| ------- |
| 데이터 마이닝 |
| 기계학습    |
| 자연어 처리  |
| 패턴 인식   |

&ensp;텍스트 마이닝<br/>
* 텍스트 마이닝은 자연어 처리 기술을 사용해서 인간의 언어로 쓰인 비정형 텍스트에서 유용한 정보를 추출하는 기술
* 다른 데이터와의 연계성을 파악하며 분류나 군집화 등 빅데이터에 숨겨진 의미 있는 정보를 발견하는 것

&ensp;웹 마이닝<br/>
* 인터넷에서 수집한 정보를 데이터 마이닝 기법으로 분석하는 기술

&ensp;기계학습<br/>
* 인공지능 분야에서 인간의 학습을 모델링한 기술

&ensp;감정 분석<br/>
* 문장의 의미를 파악해서 글의 내용이 긍정인지 부정인지, 좋음인지 나쁨인지 분석하는 기술

&ensp;5. 처리 기술과 분석 기술의 차이<br/>

| 구분 | 처리 기술                         | 분석 기술                       |
| -- | ----------------------------- | --------------------------- |
| 목적 | 데이터를 분석 가능한 상태로 정리            | 데이터에서 의미 있는 정보 도출           |
| 예시 | 일괄 처리, 실시간 처리, MapReduce, Pig | 텍스트 마이닝, 웹 마이닝, 기계학습, 감성 분석 |
| 질문 | “데이터를 어떻게 가공할까?”              | “데이터에서 무엇을 알아낼까?”           |

# 빅데이터 보안 개념

&ensp;1. 빅데이터 보안의 큰 흐름<br/>
&ensp;빅데이터 보안은 크게 두 가지 관점으로 나뉜다.<br/>

| 구분             | 의미                                 |
| -------------- | ---------------------------------- |
| 개인정보 보호 이슈     | 수집부터 폐기까지 개인정보가 유출되거나 오남용되지 않도록 보호 |
| 빅데이터 시스템 보안 이슈 | 하둡 같은 빅데이터 시스템 자체를 공격이나 침해로부터 보호   |

&ensp;빅데이터는 데이터를 많이 모으기 때문에 개인정보가 섞일 가능성이 높고, 그래서 수집·저장·처리·분석·시각화·폐기 단계마다 보안 대책이 필요하다.<br/>

&ensp;2. 개인정보 처리 과정별 보안 이슈<br/>
&ensp;수집 → 저장 → 처리 및 분석 → 표현/시각화 → 폐기<br/>

&ensp;빅데이터 수집<br/>
* 데이터 수집 시 개인 정보 포함 여부 확인 필요하며 유출 가능성 존재
* 데이터를 생성하는 주체(일반 사용자 또는 시스템)에 대한 사전/사후 동의 필요
* 수집되는 데이터에 대한 접근 통제 필요
  - 생성 데이터에 대한 접근 통제 필수적
  - 권한 부여된 시스템/사용자만 해당 데이터를 수집하고 저장할 수 있도록 설정
  - 자동화된 웹 로봇의 데이터 수집을 차단하여 개인정보 수집을 거부한 데이터 제공자의 데이터에 접근하지 못하도록 설정

&ensp;빅데이터 저장<br/>
* 수집 데이터의 안전한 저장 및 관리
  - 데이터 암호화: 데이터가 유출되어도 내용을 알아보기 어렵게 함
  - 논리적·물리적 접근 통제: 시스템 접근과 저장 장치 접근을 모두 제한
* 데이터 등급 분류 및 필터링
  - 수집된 데이터 종류에 따라 필터링되어 저장되거나 데이터 등급별로 분류하여 별도 관리
  - 개인정보는 일정 기준에 따라 등급 분류하고 등급별 처리 기준 수립하여 안전한 저장 및 관리 필요(암호화 저장)

&ensp;빅데이터 처리 및 분석<br/>
* 익명화된 데이터 처리 및 분석
  - 외부에서 제공되는 개인정보가 포함된 데이터는 익명화 과정을 통해 개인정보를 제거한 형태로 처리 및 분석 과정 필요
* 암호화된 데이터 처리
  - 데이터를 모두 암호화하여 저장하고 암호화된 형태로 데이터 처리 시 데이터 처리과정의 투명성 보장 가능
* 이용 목적 외 처리 및 분석 방지
  - 데이터 수집 시 법적 절차에 의하여 동의를 받았던 이용목적 이외의 데이터 처리 및 분석을 해서는 안 됨
  - 프라이버시를 침해하지 않는 목적으로 분석이 이루어졌다고 해도 분석된 결과가 프라이버시를 침해할 수 있음

&ensp;빅데이터 표현<br/>
* 개인정보를 침해할 수 있는 정보 생성 위험이 있으므로 유의
* 분석된 정보의 무단 이용 x
  - 개인정보보호 정책에 명시되지 않은 제 3자에게 제공하거나 명시되지 않은 항목을 제공하지 않아야 함

&ensp;빅데이터 폐기<br/>
* 데이터 분석 등 활용 이후 데이터가 완전하게 폐기되었는지 확인
* 폐기 방법
  - 논리적으로 안전한 방법을 통하여 폐기
  - 하드디스크 천공, 디가우싱(강한 자기장을 이용해 파일 삭제 및 저장 장치 사용이 불가하게 만듦) 등 물리적인 방법으로 폐기
