# 데이터베이스 시스템에서 DBMS가 중요한 이유

&ensp;데이터베이스 시스템은 여러 소프트웨어와 구성요소로 이루어져 있지만, 그중에서 가장 핵심은 단연 DBMS 이다.

&ensp;DBMS는 단순히 데이터를 저장해두는 프로그램이 아니라,<br/>
* 데이터베이스를 관리하고
* 사용자의 데이터 처리 요구를 해석하고
* 실제 데이터베이스에 반영하고
* 보안, 무결성, 권한, 회복까지 관리하는

&ensp;중앙 통제 시스템이다.

# DBMS의 정의

&ensp;DBMS(Database Management System)는 **파일 시스템의 데이터 중복과 데이터 종속 문제를 해결하기 위해 제시된 소프트웨어이다.<br/>

&ensp;조직에 필요한 데이터를 하나의 데이터베이스에 통합해서 저장하고 관리하며 응용 프로그램을 대신해서 데이터를 삽입하고, 삭제하고, 수정하고, 검색하는 역할을 수행한다.<br/>

&ensp;예를 들어 고객 관리 프로그램과 주문 관리 프로그램이 있다고 하면 파일 시스템 방식이면 각 프로그램이 자기 파일을 따로 관리할 수 있다. 그러면 같은 고객 정보가 여러 파일에 중복 저장될 수 있고 하나만 수정되면 나머지는 틀린 값으로 남아 불일치가 생긴다.

&ensp;하지만 DBMS를 사용하면 고객정보는 하나의 데이터베이스에서 통합 관리되기 때문에 중복 저장이 줄고 일관성이 유지되고 여러 프로그램이 같은 데이터를 공유할 수 있다.<br/>

# DBMS의 전체 구조

&ensp;DBMS는 기능적으로 크게 두 부분으로 나눌 수 있다.<br/>

&ensp;1. 질의 처리기(Query Processor)<br/>
&ensp;사용자의 데이터 처리 요구를 해석하고 처리하는 역할을 담당한다.<br/>

&ensp;주요 구성 요소:<br/>
* DDL 컴파일러
* DML 프리컴파일러
* DML 컴파일러
* 런타임 데이터베이스 처리기
* 트랜잭션 관리자

&ensp;2. 저장 데이터 관리자(Stored Data Manager)
&ensp;실제로 디스크에 저장된 데이터베이스와 데이터 사전에 접근하고 관리하는 역할을 담당한다. 운영체제의 도움을 받아 데이터베이스 파일에 접근한다.<br/>

<p align="center"><img src="/assets/img/database/2주차/2-1.png" width="600"></p>

# DBMS의 주요 구성 모듈

&ensp;1. 데이터 정의어 컴파일러(DDL Compiler)<br/>
&ensp;역할<br/>
* 데이터 정의어로 작성된 스키마 정의로 해석
* 새로운 데이터베이스를 구축
* 스키마 정의를 데이터 사전에 저장

&ensp;핵심 포인터<br/>
&ensp;DDL 컴파일러는 구조를 다룬다.<br/>
&ensp;즉 테이블을 만들고 구조를 정의하는 역할이다.<br/>

&ensp;예를 들어 `CREATE TABLE`, `ALTER TABLE` 같은 명령을 처리하는 쪽이 바로 이 부분이다.<br/>

&ensp;한 줄 정리<br/>
&ensp;DDL 컴파일러 = 데이터베이스의 뼈대를 만드는 모듈<br/>

&ensp;2. 데이터 조작어 프리컴파일러(DML Precompiler)<br/>
&ensp;역할<br/>
* 응용 프로그램 안에 삽입된 데이터 조작어(DML)를 추출
* 추출한 DML을 DML 컴파일러에 전달
* DML과 관련 없는 나머지 코드는 해당 프로그래밍 언어 컴파일러로 전달

&ensp;DML 프리컴파일러 = 프로그램 속 SQL만 골라내는 모듈<br/>

&ensp;3. 데이터 조작어 컴파일러(DML Compiler)<br/>
&ensp;역할<br/>
* 데이터 조작어로 작성된 삽입, 삭제, 수정, 검색 요구를 분석
* 런타임 데이터베이스 처리기가 이해할 수 있는 형태로 해석

&ensp;핵심<br/>
&ensp;실제로 데이터를 바꾸는 것이 이 모듈이 아니라 사용자의 요구를 분석해서 실행 가능한 형태로 바꾸는 것이 핵심<br/>

&ensp;한 줄 정리<br/>
&ensp;DML 컴파일러 = 사용자의 데이터 처리 요청을 해석하는 모듈<br/>

&ensp;4. 런타임 데이터베이스 처리기<br/>
&ensp;역할<br/>
* 저장 데이터 관리자를 통해 데이터베이스에 실제 접근
* DML 컴파일러가 해석한 요청을 실제로 실행

&ensp;DML 컴파일러가 "무슨 작업을 할지 정리" 해두면 런타임 데이터베이스 처리기는 그 작업을 실제 DB에 반영한다.<br/>

&ensp;한 줄 정리<br/>
&ensp;런타임 데이터베이스 처리기 = 해석된 요청을 실제로 수행하는 모듈<br/>

&ensp;5. 트랜잭션 관리자(Transaction Manager)<br/>
&ensp;역할<br/>
* 사용자의 접근 권한이 유효한지 검사
* 인증된 사용자인지 적절한 권한이 있는지 확인
* 무결성 유지를 위한 제약조건 위반 여부 확인

&ensp;중요성<br/>
&ensp;데이터베이스에서는 아무나 아무 데이터나 수정하면 안 된다.<br/>

&ensp;예<br/>
* 학생 학번은 중복되면 안 됨
* 점수는 음수가 되면 안 됨
* 권한 없는 사용자는 급여 테이블을 수정할 수 없음

&ensp;한 줄 정리<br/>
&ensp;트랜잭션 관리자 = 권한과 무결성을 검사하는 안전장치<br/>

&ensp;6. 저장 데이터 관리자(Stored Data Manager)<br/>
&ensp;역할<br/>
* 디스크에 저장된 데이터베이스와 데이터 사전을 관리
* 실제 데이터 접근 담당
* 운영체제의 도움을 받아 데이터베이스 파일에 접근

&ensp;핵심<br/>
&ensp;디스크 접근은 운영체제의 기본 기능이므로 저장 데이터 관리자는 운영체제와 협력해서 DB 파일을 읽고 쓴다.<br/>

&ensp;저장 데이터 관리자 = 디스크 속 실제 DB를 다루는 모듈<br/>

# 데이터 사전(Data Dictionary)

&ensp;데이터 사전은 데이터베이스에 저장되는 데이터에 관한 정보를 저장하는 공간<br/>

<p align="center"><img src="/assets/img/database/2주차/2-2.png" width="600"></p>

&ensp;다른 말로는<br/>
* 시스템 카탈로그(System Catalog)
* 메타데이터(metadata)
* 시스템 데이터베이스

&ensp;라고도 부른다.<br/>

&ensp;중요한 이유<br/>
&ensp;데이터 사전에는 단순 데이터 값이 아니라 그 데이터를 제대로 사용하기 위해 필요한 정보가 저장된다.<br/>

&ensp;예를 들어<br/>
* 스키마 정보
* 스키마 간의 매핑 정보
* 다양한 제약조건
* 구조 정의 정보

&ensp;"데이터에 대한 데이터(data about data)"가 저장된다.<br/>

&ensp;사용자 데이터베이스와의 차이<br/>
* 사용자 데이터베이스: 실제 사용자 데이터 저장
* 시스템 데이터베이스(데이터 사전): 구조, 규칙, 메타정보 저장

&ensp;한 줄 정리<br/>
&ensp;데이터 사전 = 데이터 자체가 아니라 데이터를 설명하는 정보 저장소<br/>

# 7. DBMS 유틸리티

&ensp;DBMS에는 핵심 모듈 외에도 데이터 관리를 도와주는 여러 유틸리티가 있다.<br/>

&ensp;1. 적재 유틸리티(Loading Utility)<br/>
* 텍스트 파일, 순차 파일 등 기존 데이터 파일을 데이터베이스에 적재
* 파일 형식을 자동 변환해 DB 파일 형식으로 저장

<p align="center"><img src="/assets/img/database/2주차/2-3.png" width="600"></p>

&ensp;추가 개념: 변환 도구<br/>
&ensp;기존 DBMS에서 새로운 DBMS로 데이터를 옮길 때 내부 스키마 정보를 바탕으로 적절한 적재 프로그램을 생성하는 도구도 있다.<br/>

&ensp;한 줄 정리<br/>
&ensp;적재 유틸리티 = 외부 파일을 DB 안으로 옮겨주는 도구<br/>

&ensp;2. 백업 유틸리티(Backup Utility)<br/>
&ensp;역할<br/>
* 데이터베이스 전체 또는 일부를 저장 매체에 복사
* 데이터베이스 사본 생성
* 디스코 고장, 자연재해, 사용자 실수 시 복구용으로 사용

&ensp;한 줄 정리<br/>
&ensp;백업 = 미리 복사본을 만들어 두는 것<br/>

&ensp;3. 파일 재조직 유틸리티(File Reorganization)<br/>
&ensp;역할<br/>
* 성능 향상을 위해 파일 구조를 재조직
* 새로운 접근 경로 생성

&ensp;의미<br/>
&ensp;데이터가 너무 비효율적으로 저장되어 있거나 검색이 느릴 경우 파일 구조를 바꿔서 더 빠르게 접근할 수 있도록 한다.<br/>

&ensp;4. 성능 모니터링 유틸리티(Performance Monitoring)<br/>
&ensp;역할<br/>
* 데이터베이스 사용 현황 모니터링
* 사용 통계를 DBA에게 제공

&ensp;DBA가 활용하는 방법<br/>
* 파일을 재조직할지
* 인덱스를 추가할지
* 인덱스를 삭제할지
* 병목이 어디서 발생하는지 

&ensp;이런 결정을 할 수 있게 해준다.<br/>

&ensp;5. 기타 유틸리티<br/>
* 파일 정렬
* 데이터 압축
* 사용자 접근 모니터링
* 네트워크 인터페이스 지원

&ensp;즉 DBMS는 단순히 질의만 처리하는 시스템이 아니라 운영, 유지보수, 보안, 성능 관리까지 포함하는 종합 시스템이다.<br/>

# 8. DBMS의 장점과 단점

&ensp;장점<br/>
&ensp;1) 데이터 중복 통제<br/>
&ensp;파일 시스템은 응용 프로그램마다 별도 파일을 유지하므로 같은 데이터가 여러 곳에 중복 저장될 수 있다.<br/>
&ensp;DBMS는 데이터를 통합해서 관리하므로 중복 문제를 줄이고 일관성을 유지할 수 있다.<br/>

<p align="center"><img src="/assets/img/database/2주차/2-4.png" width="600"></p>

&ensp;2) 데이터 동시 공유<br/>
&ensp;여러 응용 프로그램이 같은 데이터에 동시에 접근 가능하다. DBMS는 동시 접근 제어 기술을 통해 이를 안전하게 지원한다.<br/>

&ensp;3) 데이터 보안 향상<br/>
&ensp;파일 시스템은 파일 단위 보안에 그치기 쉽지만 DBMS는 중앙 집중식 관리로<br/>
* 권한 없는 사용자의 접근 차단
* 사용자별 접근 수준 차별화
* 데이터별 권한 설정

&ensp;이 가능하다.<br/>

&ensp;4) 데이터 무결성 유지<br/>
&ensp;삽입, 수정 등이 일어날 때마다 유효성 검사를 수행하여 데이터의 정확성을 유지한다.<br/>

&ensp;5) 장애 발생 시 회복 가능<br/>
&ensp;장애가 발생해도 데이터의 일관성과 무결성을 유지하며 이전 상태로 복구할 수 있다.<br/>

&ensp;6) 데이터 독립성 확보<br/>
&ensp;데이터 구조나 접근 방법이 바뀌어도 사용자나 응용 프로그램이 그 변화를 몰라도 된다. 이것이 바로 DBMS가 제공하는 중요한 특징 중 하나다.<br/>

&ensp;단점<br/>
&ensp;1) 비용이 많이 듦<br/>
* 별도 구매 및 설치 필요
* 동시 사용자 수가 많아질수록 가격 증가
* 무료 DBMS는 기능 차이가 있을 수 있음

&ensp;2) 백업과 회복이 복잡함<br/>
* 데이터 양이 많고 구조가 복잡함
* 동시 사용자 환경이라 장애 원인 파악이 어려움
* 복구도 간단하지 않음

&ensp;3) 중앙 집중 관리의 취약점<br/>
&ensp;DB나 DBMS 자체에 장애가 발생하면 전체 업무가 중단될 수 있음<br/>
&ensp;DB 의존도가 높은 시스템일수록 더 치명적<br/>

&ensp;DBMS는 강력하지만, 비용과 운영 난이도, 중앙 집중 구조의 위험성도 함께 가진다.<br/>

# 9. DBMS의 발전 과정

<p align="center"><img src="/assets/img/database/2주차/2-5.png" width="600"></p>

&ensp;1세대 DBMS<br/>
&ensp;(1) 네트워크 DBMS<br/>
* 그래프 형태(노드와 간선)로 데이터 구성
* 구조가 복잡하고 변경이 어려움
* 대표: IDS

&ensp;(2) 계층 DBMS<br/>
* 트리 형태로 데이터 구성
* 구조는 단순하지만 현실 세계를 부모-자식 관계만으로 표현하기 어려움
* 구조 변경도 어려움
* 대표: IMS

&ensp;2세대 DBMS: 관계 DBMS(RDBMS)<br/>
* 테이블 형태로 데이터 구성
* 현재까지 가장 널리 사용되는 방식
* 대표:
    - Oracle
    - Microsoft SQL Server
    - Informix
    - MySQL
    - MariaDB

&ensp;오늘날 우리가 흔히 배우고 사용하는 DBMS의 중심은 바로 관계 DBMS이다.<br/>

&ensp;3세대 DBMS<br/>
&ensp;(1) 객체지향 DBMS<br/>
* 객체 개념을 이용해 데이터베이스 구성
* 새로운 유형의 데이터 저장 가능
* 복잡한 분석 및 처리 지원
* 대표:
    - O2
    - ONTOS
    - GemStone

&ensp;(2) 객체관계 DBMS<br/>
* 관계 DBMS에 객체지향 개념을 결합한 형태

&ensp;4세대 DBMS<br/>
&ensp;(1) NoSQL DBMS<br/>
* 비정형 데이터 저장 및 처리에 적합
* 구조를 미리 엄격하게 정하지 않음
* 확장성이 뛰어남
* 분산 저장/처리에 적합
* 대표:
    - MongoDB
    - HBase
    - Cassandra
    - Redis
    - Neo4j
    - OrientDB

&ensp;(2) NewSQL DBMS<br/>
* 관계 DBMS의 안정성과 일관성 유지
* NoSQL처럼 빠르고 유연한 처리 지원
* 정형/비정형 데이터를 모두 안정적으로 처리
* 대표:
    - Google Spanner
    - VoltDB
    - NuoDB

&ensp;현재는 RDBMS + NoSQL + NewSQL이 서로 경쟁한다기보다, 상호보완적으로 공존하는 흐름으로 보는 것이 맞다.<br/>

# 데이터베이스 사용자

&ensp;데이터베이스를 이용하기 위해 접근하는 모든 사람을 데이터베이스 사용자라고 한다. 이용 목적에 따라 크게 세 부류로 나눌 수 있다.<br/>
* 데이터베이스 관리자(DBA)
* 최종 사용자(End User)
* 응용 프로그래머(Application Programmer)

&ensp;1. 데이터베이스 관리자(DBA)<br/>
&ensp;DBMS를 운영하고 관리하는 책임자<br/>
&ensp;즉, 데이터베이스 전반을 총괄하는 사람이다.<br/>

&ensp;주요 업무<br/>
* 사용자 요구사항 분석
* 데이터베이스 구성 요소 선정
* 스키마 설계 및 DDL로 정의
* 물리적 저장 구조와 접근 방법 결정
* 무결성 제약조건 정의
* 보안 및 접근 권한 정책 결정
* 백업 및 회복 방법 정의
* 시스템 데이터베이스 관리
* 성능 감시 및 분석
* 데이터베이스 재구성

&ensp;DBA는 단순 관리자라기보다 설계자 + 운영자 + 보안 관리자 + 성능 관리자 역할을 모두 담당한다.<br/>

&ensp;2. 최종 사용자(End User)<br/>
&ensp;정의<br/>
&ensp;데이터베이스에 접근하여<br/>
* 검색
* 삽입
* 삭제
* 수정

&ensp;같은 데이터 조작을 수행하는 사용자<br/>

&ensp;특징<br/>
* 깊은 DB 이론 지식이 꼭 필요하지 않음
* 주로 DML 사용
* 보통 응용 프로그램이나 메뉴, GUI를 통해 DB 사용

&ensp;세부 구분<br/>
&ensp;1) 캐주얼 사용자<br/>
* 데이터베이스에 대한 이론적 지식이 어느 정도 있음. 
* DML을 직접 이용해 데이터 처리 요청 가능
&ensp;2) 초보 사용자<br/>
* 데이터베이스 이론 지식이 거의 없음. 
* 메뉴나 GUI 형태 응용 프로그램을 통해 DB 사용

&ensp;3. 응용 프로그래머<br/>
&ensp;C, Java 같은 프로그래밍 언어로 응용 프로그램을 작성하면서 그 안에 DML을 삽입하는 사용자<br/>

&ensp;특징<br/>
* 주로 DML 사용
* 필요하면 DDL도 사용 가능
* 사용자와 DBMS 사이를 연결하는 응용 프로그램 제작

&ensp;한 줄 정리<br/>
* DBA: 관리
* 최종 사용자: 사용
* 응용 프로그래머: 연결 프로그램 개발

# DBMS의 기능

<p align="center"><img src="/assets/img/database/2주차/2-6.png" width="600"></p>

1. 분쟁 중재

&ensp;여러 응용 프로그램이 동시에 같은 데이터에 접근하면 충돌이나 중복 문제가 생길 수 있다.
DBMS는 이런 분쟁을 중재하여 데이터 일관성을 유지한다.<br/>

2. 다양한 인터페이스 제공

&ensp;사용자는 응용 프로그램 없이도 SQL 같은 인터페이스를 통해 직접 데이터 처리를 요구할 수 있다.<br/>

3. 데이터베이스 생성, 접근, 관리 담당

&ensp;DBMS는 데이터베이스를 만들고, 접근하게 하고, 관리하는 전체 역할을 수행한다.

4. 결과만 사용자에게 전달

&ensp;사용자나 응용 프로그램은 내부의 물리적 저장 구조를 몰라도 된다. DBMS가 내부 처리를 모두 맡고 결과만 제공하기 때문이다.

5. 데이터 독립성 제공

&ensp;데이터 구조나 접근 방법이 바뀌어도 사용자와 응용 프로그램은 크게 영향을 받지 않는다.

6. DBMS의 3대 핵심 기능

&ensp;1) 정의 기능<br/>
* 데이터베이스 구조 정의
* 이미 정의된 구조 수정 가능

&ensp;2) 조작 기능<br/>
* 데이터 삽입, 삭제, 수정, 검색 수행

&ensp;3) 제어 기능<br/>
* 무결성 규칙 설정
* 보안 정책 설정
* 정확하고 안전한 공유 보장

&ensp;한 줄 정리<br/>
&ensp;DBMS의 핵심 = 정의 + 조작 + 제어<br/>

# DBMS 언어(SQL)

&ensp;1. 프로그래밍 언어와 DBMS 언어의 차이<br/>
&ensp;프로그래밍 언어<br/>
* 특정 문제 해결을 위한 일반 목적 언어
* 예: C, Java, Python

&ensp;DBMS 언어<br/>
* DBMS와 통신하기 위한 언어
* 완전한 프로그래밍 언어는 아님
* 데이터베이스 정의, 조작, 제어를 위한 문법만 제공
* 일반적으로 SQL(Structured Query Language) 이라고 부름

&ensp;즉, SQL은 애플리케이션 전체를 만드는 언어가 아니라 데이터베이스 작업 전용 언어라고 보면 된다.<br/>

&ensp;2. SQL의 3가지 종류<br/>
* DDL (Data Definition Language)
* DML (Data Manipulation Language)
* DCL (Data Control Language)

&ensp;3. 데이터 정의어(DDL)<br/>
&ensp;역할<br/>
* 스키마 정의
* 기존 스키마 수정
* 스키마 삭제

&ensp;데이터 사전과의 관계<br/>
&ensp;DDL로 정의된 스키마는 데이터 사전에 저장되며, 수정/삭제가 발생하면 데이터 사전에 반영된다.<br/>

&ensp;대표 명령어<br/>
* CREATE
* ALTER
* DROP

&ensp;예<br/>
* CREATE TABLE
* ALTER TABLE
* DROP TABLE

&ensp;한 줄 정리<br/>
&ensp;DDL = 구조를 만드는 언어<br/>

&ensp;4. 데이터 조작어(DML)<br/>
&ensp;역할<br/>
&ensp;실제 저장된 데이터를 다루는 언어<br/>
* 검색
* 삽입
* 수정
* 삭제

&ensp;를 위해 사용한다.<br/>

&ensp;대표 명령어<br/>
* SELECT
* INSERT
* UPDATE
* DELETE

&ensp;의미<br/>
&ensp;DDL이 테이블의 틀을 만든다면, DML은 그 틀 안에 들어가는 실제 데이터(인스턴스)를 다룬다.<br/>

&ensp;한 줄 정리<br/>
&ensp;DML = 실제 데이터를 만지는 언어<br/>

&ensp;5. 데이터 제어어(DCL)<br/>
&ensp;역할<br/>
* 보안
* 권한 관리
* 회복
* 무결성/동시성 보장

&ensp;등을 위해 필요한 규칙과 기법을 정의한다.<br/>

&ensp;대표 명령어<br/>
* GRANT
* REVOKE
* COMMIT
* ROLLBACK

&ensp;명령어 의미<br/>
* GRANT: 권한 부여
* REVOKE: 권한 취소
* COMMIT: 작업 확정
* ROLLBACK: 비정상 종료 시 원래 상태로 복구

&ensp;필요한 이유<br/>
&ensp;DCL은 DBMS의 중요한 성질인<br/>
* 무결성
* 보안
* 회복
* 동시성

&ensp;을 보장하기 위해 사용된다.<br/>ß

&ensp;한 줄 정리<br/>
&ensp;DCL = 안전하게 관리하기 위한 언어<br/>

# DBMS 종류와 특징

&ensp;1. Oracle<br/>
&ensp;특징<br/>
* 1979년 Oracle에서 개발
* 기본은 관계형 DBMS
* 문서, 그래프, 키-값 등 다양한 데이터 모델 지원
* 클라우드 중심 발전
* 다양한 운영체제 지원
* 다양한 프로그래밍 언어 지원

&ensp;장점<br/>
* 강력한 보안
* 향상된 데이터 보호, 백업, 복구
* 대용량 데이터 처리 강점
* 기술 지원과 문서가 매우 풍부함
* 커뮤니티 지원도 강함

&ensp;단점<br/>
* 가격이 매우 비쌈
* 높은 하드웨어 사양 필요
* 설치 공간 많이 필요
* 문서가 방대해서 전문가 필요

&ensp;Oracle = 강력한 기능, 보안, 대규모 처리에 강하지만 비싸고 무거움<br/>

&ensp;2. MySQL<br/>
&ensp;특징<br/>
* 1995년 MySQL AB 개발
* 현재는 Oracle 소유
* 가장 널리 사용되는 RDBMS 중 하나
* 여러 운영체제와 언어 지원

&ensp;장점<br/>
* 오픈소스
* 무료로 시작 가능
* 다루기 쉬움
* 구문이 단순함
* 비교적 낮은 하드웨어 사양에서도 사용 가능
* 입문용/개발용으로 좋음

&ensp;단점<br/>
* 오픈소스 사용 시 기술 지원 한계
* 확장성이 아주 뛰어난 편은 아님
* 일부 표준 SQL 기능 미지원
* 다른 DBMS로 이전할 때 문제 발생 가능

&ensp;요약<br/>
&ensp;MySQL = 쉽고 가볍고 무료라 많이 쓰이지만, 대규모 확장성과 일부 고급 기능은 아쉬울 수 있음<br/>

&ensp;3. Microsoft SQL Server<br/>
&ensp;특징<br/>
* 1989년 Microsoft 개발
* 완전한 상업용 도구
* 관계형 DBMS
* 주로 T-SQL 사용
* Windows, Linux 지원

&ensp;장점<br/>
* 강력한 기술 지원
* 풍부한 문서, 백서, 데모
* Microsoft 커뮤니티 지원 활용 가능

&ensp;단점<br/>
* 비용이 큼
* Windows, Linux 외 다양한 운영체제 지원이 제한적

&ensp;요약<br/>
&ensp;MS SQL Server = 상용 환경에서 강력한 지원이 장점이지만 비용이 크고 플랫폼 제약이 있음<br/>
