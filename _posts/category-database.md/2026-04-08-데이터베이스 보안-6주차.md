# 데이터베이스 관리자(DBA)

&ensp;데이터베이스 관리자는 단순히 데이터를 보는 사람이 아니라 시스템 권한 부여, 일반 사용자 생성 및 권한 부여, 백업, 감사까지 담당하는 핵심 관리자이다. 즉 데이터베이스 보안과 운영 전체를 책임지는 역할이라고 보면 된다.<br/>

<p align="center"><img src="/assets/img/database/6주차/6-1.png" width="600"></p>

# 관리자 계정

## Oracle

&ensp;Oracle은 설치 시 여러 관리자 계정이 자동 생성된다. 대표적으로 다음 계정들이 있다.<br/>
* SYS
* SYSTEM
* SYSBACKUP
* SYSDG
* SYSKM
* SYSRAC

&ensp;SYS 및 SYSTEM 관리자 게정에는 DBA Role 자동 부여<br/>
<p align="center"><img src="/assets/img/database/6주차/6-2.png" width="600"></p>

&ensp;1. SYS 계정<br/>
&ensp;가장 강력한 관리자 계정이다.<br/>
* 모든 권한을 가진다.
* **데이터 사전(Data Dictionary)** 의 소유자이다.
* 데이터베이스 설치 시  **SYSDBA 권한**이 자동 부여된다.

&ensp;즉, SYS는 오라클 내부 구조와 메타데이터를 직접 관리하는 **최상위 관리자**라고 이해하면 된다.<br/>

&ensp;2. SYSTEM 계정<br/>
&ensp;SYSTEM 계정도 매우 강력하지만, SYS와 완전히 같지는 않다.<br/>
* SYS와 거의 유사한 기능 수행
* 다만 백업/복구
* 데이터베이스 업그레이드는 수행할 수 없다.

&ensp;즉, SYSTEM은 일반적인 관리에는 강하지만, 시스템 핵심 관리까지는 아닌 계정이다.<br/>

&ensp;3. SYSBACKUP<br/>
&ensp;이름 그대로 백업과 복구 작업 전용 계정이다.<br/>
* RMAN
* SQL*Plus 내부 작업

&ensp;등을 통해 백업/복구를 수행한다.<br/>

&ensp;4. SYSDG<br/>
&ensp;Data Guard 작업을 수행하는 계정이다. Data Guard는 장애나 재해 상황에 대비해 대기 데이터베이스를 유지하는 기능이다. 즉, 고가용성과 재해복구와 연결되는 계정이다.<br/>

&ensp;5. SYSKM<br/>
&ensp;TDE(Transparent Data Encryption) 관련 작업 수행 계정이다. 즉, 오라클의 데이터 암호화 기능을 관리할 때 사용된다.<br/>

&ensp;6. SYSRAC<br/>
&ensp;Oracle RAC 관련 작업을 담당한다. 여러 서버가 하나의 데이터베이스처럼 동작하도록 하는 클러스터 환경과 연결된다.<br/>

## MySQL

&ensp;MySQL은 설치 시 root 계정이 자동 생성된다.<br/>
* root는 모든 권한을 가진 시스템 계정이다.
* b하지만 이름이 너무 잘 알려져 있으므로 보안상 다른 계정명으로 변경 권장이다.

&ensp;예시<br/>
```sql
update user set user='dbsec' where user='root';
flush privileges;
```

&ensp;flush privileges는 권한 정보 변경 사항을 즉시 반영하는 명령어이다.<br/>

# 관리자 권한

## Oracle

&ensp;Oracle의 대표적 관리자 권한은 다음 두 가지이다.<br/>
* SYSDBA
* SYSOPER

&ensp;데이터 생성, 시작, 종료, 백업 또는 복구와 같은 고급 관리 작업을 수행하는 데 필요한 관리 권한<br/>

&ensp;사용자 이름과 연결된 스키마가 아닌 기본 스키마 사용하여 접속<br/>
<p align="center"><img src="/assets/img/database/6주차/6-3.png" width="600"></p>

&ensp;1. SYSDBA<br/>
&ensp;가장 강력한 관리자 권한<br/>
&ensp;특징<br/>
* 대부분의 작업 수행 가능
* 사용자 데이터 접근 가능
* Restricted Mode에서도 접근 가능
* 데이터베이스의 시작과 종료 가능
* 데이터베이스 생성/삭제 가능
* SPFILE(서버 파라미터 파일) 생성 가능
* ARCHIVELOG 모드 전환 가능
* 데이터베이스 복구 가능

&ensp;SYSDBA는 사용자 데이터도 볼 수 있다는 점이 중요하다. 또한 불완전 복구까지 가능한 권한이라는 점도 SYSOPER와의 차이점이다.<br/>

&ensp;2. SYSOPER<br/>
&ensp;SYSDBA보다는 약하지만, 운영에 필요한 핵심 기능은 수행 가능하다.<br/>
&ensp;특징<br/>
* 기본적인 데이터베이스 운영 가능
* 사용자 데이터를 직접 볼 수는 없음
* Restricted Session 권한 보유
* STARTUP, SHUTDOWN 가능
* ALTER DATABASE 일부 가능
* RECOVER 가능하지만 완전 복구만 가능

&ensp;SYSDBA와의 차이<br/>
* SYSDBA: 사용자 데이터 접근 가능, DB 생성/삭제 가능, 불완전 복구 가능
* SYSOPER: 사용자 데이터 접근 불가, DB 생성/삭제 불가, 완전 복구만 가능

&ensp;즉, SYSOPER는 운영자, SYSDBA는 최상위 관리자라고 생각하면 구분이 쉽다.<br/>
<p align="center"><img src="/assets/img/database/6주차/6-4.png" width="600"></p>

&ensp;그 외의 관리자 권한<br/>
<p align="center"><img src="/assets/img/database/6주차/6-5.png" width="600"></p>

&ensp;관리자 계정<br/>
* ALL PRIVILEGES 권한
    - GRANT OPTION 권한 제외한 모든 권한 부여
* GRANT 명령어 사용

&ensp;CREATE USER 권한으로 다양한 기능 수행 가능<br/>
<p align="center"><img src="/assets/img/database/6주차/6-6.png" width="600"></p>


# 사용자 생성 및 권한 부여

&ensp;1. Oracle 사용자 생성<br/>
```sql
CREATE USER 사용자명 IDENTIFIED BY 암호;
```

&ensp;하지만 이 상태만으로는 로그인할 수 없다. 왜냐하면 사용자를 만들었을 뿐 **세션 생성 권한**을 주지 않았기 때문이다.<br/>

```sql
GRANT CREATE SESSION TO 사용자명;
```

&ensp;Oracle에서는  사용자 생성 ≠ 로그인 가능 이다. 로그인하려면 반드시 CREATE SESSION 권한이 필요하다.<br/>

&ensp;2. MySQL 사용자 생성<br/>
* CREATE USER 권한 필요
* Oracle과 달리 다양한 기능 수행

<p align="center"><img src="/assets/img/database/6주차/6-7.png" width="600"></p>

&ensp;사용자 생성 구문<br/>
```sql
CREATE USER '사용자명'@'호스트명' IDENTIFIED BY 암호;
```

&ensp;예제<br/>
<p align="center"><img src="/assets/img/database/6주차/6-8.png" width="600"></p>

&ensp;의미<br/>
* `'localhost'` : 로컬 접속만 허용
* `'%'` : 모든 호스트에서 접속 가능

&ensp;3. 사용자 암호 변경<br/>
&ensp;Oracle<br/>
```sql
ALTER USER 사용자명 IDENTIFIED BY 암호;
```

&ensp;MySQL<br/>
```sql
ALTER USER '사용자명'@'호스트명' IDENTIFIED BY 암호;
flush privileges;
```

<p align="center"><img src="/assets/img/database/6주차/6-9.png" width="600"></p>

&ensp;4. 사용자 삭제<br/>
&ensp;Oracle<br/>
```sql
DROP USER user명 CASCADE;
```

&ensp;여기서 CASCADE는 그 사용자의 스키마에 있는 객체까지 함께 삭제한다는 뜻이다.<br/>

&ensp;MySQL<br/>
```sql
DROP USER '사용자명'@'호스트명';
```

# 권한 부여

&ensp;권한은 크게 시스템 권한 부여, 객체 권한 부여(테이블, 뷰 등 데이터에 대한 권한 부여)로 나뉜다.<br/>

&ensp;1. 시스템 권한<br/>
&ensp;DB 전체 차원의 작업 권한이다.<br/>
&ensp;예:<br/>
* CREATE SESSION
* CREATE TABLE
* SELECT ANY TABLE
* ALTER SYSTEM
* CREATE ROLE
* CREATE USER
* DROP USER
* ALTER USER

&ensp;즉, 시스템 권한은 데이터베이스 구조나 시스템 동작 자체를 다룰 수 있는 권한이다.<br/>

&ensp;2. 객체 권한<br/>
&ensp;특정 테이블, 뷰 등 객체에 대한 권한이다.<br/>
&ensp;예:<br/>
* SELECT
* INSERT
* UPDATE
* DELETE

&ensp;즉, 객체 권한은 특정 데이터에 접근하거나 조작하는 권한이다.<br/>

&ensp;3. Oracle 권한 부여<br/>
&ensp;시스템 권한 부여<br/>
```sql
GRANT 권한 TO 사용자 [WITH ADMIN OPTION];
```

<p align="center"><img src="/assets/img/database/6주차/6-10.png" width="600"></p>
<p align="center"><img src="/assets/img/database/6주차/6-11.png" width="600"></p>
<p align="center"><img src="/assets/img/database/6주차/6-12.png" width="600"></p>

&ensp;객체 권한 부여<br/>
* 데이터베이스에 존재하는 모든 객체는 기본적으로 해당 객체를 생성한 사용자만 사용 권한 소유
    - 필요에 따라 다른 사용자에게 자신이 소유한 객체에 대한 사용 권한 부여 가능
* GRANT를 사용해 객체에 대한 사용 권한 부여

```sql
GRANT 권한 ON 객체 TO 사용자 [WITH GRANT OPTION];
```

&ensp;구분<br/>
* WITH ADMIN OPTION: 시스템 권한을 다시 다른 사용자에게 부여 가능
* WITH GRANT OPTION: 객체 권한을 다시 다른 사용자에게 부여 가능

<p align="center"><img src="/assets/img/database/6주차/6-13.png" width="600"></p>

&ensp;4. MySQL 권한 부여<br/>
&ensp;MySQL은 Oracle과 달리 시스템 권한과 객체 권한을 같은 GRANT 형식으로 다룬다.<br/>
```sql
GRANT 권한명 ON 데이터베이스명.테이블명 TO '사용자명'@'호스트명';
```

&ensp;MySQL에서는 권한을 크게 보면 글로벌 권한과 객체 권한으로 나누어 생각할 수 있다.<br/>
* 객체 권한: 데이터베이스나 테이블을 제어하는 데 필요한 권한
    - 특정 DB나 특정 테이블에 대한 권한
* 글로벌 권한: 데이터베이스나 테이블 이외의 객체에 적용되는 권한
    - MySQL 서버 전체 수준에서 작동하는 권한


&ensp;예<br/>
```sql
GRANT ALL PRIVILEGES ON *.* TO 'park'@'localhost';
GRANT ALL PRIVILEGES ON kmooc.* TO 'lee'@'localhost';
GRANT SELECT, INSERT, UPDATE, DELETE ON kmooc.dbsec TO 'hong'@'%';
```

* *.* : 전체 DB 전체 테이블
* kmooc.* : 특정 DB 전체 테이블
* kmooc.dbsec : 특정 DB의 특정 테이블

&ensp;차이<br/>

&ensp;객체 권한: 특정 데이터베이스나 특정 테이블에 대해 부여되는 권한<br/>
&ensp;예를 들면<br/>
* 어떤 테이블에서 SELECT 가능
* 어떤 테이블에 INSERT 가능
* 어떤 데이터베이스 안의 테이블들에 대해 UPDATE 가능

&ensp;같이 데이터 접근과 조작 중심이다.<br/>

&ensp;글로벌 권한: 특정 테이블 하나가 아니라 서버 전체 범위에 영향을 준다.<br/>
* 전체 DBMS 관리
* 계정/권한 관리
* 서버 차원의 작업

# 역할(Role)

&ensp;권한 관리를 통한 보안 방법<br/>
<p align="center"><img src="/assets/img/database/6주차/6-14.png" width="600"></p>

&ensp;역할은 **여러 권한을 묶어 놓은 집합** 이다.<br/>
&ensp;즉 권한을 사용자에게 하나씩 주지 않고 **역할에 권한을 넣은 뒤 역할을 사용자에게 부여**하는 방식이다.<br/>

&ensp;역할을 쓰는 이유<br/>
&ensp;같은 권한을 여러 사람에게 반복해서 주는 작업을 줄일 수 있기 때문이다.<br/>
&ensp;예를 들어 Hong, Park, Lee 세 사람에게 모두 SELECT, INSERT, DELETE 권한을 준다고 하자.<br/>
&ensp;그럼 권한을 각각 세 번씩 줄 수도 있지만, 더 좋은 방법은 다음과 같다.<br/>
1. role_1 생성
2. role_1에 SELECT, INSERT, DELETE 권한 부여
3. role_1을 Hong, Park, Lee에게 부여

&ensp;이렇게 하면 관리가 훨씬 쉬워진다.<br/>
<p align="center"><img src="/assets/img/database/6주차/6-15.png" width="600"></p>


&ensp;역할 기반 권한 부여<br/>
<p align="center"><img src="/assets/img/database/6주차/6-16.png" width="600"></p>

&ensp;1. 역할 생성<br/>
```sql
CREATE ROLE 롤이름;
```

&ensp;Oracle은 경우에 따라 비밀번호 있는 역할도 만들 수 있다.<br/>
```sql
CREATE ROLE 롤이름 indentified by 암호
```

&ensp;2. 역할에 권한 부여<br/>
```sql
GRANT 권한 ON 객체 TO 롤이름;
```

&ensp;즉 역할은 먼저 만들고 그 역할 안에 권한을 채워 넣는다.<br/>
<p align="center"><img src="/assets/img/database/6주차/6-17.png" width="600"></p>

&ensp;3. 사용자에게 역할 부여<br/>
```sql
GRANT 롤이름 TO 사용자
```

&ensp;이 한 줄로 여러 권한을 한꺼번에 전달할 수 있다. 이것이 역할 기반 권한 부여의 핵심 장점이다.<br/>

&ensp;사용자 역할 부여 예제<br/>
<p align="center"><img src="/assets/img/database/6주차/6-18.png" width="600"></p>

&ensp;4. 역할과 권한 취소<br/>
&ensp;역할에서 권한 취소<br/>
```sql
REVOKE 권한 ON 테이블 FROM 역할;
```

&ensp;예제<br/>
&ensp;role_1 역할에서 고객 테이블의 업데이트 권한을 취소해보자<br/>
```sql
REVOKE UPDATE ON 고객 FROM role_1;
```

&ensp;사용자에게서 역할 취소<br/>
```sql
REVOKE role_1 FROM Hong;
```

&ensp;사용자에게 역할을 취소하는 것은 권한을 부여했던 객체 소유자가 아닌 데이터베이스 관리자가 담당<br/>


&ensp;역할 삭제<br/>
```sql
DROP ROLE 롤 이름;
```

&ensp;GRANT는 부여, REVOKE는 취소, DROP ROLE은 역할 자체 삭제이다.<br/>

# 뷰(View)

&ensp;1. 뷰의 정의<br/>
&ensp;뷰는 하나 이상의 테이블을 이용해 만든 가상의 테이블이다. 실제로 데이터를 따로 저장하기보다는 SELECT 문 결과를 마치 테이블처럼 보여주는 개념이다.<br/>
&ensp;예를 들어 고객정보, 제품정보, 주문정보를 조인해서 “주문고객제품 뷰”를 만들 수 있다. 즉, 여러 테이블에 흩어진 정보를 하나로 묶어 보여줄 수 있다.<br/>

<p align="center"><img src="/assets/img/database/6주차/6-19.png" width="600"></p>
<p align="center"><img src="/assets/img/database/6주차/6-20.png" width="600"></p>

&ensp;2. 뷰의 장점<br/>
&ensp;1) 질의어 간소화<br/>
&ensp;복잡한 SELECT 문을 매번 작성하지 않아도 된다.<br/>
&ensp;2) 보안성 향상<br/>
&ensp;전체 테이블을 다 보여주지 않고, 허용된 일부 컬럼이나 일부 행만 보여줄 수 있다.<br/>
&ensp;3) 논리적 데이터 독립성<br/>
&ensp;실제 테이블 구조를 직접 노출하지 않고, 응용 프로그램이 원하는 형태로 데이터를 제공할 수 있다. 즉, 뷰는 편의성 + 보안성을 동시에 챙길 수 있는 도구이다.<br/>

&ensp;3. 뷰의 단점<br/>
&ensp;뷰는 실제 물리 테이블이 아니라 가상 테이블이므로 일부 DML 작업에 제약이 있다.<br/>
* INSERT 제약 가능
* UPDATE 제약 가능
* DELETE 제약 가능
* ALTER로 뷰 정의 변경 불가

&ensp;즉, 조회용으로는 매우 유용하지만 수정 작업은 항상 가능한 것이 아니다.<br/>

&ensp;4. 뷰 생성<br/>
```sql
CREATE VIEW 뷰이름[(속성리스트)]
AS SELECT 문
[WITH CHECK OPTION];
```

&ensp;WITH CHECK OPTION 의미<br/>
&ensp;생성한 뷰에 삽입이나 수정 연산을 할 때 SELECT 문에서 제시한 뷰의 정의 조건을 위반하면 수행되지 않도록 하는 제약조건 지정<br/>

&ensp;예<br/>
```sql
CREATE VIEW 우수고객(고객아이디, 고객이름, 나이, 등급)
AS SELECT 고객아이디, 고객이름, 나이, 등급
FROM 고객
WHERE 등급='vip'
WITH CHECK OPTION;
```

&ensp;이 경우 우수고객 뷰에는 등급이 vip인 고객만 들어와야 한다. 따라서 등급이 basic인 데이터를 이 뷰에 넣으려 하면 거부된다.<br/>

&ensp;5. 뷰 삭제<br/>
```sql
DROP VIEW 뷰이름;
```

&ensp;뷰는 가상 테이블이므로 뷰를 삭제해도 원본 테이블은 삭제되지 않는다.<br/>
* ALTER 문 수행 불가하므로 수정을 하려면 이전의 뷰를 삭제하고 새로운 뷰 재생성
* 해당 뷰를 특정 뷰가 참조하고 있는 경우와 같이 제약 조건을 가진 경우 뷰 삭제 불가하므로 관련 제약조건 삭제부터 수행
* 가상의 테이블이므로 뷰를 삭제하더라도 참조했던 테이블(기본 테이블)은 영향을 받지 않음

&ensp;6. 뷰 업데이트<br/>
```sql
UPDATE 테이블 이름
SET 속성 이름1 = 값1, 속성 이름2 = 값2, ...
[WHERE 조건];
```

&ensp;7. 뷰 조작<br/>
&ensp;뷰 테이블 내 튜플 값 수정하는 것 외에 데이터에 대해 INSERT, DELETE 문을 사용하여 삽입 및 삭제 기능<br/>
&ensp;특정 경우 데이터 조작어(DML) 사용 불가<br/>

&ensp;변경 불가능한 뷰의 대표 조건<br/>
* 기본 테이블의 기본키가 포함되지 않은 경우
* NOT NULL 속성이 빠진 경우
* 집계함수 결과 포함
* DISTINCT 포함
* GROUP BY 포함
* 여러 테이블 조인으로 정의된 경우

# 데이터베이스 감사(Audit)

&ensp;감사는 시스템 안에서 발생하는 행동을 기록하고 검토하는 기능이다. 쉽게 말하면 누가, 언제, 무엇을 했는지 남기는 보안 추적 기능이다.<br/>
&ensp;감사가 필요한 이유<br/>
&ensp;데이터베이스는 여러 사용자와 프로그램이 함께 사용한다. 그래서 중요한 데이터가 바뀌었을 때,<br/>
* 누가 바꿨는지
* 언제 바꿨는지
* 어떤 작업을 했는지

&ensp;확인할 필요가 있다. 즉, 사고 원인 분석과 책임 추적을 위해 감사가 필요하다.<br/>

&ensp;Oracle 감사 기능 동작<br/>
&ensp;Oracle은 기본적으로 감사가 꺼져 있다. 감사를 사용하려면 AUDIT_TRAIL 값을 바꿔야 한다.<br/>

&ensp;값 종류<br/>
* NONE : 감사 안 함
* DB(TRUE) : 감사 로그를 DB 내부 테이블(sys.audit$)에 저장
* OS : 운영체제 파일에 저장

&ensp;즉, 감사는 자동으로 되는 것이 아니라 설정 후에 동작한다는 점이 중요하다.<br/>

&ensp;감사 규칙이 필요한 이유<br/>
&ensp;모든 행동을 무조건 기록하면 로그가 너무 많아진다. 그러면 관리도 어렵고, 문제 발생 시 원인 분석도 오래 걸린다.<br/>
&ensp;따라서<br/>
* 특정 질의문만 기록
* 로그인 성공/실패만 기록

&ensp;처럼 명확한 감사 규칙을 정해야 한다.<br/>

## 감사 유형

&ensp;1) 로그인 감사<br/>
&ensp;사용자의 로그인 성공/실패를 기록한다.<br/>

```sql
AUDIT SESSION [WHENEVER SUCCESSFUL | NOTSUCCESSFUL];
NOAUDIT SESSION [WHENEVER SUCCESSFUL | NOTSUCCESSFUL];
```

* SUCCESSFUL : 성공한 로그인만 기록
* NOTSUCCESSFUL : 실패한 로그인만 기록

<p align="center"><img src="/assets/img/database/6주차/6-22.png" width="600"></p>

&ensp;2) 행동 감사<br/>
&ensp;특정 SQL 실행 자체를 기록한다.<br/>

```sql
AUDIT action
[BY user]
[BY SESSION | ACCESS]
[WHENEVER SUCCESSFUL | NOTSUCCESSFUL];
```

&ensp;의미<br/>
* action : 감사할 질의문 작성, VIEW, TABLE 과 같은 객체만 지정하는 것도 가능 -> 객체에 대한 모든 작업 기
* BY user : 특정 사용자만 감사 (사용자 미정 -> 지정한 질의문을 수행한 모든 사용자 또는 특정 객체에 수행한 모든 질의문에 대해 감사 수행)
* BY SESSION : 세션당 한 번록 기록
* BY ACCESS : 실행할 때마다 기록
* WHENEVER SUCCESSFUL / NOTSUCCESSFUL : 성공/실패 구분 기록

```sql
NOAUDIT action
[BY user]
[WHENEVER SUCCESSFUL | NOTSUCCESSFUL];
```

<p align="center"><img src="/assets/img/database/6주차/6-23.png" width="600"></p>

&ensp;예:<br/>
```sql
AUDIT TABLE;
```

&ensp;모든 사용자가 TABLE 관련 작업을 하면 기록한다.<br/>
&ensp;또는<br/>
```sql
AUDIT TABLE
BY TOM
BY SESSION
WHENEVER NOTSUCCESSFUL;
```

&ensp;이 경우 TOM이 테이블 작업을 실패했을 때만, 그리고 세션당 한 번씩 기록한다.<br/>

&ensp;3) 객체 감사<br/>
&ensp;특정 객체에 대한 작업을 기록한다.<br/>
```sql
AUDIT action
ON object
[BY SESSION | ACCESS]
[WHENEVER SUCCESSFUL | NOTSUCCESSFUL];
```

&ensp;ON<br/>
* 감사를 수행할 특정 객체 지정
* 객체마다 사용할 수 있는 질의문이 따로 존재하기
때문에 지정되는 행동이 객체에 따라 달라질 수 있음

&ensp;행동 감사와 비슷하지만, 초점이 “행동 자체”보다 특정 객체에 대한 행동에 있다.<br/>
&ensp;예를 들어 특정 테이블에 대한 SELECT, UPDATE, DELETE 등을 따로 감사할 수 있다.<br/>
