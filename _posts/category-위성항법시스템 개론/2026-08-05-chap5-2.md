# Broadcast Model (Klobuchar Model)

> 전리층 지연을 "대충이지만 빠르게" 예측하는 경험적 모델이 Klobuchar model

&ensp;이 모델은 ionosphere 전체 물리를 정밀하게 계산하는 모델이 아니라<br/>
* 낮에는 전리층 지연이 커지고
* 밤에는 작아지고
* 위성이 낮은 고도에 있으면 경로가 길어져 지연이 커진다

&ensp;수식 구조<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-28.png" width="600"></p>

&ensp;이 식은 천정 방향(zenith) ionosphere 지연을 시간에 따라 모델링 한 것이다.<br/>

* $A_1$ : 야간 기본값(바닥값)
* $A_2$ : 낮 동안 증가하는 추가 진폭
* $A_3$ : 최대 지연이 나타나는 시간 중심
* $A_4$ : 반코사인 모양이 펼쳐지는 시간 폭(주기 관련)

&ensp;ionospheric delay 를 시간에 대해 보면<br/>
* 밤에는 거의 일정한 작은 값
* 낮에는 반코사인(half-cosine) 모양으로 올라갔다가 내려감

&ensp;ionosphere은 태양 복사로 형성되니까,<br/>
* 낮: 태양이 있으니 자유전자가 많아짐 → 지연 증가
* 밤: 태양이 없으니 전자밀도 감소 → 지연 작아짐

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-29.png" width="600"></p>

&ensp;**local time에 따른 zenith ionospheric delay** <br/>
* $A_1$ : 밤 시간 기본 지연
* $A_2$ : 그 위로 얼마나 더 올라가는지
* $A_4/2$ : 실제 낮 동안 반코사인이 펼쳐지는 유효 폭처럼 보일 수 있음

> 전리층 지연은 하루 내내 일정한 것이 아니라, 지역 시간(local time)에 따라 달라진다.

&ensp;Obliquity factor<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-30.png" width="600"></p>

&ensp;위성이 낮은 앙각에 있으면 신호가 ionosphere을 비스듬히 길게 통과한다.<br/>
* 같은 수직 지연이라도
* 실제 경사 경로(slanted path)에서는 더 큰 지연

&ensp;slant delay = OF × zenith delay<br/>

> Klobuchar model은 천정 전리층 지연을 지역 시간의 함수로 반코사인 + 상수 형태로 모델링하고,이를 obliquity factor로 경사 방향 지연으로 바꿔서 단일주파수 수신기의 전리층 오차를 보정한다.

&ensp;IS-GPS-200E의 ionospheric parameters<br/>
&ensp;Klobuchar model의 계수는 항법 메시지(navigation message)에 실려 온다. 즉 수신기는 위성이 보내주는 ionospheric parameters를 읽어서 Klobuchar model에 넣어 사용한다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-31.png" width="600"></p>

* α 계수들 → 지연 진폭(amplitude) 관련
* β 계수들 → 주기(period) 관련

&ensp;전리층 지연은 단순히 “시간만의 함수”가 아니라, 사용자 위치와 IPP 위치에 따라 달라진다 그래서 단순 상수 하나로는 부족하고, 어떤 위치 변수 $ϕ_{m}$ 같은 것을 넣은 다항식 형태로 AMP와 PER를 계산한다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-32.png" width="600"></p>

&ensp;IS-GPS-200E 식의 실제 형태<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-33.png" width="600"></p>

&ensp;half-cosine daytime + constant nighttime를 코사인 함수를 근사 다항식으로 쓴 버전<br/>

&ensp;x의 의미<br/>

$$x = \frac{2\pi (t - 50400)}{PER}$$

&ensp;여기서 t는 local time 비슷한 시간 변수고, 50400초는 50400s = 14h 이다.<br/>

> 전리층 지연 피크는 오후 2시 근처라고 가정

&ensp;AMP와 PER<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-34.png" width="600"></p>

* AMP: 전리층 지연의 크기
* PER: 전리층 지연의 시간적 폭, 주기 비슷한 역

&ensp;AMP < 0 이면 0으로 PER < 72000 이면 72000초로 제한<br/>

# Tropospheric Delay

&ensp;1. 대류권<br/>
&ensp;대류권은 지표 부근의 하층 대기이다. GPS 신호는 이 층을 통과하면서 지연을 겪는다.<br/>
&ensp;ionosphere 과 달리 troposphere은 주로 건조 기체(dry gases), 수증기(water vapor)로 이루어져 있다.<br/>

&ensp;2. 대류권은 non-dispersive<br/>
&ensp;전리층은 dispersiv → 주파수에 따라 지연이 다름<br/>
&ensp;대류권은 GPS L-band에서 non-dispersive → 주파수에 거의 의존하지 않음

&ensp;L1 코드, L2 코드, L1 carrier, L2 carrier가 거의 같은 대류권 지연을 경험한다.<br/>

&ensp;3. 굴절률 크기<br/>
&ensp;대기 굴절률은 sea level에서 n≈1.0003 정도이다. 아주 1에 가깝지만 GPS 수는 cm ~ m 단위 정밀도를 다루기 때문에 이 작은 차이도 충분히 중요한 지연을 만든다. 또 고도가 높아질수록 공기가 희박해져서 n은 1에 더 가까워진다.<br/>

## Tropospheric Delay의 성질

&ensp;1. 코드와 반송파 모두 common delay<br/>
&ensp;대류권에서는<br/>
* hase velocity와 group velocity가 사실상 같고
* 주파수 의존성이 거의 없어서
* 코드도 carrier도 같은 방향, 같은 부호의 지연을 받는다.

> Code and carrier at L1 and L2 experience a common delay

&ensp;2. 지연 크기<br/>
* 위성이 높이 떠 있으면 경로가 짧아져 지연이 작아진다.
* 위성이 낮으면 비스듬히 길게 통과하므로 지연이 커진다.

&ensp;3. 왜 GPS 측정만으로 추정하기 어렵다.<br/>
&ensp;전리층은 L1/L2에서 다르게 보이니까 분리하기 쉽다. 하지만 대류권은 비분산성이므로 L1과 L2가 거의 같은 값을 보이고 코드와 캐리어도 같은 방향 지연을 보이므로 관측값 자체만으로는 다른 거리 성분과 구분하기 어렵다.<br/>

&ensp;4. Dry delay와 Wet delay<br/>
&ensp;(1) Dry delay<br/>
&ensp;건조 기체에 의한 지연<br/>
* 상대적으로 안정적
* 위도, 계절, 고도 등에 따라 바뀜
* 예측이 비교적 쉬움

&ensp;(2) Wet delay<br/>
&ensp;수증기에 의한 지연<br/>
* 매우 가변적
* 공간적, 시간적으로 불규칙
* 모델링이 어려움

&ensp;전체 대류권 지연의 대부분은 dry 성분이라서 대략적인 모델 보정은 꽤 잘 되는 편이다. 하지만 정밀 위치결정에서 남은 wet delay는 제거하기 힘들다.<br/>

## Dry and Wet Delays

&ensp;1. Refractivity N<br/>

$$N = (n-1) \times 10^6 = N_d + N_w$$

* n: 굴절률
* N: refractivity
* $N_d$ : dry refractivity
* $N_w$ : wet refractivity

&ensp;2. Excess path delay<br/>

$$\tilde{T} = \int (n(l) -1)dl$$

&ensp;"진공에서의 경로에 비해 대기 때문에 얼마나 더 늘어난 경로 지연이 생기는가"를 뜻한다.<br/>
&ensp;refractivity를 쓰면<br/>

$$\tilde{T} = 10^ 6 \int (n_d(l) + N_w(l)dl = \tilde{T_d} + \tilde{T_w}$$

&ensp;총 대류권 지연 = dry delay + wet delay<br/>

&ensp;3. Empirical expressions<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-35.png" width="600"></p>

* P: total pressure [millibar]
* T: temperature [K]
* e: water vapor partial pressure [millibar]

&ensp;Dry refractivity<br/>

$$N_d = 77.64\frac{P}{T}$$

* 기압 P가 높을수록 커짐
* 온도 T가 높을수록 작아짐

&ensp;Wet refractivity<br/>

$$N_w = 3.73 \times 10^5 \frac{e}{T^2}$$

* 수증기 분압 e가 클수록 커짐
* 온도에 민감함

## Estimation of the Tropospheric Delay

&ensp;step1. zenith delay 계산<br/>
&ensp;대류권 지연은 위성의 위치에 따라 달라진다.<br/>
&ensp;위성이 수신기 바로 위인 zenith 방향에 있으면 신호가 대류권을 거의 수직으로 가장 짧게 통과한다.<br/>
&ensp;위성이 수신기 바로 위인 zenith 방향에 있으면 신호가 대류권을 거의 수직으로 가장 짧게 통과한다.<br/>

```img
                  위성
                   │
                   │ 가장 짧은 대기 통과 경로
                   │
                 수신기
```

&ensp;이때의 대류권 지연을 zenith delay<br/>
&ensp;반면 위성이 지평선 가까이에 있으면 신호가 대류권을 비스듬히 길게 통과한다.<br/>

```img
위성
   ＼
     ＼ 긴 대기 통과 경로
       ＼
        수신기
```

&ensp;따라서 실제 위성 방향의 지연을 바로 모델링하는 것보다, 먼저 기준이 되는 zenith delay를 계산하고 elevation angle에 따라 확대하는 방식이 편리하다.<br/>

$$\tilde{T_z} = \tilde{T_{z, d}} + \tilde{T_{z, w}}$$

* $\tilde{T_z}$ : 전체 zenith tropospheric delay
* $\tilde{T_{z, d}}$ : zenith dry delay
* $\tilde{T_{z, w}}$ : zenith wet delay

&ensp;위성이 수신기 바로 위에 있을 때에도 dry gas와 water vapor가 각각 지연을 만든다. 보통 dry delay가 전체 대류권 지연의 대부분을 차지하고 wet delay는 상대적으로 작지만 변화가 심하다.<br/>

&ensp;step 2: 실제 위성 방향으로 변환<br/>
&ensp;위성의 실제 elevation angle을 el이라고 하면 slant 방향의 대류권 지연은<br/>

$$\tilde{T} = \tilde{T_{z, d}}m_d (el) + \tilde{T_{z, w}}m_w (el)$$

* $m_d (el)$ : dry delay mapping function
* $m_w (el)$ : wet delay mapping function

&ensp;Mapping function은 zenith delay를 실제 위성 방향의 slant delay로 확대해 주는 배율이다.<br/>

# Saastamoinen Model

&ensp;1. Zenith dry delay<br/>

$$\tilde{T_{z, d}} = 0.002277(1+0.0026cos 2\varphi + 0.00028H)P_0$$

* $P_0$ : 안테나 위치의 total pressure
* ϕ: 수신기 위도
* H: 안테나의 orthometric height(geoid 또는 평균 해수면 기준 높이)

&ensp;2. Dry delay는 무엇에 가장 민감한가?<br/>
&ensp;에서 가장 직접적으로 곱해지는 값은 $P_0$ , 즉 기압이다.<br/>

$$\tilde{T_{z, d}} \propto P_0$$

&ensp;기압이 높다는 것은 수신기 위쪽에 존재하는 공기 질량이 많다는 뜻이므로 dry delay가 커진다. 위도 ϕ와 고도 H는 지구 중력과 대기 분포 차이를 반영하는 작은 보정항이다. 따라서 dry delay를 정확히 계산하려면 surface pressure 측정이 가장 중요하다.<br/>

&ensp;3. Zenith wet delay<br/>

$$\tilde{T_{z, w}} = 0.002277(\frac{1255}{T_0} + 0.05) e_0$$

* $T_0$ : 안테나 위치의 temperature
* $e_0$ : water vapor partial pressure

&ensp;4. Partial pressure<br/>
&ensp;공기는 여러 기체가 섞인 혼합물이다. 전체 기압은 각 기체가 만들어내는 partial pressure의 합이다.<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-36.png" width="600"></p>

* $P_0$ : 모든 대기 성분을 포함한 total pressure
* $e_0$ : 그중 water vapor가 만드는 partial pressure

# Hopfield Model

&ensp;Hopfield model도 대류권 zenith delay를 dry와 wet으로 나누어 계산하는 모델이다.<br/>
&ensp;Saastamoinen model과 목적은 같지만, 대기의 수직 분포를 유효 대기 높이와 연결해 표현한다.<br/>

&ensp;1. Zenith dry delay<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-37.png" width="600"></p>

&ensp;$h_d$ 는 dry atmosphere의 effective height이다. 즉 dry refractivity가 일정한 profile로 감소한다고 가정하고, 그 효과를 $h_d$ 라는 대표 높이로 나타낸 것이다.<br/>

&ensp;2. Zenith wet delay<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-38.png" width="600"></p>

&ensp;$h_w$는 water vapor의 effective height이다. 수증기는 주로 지표 가까이에 존재하므로 dry atmosphere보다 더 낮은 고도에 집중되는 경향이 있다.<br/>

&ensp;3. Dry delay가 더 정확하게 모델링되는 이유<br/>
&ensp;정확한 surface pressure를 알고 있으면 dry delay model의 오차가 몇 mm 정도이다.<br/>
&ensp;Dry atmosphere는<br/>
* 공간적으로 비교적 균일하고
* 시간 변화가 느리고
* surface pressure와 강하게 연결되기 때문

&ensp;4. Wet delay가 어려운 이유<br/>
&ensp;Wet delay는 surface meteorological data를 사용해도 일반적으로 약 1~2cm의 모델 오차가 남을 수 있다. 왜냐하면 지표에서 측정한 humidity가 수신기 위 전체 수증기 분포를 완벽히 나타내지 못하기 때문이다. 그래서 wet delay는 PPP 같은 정밀 측위에서 단순히 모델로 완전히 제거하기보다는 추정해야 할 상태변수로 두는 경우가 많다.<br/>

# Mapping Functions

&ensp;1. Mapping function의 역할<br/>
&ensp;Mapping function은 zenith delay를 실제 위성 방향의 slant delay로 바꾸는 배율이다.<br/>
&ensp;가장 단순하게 대기를 평평한 층으로 보면 $m(el) \approx \frac{1}{sin el}$ <br/>

&ensp;2. Dry mapping function<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-39.png" width="600"></p>

&ensp;Dry atmosphere의 수직 분포를 반영한 mapping function이다.<br/>

&ensp;3. Wet mapping function<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-40.png" width="600"></p>

&ensp;Water vapor가 dry gas와 다른 고도 profile을 갖기 때문에 계수가 조금 달라진다.<br/>

&ensp;4. 낮은 elevation 관측값이 불리한 이유<br/>
&ensp;낮은 elevation 위성은 대류권 지연뿐 아니라 다음 문제도 더 크게 받을 수 있다.<br/>
* 전리층 통과 경로 증가
* 대류권 지연 증가
* multipath 증가
* 건물이나 지형에 의한 차폐
* 안테나 gain 저하
* mapping function 오차 증가

&ensp;그래서 GNSS 처리에서는 보통 아주 낮은 elevation의 위성을 제외하는 elevation mask를 사용하거나, 낮은 elevation 관측값에 더 작은 weight를 준다.<br/>

# Measurement Errors

&ensp;1. 측정 오차에 영향을 주는 요소<br/>
* Signal power
* Code structure
* Receiver/antenna design

&ensp;2. Receiver noise<br/>
&ensp;Receiver noise는 수신기가 신호를 측정하는 과정에서 생기는 불규칙한 오차이다. 관측식에서는 주로 $ε_{\rho }, ε_{\varphi }$ 에 포함된다.<br/>

&ensp;1) 안테나·증폭기·케이블·수신기 잡음<br/>
&ensp;GPS 신호는 지상에 도달했을 때 매우 약하다. 그래서 안테나와 증폭기, 케이블, 수신기 전자회로가 만들어내는 작은 열잡음도 측정에 영향을 준다.<br/>

```
GPS 신호
   ↓
안테나
   ↓
저잡음 증폭기
   ↓
케이블
   ↓
수신기 RF·디지털 회로
```

&ensp;신호 세기가 약해지면 신호와 잡음을 구분하기 어려워지고 코드나 반송파를 추적하는 DLL, PLL 출력도 더 많이 흔들린다.<br/>
* 신호가 강함 ⇒ tracking noise 감소
* 신호가 약함 ⇒ tracking noise 증가

&ensp;2) Multi-access noise<br/>
&ensp;GPS 수신기는 동시에 여러 위성의 신호를 받는다. 각 위성은 서로 다른 PRN 코드를 사용하므로 이상적으로는 상호구분되지만 실제 PRN 코드 사이의 cross-correlation이 완전히 0인 것은 아니다. 따라서 한 위성 신호를 추적할 때 다른 위성의 신호가 작은 간섭 성분으로 들어올 수 있다. 또 GPS와 유사한 주파수, 구조를 가진 다른 무선 신호도 간섭을 만들 수 있다. 이러한 영향을 **multi-access noise** 라고 한다.<br/>

&ensp;3) Signal quantization noise<br/>
&ensp;수신기가 받은 아날로그 신호는 ADC를 통해 디지털 값으로 변환된다. 이 과정에서 연속적인 진폭값을 제한된 단계로 표현하기 때문에 원래 값과 디지털 값 사이에 작은 차익 생긴다.<br/>
&ensp;이 차이가 quantization noise이다.<br/>
&ensp;비트 수가 충분하고 수신기가 적절하게 설계되었다면 영향이 제한적이지만, 이것도 전체 수신기 잡음의 일부가 된다.<br/>

&ensp;3. Multipath<br/>
&ensp;Multipath는 같은 위성 신호가 두 개 이상의 경로를 통해 안테나에 도착하는 현상이다. 가장 이상적인 경우는 위성에서 안테나로 직접 도착하는 LOS 신호만 받는 것이다.<br/>
&ensp;하지만 실제로는 신호가 지면, 건물 외벽, 유리창, 차량, 금속 구조물, 수면 등에 반사된 뒤 안테나에 들어올 수 있다.<br/>

&ensp;반사 신호의 특징<br/>
&ensp;반사 신호는 직접 신호보다 경로가 길다.<br/>
* 더 늦게 도착하고
* 반사 과정에서 에너지를 잃어 더 약해지고
* 위상도 달라진다.

&ensp;직접 신호와 합쳐진다. 수신기는 두 신호를 완전히 분리하지 못하고 합쳐진 신호를 추적하기 때문에 코드 도착시각과 반송파 위상을 잘못 판단할 수 있다.<br/>

&ensp;multipath 오차 크기를 결정하는 요인<br/>
&ensp;반사 신호의 세기<br/>
&ensp;반사 신호가 직접 신호에 비해 강할수록 합성 신호를 더 크게 왜곡한다.<br/>
&ensp;두 신호의 상대적인 시간 지연<br/>
&ensp;직접 신호와 반사 신호 사이의 지연이 어느 정도인지에 따라 correlation peak가 변하는 방식이 달라진다.<br/>

&ensp;Multipath error = f(반사 신호 세기, 상대 지연)<br/>

&ensp;코드와 반송파에서의 multipath 크기<br/>
* Code multipath: 약 1∼5m
* Carrier phase multipath: 약 1∼5cm

&ensp;코드 관측값이 훨씬 크게 영향을 받는 이유는 코드의 기본 눈금이 carrier보다 훨씬 거칠기 때문이다.<br/>
&ensp;반송파는 파장이 약 19cm여서 오차도 대체로 cm 수준이지만, 코드의 한 chip은 약 293m에 해당하므로 correlation peak의 작은 왜곡도 수 m의 거리 오차가 될 수 있다.<br/>

&ensp;Multipath가 억제되는 시기<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-41.png" width="600"></p>

&ensp;그림에서 안테나는 동일한 위성으로부터 다음 신호를 동시에 받는다.<br/>
* 위성에서 직접 온 신호
* 지면에서 반사된 신호
* 건물 벽에서 반사된 신호

&ensp;직접 경로가 가장 짧고, 반사 경로는 더 길기 때문에 반사 신호는 늦게 도착한다.<br/>

&ensp;1.5 chip보다 많이 지연된 신호<br/>
&ensp;C/A 코드의 한 chip 길이는 약 1 chip = 0.9775 μs ≈ 293 m 이므로 1.5chip은 1.5 × 293 ≈ 440 m의 추가 경로 길이에 해당한다.<br/>

&ensp;긴 지연의 반사 신호는 자동으로 억제된다.<br/>
&ensp;수신기는 들어온 C/A 코드와 내부에서 생성한 C/A 코드를 correlation해서 코드 위치를 찾는다. C/A 코드의 autocorrelation은 코드가 정확히 맞을 때 크게 나타나지만, 1 chip 이상 상당히 어긋나면 거의 0에 가까워진다.<br/>
&ensp;반사 신호가 직접 신호보다 매우 늦게 도착하면 직접 신호의 correlation peak 근처에 영향을 거의 주지 못한다. 따라서 오히려 문제가 되는 것은 추가 경로가 짧은 반사 신호, 즉 direct signal과 시간적으로 가까운 multipath이다. 이런 신호는 직접 신호의 correlation peak와 겹쳐 peak의 모양을 비대칭으로 만들고, 수신기가 코드 도착시각을 잘못 추정하게 하게 한다.<br/>

&ensp;반송파 multipath의 최대 위상오차<br/>
> 반사 신호의 진폭이 직접 신호보다 작다면 carrier phase measurement error는 최대 quarter cycle 정도다.

&ensp;직접 신호와 반사 신호를 phasor로 더하면 수신기가 추적하는 합성 위상이 만들어진다.<br/>
&ensp;반사 신호가 직접 신호보다 약하다면 합성 위상이 직접 신호 위상으로부터 벗어날 수 있는 범위에 제한이 생긴다. 최악의 경우 약 $\frac{1}{4} cycle = 90^{∘}$ 정도가 된다.<br/>
&ensp;L1 파장이 약 19cm이므로 거리로 환산하면 $\frac{\lambda _{L1}}{4} \approx \frac{19cm}{4} \approx 4.8cm$ 이다.<br/>

&ensp;다만 직접 신호가 차단되고 반사 신호만 받는 NLOS 상황에서는 이 가정이 성립하지 않는다. 그때는 단순한 수 cm multipath가 아니라 훨씬 큰 위치 오차가 발생할 수 있다.<br/>

&ensp;Multipath와 elevation angle<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-42.png" width="600"></p>

&ensp;elevation angle이 낮을수록 코드 의사거리 오차가 커지고, elevation angle이 높아질수록 작아진다.<br/>
&ensp;낮은 elevation => 큰 measurement error<br/>

&ensp;낮은 elevation에서 오차가 큰 이유<br/>
* 신호가 약하다.
  - 안테나는 보통 머리 위 방향의 신호를 잘 수신하도록 설계된다. 지평선 가까이에서 오는 신호는 안테나 이득이 낮고 대기를 더 길게 통과하므로 신호 세기가 약해질 수 있다.
  - 신호가 약하면 receiver tracking noise가 커진다.
* 반사 환경이 많다.
  - 낮은 elevation의 신호는 건물, 지면, 차량 등의 표면과 만날 가능성이 높아진다.
  - direct signal과 함께 다양한 reflected signal이 안테나로 들어오기 쉽다.
* 지면 반사 신호가 강해진다.
  - 안테나 아래의 지면에서 반사된 신호는 low-elevation 위성에서 중요한 multipath 원인이 될 수 있다.

&ensp;Standard receiver와 Advanced receiver<br/>
&ensp;Standard receiver<br/>
&ensp;일반적인 correlation 방식과 안테나를 사용하는 수신기이다. 낮은 elevation에서 약 1m 이상으로 오차가 크게 증가하고, 높은 elevation에서도 일정한 noise floor가 남아 있다.<br/>

&ensp;Advanced receiver<br/>
* Narrow correlator
* Choke-ring antenna

&ensp;Advanced receiver의 그래프가 전체적으로 더 낮으므로 동일한 환경에서도 receiver noise와 multipath 영향을 줄일 수 있다는 뜻이다.<br/>

&ensp;Narrow correlator<br/>
&ensp;코드 추적에서는 early, prompt, late correlation 값을 이용해 correlation peak의 중심을 찾는다. Narrow correlator는 early와 late 사이의 간격을 더 좁게 설정해 짧은 지연 multipath가 correlation peak를 왜곡하는 영향을 줄여준다.<br/>

&ensp;Choke-ring antenna<br/>
&ensp;Choke-ring antenna는 안테나 주변에 동심원 형태의 금속 구조가 있는 정밀 GNSS 안테나이다. 이 구조는 주로 지면이나 낮은 방향에서 들어오는 반사 신호를 억제하고, 위쪽에서 오는 직접 신호를 상대적으로 잘 받도록 도와준다. 따라서 특히 정지형 측지·기준국 환경에서 multipath를 줄이는 데 유용하다.<br/>

&ensp;실제 처리<br/>
* 높은 elevation 관측값 → 높은 weight
* 낮은 elevation 관측값 → 낮은 weight
* 아주 낮은 elevation → elevation mask로 제외

# User Range Error (URE)

&ensp;단일 주파수 L1 수신기의 pseudorange 측정에 대해, 사용자에게 보이는 거리 오차를 단순화하여 모델링한다.<br/>
&ensp;1. Control Segment에 의한 거리 오차<br/>
* 위성 시계 오차와 broadcast ephemeris 오차 등을 포함
* 경험적으로 $\sigma _{RE/CS} \approx 3m (rms)$

&ensp;2. 대기 전파 모델에 의한 잔여 거리 오차<br/>
* Klobuchar model 같은 전리층 보정 모델을 적용한 뒤에도 남는 오차
* 중위도 기준 $\sigma _{RE/P} \approx 5m (rms)$

&ensp;3. 수신기 잡음 및 multipath에 의한 거리 오차<br/>
* receiver noise + multipath
* 대략 $\sigma _{RE/RNM} \approx 1m (rms)$

&ensp;결합 효과<br/>
&ensp;이 세 오차를 RSS(root-sum-square) 방식으로 합치면 URE 또는 UERE가 된다.<br/>

$$\sigma _{URE} = \sqrt{\sigma ^2_{RE/CS} + \sigma ^2_{RE/P} + \sigma ^2_{RE/RNM}} \approx 6m$$

&ensp;단일주파수 GPS 수신기의 pseudorange는 대략 6 m 정도의 rms 거리 오차를 가진다고 볼 수 있다.<br/>

# Measurement Error: Empirical Data — Multipath & Receiver Noise

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-47.png" width="600"></p>

&ensp;그래프 해석<br/>
* 오차가 0을 중심으로 위아래로 흔들린다.
* 단순한 백색잡음처럼 완전히 랜덤하지 않고,
* 어느 정도 주기성을 가지는 진동 패턴이 보인다.

&ensp;위성과 수신기, 반사체의 상대 기하가 천천히 변하면서 직접파와 반사파의 위상 관계가 점진적으로 바뀌기 때문이다. 그래서 오차가 천천히 진동하는 형태로 관측된다.<br/>

&ensp;Receiver noise와의 차이<br/>
* Receiver noise: 더 랜덤하고 빠르게 변함
* Multipath: 상대적으로 느리고 주기적인 패턴을 보임

&ensp;경험적 데이터에서 이런 진동 패턴이 보이면, 단순 잡음뿐 아니라 multipath 영향이 포함되었다고 해석할 수 있다.<br/>

# Combining Code & Carrier Measurements

&ensp;1. Code와 Carrier를 같이 사용하는 이유<br/>
&ensp;GPS/GNSS에서는 거리를 측정할 때 대표적으로 두 가지 measurement가 있다.<br/>
* Code measurement
* Carrier phase measurement

&ensp;둘은 장단점이 서로 반대로 가까워진다.<br/>

&ensp;Code measurement<br/>
&ensp;Code measurement는 위성과 수신기 사이의 absolute pseudorange를 바로 측정할 수 있다는 장점이 있다.<br/>
&ensp;하지만 측정값이 상당히 noisy하다.<br/>
* multipath
* receiver noise

&ensp;등의 영향이 비교적 크게 나타난다.<br/>
&ensp;그래서 실제 pseudorange 값을 시간에 따라 그리면 그래프가 꽤 울퉁불퉁하다.<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-48.png" width="600"></p>

&ensp;2. Carrier phase measurement의 장점<br/>
&ensp;Carrier phase는 code보다 훨씬 정밀하다. 즉 carrier phase의 multipath 및 receiver noise는 code measurement의 약 1/100 수준이다. 대략적으로 보면 Code measurement noise ∼ m 수준이라면  Carrier phase noise ∼ cm 수준까지 내려갈 수 있다는 뜻이다.<br/>

&ensp;3. Carrier phase로 absolute range를 바로 알 수 없는 이유<br/>
&ensp;Carrier phase에는 integer ambiguity N 가 존재한다. Carrier phase measurement는 "지금 carrier가 몇 cycle 진행되었는가" 를 측정하는데 신호가 위성에서 수신기까지 오기 전에 이미 몇 개의 완전한 cycle을 지나왔는지 처음에는 알 수 없다.<br/>
&ensp;그래서 carrier phase로 바로 절대거리를 측정하면 λN 이라는 미지수가 들어간다.<br/>
> Carrier phase는 매우 정확하지만 처음부터 absolute pseudorange를 바로 알기는 어렵다.

&ensp;Carrier phase가 정말 강한 부분: 거리의 변화량<br/>
&ensp;두 carrier phase measurement를 빼면 λN − λN = 0 이 되어 integer ambiguity가 사라진다.<br/>
> Carrier phase는 absolute pseudorange 측정보다는 두 epoch 사이 pseudorange 변화량을 매우 정밀하게 측정하는 데 강하다.

&ensp;5. Code와 Carrier의 측정식<br/>
&ensp;Code measurement<br/>

$$\rho (t) = r(t) + c[δt_u(t) - δt^s(t - τ)] + I(t) + T(t) + \varepsilon _{\rho }(t)$$

* r(t): 실제 geometric range
* c: speed of light
* $δt_u$ : receiver clock error
* $δt^s$ : satellite clock error
* I(t): ionospheric delay
* T(t): tropospheric delay
* $ε_ρ (t)$ : code measurement noise

&ensp;6. Carrier phase measurement 식<br/>

$$\Phi (t) = r(t) + c[δt_u(t) - δt^s(t - τ)] - I(t) + T(t) + λN + \varepsilon _{\Phi }(t)$$

* Code: +I
* Carrier: -I

&ensp;ionosphere가 code와 carrier에 서로 반대 방향으로 작용한다. <br/>

&ensp;7. 두 measurement epoch 사이의 변화량<br/>
&ensp;이제 $t_{i−1}$ 과 $t_i$ 두 시점의 차이를 계산한다.<br/>

&ensp;Code<br/>

$$Δρ(t_i) = ρ(t_i) - ρ(t_{i-1})$$

&ensp;따라서<br/>

$$Δρ(t_i) = Δρ_{IF}(t_i) + ΔI(t_i) + Δ \varepsilon_{\Phi }(t_i)$$

&ensp;그런데 code noise가 크기 때문에 $Δ \varepsilon_{\Phi }$ 도 상대적으로 크다.<br/>

&ensp;8. Carrier 변화량<br/>

$$\Delta\Phi(t_i) = \Phi(t_i) - \Phi(t_{i-1}) = \Delta\Phi(t_i) = \Delta\rho_{IF}(t_i) - \Delta I(t_i) + \Delta \varepsilon _{\Phi } (t_i)$$

&ensp;여기서 원래 carrier 식에 있던 λN이 없어졌다. 왜냐하면 λN−λN=0이기 때문이다.<br/>
&ensp;그리고 carrier phase의 noise가 워낙 작기 때문에 $\Delta \varepsilon_{\Phi }$ 는 대략 cm level이다.<br/>

&ensp;9. 가까운 epoch에서는 ionosphere 변화도 작다<br/>
&ensp;두 epoch가 시간적으로 충분히 가까우면 $ΔI(t_i) \approx 0$ 라고 볼 수 있다.<br/>

$$\Delta \rho _{IF}(t_i) \approx \Delta \Phi (t_i)$$

| Measurement    | 역할                             |
| -------------- | ------------------------------- |
| Code           | absolute pseudorange 측정         |
| Carrier phase  | pseudorange 변화량 측정              |
| Code + Carrier | 정확하면서도 absolute한 pseudorange 생성 |


# Smoothed pseudorange

&ensp;이제 carrier phase 변화량을 이용해서 code pseudorange를 smoothing한다.<br/>

$$\overline{\rho } = \overline{\rho } + [\Phi (t_i) - \Phi(t_0)]$$

&ensp;$\overline{\rho }$ 는 smoothed pseudorange를 의미한다.<br/>
&ensp;처음 시각 $t_0$ 에서 pseudorange 값을 하나 잡아놓고 $\overline{\rho (t_0)}$ 그 이후에는 carrier phase가 알려주는 정확한 변화량 $\Phi (t_i) - \Phi (t_0)$ 을 더해준다.<br/>

> 처음 위치는 code로 잡고, 그 이후의 움직임은 정확한 carrier phase로 따라간다.

&ensp;Code-Carrier Divergence<br/>
&ensp;Code의 ionosphere: +I<br/>
&ensp;Carrier의 ionosphere: −I<br/>
&ensp;즉 ionosphere가 두 measurement에서 반대 방향으로 움직인다.<br/>
&ensp;예를 들어 ionosphere가 I만큼 변하면 Code: +I, Carrier: −I.<br/>
&ensp;둘 사이의 차이는 I - (-I) = 2I 가 된다.<br/>
&ensp;그래서 smoothing을 아주 긴 시간 동안 계속하면 ionosphere 영향이 누적되어 2I 형태의 bias가 생길 수 있다. 이를 code-carrier divergence라고 한다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-49.png" width="600"></p>

&ensp;그래프에는 여러 smoothing 시간이 비교되어 있다.<br/>
* No smoothing
* 100-sec smoothing
* 15-min smoothing
* 30-min smoothing

&ensp;No smoothing은 random noise가 굉장히 크다. Carrier smoothing을 적용하면 noise는 확실히 줄어든다.<br/>
&ensp;smoothing time 증가⇒random noise 감소<br/>
&ensp;하지만 너무 긴 시간 smoothing하면 앞에서 본 ionosphere-induced divergence가 문제가 된다.<br/>
&ensp;그래서 무조건 smoothing 시간을 길게 만드는 것이 좋은 건 아니다.<br/>
&ensp;Trade-off<br/>
&ensp;긴 smoothing => noise 감소<br/>
&ensp;하지만 긴 smoothing => ionosphere divergence 증가 가능<br/>
&ensp;이 둘 사이에서 적절한 smoothing interval을 선택해야 한다.<br/>

# 여러 epoch을 이용해서 초기 pseudorange 개선

&ensp;$\Phi (t_i) - \Phi (t_0)$ 을 단 하나의 noisy한 code measurement로 정하면 정확도가 떨어질 수 있다. 그래서 여러 epoch의 measurement를 이용해서 $t_0$ 의 pseudorange를 추정한다.<br/>

&ensp;각 epoch $t_i$ 에서 $\hat{\rho}(t_0)_i = \rho (t_i) - [\Phi (t_i) - \Phi(t_0)]$ 을 계산한다.<br/>

> $t_i$ 에서 측정한 code pseudorange에서 $t_0 → t_i$ 사이의 carrier 변화량을 빼면 $t_0$ 에서의 pseudorange를 역으로 추정할 수 있다.

&ensp;여러 값을 평균내기<br/>
&ensp;각 epoch에서 하나씩 $\hat{\rho}(t_0)_1, \hat{\rho}(t_0)_2,...$ 를 만들고 평균을 내면 $\overline{\rho }(t_0) = \frac{1}{n}\sum\limits_{i}{\hat{\rho }(t_0)_i}$ <br/>

&ensp;따라서 $\overline{\rho }(t_0) = \frac{1}{n}\sum\limits_{i}{\rho (t_i) - [\Phi(t_i)-\Phi(t_0)]}$ 가 된다.<br/>

&ensp;Code noise는 random component가 크기 때문에 여러 값을 평균하면 줄어들게 된다.<br/>
&ensp;대략적인 아이디어는 많은 measurement 평균⇒random noise 감소 이다.<br/>

&ensp;실제 구현에서는 Recursive Filter를 사용<br/>
&ensp;매번 과거의 M개 measurement를 모두 저장해두고 평균을 다시 계산하면 비효율적이다. 그래서 실제로는 recursive filter 형태로 구현한다.<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-50.png" width="600"></p>

&ensp;첫 번째 항<br/>
$$\frac{1}{M}\rho (t_i)$$

&ensp;현재 시점에서 실제로 측정한 code pseudorange다. 다만 noise가 크기 때문에 작은 weight를 준다.<br/>

&ensp;두 번째 항<br/>
$$\frac{M - 1}{M}[\overline{\pho }(t_{i-1}) + \Delta \Phi (t_i)]$$

&ensp;이전의 smoothed pseudorange에 $\Delta \Phi (t_i) = \Phi (t_i) - \Phi (t_{i-1})$ 를 더한다. 즉 carrier phase가 알려주는 정밀한 range 변화량을 이용해서 현재 pseudorange를 예측하는 것이다.<br/>
&ensp;Carrier가 훨씬 정확하므로 큰 weight $\frac{M-1}{M}$ 를 준다.<br/>

&ensp;M의 의미<br/>
&ensp;M은 filter length, 즉 smoothing에 사용하는 measurement 개수라고 보면 된다.<br/>
&ensp;M이 커지면 code noise가 더 많이 smoothing되기 때문에 측정값은 더 부드러워진다. 하지만 동시에 carrier 정보를 더 오랫동안 따라가게 된다. 그러면 앞에서 본 Code: +I, Carrier: -I 때문에 code-carrier divergence가 커질 수 있다.<br/>
&ensp;따라서 M↑ 이면 Code noise↓, Ionospheric divergence 영향↑ 이라는 trade-off가 생긴다.<br/>

# Dual-Frequency Measurements & DGPS

&ensp;1. Dual-Frequency Measurements<br/>
&ensp;이번에는 GPS의 서로 다른 두 주파수, 예를 들어 L1, L2 에서 Code와 Carrier를 모두 측정하는 경우이다. 그러면 한 epoch에서 총 4개의 measurement를 얻을 수 있다.<br/>
&ensp;L1 Code + L2 Code + L1 Carrier + L2 Carrier 총 4개이다.<br/>

&ensp;두 frequency를 쓰는 이유<br/>
&ensp;가장 중요한 이유는 Ionospheric delay가 frequency에 따라 달라지기 때문이다. Ionospheric delay는 대략 $I ∝ \frac{1}{f^2}$ 의 관계를 가진다. <br/>

&ensp;즉 frequency가 다르면 ionosphere 영향도 달라진다. 그래서 L1과 L2를 동시에 측정하면 "두 measurement의 차이를 이용해서 ionosphere effect를 추정할 수 있다."<br/>

&ensp;2. L1 Code measurement<br/>
$$\rho _{L1} = \rho _{IF} + I + \varepsilon _{\rho L1}$$

* $ρ_{L1}$ : L1 code pseudorange
* $ρ_{IF}$ : ionosphere를 제외한 공통적인 range-related term
* I: L1 기준 ionospheric delay
* $\varepsilon _{\rho L1}$ : L1 code noise

&ensp;앞 페이지와 마찬가지로 code에서는 ionosphere가 +I로 들어간다.<br/>

&ensp;3. L2 Code measurement<br/>
&ensp;L2에서는 ionosphere의 크기가 달라진다.<br/>
$$\rho _{L2} = \rho _{IF} + (\frac{f_{L1}^2}{f^2_{L2}}I + \varepsilon _{\rho L2}$$

&ensp;L1과 L2에서 동일한 위성 신호를 보고 있어도 ρL1​ ≠ ρL2 일 수 있다. 그 차이의 중요한 원인 중 하나가 ​ionosphere이다. 그래서 두 frequency를 비교하면 ionosphere 정보를 얻을 수 있다.<br/>

&ensp;4. L1 Carrier phase measurement<br/>
$$\Phi _{L1} = \rho _{IF} -I +\lambda _{L1}N_{L1} + \varepsilon _{\Phi L1}$$

* $\lambda _{L1}$ : L1 carrier wavelength
* $\lambda _{L2}$ : L1 integer ambiguity
* $\varepsilon _{\Phi L1}$ : L1 carrier measurement noise

&ensp;L2 Carrier phase measurement<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-51.png" width="600"></p>

&ensp;한 epoch에서 식이 총 네 개가 생긴다.<br/>

&ensp;5. 한 epoch에서 Integer Ambiguity를 정확히 못 구한다.<br/>
&ensp;Code measurement는 noise ≈ 1m 이고 Carrier phase measurement noise ≈ 1cm 정도이다. Carrier wavelength는 수십 cm 수준인데 code measurement에 1 m 정도의 noise가 들어가버리면 integer ambiguity를 정확히 결정하기에는 너무 거친(coarse) measurement가 된다.<br/>

&ensp;여러 epoch을 사용하면?<br/>
&ensp;새로운 epoch $t_2$ 가 들어오면 다시 $\rho _{L1}, \rho _{L2}, \Phi _{L1}, \Phi _{L2}$ 라는 4개의 새로운 measurement가 생긴다. 그런데 모든 unknown이 새로 생기는 것은 아니다.<br/>

&ensp;6. Integer ambiguity는 계속 동일하다<br/>
&ensp;Carrier signal을 계속 놓치지 않고 추적한다면 $N_{L1}, N_{L2} = constant$ 이다. 즉 satellite-user link에서 carrier가 continuous tracking되고 cycle slip이 없다면 $N_{L1}(t_1) = N_{L1}(t_2) = N_{L1}(t_3) = ...$ 이고 $N_{L2}(t_1) = N_{L2}(t_2) = N_{L2}(t_3)=...$ 이다.<br/>

&ensp;7.새로운 epoch에서 실제로 새로 생기는 unknown<br/>
&ensp;새 epoch에서는 $\rho _{IF}$ 와 I는 변할 수 있다.<br/>
* satellite와 receiver가 움직이고
* ionosphere 상태도 변할 수 있기 때문이다.

&ensp;그래서 새로운 epoch마다 새롭게 생기는 unknown은 $\rho _{IF}(t_i), I(t_i)$ 두 개이다. 반면 $N_{L1}, N_{L2}$ 는 계속 똑같다. 따라서 한 epoch가 추가될 때마다 새 measurement 4개가 생기지만 새 unknown은 2개만 생긴다.<br/>

# error Mitigation: Differential GPS (DGPS)

&ensp;1. DGPS의 기본 개념<br/>
&ensp;1.1 DGPS란?<br/>
&ensp;DGPS (Differential GPS) 는 위치를 정확히 알고 있는 reference receiver/reference station이 GPS measurement에 포함된 error를 추정하고, 그 correction을 주변의 user receiver에게 전달하여 위치 정확도를 높이는 방법이다.<br/>
&ensp;핵심 아이디어는 다음과 같다.<br/>
&ensp;가까운 두 receiver가 같은 satellite를 관측하면 일부 GPS error가 공간적·시간적으로 비슷하게 나타난다.따라서 reference station에서 측정한 error를 user receiver에서도 correction으로 사용할 수 있다.<br/>

&ensp;1.2 DGPS가 줄이려는 error<br/>
&ensp;DGPS는 특히 spatially correlated 하고 temporally correlated 한 error를 줄이는 데 효과적이다.<br/>
&ensp;Spatial correlation<br/>
&ensp;reference receiver와 user receiver가 가까이 있으면 두 receiver가 경험하는 error가 비슷하다.<br/>

&ensp;따라서 $e_{\mathrm{reference}} \approx e_{\mathrm{user}}$ 라면 reference station에서 추정한 error를 user에게 적용하여 제거할 수 있다.<br/>

&ensp;Temporal correlation<br/>

&ensp;GPS error 중 일부는 매우 빠르게 무작위로 변하지 않고 일정 시간 동안 비슷한 값을 유지한다.<br/>
&ensp;따라서 reference station이 계산한 correction을 user가 짧은 latency로 받아 사용할수록 correction의 정확도가 높아진다.<br/>

&ensp;1.3 Reference receiver와 가까울수록 좋은 이유<br/>

&ensp;이유 1: Spatial correlation이 높아진다<br/>
&ensp;거리가 가까울수록<br/>

$$I_R \approx I_U$$
$$T_R \approx T_U$$

&ensp;와 같이 ionosphere와 troposphere의 영향이 비슷해진다.<br/>

&ensp;이유 2: Correction을 더 빠르게 적용할 수 있다<br/>
&ensp;correction 전달 및 적용 지연이 작을수록 reference station에서 측정한 error와 user가 현재 경험하는 error 사이의 temporal correlation이 잘 유지된다.<br/>

&ensp;2. DGPS와 Satellite-related Error<br/>

&ensp;2.1 Satellite Clock Error<br/>
&ensp;Satellite clock modeling error는 약 $2,\mathrm{m\ rms}$ 정도의 range error를 발생시킬 수 있다.<br/>

&ensp;특징<br/>
&ensp;시간에 따라 비교적 천천히 변화한다.<br/>
&ensp;수 시간(hours) 정도의 시간 scale에서 변화한다.<br/>
&ensp;receiver 사이 거리가 멀어져도 거의 decorrelation되지 않는다.<br/>
&ensp;왜냐하면 같은 satellite를 관측하는 두 receiver는 동일한 satellite clock error의 영향을 받기 때문이다.<br/>
&ensp;따라서 $e_{\mathrm{clock},R} \approx e_{\mathrm{clock},U}$ 가 매우 잘 성립한다.<br/>

&ensp;결론<br/>
&ensp;Satellite clock error는 DGPS로 거의 완전히 제거할 수 있는 error이다.<br/>

&ensp;3. Satellite Ephemeris Error<br/>

&ensp;3.1 Ephemeris Error란?<br/>
&ensp;Ephemeris는 satellite의 궤도 및 위치 정보이다.<br/>
&ensp;방송된 satellite 위치가 실제 satellite 위치와 조금 다르면 geometric range 계산에도 error가 발생한다.<br/>
&ensp;이 error 역시 대략 $2 \mathrm{m\ rms}$ 정도이며, 시간에 따라 minutes 단위로 천천히 변화한다.<br/>

&ensp;3.2 왜 Reference와 User의 거리가 중요할까?<br/>
&ensp;Satellite position error 자체는 같지만 reference receiver와 user receiver가 satellite를 바라보는 line of sight (LOS) 방향은 완전히 같지 않다.<br/>
&ensp;따라서 satellite position error vector가 각 LOS 방향으로 projection되면서 두 receiver에 나타나는 range error가 조금 달라진다.<br/>

$$e_{\mathrm{eph},R} \neq e_{\mathrm{eph},U}$$

&ensp;하지만 두 receiver가 가까우면 LOS 방향이 거의 같아지므로 두 error도 매우 비슷해진다.<br/>
&ensp;결론: Satellite ephemeris error 역시 DGPS로 효과적으로 줄일 수 있다.<br/>

&ensp;4. Ionospheric Propagation Delay<br/>

&ensp;4.1 Ionospheric Delay와 DGPS<br/>
&ensp;Ionospheric delay는 reference와 user가 가까우면 두 signal path가 비슷한 ionosphere 영역을 통과하기 때문에 어느 정도 spatial correlation을 가진다.<br/>

&ensp;$I_R \approx I_U$ 라면 reference station의 correction을 user에게 적용할 수 있다.<br/>

&ensp;4.2 Receiver 사이 거리가 멀어지면?<br/>

&ensp;reference와 user 사이 거리가 커질수록 두 signal이 ionosphere를 통과하는 위치가 달라진다.<br/>

&ensp;따라서 $I_R \neq I_U$ 가 되고 differential correction 후에도 $I_U-I_R$ 만큼 residual error가 남을 수 있다.<br/>

&ensp;4.4 TEC란?<br/>

&ensp;TEC (Total Electron Content) 는 satellite와 receiver 사이의 signal path에 존재하는 총 electron의 양을 의미한다.<br/>
&ensp;Ionospheric delay는 TEC의 영향을 받기 때문에 TEC가 공간적·시간적으로 크게 변하면 두 receiver가 경험하는 ionospheric delay 역시 달라질 수 있다.<br/>

&ensp;5. Tropospheric Propagation Delay<br/>

&ensp;5.1 Tropospheric Delay의 특징<br/>
&ensp;Tropospheric propagation delay는 signal path를 따라 존재하는 air density profile에 영향을 받는다.<br/>
&ensp;특히 다음과 같은 기상 조건의 영향을 받는다.<br/>
* Pressure
* Temperature
* Humidity
* Water vapor

&ensp;따라서 reference와 user가 서로 다른 weather condition을 경험하면 $T_R \neq T_U$ 가 될 수 있다.<br/>

&ensp;5.2 Water Vapor의 영향<br/>
&ensp;Water vapor content는 공간적으로도, 시간적으로도 상당히 크게 변할 수 있다.<br/>
&ensp;따라서 두 receiver가 비교적 가까이에 있더라도 서로 다른 tropospheric delay를 경험할 수 있다.<br/>

&ensp;receiver separation이 약 $10 \mathrm{km}$ 인 경우에도 differential correction 후 residual range error가 $0.1\sim0.2,\mathrm{m}$ 정도가 될 수 있다고 설명한다.<br/>

&ensp;결론<br/>
&ensp;Tropospheric delay는 DGPS로 어느 정도 감소시킬 수 있지만, satellite clock error처럼 완전히 제거하기는 어렵다.<br/>

&ensp;6. Multipath와 Receiver Noise<br/>

&ensp;6.1 DGPS로 제거할 수 없는 대표적인 Error<br/>
&ensp;Multipath<br/>
&ensp;Multipath는 satellite signal이 건물, 지면, 금속 구조물 등에 반사된 뒤 receiver에 도달하면서 발생한다.<br/>
&ensp;이는 receiver 주변 환경에 따라 달라지므로 reference와 user에서 서로 다른 multipath error가 발생한다.<br/>

$$MP_R \neq MP_U$$

&ensp;따라서 두 receiver의 multipath error는 uncorrelated 하다.<br/>

&ensp;Receiver Noise<br/>
&ensp;Receiver noise 역시 각 receiver 내부에서 독립적으로 발생한다.<br/>
&ensp;따라서 $\epsilon_R \neq \epsilon_U$ 이고 reference receiver에서 측정한 receiver noise를 이용해 user receiver의 noise를 보정할 수 없다.<br/>

&ensp;6.2 결론<br/>
&ensp;Multipath와 Receiver Noise는 DGPS로 보정할 수 없다.<br/>
&ensp;오히려 reference station에 multipath나 receiver noise가 크게 존재하면 그 error가 correction에 포함되어 user에게 전달될 수도 있다.<br/>
&ensp;따라서 reference station의 설치 환경과 장비 품질이 매우 중요하다.<br/>

&ensp;7. Reference Station 설치가 중요한 이유<br/>
&ensp;Reference station은 가능한 한 error가 적은 환경에 설치해야 한다.<br/>

&ensp;Multipath 감소<br/>
&ensp;주변에 다음과 같은 signal reflector가 적은 장소가 좋다.<br/>
* Buildings
* Walls
* Metal structures
* Vehicles
* Receiver Noise 감소

&ensp;정확도가 높은 receiver와 antenna를 사용해야 한다.<br/>

&ensp;8. Local DGPS의 실제 동작 방식<br/>

&ensp;8.1 Reference Station의 위치는 이미 정확히 알고 있다<br/>
&ensp;Reference station은 surveyed location에 설치되어 있으므로 자신의 정확한 좌표를 알고 있다.<br/>
&ensp;따라서 satellite 위치를 알고 있다면 reference station과 satellite 사이의 geometric range를 계산할 수 있다.<br/>

$$r_R=\sqrt{(x^s-x_R)^2+(y^s-y_R)^2+(z^s-z_R)^2}$$

&ensp;8.2 실제 Pseudorange와 비교<br/>
&ensp;Reference station이 실제로 측정한 pseudorange에는 여러 error가 들어 있다.<br/>

$$\rho_R=r_R+\text{errors}$$

&ensp;따라서 known geometric range와 measured pseudorange를 비교하면 pseudorange error를 추정할 수 있다.<br/>

&ensp;9. Satellite별 Correction 생성<br/>
&ensp;Reference station은 각 SV (Space Vehicle, satellite) 에 대해 pseudorange error를 계산한다.<br/>

&ensp;10. User Receiver에서 Correction 적용<br/>
&ensp;User receiver가 satellite (k)에 대해 측정한 pseudorange가 $\rho_U^k$ 이고 reference station으로부터 correction $PRC^k$ 를 받았다면 이를 적용하여 corrected pseudorange를 만든다.<br/>

&ensp;개념적으로<br/>

$$\rho_U^k+PRC^k$$

&ensp;그 결과 reference station과 user receiver에 공통으로 존재하는 correlated error가 크게 감소한다.<br/>

&ensp;11. Local DGPS의 정확도<br/>
&ensp;슬라이드에서는 local DGPS를 사용할 경우 reference station에서 약 $100,\mathrm{km}$ 이내의 user에게 대략 $1\mathrm{m\ level\ accuracy}$ 를 제공할 수 있다. <br/>

# Local-Area DGPS

&ensp;1. Local-Area DGPS의 measurement equation<br/>
&ensp;먼저 같은 satellite를 User receiver u 와 Reference receiver r 가 동시에 관측한다고 하자<br/>

&ensp;User의 pseudorange<br/>
$$\rho _u  = r_u + c(\delta t_u = \delta t^s) + I_u + T_u + \varepsilon _{\rho u}$$

&ensp;Reference의 pseudorange<br/>
$$\rho _r = r_r + c(\delta t_r = \delta t^r) + I_r + T_r + \varepsilon _{\rho r}$$

| 항                       | 의미                                             |
| ----------------------- | ---------------------------------------------- |
| $\rho_u, \rho_r$         | 측정된 pseudorange                                |
| $r_u, r_r$               | 실제 geometric range                             |
| $\delta t_u, \delta t_r$ | User / Reference receiver clock error          |
| $\delta t^s$            | Satellite clock error                          |
| $I_u, I_r$               | Ionospheric delay                              |
| $T_u, T_r$               | Tropospheric delay                             |
| $\varepsilon_{\rho}$       | Multipath + receiver noise 등 measurement error |

&ensp;2. Reference station은 실제 geometric range를 안다<br/>
&ensp;DGPS에서 중요한 것은 Reference station의 위치를 정확히 알고 있다는 것이다.<br/>
&ensp;Reference station의 surveyed position을 $x_r$ , satellite position을 $x^s$ 라고 하면 geometric range는 $r_r = ||x^s - x_r ||$ 로 계산할 수 있다.<br/>

&ensp;즉 reference station은<br/>
* 자신이 실제로 satellite에서 얼마나 떨어져 있어야 하는지 $r_r$
* GPS가 측정한 pseudorange $ρ_r$

&ensp;​를 둘 다 알고 있는 것이다.<br/>
&ensp;그래서 두 값을 비교하면 error를 계산할 수 있다.<br/>

&ensp;3. Differential Correction 계산<br/>
&ensp;Reference station에서 $e_r = \rho _r -r_r$ 를 계산한다.<br/>
&ensp;Reference pseudorange 식을 대입하면 $e_r= c(\delta t_r - \delta t^s) + I_r + T_r + \varepsilon _{\rho r}$ 가 된다.<br/>

&ensp;즉 $e_r$ 안에는 reference receiver가 경험하고 있는 여러 error가 들어 있다.<br/>
* Satellite clock error
* Receiver clock error
* Ionospheric delay
* Tropospheric delay
* Reference measurement noise

&ensp;이 값을 User에게 보내서 correction으로 사용하는 것이 Local-Area DGPS의 기본 원리이다.<br/>

&ensp;4. User에게 Differential Correction 적용<br/>
&ensp;User의 원래 pseudorange는 $\rho _u  = r_u + c(\delta t_u = \delta t^s) + I_u + T_u + \varepsilon _{\rho u}$ 였다. 여기에 reference station이 계산한 correction $e_r$ 을 빼준다.<br/>

$$\tilde{\rho _u} = \rho _u - e_r$$

&ensp;대입하면<br/>

$$\tilde{\rho _u} = r_u + c(\delta t_u - \delta t_r) + (I_u + I_r) + (T_u - T_r) + \varepsilon _{\rho u} - \varepsilon _{\rho r}$$

&ensp;5. Satellite clock error가 사라졌다<br/>

&ensp;원래 User measurement에는 $-c\delta t^s$ 가 있었고 Reference correction에도 $-c\delta t^s$ 가 있었다. 두 값을 빼면서 $\delta t^s -> 0$ <br/>

&ensp;즉 Satellite clock error가 완전히 cancel 된다. <br/>

&ensp;6. Ionosphere와 Troposphere는 '차이'만 남는다<br/>
&ensp;Correction 후에는 ionosphere가 $I_u - I_r$ 형태로 남고 troposphere는 $T_u - T_r$ 형태가 남는다. 그런데 User와 Reference가 충분히 가까우면 $I_u \approx I_r$ 그리고 $T_u \approx T_r$ 라고 볼 수 있다.<br/>

&ensp;따라서 corrected pseudorange를 대략 $\tilde{\rho}_u \approx r_u + c(\delta t_u - \delta t_r) + \varepsilon _{\rho , ur}$ 으로 표현할 수 있다.<br/>

&ensp;7. 이것이 DGPS에서 '가까울수록 좋다'는 이유<br/>
&ensp;거리가 가까우면<br/>

$$I_u - I_r -> 0$$

$$T_u - T_r -> 0$$

&ensp;가 되기 때문이다. 반대로 멀어지면 두 signal이 서로 다른 atmosphere를 통과하므로 차이가 커진다.<br/>

&ensp;8. Multipath와 Receiver Noise는 여전히 남는다<br/>
&ensp;Correction 식에 $\varepsilon _{\rho u} - \varepsilon _{\rho r}$ 가 남아 있다.<br/>
&ensp;Multipath와 receiver noise는 reference와 user가 공통으로 경험하는 error가 아니다. 따라서 Multipath와 RX noise 는 DGPS correction 후에도 남는다.<br/>

&ensp;9. Reference와 User의 Coordination이 중요하다<br/>
&ensp;Reference station과 User는 같은 방식으로 measurement를 처리해야 한다. 예를 들어 Reference station이 correction을 계산하기 전에 Ionospheric delay model, Tropospheric delay model 을 적용했다고 하면 ser 역시 동일한 model을 적용해 한다.<br/>
&ensp;또한 두 receiver는 동일한 Ephemeris parameters 를 사용해야 한다.<br/>
&ensp;왜냐하면 서로 다른 model이나 ephemeris를 사용하면 correction에 포함된 error의 의미가 달라져서 깔끔하게 cancel되지 않기 때문이다. 즉 Reference와 User의 processing 방식이 일관되어야 한다.<br/>

# Relative Positioning

&ensp;DGPS에서는 보통 Reference가 correction $e_r$ 을 계산해서 User에게 보내준다.<br/>
&ensp;그런데 Relative Positioning에서는 correction을 따로 계산하지 않고, 두 receiver가 같은 시각에 측정한 measurement를 직접 빼버린다.<br/>
&ensp;=> Differencing time-matched measurements 를 사용한다.<br/>

&ensp;Code measurement를 직접 빼기<br/>
&ensp;Reference measurement에서 User measurement를 빼면 $\rho _{ru} = \rho _r - \rho _u$ 가 된다.<br/>

$$\rho _{ru} = (r_r - r_u) + c(\delta t_r - \delta t_u) + (I_r - I_u) + (T_r - T_u) + (\varepsilon _{\rho r} - \varepsilon _{\rho u})$$

&ensp;Satellite clock error가 없다.<br/>
&ensp;두 measurement 모두 동일한 $\delta t^s$ 를 가지고 있었기 때문에 subtraction을 하면 정확하게 cancel된다.<br/>

&ensp;$r_{ru} = r_r - r_u$ 는 두 receiver와 satellite 사이 geometric range의 차이이다. 주의할 점은 $r_{ru}$ 가 단순히 Reference와 User 사이의 물리적 거리 자체를 의미하는 건 아니다.<br/>

&ensp;GNSS에서 이런 식으로 같은 satellite를 두 receiver가 관측한 measurement를 서로 빼는 것을 흔히 Between-Receiver Single Difference라고 생각하면 된다.<br/>
&ensp;$\rho _{ru} = \rho _r - \rho _u$ 를 만들면서 같은 satellite에서 오는 공통 error를 제거한다.<br/>

&ensp;Carrier phase measurement 역시 $\varphi _{ru} = \varphi _{r} - \varphi _{u}$ 로 뻬줄 수 있다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-52.png" width="600"></p>

&ensp;즉 receiver별 ambiguity의 차이가 새로운 single-difference ambiguity가 된다.<br/>

&ensp;1. Code와 Carrier Single Difference의 장점<br/>
&ensp;둘 다 공통적으로 Satellite clock error 제거, Ionospheric error 감소, Tropospheric error 감소 효과를 얻는다.<br/>
&ensp;하지만 여전히 Receiver clock difference, Multipath, Receiver noise, Carrier ambiguity 등은 남아 있다. 즉 differencing이 모든 error를 없애주는 것은 아니다.<br/>

&ensp;2. Relative Positioning에서도 Carrier Smoothing 가능<br/>
&ensp;Single receiver에서는 $\overline{\rho}(ti​)=\frac{1}{M}​ρ(ti​)+\frac{M-1}{M}​[\overline{\rho}(t_{i-1}) + \Delta \Phi ]$ 형태였다.<br/>
&ensp;이번에는 이걸 differenced measurements에 적용한다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-53.png" width="600"></p>

> Code difference로 absolute 정보를 얻고 Carrier difference로 정확한 변화량을 얻어 smoothing한다.

&ensp;3. Differential + Carrier Smoothing의 장점<br/>
&ensp;Carrier-smoothed differentially corrected pseudorange를 filter length별로 비교한다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-54.png" width="600"></p>

&ensp;Differencing을 하면 Code ionosphere는 $I_r - I_u$ 가 되고 Carrier ionosphere도 반대 부호의 $-(I_r - I_u)$ 가 된다. Reference와 User가 가까우면 $I_r - I_u \approx 0$ 이므로 두 measurement 모두 ionosphere effect가 매우 작아나낟..지 따라서 code-carrier divergence도 2I 가 아니라 대략 $2(I_r - I_u)$ 수준만 문제가 된다. 그리고 $|I_r - I_u| << |I|$ 이므로 훨씬 작다.<br/>

&ensp;그래서 DGPS에서는 긴 Carrier Smoothing이 더 유리하다.<br/>
&ensp;Single receiver에서는 smoothing 시간을 길게 하면 noise는 감소하지만 ionosphere divergence가 커지는 문제가 있다. 반면 DGPS에서는 ionosphere가 differential correction에 의해 상당 부분 제거되기 때문에 Code-Carrier Divergence가 훨씬 작은 문제가 된다. 따라서 Carrier smoothing을 더욱 효과적으로 사용할 수 있다.<br/>

&ensp;실제 활용: GBAS<br/>
&ensp;GBAS는 Ground-Based Augmentation System. 즉 공항 같은 local area에서 ground reference stations가 GPS correction을 생성해 항공기에게 제공하여 정밀한 positioning을 지원하는 시스템으로 연결된다.<br/>

&ensp;Single Receiver와 비교하기<br/>

&ensp;Single receiver carrier smoothing<br/>

$$\overline{\rho}(t_i) = \overline{\rho}(t_0) + [\Phi (t_i) - \Phi (t_0)]$$

&ensp;그런데 single receiver에서는 Code: +I, Carrier: -I 이기 때문에 code-carrier divergence에 의해 ionosphere effect가 크게 나타날 수 있다.<br/>

|                         | Single Receiver Carrier Smoothing | DGPS + Carrier Smoothing |
| ----------------------- | --------------------------------- | ------------------------ |
| Code ionosphere         | $+I$                              | $+(I_r-I_u)$             |
| Carrier ionosphere      | -$I$                              | $-(I_r-I_u)$             |
| Code-carrier divergence | 약 $2I$                            | 약 $2(I_r-I_u)$           |
| Ionosphere 영향           | 큼                                 | 상당 부분 제거                 |
| 긴 smoothing             | divergence 문제가 커짐                 | 상대적으로 더 유리               |
| Measurement error       | 상대적으로 큼                           | 훨씬 감소                    |
