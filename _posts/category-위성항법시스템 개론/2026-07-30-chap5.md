# GPS Measurements

&ensp;1. 코드 추적 - Code tracking<br/>
&ensp;위성은 자신만의 고유한 PRN 코드,  C/A 코드를 계속 송신한다. 수신기는 내부에서도 똑같은 코드를 만들어서 수신된 코드와 비교한다. 내부 코드를 조금씩 시간축으로 이동시키다가 두 코드가 가장 잘 겹치는 위치를 찾는다.<br/>

&ensp;이 과정을 코드 추적이라고 한다.<br/>
&ensp;두 코드가 얼마나 시간적으로 어긋나 있는지를 측정하면 신호가 이동한 시간을 츠정할 수 있다.<br/>

$$거리 ≈ 신호 이동시간 \times c$$

&ensp;위성 시계와 수신기 시계가 완벽하게 맞지 않기 때문에 코드 추적으로 구한 거리는 실제 거리와 정확하게 같지 않다. 그래서 코드 측정값은 **편향된 거리 측정값**이다.<br/>

&ensp;2. 반송파 위상 추적 — Carrier phase tracking<br/>
&ensp;GPS 신호는 약 1.575 GHz의 매우 빠른 반송파 위에 실려온다. 수신기는 수신된 반송파의 위성과 수신기 내부 시계가 만든 기준 사인파의 위상을 비교한다. 반송파 한 파장의 길이는 L1 신호의 경우 약 19cm이다. 따라서 위상의 아주 작은 차이도 측정하면 매우 정밀한 거리 변화를 알 수 있다. 하지만 처음 신호를 수신했을 때 위성과 수신기 사이에 완전한 파장이 몇 개 들어 있는지 알 수 없다는 문제가 있다.<br/>

&ensp;예를 들어 $거리 = Nλ + 측정된 일부 위상$ <br/>

* λ: 반송파 파장
* N: 위성과 수신기 사이에 존재하는 완전한 파장의 개수
* N은 처음에는 알 수 없는 정수

&ensp;이 N을 정수 미지정수 또는 정수 모호정수(integer ambiguity)라고 한다. 그래서 반송파 위상 측정은 매우 정밀하지만 처음에는 거리를 바로 결정할 수 없다.는 모호성이 있다.<br/>

| 측정 방식     | 장점               | 단점                  |
| --------- | ---------------- | ------------------- |
| 코드 측정     | 전체 거리를 바로 알 수 있음 | 정확도가 상대적으로 낮음       |
| 반송파 위상 측정 | 매우 정밀함           | 정수 모호정수 (N)을 해결해야 함 |


&ensp;3. GPS에서 말하는 사용자 위치<br/>
&ensp;GPS가 계산하는 위치는 엄밀하게 말하면 휴대전화나 차량 중심의 위치가 아니다.<br/>
&ensp;"수신기 안테나의 전기적 위상 중심 위치"<br/>
&ensp;GPS 관측값이 실제로 기준으로 삼는 점은 **안테나의 electrical phase center** 이다.<br/>
&ensp;정밀 측위에서는 안테나의 물리적 중심과 전기적 위상 중심이 조금 다를 수 있기 때문에 안테나 보정값도 고려해야 한다.<br/>

&ensp;반송파는 매우 빠르게 진동하기 때문에 정밀한 위상 측정이 가능하다. 하지만 파형이 계속 반복되므로 전체 파장의 개수는 알 수 없다.<br/>

&ensp;2. C/A 코드<br/>
&ensp;C/A 코드는 총 1023 칩으로 구성돼 있으므로 코드 한 주기의 길이는 1ms. 즉 C/A 코드는 1 ms마다 반복된다.<br/>

&ensp;3. 항법 메시지 — Navigation message<br/>
&ensp;항법 메시지의 전송 속도는 50 bps이므로 한 비트가 지속되는 시간은 1/50 = 0.02 s = 20ms. 빛이 20ms 동안 이동하는 거리는 c x 0.02 ≈ 6000 km<br/>

&ensp;6000 km = 20 ms <br/>
&ensp;여기서 6000 km는 실제 위성과 수신기 사이의 거리를 의미한다기보다 20 ms라는 시간을 빛의 이동거리로 환산한 값이다.<br/>

&ensp;4. 세 신호의 관계<br/>
&ensp;신호의 시간 규모를 비교하면 다음과 같다.<br/>
* 반송파 한 주기        약 0.635 ns     ↔ 약 19 cm
* C/A 코드 한 칩        약 1 μs         ↔ 약 300 m
* 항법 메시지 한 비트   20 ms           ↔ 약 6000 km

&ensp;반송파는 가장 정밀하지만 반복이 너무 빠르고 코드는 비교적 거칠지만 신호의 도착 시간을 쉽게 구별할 수 있다. 실제 GPS 신호는 개념으로 GPS 신호 = 반송파 × PRN 코드 x 항법 데이터 와 같은 구조라고 이해하면 된다.<br/>

# Code Phase Measurements

&ensp;코드 측정에서 가장 기본적으로 측정하는 것은 **겉보기 전파시간(apparent transit time)** 이다.<br/>
&ensp;위성이 신호를 보낸 시각과 수신기가 신호를 받는 시각의 차이를 구하는 것이다.<br/>

$$겉보기 전파 시간 = 수신기 측 수신시각 - 위성 측 송신시각$$

&ensp;위성은 위성 자신의 시계를 사용하고 수신기는 수신기 자신의 시계를 사용한다.<br/>
* 위성 송신시각 → 위성 시계로 기록
* 수신기 수신시각 → 수신기 시계로 기록

&ensp;두 시계가 정확히 동기화되어 있지 않기 때문에 두 시각을 단순히 빼면 실제 전파시간과 차이가 생긴다. 그래서 이 전파시간은 true transit time이 아니라 **aparent transit time** 이다.<br/>

&ensp;세 종류의 시간<br/>
1. GPS Time, GPST: GPS 시스템이 기준으로 삼는 이상적인 시간
2. Satellite clock time: 위성 시계가 나타내는 시간
3. Receiver clock time: 수신기 시계가 나타내는 시간

&ensp;의사거리으 기본 정의<br/>
&ensp;겉보기 전파시간에 빛의 속도를 곱한 값이 의사거리이다.<br/>

$$ρ = c \times 겉보기 전파시간$$
	
&ensp;이를 pseudorange, 즉 의사거리라고 한다.<br/>

## Apparent Transit Time과 표기법

&ensp;1. 실제 전파시간 τ<br/>
&ensp;τ 는 신호가 위성에서 수신기까지 실제로 전파되는 데 걸린 시간이다. GPS 위성과 지상 수신기 사이의 거리는 대략 20,000 ~ 26,000km 이므로 전파시간은 약 70 ms ~ 90 ms 정도이다. GPS 신호가 빛의 속도로 이동해도 수신기에 도착하기까지 약 0.07~0.09초가 걸린다.<br/>

&ensp;2. GPS 기준 수신시각 t<br/>
&ensp;t는 신호가 수신기에 도착한 진짜 GPS 시간, 즉 GPST 기준의 수신시각이다.<br/>
&ensp;위성이 신호를 보낸 GPS 시간: t - τ <br/>

&ensp;3. 위성 시계가 기록한 송신시각 $t^{s}(t - \tau )$

&ensp;여기서 위 첨자 s는 saatellite이다.<br/>
&ensp;실제 송신시각 t - τ를 위성 시계가 기록한 값<br/>

&ensp;4. 수신기 시계가 기록한 수신시각$t_u (t)$ <br/>
&ensp;u는 user 또는 user receiver를 의미한다. 이는 실제 GPS 수신시각 t를 수신기 시계가 기록한 값<br/>

&ensp;측정된 겉보기 전파시간<br/>
&ensp;수신기가 측정하는 시간차: $t_u (t) - t^s (t - \tau )$ <br/>
&ensp;의사거리: $\rho = c[t_u (t) - t^s (t - \tau )]$ <br/>

## 시계 바이어스

&ensp;실제 GPS 시간과 각 시계가 표시하는 시간의 차이를 clock bias<br/>

&ensp;1. 수신기 시계<br/>
&ensp;수신기 시계가 기록한 시간: $t_u (t) = t + \delta t_u (t)$ <br/>
* t: 진짜 GPS 시간
* $\delta t_u$ : GPS 시간에 대한 수신기 시계 오차

&ensp;빛은 1 μs 동안 약 300 m를 이동하므로, 수신기 시계가 1 μs만 틀려도 거리 오차가 약 300 m 생긴다.<br/>

&ensp;2. 위성 시계<br/>
&ensp;위성 시계가 기록한 송신시각: $t^s (t - \tau ) = (t - \tau ) + \delta t^s (t - \tau )$ <br/>
&ensp;$\delta t^s$ 는 GPS 시간에 대한 위성 시계 오차이다.<br/>

&ensp;위성 시계 오차는 GPS 제어국(Control Segment)가 지속해서 추정한다. 추정된 시계 오차는 항법 메시지에 다음과 같은 다항식 계수로 실려온다.<br/>

$$\delta t^s (t) = af_{f0} + a_{f1}(t - t_{0c} + a_{f2}(t - t_{0c})^2 + \Delta t_r$$

* $a_{f0}$ : 기준시각에서의 시계 오프셋
* $a_{f1}$ : 시계가 빨라지거나 느려지는 속도
* $a_{f2}$ : 시계 변화율의 변화
* $\Delta t_r$ : 위성 궤도의 상대론적 효과 보정
* $t_{0c}$ : 시계 보정 계수의 기준시각

&ensp;위성 시계 오차는 항법 메시지를 통해 어느 정도 보정할 수 있다. 반면 수신기 시계 오차 $\delta t_u$ 는 처음에는 알 수 없으므로 수신기 위치와 함께 추정해야 한다. 이 때문에 일반적인 GPS 위치 계산에는 $x, y, z, \delta t_u$ 라는 네 개의 미지수를 풀기 위해 최소 4개의 위성이 필요하다.<br/>

## 실제 전파시간과 기하학적 거리

&ensp;겉보기에는 cτ가 단순한 거리처럼 보이지만, 신호가 진공이 아니라 지구 대기를 통과하기 때문에 추가 지연이 발생한다.<br/>

$$cτ = r(t, t − τ) + I_{ρ}(t) + T_{ρ}(t)$$

&ensp;$r(t, t- τ)$ : 기하학적 거리<br/>
* 수신기가 신호를 받은 시각 t에서의 수신기 위치
* 위성이 신호를  보낸 시각 t - τ 에서의 위성 위치

$$r=∥x_u (t) − x^s (t−τ)∥$$

&ensp;위성이 신호를 보낸 뒤 약 70 ~ 90ms 동안 움직이므로 위성 위치를 수신시각 t가 아니라 송신시각 t - τ 에서 계산해야 한다.<br/>

&ensp;$I_ρ$ : 전리층 지연<br/>
&ensp;전리층의 자유전자 때문에 GPS 신호의 전파가 지연되는 효과이다. 코드 의사거리에서는 전리층 지연이 일반적으로 거리를 더 길게 측정하게 하므로 +로 들어간다.<br/>

&ensp;$T_ρ$ : 대류권 지연<br/>
&ensp;대류권의 건조 공기와 수증기 때문에 발생하는 전파 지연이다. 이 역시 코드 의사거리에서는 측정 거리를 더 크게 만들어 +로 들어간다.<br/>

# Receiver Clock Drift

&ensp;1. 수신기 시계가 계속 틀어지는 이유<br/>
&ensp;일반적인 GPS 수신기에는 위성처럼 정밀한 원자시계가 들어 있지 않는다. 대부분 비교적 저렴한 수정 발진기(quartz crystal oscillator, XO)를 사용한다. 수정 발진기는 일정한 주파수로 진동하며 시간을 만들지만 다음과 같은 영향을 받아 조금씩 주파수가 달라질 수 있다.<br/>
* 온도 변화
* 전압 변화
* 부품의 노화
* 제조 오차
* 외부 진동이나 환경 변화

&ensp;2. Clock bias와 clock drift의 차이<br/>
&ensp;Clock bias<br/>
&ensp;특정 순간에 수신기 시계와 GPS 시간 사이에 존재하는 시간 차이<br/>
$$\delta t_u(t) = t_u(t) - t$$

&ensp;Clock drift<br/>
&ensp;clock bias가 시간에 따라 변하는 속도이다.<br/>

$$\dot{δ}t_{u}$$

* bias: 현재 시계가 얼마나 틀렸는가
* drift: 시계 오차가 얼마나 빠르게 증가하거나 감소하는가

&ensp;3. 작은 시간 오차가 큰 거리 오차가 되는 이유<br/>
&ensp;GPS에서는 시간차에 빛의 속도를 곱해 거리를 계산한다.<br/>

$$\Delta \rho = c \Delta t$$

&ensp;수신기 시계가 GPS 시간에서 1 ms만 어긋나도 의사거리에는 약 300 km에 해당하는 공통 오차가 들간다. GPS는 여러 위성을 이용해 이 수신기 시계 오차도 위치와 함께 추정하지만, 수신기 시계가 너무 크게 벗어나면 코드 주기와 시각 판별에 문제가 생길 수 있다. 그래서 수신기 시계를 일반적으로 GPS 시간의 정수 초 경계에서 약 ±1 ms 이내로 유지하려고 한다.<br/>

## 수신기 시계를 관리하는 두 가지 방법

&ensp;첫 번째 방법: 시계를 연속적으로 조정<br/>
&ensp;수신기가 계산한 clock bias를 이용해서 내부 시계를 조금씩 계속 조정하는 방법이다. 예를 들어 수신기 시계가 GPS 시간보다 점점 빨라지고 있다고 판단되면 소프트웨어가 시계 진행 속돌르 조금 늦추는 식으로 제어한다.<br/>

&ensp;두 번째 방법: 일정 수준까지 두었다가 한 번에 리셋<br/> 
&ensp;시계가 조금씩 틀어지는 것을 허용하다가, 오차가 임계값에 도달하면 한 번에 되돌리는 방식이다. 예를 들어 수신기 clock bias가 계속 커져서 +1 ms에 도달하면, 수신기 시계를 갑자기 1 ms 뒤로 옮겨 bias를 0에 가깝게 만든다. 이때 수신기 시각이 불연속적으로 바뀌기 때문에 GPS 측정값에도 갑작스러운 변화가 나타날 수 있다.<br/>

&ensp;3. 1 ms clock jump가 의사거리에 미치는 영향<br/>
&ensp;의사거리 식에서 수신기 clock bias는 모든 위성에 공통으로 들어간다.<br/>

$$ρ_{i} = r_{i} + c \delta t_{u} - c \delta t^s_i + ⋯$$

&ensp;i는 위성 번호이다. 수신기 시계가 1ms 점프하면<br/>

$$c \Delta t = 3 \times 10^8 \times 10^{-3} = 3 \times 10^5 m$$

&ensp;1ms = 300km에 해당하는 의사거리 변화가 생긴다. 이 변화가 **특정 위성 하나가 아니라 추적 중인 모든 위성의 의사거리에 동시에 나타난다** 는 것이다.<br/>
&ensp;왜냐하면 수신기 시계는 하나이고, 그 하나의 시계를 이용해 모든 위성 신호의 수신시각을 기록하기 때문이다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-4.png" width="600"></p>

&ensp;그래프는 정지해 있는 수신기가 서로 다른 세 위성을 추적하면서 얻은 의사거리를 보여준다. 가로축은 시간이고 세로축은 의사거리이다. 수신기는 정지해 있지만 위성은 계속 움직이므로 기하학적 거리 $r_{i}$ 는 시간에 따라 변한다. 그래서 각 곡선이 내려갔다가 올라가는 모양을 보여준다.<br/>
* 위성이 수신기 쪽으로 접근하면 거리 감소
* 위성이 가장 가까운 지점을 지나면 최소값
* 위성이 멀어지면 거리 증가

&ensp;곡선의 긴 변화는 주로 위성의 이동에 따른 것이고 모든 관측값에서 동시에 나타나는 작은 불연속이나 공통 이동은 수신기 clock reset과 관련되어 있다.<br/>
&ensp;즉 정지 수신기라고 해서 의사거리가 일정한 것은 아니다. 수신기는 정지해도 위성이 움직이기 때문이다.<br/>

# GPS Navigation Data Message

&ensp;GPS 수신기가 의사거리를 이용해 위치를 계산하려면 거리 측정값만 있어서는 안 된다.<br/>
&ensp;수신기는 다음 정보도 알아야 한다.<br/>
* 위성의 궤도 정보
* 위성 시계 보정값
* 위성 상태
* GPS 시간
* 전리층 보정 계수
* 다른 GPS 위성들의 대략적인 궤도 정보

&ensp;이 정보들을 각 위성이 자신의 신호에 실어 방송하는데 이것을 GPS navigation message라고 한다.<br/>

&ensp;1. 항법 메시지는 각 위성이 직접 방송한다.<br/>
&ensp;각 GPS 위성은 자신만의 C/A 코드와 함께 항법 데이터를 송신한다. 따라서 수신기가 특정 위성을 추적하고 있다면 그 위성으로부터 항법 메시지도 받을 수 있다. 이 항법 메시지에는 특히 해당 위성의 정밀한 궤도 정보와 시계 보정값이 들어 있다.<br/>

&ensp;2. 전송 속도는 50 bps<br/>
&ensp;항법 메시지 전송 속도는 50 bits/s 이다. 따라서 한 비트가 유지되는 시간은 $T_{bit} = \frac{1}{50} = 0.02 s = 20ms$ 이다.<br/>

&ensp;C/A 코드 한 주기는 1 ms이므로, 항법 데이터 한 비트가 유지되는 동안 C/A 코드가 20번 반복된다.<br/>

## Frame과 Subframe 구조

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-5.png" width="600"></p>

&ensp;GPS의 legacy navigation message는 계층적으로 구성된다.<br/>
&ensp;bit -> word -> subframe -> frame -> master frame <br/>

&ensp;1. Word<br/>
&ensp;하나의 word는 30비트이다. 전송 속도가 50 bps 이므로 30비트를 보내는 데 걸리는 시간: $\frac{30}{50} = 0.6s$ <br/>

&ensp;2. Subframe<br/>
&ensp;하나의 subframe은 10개의 word로 구성된다. $10 \times 30 = 300 bits$ <br/>
&ensp;전송시간은 $\frac{300}{50} = 6s$ 이다. 따라서 1 subframe = 300 bits = 6 seconds <br/>

&ensp;3. Frame<br/>
&ensp;하나의 frame에는 5개의 subframe이 있다. $5 \times 300 = 1500 bits$ <br/>
&ensp;걸리는 시간은 $5 \times 6 = 30 s$ 따라서 1frame = 1500 bits = 30 seconds<br/>

&ensp;4. Master frame<br/>
&ensp;25개의 frame이 모이면 하나의 master frame이 된다. 25 × 30s = 750s = 12.5 min 따라서 완전한 항법 메시지 구조가 한 번 모두 전송되는 데 최대 약 12.5분이 걸린다.<br/>

&ensp;1 master frame = 25 frames = 12.5 minutes<br/>

&ensp;각 Subframe에는 무엇이 들어갈까?<br/>
&ensp;한 frame의 5개 subframe은 서로 다른 정보를 담고 있다.<br/>
&ensp;Subframe 1<br/>
&ensp;주로 해당 위성의 시계와 상태 정보가 들어 있다.<br/>
* 위성 clock correction
* 위성 상태 health
* 정확도 관련 정보
* week number 등의 시간 정보

&ensp;앞에서 본 위성 시계 보정 계수<br/>
$$a_{f0}, a_{f1}, a_{f2}$$

&ensp;Subframe 2와 3<br/>
&ensp;해당 위성이 정밀 궤도 정보인 ephmeris가 들어있다. Ephemeris를 이용하면 수신기는 특정 송신시각에서 위성의 위치를 계산할 수 있다.<br/>
&ensp;의사거리의 기하학적 거리<br/>
$$r(t, t − τ) = ∥x_{u}(t) − x^s(t − τ)∥$$

&ensp;를 계산하려면 위성 위치 $x^{s}$ 가 필요하므로 ephemeris가 매우 중요하다.<br/>
&ensp;Subframe 2와 3은 함께 사용되어야 해당 위성의 궤도를 완전히 계산할 수 있다.<br/>

&ensp;Subframe 4와 5<br/>
&ensp;주로 다음과 같은 시스템 전체 정보가 들어 있다.<br/>
* Almanac
* 전리층 모델 계수
* GPS와 UTC의 시간 차이
* 다른 위성의 상태 정보

&ensp;Ephemeris와 Almanac의 차이<br/>
&ensp;Ephemeris는 특정 위성의 정밀한 궤도 정보이다. Almanac은 여러 위성의 대략적인 궤도 정보이다.<br/>

| 구분    | Ephemeris     | Almanac       |
| ----- | ------------- | ------------- |
| 정확도   | 높음            | 비교적 낮음        |
| 대상    | 해당 위성         | 전체 위성군        |
| 사용 목적 | 정밀한 위성 위치 계산  | 위성 탐색·가시성 예측  |
| 주요 위치 | Subframe 2, 3 | Subframe 4, 5 |

&ensp;수신기는 almance을 통해 어느 위성이 현재 하늘에 있을 가능성이 높은지 빠르게 파악할 수 있다.<br/>

&ensp;subframe 1, 2, 3은 매 frame마다 반복된다. 한 frame이 30초이므로 **Subframe 1 ~ 3은 30초마다 반복** 이 된다.<br/>

&ensp;이 정보들은 현재 추적 중인 위성의 정밀 시계와 궤도 정보이므로 자주 전달해야 한다. 반면 Subframe 4와 5는 매 frame에서 같은 내용을 반복하는 것이 아니라 페이지를 바꾸어가면서 여러 정보를 나누어 보낸다. 25개의 frame이 지나야 모든 페이지가 전송되므로 Subframe 4~5의 전체 내용은 12.5분마다 반복된다.<br/>

## TLM과 HOW

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-6.png" width="600"></p>

&ensp;각 6초 subframe에는 10개의 30비트 word가 있다. 그중 첫 번째와 두 번째 word는 항상 특별한 역할을 한다.<br/>

&ensp;1. TLM: Telemetry Word<br/>
&ensp;TLM은 각 subframe의 첫 번째 30비트 word이다. 가장 중요한 부분은 맨 앞의 8비트 preamble이다. GPS legacy navigation message의 preamble은 10001011 이다.<br/>
* 8비트 preamble
* reserved bits
* parity bits

&ensp;마지막 parity 비트는 데이터 전송 중 오류가 발생했는지 확인하는 데 사용된다.<br/>

&ensp;2. HOW: Hand-Over Word<br/>
&ensp;HOW는 각 subframe의 두 번째 30비트 word이다.<br/>
* truncated TOW count
* subframe ID
* 상태 flag
* parity

&ensp;가장 중요한 것: TOW count<br/>

&ensp;TOW는 Time Of Week를 뜻한다. 즉 GPS 주가 시작된 뒤 몇 초가 지났는지를 알려주는 시간이다. 그리고 subframe ID를 통해 현재 수신한 것이 1번, 2번, 3번, 4번, 5번 subframe 중 무엇인지 알 수 있다.<br/>

&ensp;HOW에 포함된 시간은 현재 subframe 시작시각이 아니라, 다음 subframe의 시작 송신시각을 나타낸다. 수신기는 이를 이용해 항법 비트와 C/A 코드의 송신시각을 연결할 수 있다.<br/>

## Z-count

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-7.png" width="600"></p>

&ensp;GPS 위성은 GPS 시간을 Z-count라는 카운터 형태로 관리한다. Z-count는 기본적으로 1.5초마다 1씩 증가한다.<br/>
&ensp;1 Z-count = 1.5s<br/>

### 전체 Z-count의 29비트 구조

&ensp;1. 상위 10비트: GPS week number<br/>
&ensp;GPS 시간이 시작된 이후 몇 번째 주인지를 나타낸다. 10비트로 표현할 수 있는 값은 0 ~ 1023이므로 1024주가 지나면 다시 0으로 돌아간다. 1024주는 약 19.7년이기 때문에 이를 **GPS week number rollover** 라고 한다.<br/>

&ensp;2. 하위 19비트: Time of Week<br/>
&ensp;한 주가 시작된 후 몇 개의 1.5초 구간이 지났는지를 나타낸다. 한 주는 7 x 24 x 60 x 60 = 604800 s이므로 1.5초 구간의 개수는 $\frac{604800}{1.5} = 403200$ 개이다.<br/>

&ensp;19비트로 표현할 수 있는 최대 수는 $2^{19} - 1 = 524287$ 이므로 한 주 동안의 1.5초 구간을 충분히 표현할 수 있다.<br/>

&ensp;전체 TOW count는 19비트인데, HOW에는 17비트만 들어간다. HOW가 subframe 경계에서 사용되기 때문이다. Subframe 하나는 6초이고 6s = 4 × 1.5 s 이므로 subframe 시작시각에서 전체 19비트 Z-count 값은 항상 4의 배수이다. 이진수에서 4의 배수는 마지막 두 비트가 항상 00이다.<br/>

&ensp;17-bit HOW TOW×4=19-bit full TOW count<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-8.png" width="600"></p>

* GPS time: 일반적인 초 단위 시간축
* Z-count: 1.5초마다 1씩 증가
* Truncated Z-count: HOW에서 전송되는 값으로, 6초마다 1씩 증가

# Measurement of $t^{s}(t−τ)$

&ensp;송신시각을 구성하는 단계<br/>

$$t^{s}(t − τ) = (Z-count 기반 큰 시간)+(항법 데이터 비트)+(C/A 코드 반복 수)+(whole chips)+(fractional chip)$$

&ensp;(1) Z-count ×1.5 seconds<br/>
&ensp;지금 GPS 주의 시작 이후 몇 개의 1.5초 구간이 지났는가를 알려준다.<br/>

&ensp;(2) number of navigation data bits transmitted ×20 ms<br/>
&ensp;항법 메시지는 50 bps니까 한 비트 길이는 $\frac{1}{50} = 20 ms$ 이다.<br/>
&ensp;그래서 Z-count로 큰 시간대를 잡은 다음 그 1.5초 구간 안에서 항법 데이터 비트가 몇 개 더 진행됐는가를 세면 20ms 단위로 시간을 더 세밀하게 알 수 있다.<br/>

&ensp;(3) number of C/A-code repeats ×1 ms<br/>
&ensp;C/A 코드는 1023칩이고 1ms마다 한 번 반복된다. 그래서 현재 항법 비트 안에서 C/A 코드가 몇 번 반복되었는가를 세면 1ms 해상도로 내려갈 수 있다.<br/>

&ensp;(4) number of whole C/A-code chips /( $1.023×10^6$ )<br/>
&ensp;C/A 코드는 $1.023 \times 10^6 chips/s$ 속도로 진행된다. 따라서 한 칩의 시간 길이는 $\frac{1}{1.023 \times 10^6}s ≈ 0.9775 μs$ 이다. 그러므로 현재 1ms 코드 주기 안에서 몇 개의 완전한 chip이 지나갔는지 알면 약 1마이크로초 수준까지 시간을 더 정밀하게 읽을 수 있다.<br/>

&ensp;5) fraction of a C/A-code chip /( $1.023×10^6$ )<br/>
&ensp;마지막으로 한 칩 내부에서도 정확히 어느 위치까지 왔는지 알면 칩보다 더 잘게 쪼갠 부분까지 읽을 수 있다. 이 값은 보통 수신기의 DLL(Delay Lock Loop) 같은 코드 추적 루프가 추정한다.<br/>
* whole chip = 칩 몇 개가 완전히 지났는가
* fractional chip = 현재 칩 안에서 어디까지 왔는가

&ensp;를 합치면 코드 위상을 매우 정밀하게 읽을 수 있다.<br/>

# Carrier Phase Measurements

&ensp;1. carrier phase란 무엇인가?<br/>
&ensp;반송파 위상 측정은 수신기 내부에서 만든 반송파와 위성으로부터 받은 반송파의 위상 차이를 측정하는 것이다.<br/>
&ensp;즉 수신기는 자기 안에서 기준 사인파를 만들고 있고 도착한 위성의 반송파와 비교해서 지금 위상이 얼마나 어긋나 있는지를 보는 것이다.<br/>

&ensp;정밀한 이유<br/>
&ensp;반송파 파장은 약 19cm이다. 즉 위상의 작은 차이도 거리로 바꾸면 아주 미세한 변화가 된다.<br/>

&ensp;하지만 Indirect and ambiguous measurement of the signal transit time이다. carrier phase는 직접 전파시간을 재는 것이 아니라 파형의 위상차를 보고 간접적으로 거리를 추론하기 때문이다. 또한 위상은 주기적으로 반복되므로 지금 보이는 위상차는 알 수 있지만 그 전에 완전한 파장이 몇 번 지나갔는지는 알 수 없다. 그래서 ambiguity가 생긴다.<br/>

&ensp;위상은 시간에 따라 표현 방법<br/>

$$\varphi (t) = \varphi (t_0) + \intop\limits_{t_0}^{t}{f(s)}ds$$

&ensp;1. 식의 의미<br/>

> 어떤 시각 t_0 에서 시작해서 시각 t까지 주파수를 적분하면 누적 위상이 된다.

* $ϕ(t_0)$ : 처음 위상
* f(s): 시간에 따라 변할 수 있는 주파수

&ensp;주파수는 초당 몇 주기 도는가를 나타내고 그걸 시간에 따라 누적하면 총 몇 주기가 진행됐는지가 나온다.<br/>

&ensp;carrier phase measurement는 결국 지금까지 누적된 반송파 진동 수를 얼마나 읽을 수 있는가와 관계된다. 그래서 위상을 단순 각도라기 보다 누적 주기 수(cycles)의 관점에서 본다.<br/>

## 짧은 시간구간에서의 근사

$$\varphi (t) = \varphi (t_0) + \intop\limits_{t_0}^{t}{f(s)}ds \approx \varphi(t_0) + f\cdot (t - t_0)$$

&ensp;1. 의미<br/>
&ensp;짧은 구간에서는 위상 변화량 = 주파수 × 시간<br/>

&ensp;2. imperfect oscillator<br/>
&ensp;수신기 내부 발전기는 완벽하지 않기 때문에 실제 생성 주파수는 이상적인 값과 조금 다를 수 있다.<br/>
* nominal frequency $f_0$ 는 설계값
* 실제 주파수는 $f_0$ 에서 약간 벗어날 수 있음

&ensp;이런 오차가 있으면 위상 누적에도 오차가 계속 쌓인다. 이것이 결국 수신기 clock frequency bias와 연결된다. 즉 수신기 내부 발전기가 조금만 틀어져도 carrier phase 변화율에도 영향을 준다.<br/>

## Carrier Phase Measurements & Integer Ambiguity

&ensp;1. 측정되는 위상차<br/>

$$\varphi (t) = \varphi _{u}(t) - \varphi ^{s}(t - \tau ) + N$$

* $ϕ_{u}(t)$ : 수신기가 만든 기준 반송파의 위상
* $ϕ^{s}(t − τ)$ : 위성이 보낸 반송파가 송신될 때의 위상
* N: integer ambiguity

&ensp;수신기가 실제로 보는 것은 수신기 기준 위상과 도착한 위성 신호 위상의 차이 인데 여기에 정수 개수의 완전한 파장이 더해져 있다.<br/>

&ensp;2. integer ambiguity N<br/>
&ensp;반송파는 주기적으로 반복되는 파형이다.<br/>
&ensp;그 전에 몇 개의 완전한 주기가 있는지 모른다. 그 미지의 정수 개수가 N이다.<br/>

&ensp;3. 측정식의 의미<br/>

$$\varphi = \frac{1}{\lambda }(r + I_{\varphi } + T_{\varphi } + \frac{c}{\lambda }(\delta t_{u} - \delta t^{s}) + N + \varepsilon _{\varphi }$$

&ensp;단위는 cycles이다.<br/>
* ϕ: 측정된 carrier phase
* λ: 반송파 파장
* r: 기하학적 거리
* $I_{ϕ}$ : 전리층 관련 항
* $T_{ϕ}$ : 대류권 관련 항
* $c(δt_u − δt^s )$ : 수신기/위성 시계 오차에 따른 거리 항
* N: 정수 모호정수
* $ε_{ϕ}$ : 측정 잡음 및 모델 오차

&ensp;4. $\frac{1}{λ}$ <br/>
&ensp;코드 의사거리는 meter 단위이다. 하지만 carrier phase는 몇 개의 파장인가를 세는 거라서 cycles 단위로 표현된다. 거리 r를 반송파 파장 λ로 나누면, $\frac{r}{λ}$ 가 되고 이는 총 몇 파장인가를 뜻한다. <br/>

## carrier phase가 시간에 따라 변함

&ensp;1. range나 시계 바이어스가 변하면 위상도 변한다.<br/>
&ensp;수신기와 위성 사이 거리 r가 시간에 따라 변하면 carrier phase도 변한다. 또 수신기 clock bias나 clock frequency bias가 변해도 carrier phase가 변한다.<br/>
&ensp;=> 일정 시간 동안 carrier phase가 얼마나 변했는가를 보면 거리 변화량과 관련된 정보를 얻을 수 있다.<br/>
* Integrated Doppler
* Delta pseudorange

&ensp;위상 변화량 = 누적 거리 변화 정보<br/>

&ensp;2. 위상 변화율 = pseudorange rate<br/>
&ensp;carrier phase를 시간에 대해 미분하면 대략 거리 변화율 + 수신기 시계 주파수 오차 성분연 연결된다.<br/>

## Code phase vs Carrier phase

&ensp;1. 코드 측정식<br/>

$$\rho = r + c(\delta t_{u} - \delta t^s) + I_{\rho } + T_{\rho } + \varepsilon _{\rho }$$

* 단위: meter
* 코드 측정은 아예 거리 개념으로 바로 표현된다.

&ensp;2. carrier phase 측정식<br/>

$$\varphi = \frac{1}{\lambda }(r + I_{\varphi } + T_{\varphi }) + \frac{c}{\lambda }(\delta t_{u} - \delta t^{s}) + N + \varepsilon _{\varphi }$$

* 단위: cycles
* 필요하면 λ를 곱해서 meter로 바꿀 수도 있지만, 본질적으로는 파장 수를 세는 측정값

&ensp;3. code measurement의 특징<br/>
&ensp;장점<br/>
* unambiguous
* 큰 틀의 거리를 바로 알 수 있음

&ensp;왜냐하면 C/A 코드는 반복은 하지만 항법 데이터와 코드 동기를 통해 어느 코드 구간인지 판별할 수 있기 때문이다.<br/>

&ensp;단점<br/>
* 상대적으로 거칠다
* 한 칩이 약 1µs ≈ 300m 수준이므로, 반송파에 비해 눈금이 거칠다.

&ensp;correlation과 보간으로 칩보다 훨씬 잘게 추정하지만, 그래도 근본적인 정밀도 한계는 carrier보다 낮다.<br/>

&ensp;4. carrier phase measurement의 특징<br/>
&ensp;장점<br/>
* extremely precise
* 파장이 19cm 수준이라서 아주 정밀함

&ensp;단점<br/>
* integer ambiguity
* 추적이 끊기면 N이 바뀔 수 있음

&ensp;5. tracking break<br/>
&ensp;반송파 추적이 끊겼다가 다시 잡히면 수신기는 그 사이에 몇 개의 파장이 더 지나갔는지를 모르게 된다. 그러면 원래의 N 값을 유지할 수 없고 새로운 ambiguity를 다시 설정해야 한다. 이 현상을 보통 cycle slip이라고 한다. 즉 carrier phase는 정밀하지만, 추적 연속성이 아주 중요하다.<br/>

# Error Sources and Models

&ensp;1. Noise와 Bias<br/>
&ensp;GPS 측정 오차는 크게 noise와 bias로 구분할 수 있다.<br/>

&ensp;Noise<br/>
&ensp;Noise는 짧은 시간 동안 빠르게 불규칙하게 변하는 오차이다. 예를 들어 코드 의사거리 측정값이 실제 값 주변에서 +0.8, -0.5, +0.3, -0.7 처럼 흔딜리는 경우이다.<br/>
&ensp;평균을 여러 번 내면 양수와 음수가 어느 정도 상쇄되므로, 슬라이드에서 짧은 시간 동안 평균하면 0에 가까워지는 오차라고 설명한다.<br/>
&ensp;개념적으로는 E[ε] ≈ 0인 확률적 오차로 생각할 수 있다.<br/>

&ensp;Bias<br/>
&ensp;Bias는 측정값을 일정한 방향으로 계속 밀어내는 오차이다. 예를 ㄷ르어 실제 거리가 20,000,000m인데 측정값이 한동안 계속 20,000,005 m 부근에 머무른다면 약 +5m의 편향이 있는 것이다.<br/>
&ensp;Bias는 단순히 여러 번 평균한다고 반드시 사라지지 않는다.<br/>
&ensp;예<br/>
* 위성 시계 보정의 잔여 오차
* 궤도력 오차
* 잘못 모델링된 대기 지연
* 정적인 주변 환경에서의 다중경로

&ensp;2. Noise와 Bias를 구분하는 이유<br/>
&ensp;둘은 처리 방법이 다르다.<br/>
&ensp;Noise는 여러 관측값을 평균하거나 필터를 적용하면 줄일 수 있다.<br/>

$$\overline{\varepsilon } = \frac{1}{n}\sum\limits_{k=1}^{n}{\varepsilon _{k}}$$

&ensp;독립적인 잡음이라면 표준편차가 대략 $\frac{1}{\sqrt{n}}$ 비율로 감소한다.<br/>

&ensp;반면 bias는 모델을 사용해 보정하거나 추가 관측값을 이용해 추정해야 한다.<br/>

## GPS 오차원의 세 가지 분류

&ensp;1. Control Segment Error<br/>
&ensp;GPS 제어부는 위성의 실제 궤도와 시계 상태를 추정해서 항법 메시지에 들어갈 정보를 만든다. 하지만 이 추정값과 예측값이 완벽하지 않기 때문에 다음 오차가 생긴다.<br/>
* 위성 시계 오차
* 위성 궤도력, 즉 ephemeris 오차

> 제어국이 추정하고 예측하여 방송한 값과 실제 값 사이에 남아 있는 오차

&ensp;2. Propagation Medium Error<br/>
&ensp;신호가 위성에서 수신기까지 올 때 전리층과 대류권을 통과한다. 따라서 진공에서 이동할 때보다 전파시간이 달라진다. 대표적인 것이 $I_ρ , T_ρ$ 이다.<br/>
* $I_ρ$ : 전리층 지연
* $T_ρ$ : 대류권 지연

&ensp;이들은 신호가 지나온 공간, 즉 전파 매질 때문에 생긴다.<br/>

&ensp;3. Receiver Noise and Multipath<br/>
&ensp;수신기 자체에도 잡음이 있다. 또 위성 신호가 안테나에 바로 도달하지 않고 건물이나 지면에 반사된 뒤 도달할 수도 있다. 이를 multipath, 다중경로라고 한다.<br/>
&ensp;수신기는 직접 신호와 지연된 반사 신호를 동시에 받기 때문에 코드와 반송파의 위상을 잘못 측정할 수 있다.<br/>

## Satellite Clock and Ephemeris Errors

&ensp;위성은 항법 메시지에 다음 정보를 실어 보낸다.<br/>
* 위성 궤도력 ephemeris
* 위성 시계 보정 계수
* 위성 상태 정보

&ensp;수신기는 이 방송 정보를 사용해 위성의 위치와 시계 오차를 계산한다.<br/>

&ensp;1. 제어국은 현재 상태를 추정한다.<br/>
&ensp;GPS 제어부는 지상 추적국에서 얻은 관측값을 사용해 위성의 궤도와 시계 상태를 추정한다. 이 과정에 Kalman filter가 사용된다.<br/>
&ensp;제어부가 추정해야 하는 값은 예를 들어 다음과 같다.<br/>
* 위성 위치,
* 위성 속도
* 위성 시계 바이어스
* 위성 시계 드리프트

&ensp;그러나 관측값 자체에도 잡음이 있으므로 현재 상태를 100% 정확하게 알 수는 없다.<br/>
&ensp;=> 현재 상태 추정 오차<br/>

&ensp;2. 미래 상태를 예측한다.<br/>
&ensp;항법 메시지가 생성되자마자 모든 수신기에 실시간으로 완벽한 상태를 전달하는 것은 아니다.<br/>
&ensp;제어부는 현재 추정값을 바탕으로 위성의 미래 위치와 시계 상태를 예측해서 방송 파라미터를 만든다.<br/>
&ensp;그런데 시간이 지날수록 실제 궤도와 예측 궤도의 차이가 커질 수 있다.<br/>
&ensp;=> 미래 상태 예측 오차<br/>

&ensp;3. Age of Data, AoD<br/>
&ensp;Age of Data는 마지막으로 위성에 파라미터를 업로드한 뒤 얼마나 시간이 지났는지를 뜻한다.<br/>
&ensp;일반적으로 시간이 오래 지날수록 실제 궤도와 예측 궤도의 차이가 커질 가능성이 있다.<br/>
&ensp;AoD 증가 => 예측 오차 증가 가능성<br/>
&ensp;반대로 제어부가 데이터를 자주 업데이트하면 예측해야 할 시간 구간이 짧아지므로 오차를 줄일 수 있다.<br/>

> 방송 궤도와 시계 정보에도 수 m 수준의 잔여 오차가 있을 수 있다

## Ephemeris Errors

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-9.png" width="600"></p>

&ensp;Ephemeris error는 항법 메시지로 계산한 위성 위치와 실제 위성 위치의 차이이다.<br/>
* S(t): 실제 위성 위치
* S′(t): 항법 메시지로 계산한 위성 위치
* ε: 두 위치 사이의 오차 벡터

&ensp;라고 볼 수 있다.<br/>

$$\varepsilon = S'(t) - S(t)$$

&ensp;이 벡터는 세 방향으로 나눌 수 있다.<br/>

&ensp;1. Radial 방향<br/>
&ensp;Radial은 지구 중심에서 위성으로 향하는 방향이다.<br/>
&ensp;위성의 고도 방향이라고 생각하면 된다.<br/>
&ensp;Radial error는 위성이 실제보다 지구에서 조금 더 멀리 있거나 가까이 있다고 계산되는 오차이다.<br/>

$$ε_{R}$$

&ensp;2. Along-track 방향<br/>
&ensp;Along-track은 위성이 궤도를 따라 움직이는 방향이다. 즉 위성의 진행 방향이다. 위성이 실제 위치보다 궤도상에서 조금 앞이나 뒤에 있다고 계산될 때 발생한다.<br/>

$$\varepsilon _{AT}$$

&ensp;3. Cross-track 방향<br/>
&ensp;Cross-track은 궤도면에서 벗어나는 방향이다. 즉 위성 궤도면에 수직인 방향이라고 생각하면 된다.<br/>

$$\varepsilon _{XT}$$

&ensp;4. 세 방향을 그림으로 보면<br/>

```img
                 Cross-track
                      ↑
                      │
                      ● 위성
                     /
                    /  Along-track
                   →
                  /
          지구 중심
             ↑
          Radial
```

&ensp;세 축이 서로 직교하는 위성 중심의 국소 좌표계를 이룬다.<br/>

---------

&ensp;위성 위치 오차가 의사거리에 모두 들어가는 것은 아니다<br/>

&ensp;위성 위치 오차가 3차원 공간에서 ε 만큼 존재한다고 해서 의사거리에도 그 크기 전체가 그대로 들어가는 것은 아니다. 의사거리는 수신기와 위성을 잇는 LOS, line-of-sight 방향의 거리를 측정한다. 따라서 위성 위치 오차 중 LOS 방향으로 투영된 부분만 1차적으로 의사거리에 영향을 준다. LOS 단위벡터를 u라고 하면 $\delta \rho_{eph} \approx u^{T}\varepsilon$ 처럼 표현할 수 있다.<br/>

&ensp;부호는 LOS 벡터를 어느 방향으로 정의하느냐에 따라 달라질 수 있지만 핵심은 의사거리 오차 = 위성 위치 오차를 LOS 방향으로 투영한 성분이다.<br/>

-----------

&ensp;일반적으로 radial error가 가장 작다. 그 이유는 위성 궤도 추정이 주로 거리 관측값을 이용하기 때문이다. 지상 추적국은 위성까지의 거리를 매우 정밀하게 측정할 수 있고 이 거리 관측은 위성의 방사 방향 위치를 강하게 제한한다.<br/>
&ensp;따라서 radial 방향은 상대적으로 잘 추정되는 편이다. 반면 along-track과 cross-track방향은 거리 관측만으로 직접 분리하기가 더 어려워서 오차가 더 클 수 있다.<br/>

$$|\varepsilon _{R}| < |\varepsilon _{AT}|, |\varepsilon _{XT}|$$

----

&ensp;의사거리에는 radial component가 중요한 이유<br/>

> radial error는 가장 작다는데 왜 pseudorange error는 주로 radial component에 좌우될까?

&ensp;GPS 위성에서 지상의 수신기를 바라보는 LOS 방향이 위성의 radial 방향과 비교적 비슷하기 때문이다.<br/>
&ensp;특히 위성이 수신기 머리 위에 가까이 있을수록,<br/>

```img
지구 중심 ─→ 수신기 ─────────→ 위성
                         LOS
```

&ensp;LOS 방향과 radial 방향이 거의 나란해진다.<br/>
&ensp;따라서 radial error는 LOS에 크게 투영되고, along-track이나 cross-track 오차는 LOS에 덜 투영될 수 있다.<br/>
* long-track·cross-track 오차 자체는 더 클 수 있지만
* 의사거리 방향으로 투영되는 양은 작을 수 있음
* radial 오차는 작아도 의사거리에 직접 들어가기 쉬움

# 위성 시계 오차와 궤도력 오차의 결합

&ensp;코드 의사거리 식에서 위성 관련 오차를 단순히 보면<br/>

$$\delta \rho \approx -c\delta t^{s} + \delta \rho_{eph}$$

* $−cδt^{s}$ : 위성 시계 오차의 거리 환산값
* $δρ_{eph}$ : 궤도 오차의 LOS 성분

&ensp;이 두 오차가 서로 독립적이라고 가정하면 전체 크기를 RSS로 합칠 수 있다.<br/>

$$\sigma _{clock+eph} = \sqrt{\sigma ^{2}_{clock} + \sigma ^{2}_{eph, LOS}}$$

&ensp;RSS는 root-sum-square, 제곱합의 제곱근이다.<br/>

* 제어부의 실시간 상태 추정에서는 약 1m RMS 이내
* 하루 한 번 정도의 일반적인 업로드에서는 시계와 궤도 오차가 각각 약 1.5m
* 오차가 커졌을 때 긴급 데이터 업로드를 수행하는 기준으로 약 5m threshold

$$RMS = \sqrt{\frac{1}{n}\sum_{k=1}^{n}e_{k}^{2}}$$

# Signal Refraction

&ensp;GPS 위성은 지상 약 20,000km 높이에 있다. 신호가 이동하는 대부분의 구간은 거의 진공이다. 진공에서 전자기파의 속도는 c = 299,792,458 m/s 이다. 하지만 신호가 지구에 가까워지면 마지막 일부 구간에서 대기를 통과한다.<br/>
* 대류권: 대략 지표에서 수십 km
* 전리층: 대략 수십 km부터 수백~1,000km 이상

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-10.png" width="600"></p>

&ensp;1. 대기는 신호의 속도를 바꾼다.<br/>
&ensp;대기가 없는 진공이라면 신호는 일정한 속도 c로 직선 이동한다. 하지만 대기에는 분자와 전자 같은 입자들이 있으므로 신호의 전파 특성이 변한다.<br/>
&ensp;대기는 신호의 1) 전파 속력, 2) 전파 방향을 바꿀 수 있다.<br/>

&ensp;이 현상을 넓은 의미에서 refraction, 굴절이라고 한다.<br/>

&ensp;2. GPS에서는 방향 변화보다 시간 변화가 더 중요하다.<br/>
&ensp;대기를 지나면서 신호 경로가 약간 휘어질 수 있지만, GPS에서는 일반적으로 신호 굽힘 효과가 아주 크지는 않다. 다만 위성이 지평선 가까이에 있는 저앙각에서는 신호가 대기층을 길게 통과하므로 굽힘과 지연이 더 커진다. GPS 측정에서 더욱 직접적인 문제는 신호의 속도가 변해 전파시간 τ가 달라진다는 것이다.<br/>
&ensp;의사거리 = cτ<br/>
&ensp;수신기는 신호가 진공 속도 c로 이동했다고 보고 시간에 c를 곱해 거리를 계산한다.<br/>
&ensp;그런데 실제로 대기에서 신호 속도가 달라지면, "cτ ≠ 순수한 기하학적 거리" 가 된다.<br/>

## Refractive Index

&ensp;대기가 신호 속도에 미치는 영향을 나타내는 값이 굴절률(refractive index)이다.<br/>

$$n(l) = \frac{c}{\nu }$$

* c: 진공에서의 빛의 속도
* $\nu $: 해당 매질에서의 전파속도
* n(l): 경로 위치 l에서의 굴절률

&ensp;1. 굴절률의 의미<br/>
&ensp;진공에서는 v=c 이므로 n = 1이다. 매질에서 전파속도가 진공보다 느리다면 v < c 이므로 n > 1이 된다. 즉 굴절률이 1보다 클수록 해당 매질에서 신호가 더 느리리게 전파된다.<br/>

&ensp;2. n(l)<br/>
&ensp;대기는 위치에 따라 성질이 달라진다.<br/>
* 고도가 달라지면 밀도가 변하고
* 온도와 압력이 변하며
* 전리층 전자 밀도도 시간과 위치에 따라 달라진다.

&ensp;따라서 굴절률은 경로 전체에서 일정하지 않고 n = n(l) 처럼 위치에 따라 변한다.<br/>

## 전파시간 식 유도

&ensp;아주 짧은 거리 dl를 신호가 속도 v로 이동한다면,<br/>

$$dt = \frac{dl}{v}$$

&ensp;전체 전파시간은 위성에서 수신기까지 이를 적분한 값이므로<br/>

$$\tau = \intop\limits_{SV}^{RX}{dt} = \intop\limits_{SV}^{RX}{\frac{dl}{v}}$$

&ensp;굴절률<br/>

$$n(l) = \frac{c}{v} => \frac{1}{v} = \frac{n(l)}{c}$$

$$\tau = \frac{1}{c}\intop\limits_{SV}^{RX}{n(l)}dl$$

&ensp;1. 진공일 때<br/>
&ensp;진공에서는 n=1이므로 $\tau_{vac} = \frac{1}{c}\intop dl = \frac{r}{c}$ 이다.<br/>
&ensp;따라서 $c\tau _{vac} = r$ 이 된다.<br/>

&ensp;2. 대기가 있을 때<br/>
&ensp;대기 굴절률이 경로에서 변하면 $c\tau = \intop n(l)dl$ 이다.<br/>

&ensp;이를 n(l)=1+(n(l)−1) 로 나누면 $c\tau = \intop{(n(l) - 1)}dl$ 가 된다.<br/>

> 굴절률이 신호의 주파수에 따라 달라지면 그 매질은 dispersive하다.

| 매질  | GPS L-band 특성 | 주파수 의존성 |
| --- | ------------- | ------- |
| 전리층 | 분산매질          | 큼       |
| 대류권 | 비분산매질로 근사     | 거의 없음   |

&ensp;신호 예<br/>

$$s(t)=cos(ω_mt)cos(ω_ct)$$

* $ω_c$ : 반송파 각주파수 (약 1.5GHz의 반송파)
* $ω_m$ : 변조신호 각주파수 (약 1MHz 규모의 코드 변조 성분)

&ensp;1. 두 주파수 성분으로 분해<br/>

&ensp;변조된 하나의 신호를 사실상 두 개의 가까운 주파수 성분으로 볼 수 있다. <br/>

$$ω_c + ω_m , ω_c − ω_m$$

&ensp;신호가 거리 x만큼 전파되면 공간 위상 항이 붙는다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-12.png" width="600"></p>

* $k - Δk: ω_c - ω_m$ 에 해당하는 파수

&ensp;분산매질에서는 주파수가 달라지면 파수 k도 단순 비례하지 않으므로 두 성분의 전파속도가 조금 달라진다.<br/>

## Wave Equation

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-13.png" width="600"></p>

* $s_0$ : 진폭
* ω: 각주파수
* k: 파수
* x: 위치
* t: 시간
* $ϕ_0$ : 초기 위상

&ensp;1. 각주파수<br/>
&ensp;주기가 T이면 $\omega = \frac{2\pi }{T} = 2\pi f$ 이다.<br/>
&ensp;시간축에서 파동이 얼마나 빠르게 반복되는지를 나타낸다.<br/>

&ensp;2. 파수<br/>
&ensp;파장이 λ이면 $k = \frac{2\pi }{\lambda }$ <br/>

&ensp;파수는 공간축에서 파동이 얼마나 빠르게 반복되는지를 나타낸다.<br/>
* f: 시간 주파수
* k: 공간 주파수

-------

&ensp;위상속도 $v_p$ <br/>
&ensp;예를 들어 파동의 꼭대기점은 위상 $ωt − kx + ϕ_0$ 가 일정한 점이다. 따라서 시간에 대해 미분하면 $\omega - k\frac{dx}{dy} = 0$ 이므로<br/>

$$v_p = \frac{dx}{dy} = \frac{\omega }{k}$$

&ensp;이것을 위상속도(phase velocity)라고 한다.<br/>

## Group Velocity와 Phase Velocity

&ensp;앞의 두 주파수 성분을 다시 합치면 다음과 같은 형태가 된다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-14.png" width="600"></p>

&ensp;이를 속도 형태로 쓰면<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-15.png" width="600"></p>

&ensp;1. 군속도<br/>

$$v_g = \frac{dw}{dk}$$

&ensp;군속도는 파동의 포락선(envelope)이 이동하는 속도이다.<br/>
&ensp;GPS에서는 C/A 코드, 항법 메시지, 신호의 시간 정보 가 포락선 또는 변조 정보에 해당한다. 따라서 코드가 이동하는 속도는 군속도와 관련되어 있다.<br/>

&ensp;2. 위상속도<br/>

$$v_p = \frac{w}{k}$$

&ensp;위상속도는 포락선 내부에 있는 빠른 반송파의 봉우리와 골이 이동하는 속도이다. 따라서 반송파 위상 측정은 위상속도와 관련되어 있다.<br/>

&ensp;진공이나 이상적인 비분산매질에서는 $k = \frac{w}{v}$ 처럼 w와 k가 선형관계를 가진다.<br/>

&ensp;따라서 $v_g = v_p$ 이다. 이 경우 코드와 반송파 위상이 같은 속도로 이동한다.<br/>

## Code-Carrier Divergence

&ensp;GPS 전리층에서는 일반적으로 $v_g < c < v_p$ 형태가 나타난다.<br/>
* 코드와 정보는 군속도 $v_g$ 로 이동하며 진공보다 느려짐
* 반송파 위상은 위상속도 $v_p$ 로 이동하며 c보다 커질 수 있음

&ensp;전리층에서 코드와 반송파가 서로 다른 영향을 받는 현상을 code-carrier divergence라고 한다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-17.png" width="600"

&ensp;1. 코드에는 group delay<br/>
&ensp;전리층에서 $v_g < c$ 이므로 코드가 진공에서보다 늦게 도착한다.<br/>
&ensp;수신기는 도착 시간이 늦어진 것을 신호가 더 긴 거리를 이동한 것으로 해석하므로 코드 의사거리가 증가한다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-16.png" width="600"></p>

&ensp;2. 반송파에는 phase advance<br/>
&ensp;반송파의 위상속도는 전리층에서 $v_p > c$ 가 될 수 있다. 그래서 특정 위상점은 진공 기준보다 앞서서 나타난다. 이를 phase advance라고 한다.<br/>
&ensp;결과적으로 반송파 위상 관측에서는 전리층 효과가 코드와 반대 부호로 나타난다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-18.png" width="600"></p>

# Ionospheric Delay

&ensp;전리층은 태양 복사 에너지로 인해 대기 입자들이 이온화된 영역이다.<br/>
&ensp;태양에서 강한 자외선과 X선이 들어오면 중성 원자나 분자에서 전자가 떨어져 나가면서 자유전자, 양이온이 만들어진다. 즉, 전리층은 단순한 공기층이 아니라 전기적으로 대전된 입자들이 존재하는 플라스마 영역이다. GPS 전파에 특히 중요한 것은 양이온보다 자유전자 수이다. 자유전자들이 전자기파와 상호작용하면서 GPS 신호의 전파속도를 바꾸기 때문이다.<br/>
* D층: 약 60~90km
* E층: 약 90~150km
* F층: 약 150km 이상
* F2층: 보통 전자밀도가 가장 높은 영역

&ensp;전자밀도의 최대치는 대체로 250 ~ 400 km 고도의 F2층에서 나타난다. 그래서 전리층을 단순화할 때 평균적인 높이를 약 350km로 잡는 경우가 많다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-19.png" width="600"></p>

&ensp;세로축은 고도, 가로축은 전자 또는 플라스마 밀도이다. 가로축이 로그 스케일이기 때문에 오른쪽으로 갈수록 전자밀도가 매우 크게 증가한다. 낮에는 태양 복사가 강하므로 이온화가 활발해져 자유전자가 많아진다. 밤에는 태양 복사가 사라지므로 자유전자와 이온이 다시 결합하는 재결합이 일어나 전자밀도가 감소한다. 특히 D층은 밤에 거의 사라질 수 있고, F층은 높은 고도에 있어 재결합 속도가 상대적으로 느리므로 밤에도 상당 부분 유지된다. 따라서 일반적으로 낮의 전리층 전자밀도 > 밤의 전리층 전자밀도이고 낮에 전리층 지연도 더 커지는 경향이 있다.<br/>

--------

&ensp;태양 활동과 11년 주기<br/>
&ensp;전리층은 태양 복사로 형성되기 때문에 태양 활동 변화에 매우 민감하다. 태양 활동은 대략 11년 주기로 강해졌다가 약해지는데, 태양 활동이 강한 시기에는 전리층의 전자밀도도 커질 수 있다. 그래서 전리층 오차는 고정된 값이 아니라 다음 요소들에 따라 변한다.<br/>
* 낮과 밤
* 계절
* 위도
* 태양 활동
* 지자기 폭풍
* 위성의 앙각
* 신호가 통과하는 지역

## TEC, Total Electron Content

&ensp;전리층 지연은 신호가 지나가는 경로에 자유전자가 얼마나 많이 존재하는지에 따라 결정된다. 이를 나타내는 값이 TEC, 총전자량이다.<br/>

$$TEC = \intop\limits_{SV}^{RX}{n_e(l)}dl$$

* $n_e(l)$ : 경로 위치 l에서의 전자밀도
* dl: 신호 경로의 아주 작은 길이
* SV: 위성
* RX: 수신기

&ensp;1. TEC는 단순히 한 지점의 전자밀도가 아니다<br/>
&ensp;전자밀도 $n_e$ 는 단위부피당 자유전자 수이다.<br/>

$$[n_e] = electrons / m^3$$

&ensp;이를 경로 길이 dl, 즉 m 단위와 곱해 적분하면<br/>

$$[TEC] = \frac{electrons}{m^3} \times m = \frac{electrons}{m^2}$$

&ensp;TEC는 신호 진행 방향을 따라 만든 가상의 단면 $1 m^2$ 기둥 안에 전자가 총 몇 개 들어 있는지를 의미한다.<br/>

&ensp;전자밀도가 조금 낮아도 긴 경로를 통과하면 TEC가 클 수 있고, 전자밀도가 높은 영역을 통과해도 TEC가 커질 수 있다.<br/>

&ensp;2. TECU<br/>
&ensp;TEC 값은 숫자가 너무 크므로 TECU라는 단위를 사용한다.<br/>

&ensp;$1 TECU = 10^{16} electrons/m^2$ <br/>

&ensp;3. 1 TECU가 L1 신호에 주는 영향<br/>
&ensp;전리층은 1차 지연은 $I = \frac{40.3 TEC}{f^2}$ 로 계산된다.<br/>
&ensp;GPS L1 주파수는 $f_{L1} = 1575.42 MHz$ 이므로 $TEC = 1 TECU = 10^{16}$ 을 대입하면 $I_{L1} = \frac{40.3 \times 10^{16}}{(1.5742 \times 10^{9})^2} ≈ 0.162 m$ 이다.<br/>
&ensp;1 TECU -> L1에서 약 16cm 의 전리층 영향을 만든다.<br/>

## 반송파의 Phase Advance

&ensp;1. Phase refractive index<br/>
&ensp;반송파 위상에 대한 굴절률은 $n_p = \frac{c}{v_p} ≈ 1 - \frac{40.3 n_e}{f^2}$ 이다.<br/>
* $n_p$ : 위상 굴절률
* $v_p$ : 위상속도
* $n_e$ : 전자밀도
* f: 신호 주파수

&ensp;식에서 $n_p < 1$ 이므로 $\frac{c}{v_p} < 1$ 이고 $v_p > c$ 가 된다. <br/>
&ensp;반송파의 특정 위상점은 전리층에서 진공 기준보다 앞서 이동하는 것처럼 나타난다.<br/>
&ensp;이를 phase advance 위상 전진이라고 한다. 위상속도가 c보다 커도 정보나 에너지가 c보다 빨리 이동하는 것은 아니므로 상대성이론을 위반하지 않는다. 실제 정보는 군속도로 전달된다.<br/>

&ensp;2. 위상 전파시간 변화<br/>
&ensp;진공과 비교한 추가 위상 전파시간은 <br/>

$$\Delta \tau _p = \frac{1}{c}\intop\limits_{SV}^{RX}{(n_p(l) - 1)}dl$$

&ensp;그런데 $n_p - 1 = -\frac{40.3 n_e}{f^2}$ 이므로 $\Delta \tau _p = -\frac{1}{c}\intop\limits_{SV}^{x}{\frac{40.3 n_e(l)}{f^2}}dl$ 가 된다.<br/>

$$\Delta \tau _p = -\frac{40.3 TEC}{cf^2}$$

&ensp;3. meter 단위로 바꾸기<br/>
&ensp;시간 오차에 c를 곱하면 거리 단위가 된다.<br/>

$$I_{\varphi} = -\frac{40.3 TEC}{f^2}$$

&ensp;마이너스 부호가 핵심이다.<br/>
&ensp;이는 반송파 관측에서 전리층 효과가 실제 기하학적 거리보다 관측값을 작아지는 방향으로 만든다는 뜻이다.<br/>

$$\lambda \Phi = r + \bullet \bullet \bullet - \frac{40.3 TEC}{f^2} + \lambda N + \bullet \bullet \bullet$$

## 코드의 Group Delay

&ensp;1. Group refractive index<br/>
&ensp;군굴절률은<br/>

$$n_g = \frac{c}{v_g} \approx 1 + \frac{40.3 n_e}{f^2}$$

&ensp;$n_g>1$ 이고 $v_g < c$ 가 된다. <br/>
&ensp;코드 신호는 전리층을 통과하면서 진공보다 느리게 이동해 늦게 도착한다.<br/>

&ensp;2. 코드 의사거리의 전리층 지연<br/>
&ensp;meter 단위의 group delay는<br/>

$$I_{\rho} = \frac{40.3 TEC}{f^2}$$

&ensp;플러스이므로 코드 의사거리는 실제 거리보다 더 길게 측정된다.<br/>

$$\rho = r + \cdot \cdot \cdot + \frac{40.3 TEC}{f^2} + \cdot \cdot \cdot$$

&ensp;수신기는 신호가 늦게 도착한 이유를 위성이 더 멀리 있는 때문이라고 해석하기 때문에 의사거리가 증가하는 것이다.<br/>

&ensp;3. 코드와 반송파 비교<br/>
&ensp;1차 전리층 효과에서<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-20.png" width="600"></p>

&ensp;$I_{\rho } = -I_{\varphi }$ <br/>

&ensp;4. TEC와 주파수의 영향<br/>
&ensp;전리층 오차는 1 ∝ TEC 이므로 전자 수가 2배가 되면 오차도 2배가 된다.<br/>
&ensp;$1 \propto \frac{1}{f^2}$ 이므로 주파수가 높을수록 전리층 영향은 작아진다.<br/>

# Obliquity Factor

&ensp;위성이 머리 위에 있을 때와 지평선 가까이에 있을 때는 전리층을 통과하는 경로 길이가 다르다. 이를 처리하기 위한 값이 obliquity factor, 사경계수 또는 경사계수이다.<br/>

&ensp;1. Thin-shell model<br/>
&ensp;실제 전리층은 50~1000km에 걸쳐 넓게 분포해 있지만 계산을 단순화하기 위해 모든 전자가 하나의 얇은 구면에 모여 있다고 가정한다. 이것을 thin-shell model이라고 한다.<br/>
&ensp;일반적으로 평균 전리층 높이를 $h_I ≈ 350 km$ 정도로 둔다.<br/>

&ensp;2. IPP<br/>
&ensp;위성–수신기 LOS가 이 전리층 얇은 구면을 통과하는 지점을 IPP(Ionospheric Pierce Point)라고 한다. 즉 IPP는 “해당 위성 신호가 전리층 대표면을 뚫고 지나간 위치” 이다. 위성이 바뀌거나 이동하면 IPP도 달라진다.<br/>

&ensp;3. VTEC와 STEC<br/>
&ensp;전리층을 수직으로 통과했을 때의 TEC를 VTEC, Vertical TEC라고 하고, 기울어진 위성 신호 경로를 따라 측정한 TEC를 STEC, Slant TEC라고 한다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-21.png" width="600"></p>

$$STEC = OF_{I}(ξ) \cdot VTEC$$

&ensp;4. Obliquity factor 식<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-22.png" width="600"></p>

* $R_E$ : 지구 반지름
* $h_I$ : 전리층 대표 높이
* ξ: 수신기에서 본 위성의 천정각

&ensp;천정각과 앙각의 관계는 $ξ=90^{∘} − e$ 이다.<br/>

&ensp;5. 위성이 머리 위에 있을 때<br/>
&ensp;천정 방향이라면 $ξ = 0^{∘}$ 이므로 sinξ=0 이고 $OF_{I} = 1$ 이 된다. 즉 STEC = VTEC 이다.<br/>

&ensp;6. 위성이 지평선 가까이에 있을 때<br/>
&ensp;앙각이 낮으면 신호가 전리층을 비스듬히 길게 통과한다. 그래서 STEC > VTEC 가 된다.<br/>

&ensp;수직 전리층 지연이 3m라면 낮은 앙각 위성에서는 대략 3 × 3 = 9 m 수준으로 증가할 수 있다. 이 때문에 GNSS 처리에서는 매우 낮은 앙각의 위성 관측값을 제외하거나 더 낮은 가중치를 준다.<br/>

# Dual-Frequency로 전리층 제거

&ensp;전리층 오차의 중요한 특징은<br/>

$$I_{q} = \frac{40.3 TEC}{f_{q}^{2}}$$

&ensp;처럼 주파수에 따라 달라진다. 그래서 서로 다른 두 주파수 L1과 L2를 동시에 관측하면 전리층 영향을 제거할 수 있다.<br/>

&ensp;1. 두 주파수의 의사거리 식<br/>
&ensp;L1과 L2 의사거리를 각각 쓰면<br/>
<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-23.png" width="600"></p>

&ensp;공통 부분 B라고 쓰면 $B = r + c(\delta t_{u} - \delta t^{s}) + T$ 이다.<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-24.png" width="600"></p>

&ensp;2. Ionosphere-Free 조합<br/>
&ensp;두 측정값을 $\rho_{IF} = a\rho _{L1} + b\rho _{L2}$ 처럼 조합한다.<br/>
&ensp;기하학적 거리, 시계 오차, 대류권 지연 같은 공통항 B는 그대로 유지해야 하므로 a+b = 1이어야 한다.<br/>
&ensp;전리층 항을 제거하려면 $\frac{a}{f_{1}^{2}} + \frac{b}{f_{2}^{2}} = 0$ 이어야 한다.<br/>
&ensp;두 조건을 풀면<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-25.png" width="600"></p>

&ensp;GPS L1과 L2 주파수를 대입하면 a ≈ 2.546, b ≈ −1.546 이므로 $\rho _{IF} = 2.546\rho _{L1} - 1.546 \rho_{L2}$ 가 된다.<br/>

&ensp;3. 실제로 전리층 항이 사라지는 과정<br/>

<p align="center"><img src="/assets/img/위성항법시스템 개론/chap5/5-26.png" width="600"></p>

&ensp;공통항은 (2.546 − 1.546)B = B가 되어 유지된다.<br/>
&ensp;전리층 항은 계수들이 $\frac{1}{f^2}$ 관계를 제거하도록 정해졌으므로 $2.546I_{L1} - 1.546I_{L2} = 0$ 이 된다. 따라서 $\rho _{IF} = B + 2.546 ε_{1} - 1.546 ε_{2}$ 가 남는다. 즉 1차 전리층 오차가 없었다면 얻었을 법한 의사거리를 만들어낸다.<br/>
