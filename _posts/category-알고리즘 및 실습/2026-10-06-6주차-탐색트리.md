# 이진탐색트리 BST

&ensp;**이진탐색트리(Binary Search Tree)**는 내부노드에 (키, 원소)를 저장하는 이진트리이며, 노드 v에 대해 `왼쪽 부트리의 키 < key(v) ≤ 오른쪽 부트리의 키` 관계를 만족한다.<br/>
* key(u) < key(v) ≤ key(w)

&ensp;그리고 BST를 중위순회(inorder traversal) 하면 키가 증가하는 순서로 방문된다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-1.png" width="600"></p>

&ensp;중위 순회: 1 → 2 → 7 → 9 → 11 → 15<br/>

> BST + 중위순회 = 오름차순

---

## BST 탐색

&ensp;핵심 원리: 찾고 싶은 키 k와 현재 노드의 키를 비교한다.<br/>
* k < 현재키 → 왼쪽
* k > 현재키 → 오른쪽
* k = 현재키 → 찾음

&ensp;외부노드까지 내려갔는데 발견하지 못했다면 존재하지 않는 키다.<br/>

&ensp;BST탐색 의사코드<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-2.png" width="600"></p>

&ensp;treeSearch 의사코드 줄별 의미<br/>
&ensp;`if (isExternal(v)) return v`: 외부노드까지 도달 → 키 k는 존재하지 않는다. 다만 treeSearch는 실패했다고 바로 오류를 반환하는 게 아니라, **k가 존재했다면 들어갔을 위치인 외부노드** 를 반환한다.<br/>

&ensp;`if (k == key(v))` : 현재 노드의 키가 찾는 키와 같으면 탐색 성공.<br/>
&ensp;`elseif (k < key(v))` : 찾는 값이 작으므로 왼쪽.<br/>

&ensp;findElement 핵심 차이<br/>
* treeSearch → 노드를 반환
* findElement → 실제 element를 반환

&ensp;그리고 탐색 실패 시<br/>
* treeSearch → 외부노드
* findElement → NoSuchKey

## BST 삽입

&ensp;삽입도 먼저 탐색부터 한다.<br/>
* 내부노드 → 이미 존재
* 외부노드 → 그 위치에 새 노드 삽입

&ensp;외부노드를 내부노드로 바꾸는 작업을 `expandExternal(w)` 라고 표현한다.<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-3.png" width="600"></p>

&ensp;insertItem 의사코드<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-4.png" width="600"></p>

&ensp;실행 순서<br/>
&ensp;예를 들어 `insertItem(8)` <br/>
&ensp;기존 트리가<br/>
```tree
        9
       / \
      2   15
     / \
    1   7
```

&ensp;이라면<br/>
* 8 < 9 → 왼쪽
* 8 > 2 → 오른쪽
* 8 > 7 → 오른쪽

&ensp;7의 오른쪽 외부노드에서 탐색 종료. 그 외부노드를 내부노드 8로 바꾼다.<br/>
```tree
        9
       / \
      2   15
     / \
    1   7
         \
          8
```

## BST 삭제

&ensp;1. 삭제 Case 1<br/>
&ensp;삭제할 노드 w의 자식 중 하나라도 외부노드라면 Case 1이다. 그 외부노드를 z라고 할 때 `reduceExternal(z)` 를 수행한다. 이 과정에서 w와 z를 제거한다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-5.png" width="600"></p>

&ensp;2. 삭제 Case 2<br/>
&ensp;삭제할 노드의 왼쪽/오른쪽 자식이 모두 내부노드이면 바로 삭제할 수 없다. 이때 **중위순회 계승자(inorder successor)**를 사용한다.<br/>
1. w의 중위순회 계승자 y를 찾는다.
2. y의 내용을 w에 복사한다.
3. y와 y의 왼쪽 외부노드 z를 삭제한다.

&ensp;중위순회 계승자 찾는 법<br/>
&ensp;삭제할 노드가 w라면<br/>
1. w의 오른쪽 자식으로 이동
2. 거기서 계속 왼쪽으로 이동

&ensp;끝까지 가서 만나는 내부노드가 `inorder successor` 이다.<br/>

> 오른쪽 부트리에서 가장 작은 값

&ensp;예: removeElement(2)<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-6.png" width="600"></p>

&ensp;removeElement 전체 의사코드<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-7.png" width="600"></p>

&ensp;헷갈리는 부분<br/>
```text
z ← leftChild(w)

if (!isExternal(z))
    z ← rightChild(w)
```

&ensp;이건 단순히 **w의 자식 중 외부노드가 있는지 검사** 하는 과정이다.<br/>

&ensp;경우 1<br/>
&ensp;왼쪽 자식이 외부노드 `z = leftChild(w)` 그대로 Case 1<br/>

&ensp;경우 2<br/>
&ensp;왼쪽이 내부노드이면 `z = rightChild(w)` 로 바꾼다. 오른쪽마저 내부노드이면 Case 2가 된다.<br/>

----

&ensp;BST 성능<br/>
&ensp;높이를 h라고 하면 findElement, insertItem, removeElement 모두 **O(h)** 이다.<br/>
&ensp;문제는 BST가 균형을 보장하지 않는다는 것이다.<br/>

&ensp;최선<br/>
```tree
        4
      /   \
     2     6
```

&ensp;높이: `O(log n)` <br/>
&ensp;=> 탐색: **O(log n)** <br/>

&ensp;최악<br/>
```tree
1
 \
  2
   \
    3
     \
      4
```

&ensp;높이: O(n)<br/>
&ensp;=> 탐색: **O(n)** <br/>

# AVL 트리

&ensp;BST의 가장 큰 문제는 **한쪽으로 치우칠 수 있다.** <br/>
&ensp;AVL은 이를 해결한다.<br/>

&ensp;정의<br/>
&ensp;모든 내부노드에서 **왼쪽 부트리 높이와 오른쪽 부트리 높이의 차이 ≤ 1** 이어야 한다.<br/>
&ensp;이를 **height-balance property(높이균형 속성)** 이라고 한다.<br/>

&ensp;핵심<br/>
&ensp;`|왼쪽 높이 - 오른쪽 높이| ≤ 1` 이면 균형.<br/>
* 차이 = 0 → 균형
* 차이 = 1 → 균형
* 차이 = 2 → 불균형

<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-8.png" width="600"></p>

---

&ensp;AVL 삽입<br/>
&ensp;n개의 항목을 저장하는 AVL 트리의 높이: O(log n)<br/>
&ensp;findElement 작업: O(log n) 시간 소요<br/>

&ensp;AVL의 삽입 자체는 BST 삽입과 동일하다. 문제는 삽입 후 트리가 불균형해질 수 있다는 것이다. 따라서 다음과 같은 과정을 수행한다.<br/>

```text
BST 삽입
   ↓
균형 검사
   ↓
불균형 발견
   ↓
restructure
```

<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-9.png" width="600"></p>
<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-12.png" width="600"></p>

&ensp;BST와 차이: searchAndFixAfterInsertion(w)가 추가된다.<br/>

&ensp;삽입 후 불균형 찾기<br/>
&ensp;`searchAndFixAfterInsertion(w)` <br/>
&ensp;핵심은 z, y, x를 찾는 것이다.<br/>
* w = 새로 삽입된 노드
* z = w에서 루트로 올라가며 처음 만나는 불균형 노드
* y = z의 높은 자식
* x = y의 높은 자식

&ensp;그 다음 `restructure(x, y, z)` 를 수행한다.<br/>

&ensp;예: insertItem(54, e)<br/>

* z = 조부모

## restructure 통합 알고리즘

&ensp;1단계<br/>
&ensp;x, y, z를 중위순회 순서대로 나열.<br/>
&ensp;`a < b < c` <br/>

&ensp;2단계<br/>
&ensp;주변 4개 부트리를 순서대로 `T0, T1, T2, T3` 라고 한다.<br/>

&ensp;3단계<br/>
&ensp;b를 새로운 루트로 만든다.<br/>

&ensp;4단계<br/>
```tree
        b
       / \
      a   c
```

&ensp;5단계<br/>
```tree
          b
        /   \
       a     c
      / \   / \
     T0 T1 T2 T3
```

&ensp;회전 전후에도 **중위순회 순서** 는 보존된다.<br/>

&ensp;AVL 삭제도 기본적인 삭제는 BST와 동일하다.<br/>
```text
BST 삭제
    ↓
불균형 검사
    ↓
restructure
```

&ensp;removeElement<br/>
&ensp;BST 버전과 거의 같은데 마지막에 `searchAndFixAfterRemoval(...)` 이 추가된다.<br/>

&ensp;AVL 삽입과 삭제의 중요한 차이<br/>
&ensp;삽입<br/>
&ensp;첫 불균형 노드 하나를 고치면 `restructure 1번` 으로 균형이 복구된다.<br/>

&ensp;삭제<br/>
&ensp;한 번 restructure를 해도 `부트리의 높이가 감소` 할 수 있다. 그러면 위쪽 조상까지 또 불균형해질 수 있다.<br/>
> 삭제는 루트까지 올라가며 여러 번 개조가 필요할 수 있다.

&ensp;예: removeElement(32)<br/>

&ensp;AVL 삭제에서 x 선택<br/>
&ensp;삭제에서는 y의 두 자식 높이가 같을 수 있다.<br/>
* 한쪽이 더 높으면 → 높은 쪽을 x
* 두 자식 높이가 같으면 → y와 같은 방향의 자식을 x

## AVL 성능

&ensp;AVL은 항상 `높이 = O(log n)`을 유지한다.<br/>

| 작업 | 시간 |
|---|---:|
| findElement | O(log n) |
| insertItem | O(log n) |
| removeElement | O(log n) |
| restructure 1회 | O(1) |
| 공간 | O(n) |

# 스플레이 트리

&ensp;AVL과 완전히 다른 방식이다. 스플레이 트리는 **접근한 노드를 루트까지 끌어올리는 자기조정 BST** 이다.<br/>

&ensp;노드 x를 스플레이한다는 것은 연속적인 재구성을 통해 x를 루트로 이동시키는 것이다.<br/>

&ensp;스플레이를 하는 경우<br/>
&ensp;예를 들어 특정 키를 자주 찾는다면, 한번 접근한 뒤 그 노드를 루트로 올려놓는다. 그러면 다음번에는 **O(1)** 에 가까운 위치에서 찾을 가능성이 높다.<br/>

> 자주 접근하는 항목이 자동으로 위로 올라온다.

&ensp;언제 무엇을 스플레이하는가<br/>

## 스플레이의 3가지 회전

&ensp;스플레이는 zig, zig-zig, zig-zag 세 가지가 있다.<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-21.png" width="600"></p>

&ensp;1. zig<br/>
&ensp;x의 부모가 루트일 때.<br/>
> 루트까지 한 단계 남았을 때 사용하는 회전.

&ensp;2. zig-zig<br/>
&ensp;x, 부모 p, 조부모 g가 같은 방향.<br/>
> 두 번 같은 방향으로 회전한다.

&ensp;3. zig-zag<br/>
&ensp;방향이 서로 다르다.<br/>

## 스플레이 의사코드

<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-23.png" width="600"></p>

<p align="center"><img src="/assets/img/알고리즘 및 실습/6주차/6-22.png" width="600"></p>

&ensp;네 가지 위치 관계를 판별한다.<br/>
&ensp;LL<br/>
```alg
x = leftChild(leftChild(g))

rightRotate(p, g)
rightRotate(x, p)
```

&ensp;RR<br/>
```alg
x = rightChild(rightChild(g))

leftRotate(p, g)
leftRotate(x, p)
```

&ensp;RL<br/>
```alg
x = leftChild(rightChild(g))

rightRotate(x, p)
leftRotate(x, g)
```

&ensp;LR<br/>
```alg
x = rightChild(leftChild(g))

leftRotate(x, p)
rightRotate(x, g)
```

&ensp;스플레이 실행 순서 문제 푸는 법<br/>
&ensp;시험에서 트리 하나 주고 14를 splay 하시오 같은 문제가 나오면 다음 순서로 풀기<br/>

&ensp;Step 1. x 찾기<br/>
&ensp;`x = 14` <br/>

&ensp;Step 2. 부모와 조부모 확인<br/>
* p = parent(x)
* g = parent(p)

&ensp;Step 3. 방향 비교<br/>
&ensp;예:<br/>
* g → 오른쪽 → p
* p → 왼쪽 → x

&ensp;이면 `zig-zag` <br/>

&ensp;Step 4. 회전<br/>
&ensp;트리를 다시 그린다.<br/>

&ensp;Step 5. x가 루트인지 검사<br/>
&ensp;아직 아니면 다시 p, g 를 정해서 반복한다.<br/>

&ensp;AVL과 Splay의 가장 중요한 차이<br/>

| | AVL | Splay |
|---|---|---|
| 종류 | 균형 BST | 자기조정 BST |
| 균형 유지 | 항상 유지 | 유지하지 않음 |
| 높이 정보 | 저장 필요 | 필요 없음 |
| 조정 시점 | 불균형 발생 | 접근할 때 |
| 조정 대상 | 불균형 부분 | 접근한 노드를 루트로 |
| 높이 | O(log n) | 최악 O(n) 가능 |
| 탐색 | O(log n) | 상각 O(log n) |
| 삽입 | O(log n) | 상각 O(log n) |
| 삭제 | O(log n) | 상각 O(log n) |

&ensp;O(log n) 상각실행시간: 매 연산이 O(log n)이라는 뜻은 아니다.<br/>
* 한 번의 연산: 최악 O(n) 가능
* 여러 번의 연산 전체를 평균적으로 보면: O(log n)

&ensp;세 트리 시간복잡도 총정리<br/>

| 자료구조 | 탐색 | 삽입 | 삭제 |
|---|---:|---:|---:|
| BST | O(h) | O(h) | O(h) |
| AVL | O(log n) | O(log n) | O(log n) |
| Splay | O(log n) 상각 | O(log n) 상각 | O(log n) 상각 |

&ensp;BST에서 최선 h = O(log n), 최악 h = O(n) 이다.<br/>
