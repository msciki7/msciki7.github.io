# 힙(Heap)

&ensp;1. 힙(Heap)<br/>
&ensp;힙은 키(key)를 내부 노드에 저장하면서 다음 두 가지 조건을 만족하는 이진트리다.<br/>

&ensp;1) 힙순서(Heap-order)<br/>
&ensp;기본적으로 최소힙(Min Heap)을 기준으로 설명한다. 루트를 제외한 모든 내부 노드 v에 대해 key(v) ≥ key(parent(v)). 즉 부모의 키 ≤ 자식의 키 이다.<br/>

&ensp;예<br/>
```
        2
      /   \
     5     6
    / \
   9   7
```

&ensp;이 트리에서는<br/>
* 2 ≤ 5
* 2 ≤ 6
* 5 ≤ 9
* 5 ≤ 7

&ensp;이므로 최소힙 조건을 만족한다.<br/>
&ensp;중요한 점은 힙 전체가 정렬되어 있는 것은 아니다. 예를 들어 5와 6, 7과 6 사이에는 직접적인 순서 조건이 없다. 즉 힙이 보장하는 것은 부모 ≤ 자식 관계뿐이다.<br/>

&ensp;2. 완전이진트리(Complete Binary Tree)<br/>
&ensp;힙은 완전이진트리여야 한다.<br/>
&ensp;완전이진트리의 특징<br/>
* 마지막 레벨을 제외한 모든 레벨이 채워져 있고
* 마지막 레벨의 노드는 왼쪽부터 채워진다.

<p align="center"><img src="/assets/img/알고리즘 및 실습/2주차/2-1.png" width="600"></p>


&ensp;3. 힙의 높이<br/>
&ensp;n개의 키를 가진 힙의 높이는 O(log n) 이다.<br/>
&ensp;완전이진트리는 깊이가 증가할 때마다 노드 수가 약 2배씩 증가한다.<br/>
```
depth 0 → 1
depth 1 → 2
depth 2 → 4
depth 3 → 8
...
```

&ensp;따라서 $n ≈ 2^h$ 이므로 $n ≈ \log(n)$ 이다.<br/>
&ensp;이 성질 때문에 upHeap, downHeap의 시간복잡도가 $O(\log n)$ 이 된다.<br/>

# 힙과 우선순위 큐

&ensp;1. 힙 기반 우선순위 큐<br/>
&ensp;힙을 사용하면 우선순위 큐를 구현할 수 있다. 최소힙에서는 가장 작은 키가 루트에 있다. 따라서 `minKey(), minElement()` 는 루트만 확인하면 되므로 O(1) 이다. 반면 삽입과 삭제는 힙순서를 다시 맞춰야 하므로 $O(\log n)$ 이 필요하다.<br/>

# 힙 삽입

&ensp;1. 삽입의 기본 흐름<br/>
&ensp;우선순위 큐의 `insertItem()` 은 힙에 새로운 키를 넣는 연산이다. 삽입은 세단계로 진행된다.<br/>
1. 새로운 마지막 노드 위치를 찾는다.
2. 해당 위치에 키 k를 저장한다.
3. upHeap으로 힙순서를 복구한다.

<p align="center"><img src="/assets/img/알고리즘 및 실습/2주차/2-4.png" width="600"></p>

&ensp;2. insertItem 의사코드<br/>
```
Alg insertItem(k)
input key k, node last
output none

1. advanceLast()  // 새로운 원소가 들어갈 위치로 last를 이동
2. z ← last       // 삽입할 위치를 z로 둔다.
3. Set node z to k  // 해당 위치에 새로운 키 k를 저장한다.
4. expandExternal(z)  // 외부노드였던 z를 내부노드로 확장.
5. upHeap(z)          // 삽입 때문에 깨질 수 있는 힙순서를 복구.
6. return
```

&ensp;4. UpHeap<br/>

&ensp;4-1. UpHeap의 목적<br/>
&ensp;새로운 키가 삽입되면 부모보다 값이 작을 수 있다. 이 경우 부모 ≤ 자식 이라는 최소힙 조건이 깨진다. `upHeap` 은 삽입된 노드에서 시작해 **부모 방향으로 올라가며** 힙순서를 복구한다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/2주차/2-7.png" width="600"></p>

&ensp;4-2. UpHeap 의사코드<br/>
```
Alg upHeap(v)
input node v
output none

1. if (isRoot(v))
       return

2. if (key(v) >= key(parent(v)))  // 부모 ≤ 자식를 만족하므로 종료.
       return

3. swapElements(v, parent(v))  // 현재 노드가 부모보다 작다면 힙순서가 깨졌으므로 둘을 교환한다.

4. upHeap(parent(v))  // 교환된 값이 한 단계 위로 올라갔으므로 위쪽에서도 조건이 맞는지 다시 검사한다.
```

&ensp;4-3. 실제 진행 과정<br/>
&ensp;현재 힙:<br/>
```
        2
      /   \
     5     6
    / \
   9   7
```

&ensp;1을 삽입한다.<br/>

&ensp;삽입 직후<br/>
```
        2
      /   \
     5     6
    / \   /
   9   7 1
```

&ensp;현재 v = 1.<br/>

&ensp;1차 비교: 1 < 6 이므로 교환.<br/>
```
        2
      /   \
     5     1
    / \   /
   9   7 6
```

&ensp;2차 비교: 1 < 2 이므로 다시 교환.<br/>
```
        1
      /   \
     5     2
    / \   /
   9   7 6
```

&ensp;종료: 이제 1이 루트이므로 종료한다.<br/>

&ensp;최종 결과<br/>
```
        1
      /   \
     5     2
    / \   /
   9   7 6
```

&ensp;4-4. 시간복잡도<br/>
&ensp;최악의 경우 leaf에서 root까지 올라간다. 힙 높이가 $O(\log n)$ 이므로 $O(\log n)$ 이다.<br/>

# 힙 삭제

&ensp;1. removeMin의 기본 흐름<br/>
&ensp;최소힙에서 삭제 연산은 루트의 최소값을 삭제하는 `removeMin()` 이다. 삭제 과정은 다음과 같다.<br/>
1. 루트 값을 마지막 노드의 값으로 대체
2. 마지막 노드 제거
3. downHeap으로 힙순서 복구

<p align="center"><img src="/assets/img/알고리즘 및 실습/2주차/2-8.png" width="600"></p>

&ensp;2. removeMin 의사코드<br/>
```
Alg removeMin()
input node last
output key

1. k ← key(root())
2. w ← last
3. Set root to key(w)
4. retreatLast()
5. z ← rightChild(w)
6. reduceExternal(z)
7. downHeap(root())
8. return k
```

&ensp;3. DownHeap<br/>
&ensp;3-1. DownHeap의 목적<br/>
&ensp;루트 값을 마지막 노드의 값으로 바꾸면 새로운 루트가 자식보다 클 수 있다. 이때 `downHeap` 은 루트에서 시작해 아래쪽으로 내려가며 힙순서를 복구한다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/2주차/2-9.png" width="600"></p>

&ensp;3-2. DownHeap 의사코드<br/>
```
Alg downHeap(v)

1. if (isExternal(leftChild(v)) &
       isExternal(rightChild(v)))  // 자식이 없다면 leaf이므로 종료한다.
       return

2. smaller ← leftChild(v)  // 우선 왼쪽 자식을 더 작은 자식이라고 가정한다.

3. if (isInternal(rightChild(v)))
       if (key(rightChild(v)) < key(smaller))
           smaller ← rightChild(v)  // 오른쪽 자식이 존재하고 오른쪽이 더 작다면 smaller를 오른쪽 자식으로 변경한다.

4. if (key(v) <= key(smaller))  // 현재 노드가 더 작은 자식보다 이미 작거나 같으면 힙순서를 만족하므로 종료한다.
       return

5. swapElements(v, smaller)  // 현재 노드가 더 크다면 더 작은 자식과 교환한다.

6. downHeap(smaller)   // 교환된 위치에서 다시 downHeap을 수행한다.
```

&ensp;3-3. 실제 진행 과정<br/>
&ensp;삭제 전:<br/>
```
        2
      /   \
     5     6
    / \
   9   7
```

&ensp;2를 제거하고 마지막 값 7을 루트로 올린다.<br/>
```
        7
      /   \
     5     6
    /
   9
```

&ensp;자식 비교: 5 < 6 이므로 smaller = 5.<br/>
&ensp;현재 노드와 비교: 7 > 5 따라서 교환한다.<br/>
```
        5
      /   \
     7     6
    /
   9
```

&ensp;이제 7 < 9 이므로 종료한다.<br/>

&ensp;3-4. 시간복잡도<br/>
&ensp;루트에서 leaf까지 내려갈 수 있으므로 $O(\log n)$ 이다.<br/>

&ensp;4. reduceExternal<br/>
&ensp;역할: 삭제된 마지막 내부노드와 외부노드를 제거해 트리 구조를 정리하는 연산이다.<br/>

# 마지막 노드 갱신

&ensp;연결 구조 힙에서는 삽입 또는 삭제 후 마지막 노드를 직접 찾아야 한다.<br/>

&ensp;1. advanceLast<br/>
&ensp;삽입 위치를 찾는 연산이다.<br/>
&ensp;흐름<br/>
&ensp;현재 노드가 오른쪽 자식이면 부모로 이동 → 왼쪽 자식을 만날 때까지 이동 → 형제 노드로 이동 → 왼쪽 자식을 따라 내려감<br/>
&ensp;시간 복잡도: $O(\log n)$ <br/>

&ensp;2. retreatLast<br/>
&ensp;삭제 이후 마지막 노드를 찾는다. `advanceLast()`의 반대 방향으로 동작한다.<br/>

# 힙 정렬(Heap Sort)

&ensp;1. 기본 개념<br/>
&ensp;힙 기반 우선순위 큐를 이용하면 리스트를 정렬할 수 있다.<br/>
&ensp;기본 아이디어는 모든 원소를 힙에 넣음 → 최소값을 계속 삭제 → 순서대로 리스트에 저장 이다.<br/>

&ensp;2. heapSort 의사코드<br/>
```
Alg heapSort(L)
input list L
output sorted list L

1. H ← empty heap  

2. while (!L.isEmpty())
       k ← L.removeFirst()
       H.insertItem(k)

3. while (!H.isEmpty())
       k ← H.removeMin()
       L.addLast(k)

4. return
```

&ensp;1단계 — Heap 생성<br/>
&ensp;원소들을 하나씩 `insertItem()` 으로 힙에 넣는다. 결과적으로 최소힙이 만들어진다.<br/>

&ensp;2단계 — 정렬<br/>
&ensp;이제 `removeMin()` 을 반복한다.<br/>

&ensp;시간복잡도<br/>
&ensp;삽입: $n \times O(\log n)$ <br/>
&ensp;삭제: $n \times O(\log n)$ <br/>
&ensp;따라서 $O(n\log n)$ 이다.<br/>

## Heap Sort 개선

&ensp;1. 제자리 힙 정렬(In-place Heap Sort)<br/>
&ensp;일반 Heap Sort 는 별도의 힙을 만들어야 한다. 제자리 힙 정렬은 원래 배열 자체를 힙으로 사용한다. 최소힙 대신 최대힙(Max Heap)을 사용한다.<br/>
&ensp;최대힙 조건: 부모 ≥ 자식<br/>

&ensp;제자리 힙 정렬 알고리즘<br/>
&ensp;inPlaceHeapSort 의사코드<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/2주차/2-14.png" width="600"></p>

&ensp;핵심 원리<br/>
&ensp;최대힙에서는 `A[1] = 현재 힙에서 가장 큰 값` 이다. 따라서 `A[1] ↔ A[i]` 를 하면 최대값이 배열의 가장 뒤로 이동한다. 그 다음 힙 크기를 하나 줄인다. `downHeap(1, i-1)` 을 통해 남은 영역을 다시 최대힙으로 만든다.<br/>

&ensp;제자리 Heap Sort의 1기와 2기<br/>
&ensp;1기 — 힙 생성<br/>
&ensp;배열 왼쪽에서 오른쪽으로 경계를 이동하면서 최대힙을 만든다. `일반 배열 -> Max Heap` <br/>
&ensp;2기 — 정렬<br/>
&ensp;오른쪽에서 왼쪽으로 힙의 범위를 줄인다.<br/>
&ensp;각 단계마다<br/>
1. root의 최대값을 배열 끝으로 보냄
2. 힙 크기 감소
3. downHeap 수행

&ensp;한다.<br/>

# 상향식 힙생성

&ensp;기존 힙 생성 방식<br/>
&ensp;기존 heapSort의 1기에서는 `insertItem()`을 n번 수행한다.<br/>
&ensp;각 삽입은 $O(\log n)$ 이므로 $O(n\log n)$ 이 필요하다.<br/>

&ensp;상향식 힙생성의 핵심: 모든 키가 미리 주어져 있다면 O(n) 시간에 힙을 만들 수 있다. <- 상향식 힙생성<br/>

## 재귀적 상향식 힙생성

<p align="center"><img src="/assets/img/알고리즘 및 실습/2주차/2-22.png" width="600"></p>

&ensp;실행 순서<br/>
&ensp;이 알고리즘의 중요한 점은 downHeap(v)보다 먼저 `rBuildHeap(leftChild(v)), rBuildHeap(rightChild(v))` 를 호출한다.<br/>
&ensp;왼쪽 서브트리 힙화 → 오른쪽 서브트리 힙화 → 현재 노드 downHeap 순서로 진행된다.<br/>

&ensp;두 힙의 합병<br/>
&ensp;상향식 힙생성은 작은 힙을 합쳐 더 큰 힙을 만드는 방식으로 볼 수 있다. 두 개의 힙과 키 k가 있을 때<br/>
```
      k
     / \
  Heap Heap
```

&ensp;형태로 만든다.<br/>
&ensp;하지만 k가 자식보다 클 수 있으므로 `downHeap(k)` 을 수행해 전체를 다시 힙으로 만든다.<br/>

## 배열 기반 비재귀적 상향식 힙생성

&ensp;1. 시작 위치<br/>
&ensp;배열 기반에서는 n/2 부터 시작한다.<br/>
&ensp;왼쪽 자식의 위치는 2i 이다. 자식이 존재하려면 $2i ≤ n$ . 따라서 $i ≤ \frac{n}{2}$​ 이다. 즉 `1 ~ floor(n/2)` 은 내부노드이고 `floor(n/2)+1 ~ n` 은 leaf이다. leaf는 이미 힙이므로 검사할 필요가 없다.<br/>

&ensp;비재귀적 buildHeap 의사코드<br/>
```
Alg buildHeap(A)
input array A of n keys
output heap A of size n

1. for i ← floor(n/2) downto 1
       downHeap(i, n)

2. return
```

&ensp;실행 순서<br/>
&ensp;예를 들어 n = 6 이라면 6/2 = 3 이므로<br/>
* i = 3
* i = 2
* i = 1

&ensp;순서로 `downHeap()` 을 수행한다. 즉 가장 아래쪽 내부노드부터 루트까지 올라온다.<br/>
&ensp;상향식 힙생성 시간복잡도<br/>
&ensp;겉으로 보면 `노드 n개 × downHeap O(log n)` 이라서 $O(n \log n)$ 처럼 보인다.<br/>
&ensp;**하지만 실제로는 O(n) 이다.** <br/>
&ensp;이유는 대부분의 노드가 아래쪽에 있기 때문이다.<br/>
* leaf 근처 노드 → 내려갈 수 있는 거리 짧음
* root 근처 노드 → 내려갈 수 있는 거리 길음

&ensp;즉 모든 노드가 $O(\log n)$ 만큼 내려가는 것이 아니다.<br/>

&ensp;Heap Sort 최종 시간복잡도<br/>
&ensp;상향식 힙생성을 적용하면<br/>
&ensp;힙 생성: O(n)<br/>
&ensp;정렬 과정: downHeap을 반복하므로 $O(n\log n)$ . 따라서 전체는 여전히 $O(n \log n)$ 이다.<br/>
&ensp;상향식 힙생성은 Heap Sort의 1기만 개선한다.<br/>
