# 해시테이블 Hash Table

&ensp;**해시테이블(Hash Table)은 키와 주소의 매핑을 이용하여 사전 ADT를 구현한 자료구조이다.** <br/>

&ensp;사전 ADT Dictionary ADT<br/>
&ensp;사전 ADT는 데이터를 (키, 원소)의 쌍으로 관리하는 추상 자료형이다.<br/>
* 키(Key): 데이터를 식별하는 값
* 원소(Element): 키에 연결된 실제 데이터

&ensp;사전 ADT는 일반적으로 다음 연산을 제공한다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/9주차/9-1.png" width="600"></p>

&ensp;사전 ADT는 필요한 연산을 정의한 것이고, 해시테이블은 그 연산을 구현하는 방법 중 하나이다.<br/>

---

&ensp;키-주소 매핑 Key-Address Mapping<br/>
&ensp;키-주소 매핑이란 키를 이용하여 데이터가 저장될 배열의 위치를 결정하는 것이다. 일반적인 배열에서 원하는 데이터를 찾으려면 여러 원소를 순서대로 확인해야 할 수 있다.<br/>
&ensp;하지만 해시테이블에서는 키를 이용하여 저장 위치를 계산할 수 있다. 예를 들어 다음과 같은 해시함수가 있다고 하자. $h(k)=k\bmod13$ . 키가 25라면 $h(25)=25\bmod13=12$ 이므로 배열의 12번 인덱스를 저장 위치로 사용한다.<br/>
&ensp;즉, 전체 배열을 처음부터 탐색하는 대신 키로부터 계산된 위치를 먼저 확인할 수 있다.<br/>

---

&ensp;해시테이블의 구성<br/>
&ensp;해시테이블은 크게 두 가지로 구성된다.<br/>
&ensp;해시테이블 = 버켓 배열 + 해시함수<br/>
1. 버켓 배열(Bucket Array): 데이터를 저장하는 배열
2. 해시함수(Hash Function): 키를 배열의 인덱스로 변환하는 함수

&ensp;해시함수로 인덱스를 계산한 뒤, 해당 위치에 데이터를 저장하거나 탐색한다. 다만 여러 키가 같은 인덱스로 매핑되는 충돌이 발생할 수 있으므로 충돌 해결 전략도 필요하다.<br/>

---

&ensp;해시테이블의 성능<br/>
&ensp;탐색, 삽입, 삭제 연산의 시간복잡도는 일반적으로 다음과 같다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/9주차/9-2.png" width="600"></p>

&ensp;좋은 해시함수와 적절한 적재율을 유지하면 탐색·삽입·삭제를 기대 O(1) 시간에 수행할 수 있다. 하지만 충돌이 심하게 발생하면 많은 원소를 확인해야 하므로 최악의 경우 O(n) 시간이 걸릴 수 있다. 여기서는 테이블 크기를 원소 수에 비례하도록 관리한다고 가정한다.<br/>
&ensp;핵심: 해시테이블은 항상 O(1)인 자료구조가 아니라, 적절한 조건에서 기대시간 O(1)을 달성하는 자료구조다.<br/>

# 버켓 배열

&ensp;버켓 배열은 크기가 M인 1차원 배열 A이다.<br/>
* A: 버켓 배열
* M: 배열의 용량
* 버켓(Bucket): 배열의 각 칸
* 슬롯(Slot): 버켓과 같은 의미로 사용하는 용어

&ensp;예를 들어 M=13이면 배열은 0번부터 12번까지 총 13개의 버켓으로 구성된다.<br/>

---

&ensp;직접주소 방식<br/>
&ensp;가장 간단한 저장 방식은 키를 배열의 인덱스로 직접 사용하는 것이다. 키가 k인 원소 e를 다음 위치에 저장한다.(A[k]) 예를 들어 키가 3인 원소는 A[3], 키가 8인 원소는 A[8]에 저장한다. 이러한 방식을 직접주소 방식(Direct Addressing)이라고 한다. 이때 존재하지 않는 키의 버켓에는 NoSuchKey와 같은 특별한 값을 저장한다고 가정할 수 있다. 이 값은 해당 키에 대응하는 원소가 존재하지 않는다는 의미다.<br/>

---

&ensp;버켓 배열 분석<br/>

&ensp;직접주소 방식의 시간복잡도<br/>
&ensp;키가 다음 조건을 만족한다고 하자.<br/>
1. 키는 정수이다.
2. 키의 범위가 [0,M-1]이다.
3. 각 키는 유일하다.

&ensp;이 경우 키를 배열의 인덱스로 직접 사용할 수 있다.<br/>
&ensp;따라서 탐색·삽입·삭제에 필요한 시간은 다음과 같다.<br/>

$$O(1)$$

&ensp;배열의 특정 인덱스에 직접 접근할 수 있기 때문이다.<br/>

&ensp;직접주소 방식의 문제점<br/>
&ensp;직접주소 방식에는 두 가지 중요한 결함이 있다.<br/>

&ensp;첫 번째 문제 공간 낭비<br/>
&ensp;배열의 크기 M이 실제 저장된 원소 수 n보다 매우 크면 공간이 낭비된다. 예를 들어 학번이 99999999인 학생의 정보를 저장하려면, 키를 그대로 인덱스로 사용하는 배열은 매우 커져야 한다. 실제 학생 수가 100명이더라도 대부분의 배열 공간이 비어 있을 수 있다.<br/>
&ensp;크기가 M인 배열을 생성하므로 배열 공간복잡도는 다음과 같다.<br/>

$$\Theta(M)$$

&ensp;M이 n에 비례하는 경우에는 $\Theta(n)$으로 볼 수 있지만, 일반적으로 두 값을 동일하게 취급하면 안 된다.<br/>

&ensp;두 번째 문제 키의 제한<br/>
&ensp;직접주소 방식에서는 키가 배열의 인덱스로 사용 가능한 정수여야 한다. 하지만 실제 키는 다음과 같이 다양한 형태로 나타난다.<br/>
* 학번
* 주민등록번호
* 전화번호
* 문자열
* 객체

&ensp;문자열 `"apple"` 을 그대로 배열 인덱스로 사용할 수는 없다.<br/>
&ensp;따라서 다양한 키를 작은 정수 범위로 변환하는 과정이 필요하다.<br/>

&ensp;해결 방향<br/>
&ensp;두 문제를 해결하기 위해 해시함수를 도입한다. 해시함수는 키를 배열 크기에 맞는 정수 인덱스로 변환한다. 즉, 모든 키를 직접 배열 인덱스로 사용하는 것이 아니라, 키에 해시함수를 적용하여 저장 위치를 계산한다.<br/>

---

# 해시함수

&ensp;해시함수(Hash Function)는 키를 일정한 범위의 정수로 변환하는 함수이다. 배열 크기가 M이라면 해시함수는 다음 조건을 만족해야 한다.<br/>

$$0\le h(k)<M$$

&ensp;즉, 해시함수의 결과가 반드시 유효한 배열 인덱스여야 한다.<br/>

&ensp;나머지 연산을 이용한 해시함수<br/>
&ensp;정수 키에 가장 간단하게 적용할 수 있는 해시함수는 다음과 같다.<br/>

$$h(k) = k mod M$$

&ensp;여기서 mod는 나머지 연산이다.<br/>
&ensp;예를 들어 M=13, k=28 이면 $h(28)=28\bmod13=2$ 이다. 따라서 키 28은 2번 버켓으로 매핑된다. 이때 계산된 값 h(k)를 해시값(Hash Value)이라고 한다.<br/>

---

&ensp;해시테이블에 항목 저장<br/>
&ensp;사전의 항목이 (k,e)라고 하자. 해시테이블은 이 항목을 다음 위치에 저장하는 것을 목표로 한다.<br/>
$$i=h(k)$$

&ensp;A[h(k)]에 항목을 저장한다. 단 이미 같은 버켓에 다른 항목이 있으면 충돌 해결 과정이 필요하다.<br/>

---

&ensp;간단한 해시테이블 설계 예<br/>

&ensp;전화번호와 이름을 저장하는 사전<br/>
&ensp;전화번호를 키로, 이름을 원소로 사용하는 사전을 생각해보자. <br/>
&ensp;예를 들어<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/9주차/9-3.png" width="600"></p>


&ensp;전화번호를 정수 키로 취급한다고 가정한다. 하지만 전화번호 전체를 배열 인덱스로 사용하려면 배열의 크기가 너무 커질 수 있다. 따라서 전화번호의 마지막 네 자리를 이용하는 해시함수를 설계할 수 있다.<br/>

&ensp;해시함수 설계<br/>
&ensp;배열의 크기를 다음과 같이 설정한다. M = 10000<br/>
&ensp;해시함수는 전화번호의 마지막 네 자리를 반환하도록 정의한다.<br/>
$$h(k)=k\bmod10000$$

&ensp;예를 들어 전화번호가 010-612-0001이라면 마지막 네 자리는 0001이다. 따라서 1번 버켓에 저장한다. 전화번호가 010-751-9998이면 9998번 버켓에 저장한다. 이 방식에서는 전체 전화번호를 사용하지 않고도 0부터 9999 사이의 인덱스를 계산할 수 있다.<br/>

&ensp;마지막 네 자리가 같은 전화번호는 동일한 버켓으로 매핑된다. 예를 들어 010-1234-5678, 010-9876-5678 은 서로 다른 전화번호지만 해시값은 모두 5678이다. 따라서 충돌이 발생한다.<br/>

----

&ensp;해시함수의 구성<br/>

&ensp;해시함수의 두 단계<br/>
&ensp;해시함수는 일반적으로 다음 두 함수의 결합으로 생각할 수 있다.<br/>
1. 해시코드맵(Hash Code Map)
2. 압축맵(Compression Map)

&ensp;해시코드맵 $h_1$ <br/>
&ensp;키를 정수로 변환하는 함수이다.<br/>

$$h_1:\text{Keys}\rightarrow\text{Integers}$$

&ensp;압축맵 $h_2$ <br/>
&ensp;해시코드맵으로 얻은 정수를 배열의 인덱스 범위로 변환하는 함수이다.<br/>

$$h_2:\text{Integers}\rightarrow[0,M-1]$$

&ensp;전체 해시함수는 다음과 같이 표현한다.<br/>

$$h(k)=h_2(h_1(k))$$

&ensp;즉, 먼저 키에 해시코드맵을 적용하고, 그 결과에 압축맵을 적용한다.<br/>

&ensp;좋은 해시함수의 조건<br/>
&ensp;① 키를 고르게 분산시켜야 한다.<br/>
&ensp;특정 버켓에 키가 집중되면 충돌이 많이 발생한다. 따라서 해시값이 가능한 한 무작위처럼 고르게 분포하도록 설계하는 것이 중요하다.<br/>

&ensp;② 계산이 빠르고 쉬워야 한다.<br/>
&ensp;해시테이블은 빠른 탐색을 목적으로 사용한다. 그런데 해시함수 자체를 계산하는 데 시간이 많이 걸리면 해시테이블을 사용하는 장점이 줄어든다. 따라서 해시함수의 계산 비용이 작아야 한다.<br/>

&ensp;해시코드맵<br/>

&ensp;해시코드맵은 키를 정수로 변환하는 함수다.<br/>
&ensp;1. 메모리 주소 Memory Address<br/>
&ensp;객체의 메모리 주소와 관련된 정보를 정수로 해석하여 해시코드로 사용하는 방식이다. 객체에 대응하는 정수값을 만들 수 있지만, 값 자체가 같은 객체를 동일한 해시코드로 처리해야 하는 상황에서는 적절하지 않을 수 있다.<br/>

&ensp;2. 정수 캐스트 Integer Cast<br/>
&ensp;키의 비트값을 정수로 해석하는 방식이다. 정수형에 할당된 비트 수를 초과하지 않는 길이의 키에 적합하다.<br/>

---

&ensp;해시코드맵의 요소합<br/>

&ensp;요소합 Component Sum<br/>
&ensp;요소합은 긴 키를 여러 개의 고정 길이 요소로 나눈 뒤, 각 요소를 더하는 방식이다. 예를 들어 키의 비트들을 16비트 또는 32비트 단위로 나누어 각 부분을 더할 수 있다. 이때 정수형의 표현 범위를 초과하는 오버플로는 강의록의 단순화된 방식에서는 무시한다. 긴 수치형 키의 해시코드를 계산할 때 사용할 수 있다.<br/>

&ensp;요소합의 문제점<br/>
&ensp;요소합은 덧셈을 사용하기 때문에 요소의 순서를 구분하지 못한다. 예를 들어 문자 코드가 다음과 같다고 하자.<br/>
* a = 97
* b = 98

&ensp;문자열 ab의 요소합은 97 + 98 = 195이다.<br/>
&ensp;문자열 ba의 요소합도 98 + 97 = 195이다.<br/>

&ensp;두 문자열은 서로 다르지만 같은 해시코드가 만들어진다. 따라서 문자열처럼 순서가 중요한 키에는 단순 요소합이 적절하지 않을 수 있다.<br/>

---

&ensp;해시코드맵의 다항 누적<br/>

&ensp;다항 누적 Polynomial Accumulation<br/>
&ensp;다항 누적은 요소의 위치를 반영하여 해시코드를 계산하는 방식이다. 키를 다음과 같이 여러 요소로 분할한다. $a_0,a_1,\ldots,a_{n-1}$ <br/>
&ensp;그다음 고정된 정수 z를 이용하여 다음 다항식을 계산한다.<br/>

$$p(z)=a_0+a_1z+a_2z^2+\cdots+a_{n-1}z^{n-1}$$

&ensp;요소합과 다른 점은 각 요소에 위치에 따른 가중치가 적용된다는 것이다. 따라서 요소의 순서가 달라지면 해시코드도 달라질 수 있다.<br/>

&ensp;다항 누적 계산 예제<br/>
&ensp;문자열 ab와 ba를 비교해 보자.<br/>
&ensp;z = 33으로 설정한다.<br/>

&ensp;압축맵<br/>

&ensp;1. 나누기 방식 Division<br/>
&ensp;나누기 방식은 해시코드를 배열 크기 M으로 나눈 나머지를 사용한다.<br/>

$$h_2(k)=|k|\bmod M$$

&ensp;절댓값은 음수 해시코드를 처리하여 음수 인덱스가 나오지 않도록 하기 위한 것이다. 예를 들어 k=3331, M=13 이라면 $h_2(3331)=3331\bmod13=3$ 이다. 따라서 3번 버켓에 저장할 위치가 결정된다.<br/>

&ensp;배열 크기 M을 소수로 선택하는 이유<br/>
&ensp;배열 크기를 소수로 설정하면 특정 규칙을 가진 키들이 같은 버켓에 몰리는 현상을 줄이는 데 도움이 될 수 있다. 예를 들어 모든 키가 10의 배수인데 M=10이면 나머지가 항상 0이다. 반면 M=13이면 나머지가 다양한 값으로 나타날 수 있다. 단, 소수 크기의 배열을 사용한다고 충돌이 없어지는 것은 아니다.<br/>

&ensp;2. MAD 방식 Multiply Add and Divide<br/>
&ensp;MAD 방식은 곱셈과 덧셈을 수행한 뒤 나머지 연산을 적용한다.<br/>

$$h_2(k)=|ak+b|\bmod M$$

&ensp;여기서 a와 b는 음이 아닌 정수로 설정한다. ( $a\bmod M\ne0$ )<br/>

&ensp;3. MAD 계산 예제<br/>
&ensp;a=3, b=5, M=13 이라고 하자.<br/>
&ensp;키가 10이면 $h_2(10)=|3(10)+5|\bmod13 =35\bmod13$ <br/>

$$h_2 (10) = 9$$

&ensp;키 10에 대응하는 해시코드가 이 압축맵의 입력으로 들어오면 9번 버켓으로 매핑된다.<br/>

# 충돌 해결

&ensp;1. 충돌의 정의<br/>
&ensp;충돌(Collision)은 서로 다른 두 키가 동일한 해시값을 가지는 현상이다. 서로 다른 키 $k_1, k_2$ 에 대해 $k_1\ne k_2$ 이지만 $h(k_1) = h(k_2)$ 이면 충돌이 발생했다고 한다.<br/>
&ensp;예를 들어 M = 13, h(k) = k mod 13 일 때 h(15) = 2, h(28) = 2 이다.<br/>
&ensp;키 15와 28은 서로 다르지만 모두 배열의 2번 버켓에 저장되려고 한다. 이때 이미 15가 저장되어 있다면 28을 같은 위치에 단순히 덮어쓸 수 없다. 그렇게 하면 15의 데이터가 사라지기 때문이다. 따라서 충돌을 올바르게 처리할 전략이 필요하다.<br/>

&ensp;2. 충돌 해결의 대표적인 방법<br/>
1. 분리연쇄법(Separate Chaining)
2. 개방주소법(Open Addressing)

&ensp;두 방법은 충돌한 원소를 저장하는 방식이 다르다.<br/>

&ensp;분리연쇄법 Separate Chaining<br/>

&ensp;1. 분리연쇄법의 정의<br/>
&ensp;분리연쇄법은 각 버켓에 리스트를 두고, 같은 해시값을 가진 원소들을 해당 리스트에 저장하는 방식이다. 배열의 i번 버켓은 리스트 $L_i$ 를 참조한다. 이 리스트에는 해시함수의 결과가 i인 모든 항목이 저장된다.<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/9주차/9-9.png" width="600"></p>

&ensp;예를 들어 h(15) = 2, h(28) = 2 라면 두 키는 모두 2번 버켓의 리스트에 저장된다. `A[2] → (15, e₁) → (28, e₂)` 따라서 하나의 버켓에 여러 항목이 매핑되더라도 모든 항목을 유지할 수 있다.<br/>

&ensp;2. 분리연쇄법의 특징<br/>
&ensp;분리연쇄법에서는 각 버켓의 리스트를 작은 사전처럼 생각할 수 있다. 해시함수로 버켓을 결정한 뒤, 해당 리스트 안에서 키를 탐색하거나 항목을 삽입, 삭제한다.<br/>

&ensp;장점<br/>
* 구현이 비교적 단순하다.
* 충돌이 발생해도 리스트에 원소를 추가할 수 있다.
* 원소 삭제가 비교적 쉽다.
* 원소 수가 버켓 수보다 많아도 저장할 수 있다.

&ensp;단점<br/>
* 리스트를 위한 추가적인 공간이 필요하다.
* 연결리스트를 사용하면 포인터를 관리해야 한다.
* 특정 버켓에 원소가 집중되면 탐색 시간이 증가한다.

&ensp;개방주소법 Open Addressing<br/>

&ensp;개방주소법은 충돌한 원소를 버켓 배열 내부의 다른 빈 칸에 저장하는 방식이다. 분리연쇄법은 리스트에 원소를 추가하지만, 개방주소법은 별도의 리스트를 사용하지 않는다.<br/>
&ensp;예를 들어 h(15) = 2, h(28) = 2 이고 2번 버켓에 15가 저장되어 있다. 28을 삽입할 때 2번에서 충돌이 발생한다. 그러면 미리 정한 규칙에 따라 다른 버켓을 조사하여 빈 칸을 찾는다.<br/>

&ensp;개방주소법의 특징<br/>
&ensp;장점은 별도의 리스트가 필요하지 않아 추가 저장공간을 절약할 수 있다는 것이다. 반면 다음과 같은 문제가 있다.<br/>
* 삭제 과정이 복잡하다.
* 충돌이 많아지면 빈 칸을 찾는 시간이 길어진다.
* 원소들이 특정 영역에 모이는 군집화(Clustering)가 발생할 수 있다.

&ensp;개방주소법에서는 조사 규칙을 어떻게 설정하는지가 매우 중요하다.<br/>

&ensp;선형조사법 Linear Probing<br/>
&ensp;선형조사법은 충돌이 발생하면 바로 다음 칸부터 한 칸씩 이동하면서 빈 버켓을 찾는 방법이다. 일반적인 조사식은 다음과 같다.<br/>

$$(h(k) + f(i)) mod M$$

&ensp;선형조사법에서는 $f(i) = i$ 를 사용한다.<br/>

$$(h(k) + i) mod M$$

&ensp;여기서 $i=0,1,2,\ldots$ 이다.<br/>
&ensp;조사 순서는 다음과 같다.<br/>
$$h(k),\ h(k)+1,\ h(k)+2,\ldots$$

&ensp;배열의 끝에 도달하면 나머지 연산에 의해 0번 인덱스로 돌아간다.<br/>

&ensp;선형조사법 삽입 예제<br/>
$$M=13,\qquad h(k)=k\bmod13$$

&ensp;삽입할 키는 다음과 같다.<br/>
$$25, 13, 16, 15, 7, 28, 31, 20, 1, 38$$

&ensp;앞의 다섯 키는 충돌 없이 저장된다.<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/9주차/9-14.png" width="600"></p>

&ensp;키 28 삽입<br/>
$$h(28) = 2$$

&ensp;2번 버켓에 15가 있으므로 충돌한다.<br/>
* i=0: 2번 → 충돌
* i=1: 3번 → 충돌
* i=2: 4번 → 비어 있음

&ensp;따라서 28은 4번 인덱스에 저장된다.<br/>

&ensp;키 31 삽입<br/>
$$h(31) = 5$$

&ensp;5번 인덱스가 비어 있으므로 저장한다.<br/>

&ensp;키 20 삽입<br/>
$$h(20) = 7$$

&ensp;7번에는 이미 7이 있으므로 충돌한다. 8번 인덱스가 비어 있으므로 20을 8번에 저장한다.<br/>

&ensp;키 1 삽입<br/>
$$h(1) = 1$$

&ensp;1번 인덱스에 저장한다.<br/>

&ensp;키 38 삽입<br/>
$$h(38) = 12$$

&ensp;12번에는 이미 25가 저장되어 있다.<br/>

&ensp;1차 군집화 Primary Clustering<br/>
&ensp;선형조사법은 충돌이 발생하면 바로 다음 칸으로 이동한다. 따라서 원소들이 연속된 인덱스에 모이기 쉽다. 이미 연속된 구간에 새로운 충돌이 발생하면 그 구간의 끝까지 조사해야 하므로 군집이 더 길어질 수 있다. 이를 1차 군집화라고 한다.<br/>
&ensp;핵심: 선형조사법은 구현이 간단하지만 1차 군집화로 인해 조사 횟수가 증가할 수 있다.<br/>

&ensp;2차 조사법 Quadratic Probing<br/>
&ensp;2차 조사법은 충돌이 발생하면 조사 횟수의 제곱을 이용하여 다음 버켓을 선택하는 방법이다.<br/>

$$f(i)=i^2$$

&ensp;따라서 조사식은 다음과 같다.<br/>
$$(h(k) + i^2 ) mod M$$

&ensp;여기서 $i=0,1,2,\ldots$ 이다. 이동량은 다음과 같다. 0, 1, 4, 9, 16, ....<br/>
&ensp;**항상 원래 해시값 h(k)에 $i^2$ 를 더한다**<br/>

&ensp;2차 조사법 삽입 예제<br/>

$$M=13,\qquad h(k)=k\bmod13$$

&ensp;삽입 순서: 25, 13, 16, 15, 7, 28, 31, 20, 1, 38<br/>
&ensp;앞의 다섯 키는 충돌 없이 저장된다.<br/>

&ensp;키 28 삽입<br/>
$$h(28) = 2$$

&ensp;2번에는 15가 있으므로 충돌한다.<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/9주차/9-17.png" width="600"></p>

&ensp;따라서 28은 6번 인덱스에 저장된다. 이루 31은 5번, 20은 8번 1은 1번에 저장된다.<br/>

&ensp;키 38 삽입<br/>
$$h(38) = 12$$

&ensp;12번에 이미 25가 있으므로 충돌한다.<br/>

&ensp;2차 군집화 Secondary Clustering<br/>
&ensp;2차 조사법은 선형조사법의 1차 군집화를 줄일 수 있다. 하지만 기본 해시값이 같은 키들을 동일한 조사열을 따른다. 예를 들어 두 키의 해시값이 모두 2라면 다음 순서를 사용한다.<br/>
$$2\rightarrow3\rightarrow6\rightarrow11\rightarrow\cdots$$

&ensp;따라서 해시값이 같은 키들 사이에서 충돌이 반복될 수 있다.<br/>
&ensp;이를 2차 군집화라고 한다.<br/>

&ensp;2차 조사법의 주의점<br/>
&ensp;2차 조사법은 모든 인덱스를 방문한다는 보장이 없다. 따라서 배열에 빈 칸이 남아 있어도 조사열에서 그 칸을 방문하지 못하면 삽입에 실패할 수 있다.<br/>

&ensp;이중해싱 Double Hashing<br/>
&ensp;이중해싱은 두 번째 해시함수를 이용하여 충돌 시 이동할 간격을 결정하는 방법이다. 첫 번째 해시함수 h(k)는 기본 위치를 결정한다. 두 번째 해시함수 $h'(k)$ 는 다음 버켓으로 이동하는 간격을 결정한다. 조사 함수는 다음과 같다.<br/>

$$f(i)=i\cdot h'(k)$$

&ensp;따라서 전체 조사식은 $(h(k)+i\cdot h'(k))\bmod M$ 이다.<br/>
&ensp;이중해싱은 해시값이 같은 키라도 두 번째 해시값이 다르면 서로 다른 조사열을 사용할 수 있다. 따라서 군집화를 줄이는 데 도움이 된다.<br/>

&ensp;두 번째 해시함수의 조건<br/>
&ensp;① 두 번째 해시값은 0이 되면 안 된다.<br/>
$$h'(k)\ne0$$

&ensp;0이 되면 조사식이 항상 같은 인덱스를 반환하기 때문이다.<br/>

&ensp;② 두 번째 해시값과 M은 서로소인 것이 좋다.<br/>
$$\gcd(h'(k),M)=1$$

&ensp;서로소란 두 수의 최대공약수가 1이라는 뜻이다. 이 조건을 만족하면 조사열이 같은 인덱스를 일찍 반복하지 않고 배열의 모든 인덱스를 방문할 수 있다. 일반적으로 방문 가능한 서로 다른 인덱스 수는 다음과 같다.<br/>

$$\frac{M}{\gcd(M,h'(k))}$$

&ensp;따라서 최대공약수가 1이면 M개의 서로 다른 인덱스를 방문한다.<br/>

&ensp;이중해싱 예<br/>
&ensp;배열 크기: M = 13<br/>
&ensp;첫 번째 해시함수는 $h(k)=k\bmod13$ 이다.<br/>
&ensp;두 번째 해시함수는 $h'(k)=11-(k\bmod11)$ 이다.<br/>
&ensp;삽입 순서: 25, 13, 16, 15, 7, 28, 31, 20, 1, 38<br/>
&ensp;앞의 다섯 키는 충돌 없이 저장된다.<br/>

&ensp;키 28 삽입<br/>
&ensp;기본 해시값은 h(28) = 2 이다. 2번에 이미 15가 있으므로 충돌한다. 두 번째 해시값은 $h'(28)=11-(28\bmod11)=5$ 이다. 따라서 조사식은 $(2+5i)\bmod13$ 이다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/9주차/9-19.png" width="600"></p>

&ensp;따라서 28은 4번 인덱스에 저장된다.<br/>

&ensp;키 20 삽입<br/>
$$h(20) = 7$$

&ensp;7번에서 충돌한다.<br/>

$$h'(20)=11-(20\bmod11)=2$$

&ensp;따라서 이동 간격은 2다.<br/>
* 7번 → 충돌
* 9번 → 비어 있음

&ensp;20은 9번 인덱스에 저장된다.<br/>

&ensp;키 38 삽입<br/>
$$h(38) = 12$$

&ensp;12번에서 충돌한다.<br/>
$$h'(38)=11-(38\bmod11)=6$$

&ensp;따라서 다음 순서로 조사한다.<br/>

$$12\rightarrow5\rightarrow11$$

&ensp;12번과 5번은 이미 사용 중이고, 11번이 비어 있으므로 38은 11번에 저장된다.<br/>

# 해시테이블 성능

&ensp;적재율 Load Factor<br/>
&ensp;적재율은 해시테이블의 크기에 비해 얼마나 많은 원소가 저장되어 있는지를 나타내는 값이다.<br/>

$$\alpha=\frac{n}{M}$$

* $\alpha$ : 적재율
* n: 저장된 원소 수
* M: 버켓 배열 크기

&ensp;적재율과 성능의 관계<br/>
&ensp;적재율이 높을수록 충돌이 발생하거나 긴 조사열을 따라야 할 가능성이 높아진다. 분리연쇄법에서는 하나의 버켓에 더 많은 원소가 저장될 수 있다. 개방주소법에서는 빈 칸이 줄어들어 삽입과 탐색에 필요한 조사 횟수가 증가할 수 있다. 따라서 해시테이블의 적재율을 적절하게 유지해야 한다.<br/>

&ensp;분리연쇄법의 적재율<br/>
&ensp;분리연쇄법에서는 버켓 하나에 여러 원소를 저장할 수 있다. 따라서 $\alpha >1$ 인 경우에도 동작할 수 있다. 예를 들어 배열 크기가 10이고 원소가 15개라면 $\alpha =\frac{15}{10}=1.5$ 이다.<br/>

&ensp;하지만 적재율이 지나치게 높아지면 리스트의 길이가 길어져 비효율적일 수 있다. 좋은 해시함수로 키가 균일하게 분포한다면, 각 버켓의 평균 원소 수는 약 $\alpha$ 이다. 분리연쇄법의 기대 탐색 시간은 일반적으로 다음과 같이 표현한다.<br/>

$$\Theta(1+\alpha)$$

&ensp;따라서 적재율을 일정한 상수 이하로 유지하면 기대시간을 $O(1)$ 로 만들 수 있다.<br/>

&ensp;개방주소법의 적재율<br/>
&ensp;개방주소법에서는 모든 원소를 버켓 배열 내부에 저장한다. 따라서 다음 조건을 만족해야 한다.<br/>

$$n\le M$$

&ensp;즉 $\alpha\le1$ 이다.<br/>
&ensp;하지만 실제로는 배열을 완전히 채우기 전에 크기를 늘리는 것이 좋다. 형조사법과 2차 조사법의 경우 적재율이 0.5보다 커지면 군집화의 영향이 커질 수 있다. 적재율이 낮을수록 빈 칸을 찾기 쉬우므로 기대 조사 횟수를 줄일 수 있다.<br/>

&ensp;재해싱 Rehashing<br/>
&ensp;재해싱(Rehashing)은 해시테이블의 크기를 변경하고, 기존 원소들의 해시값을 다시 계산하여 새로운 테이블에 저장하는 과정이다. 데이터가 계속 삽입되면 원소 수 n이 증가한다. 배열 크기 M이 그대로라면 적재율도 증가한다.<br/>

$$\alpha=\frac{n}{M}$$

&ensp;적재율이 높아지면 충돌이나 조사 횟수가 증가할 수 있다. 따라서 더 큰 배열을 만들어 기존 원소들을 다시 배치하는 과정이 필요하다.<br/>

&ensp;재해싱이 필요한 경우<br/>
1. 적재율이 설정한 한계를 초과했을 때
2. 삽입에 실패했을 때
3. 비활성화된 셀이 많아져 성능이 저하되었을 때

&ensp;재해싱의 단계<br/>
&ensp;① 버켓 배열의 크기를 증가시킨다.<br/>
&ensp;기존 배열 크기가 M = 13이라면 대략 두 배 크기의 소수인 29로 증가시킬 수 있다.<br/>

$$M'=29$$

&ensp;② 새로운 배열 크기에 맞게 압축맵을 수정한다.<br/>
&ensp;기존 해시함수가 $h(k)=k\bmod 13$ 이었다면 새로운 해시함수는 $h_{\text{new}}(k)=k\bmod 29$ 가 된다.<br/>

&ensp;③ 기존 원소들의 해시값을 다시 계산한다.<br/>
&ensp;예를 들어 키 25의 기존 해시값은 $25\bmod 13=12$ 였지만 새 해시값은 $25\bmod 29=25$ 가 된다. 따라서 기존 원소의 저장 위치가 달라질 수 있다.<br/>

&ensp;④ 모든 활성 원소를 새 테이블에 다시 삽입한다.<br/>
&ensp;기존 원소를 순회하면서 새로운 해시함수로 위치를 계산한 뒤 새 테이블에 삽입한다. 비활성화된 셀은 다시 삽입하지 않는다.<br/>

&ensp;재해싱의 시간복잡도<br/>
&ensp;기존 원소가 n개라면 모든 원소를 다시 삽입해야 하므로 한 번의 재해싱에 일반적으로 $O(n)$ 시간이 필요하다. 새 배열을 초기화하는 비용까지 포함하면 $O(M'+n)$ 이다.<br/>
&ensp;하지만 재해싱은 매 삽입마다 수행하는 작업이 아니다. 테이블 크기를 기하급수적으로 증가시키고 좋은 해시 분포를 유지하면, 여러 삽입에 걸친 분할상환 기대시간은 $O(1)$ 이 될 수 있다.<br/>

&ensp;해싱의 성능<br/>

&ensp;해시테이블의 시간복잡도<br/>
&ensp;해시테이블의 탐색·삽입·삭제는 좋은 해시함수와 적절한 적재율을 유지할 때 기대 $O(1)$ 시간에 수행할 수 있다. 하지만 최악의 경우에는 많은 원소가 같은 버켓에 매핑되거나 긴 조사열이 만들어질 수 있다.<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/9주차/9-28.png" width="600"></p>

&ensp;최악시간은 배열 크기를 원소 수에 비례하도록 관리하는 일반적인 조건의 표현이다. 개방주소법에서는 최대 M개의 버켓을 조사할 수 있으며, 재해싱이 필요한 삽입은 추가 비용이 발생한다.<br/>

&ensp;최악시간이 발생하는 이유<br/>
&ensp;모든 키가 같은 해시값을 가진다고 가정하자. 분리연쇄법에서는 모든 원소가 하나의 리스트에 저장될 수 있다. 이 경우 원하는 원소를 찾기 위해 최대 n개의 원소를 확인해야 할 수 있다. 따라서 시간복잡도는 $O(n)$ 이 된다. 선형조사법에서도 군집화가 심하게 발생하면 많은 버켓을 조사해야 할 수 있다.<br/>

&ensp;적재율과 기대 조사 횟수<br/>
$$\frac{1}{1 - \alpha }$$

&ensp;이 식은 무작위 조사에 관한 가정 아래 빈 칸을 찾는 데 필요한 예상 조사 횟수의 척도로 사용할 수 있다.<br/>
&ensp;적재율이 높아질수록 예상 조사 횟수가 크게 증가한다. 이 식을 모든 충돌 해결 방법의 정확한 평균 조사 횟수로 사용해서는 안 된다. 특시 선형조사법은 군집화의 영향을 별도로 받는다.<br/>
