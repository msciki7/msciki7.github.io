# 분할통치법(Divide-and-Conquer)

&ensp;분할통치법의 개념<br/>
&ensp;분할통치법은 하나의 큰 문제를 작은 문제들로 나누어 해결한 뒤 그 결과를 다시 합쳐 전체 문제를 해결하는 **알고리즘 설계 기법** 이다. <br/>

&ensp;분할(Divide): 입력 데이터 L을 서로 분리된 부분집합 L1, L2, ...로 나눈다.<br/>
&ensp;재귀(Recur): 나누어진 각 부문제 L1, L2, ...를 다시 같은 방법으로 해결한다.<br/>
&ensp;통치(Conquer): 각 부문제에서 얻은 해결 결과를 합쳐 원래 문제 L의 답을 만든다.<br/>

> 큰 문제 → 작은 문제로 나눔 → 각각 해결 → 결과를 합침

&ensp;재귀의 베이스 케이스(Base Case)<br/>
&ensp;분할통치법은 계속 문제를 나누기 때문에 언제 재귀를 멈출 것인지가 반드시 필요하다.<br/>

&ensp;상수 크기의 부문제는 재귀의 베이스 케이스이다.<br/>
&ensp;합병 정렬에서는 리스트 크기가 1이면 이미 정렬되어 있다고 볼 수 있으므로 더 이상 나누지 않는다.<br/>

&ensp;예: `[6, 1, 8, 2]` <br/>
&ensp;계속 나누면<br/>
```
[6, 1] [8, 2]

[6] [1] [8] [2]
```

&ensp;[6], [1], [8], [2]처럼 원소가 하나인 리스트가 베이스 케이스다.<br/>

&ensp;분할통치법을 사용하는 알고리즘<br/>
* 합병 정렬(Merge Sort)
* 퀵 정렬(Quick Sort)

# 합병 정렬(Merge Sort)

&ensp;합병 정렬의 기본 개념<br/>
&ensp;합병 정렬은 분할통치법에 기반한 정렬 알고리즘이다.<br/>

&ensp;핵심 아이디어<br/>
```
무순 리스트
↓
반으로 계속 나눈다
↓
원소 하나까지 나눈다
↓
정렬하면서 다시 합친다
↓
정렬 완료
```

&ensp;예를 들어 `6 1 8 2` 가 있으면 `6 1 | 8 2` 로 나누고 `6 | 1 | 8 | 2` 까지 나눈다.<br/>

&ensp;그 뒤 `6 + 1 → 1 6, 8 + 2 → 2 8` 로 정렬하면서 합친 후 `1 6 + 2 8 → 1 2 6 8` 로 만든다.<br/>

&ensp;합병 정렬의 특징<br/>
&ensp;합병 정렬은 힙 정렬처럼<br/>
* 비교에 기반한 정렬
* O(n log n) 시간에 수행

&ensp;된다.<br/>

&ensp;그러나 힙 정렬과 달리 외부의 우선순위 큐를 사용하지 않고 데이터를 **순차적인 방식으로 접근** 한다.<br/>

# 합병 정렬의 3단계

&ensp;n개의 원소를 가진 리스트 L에 합병 정렬을 적용하면 다음 세 단계를 거친다.<br/>

&ensp;분할 Divide<br/>
&ensp;무순 리스트 L을 각각 약 n/2개의 원소를 가진 L1, L2 두 리스트로 나눈다.<br/>
&ensp;예<br/>
```
L = [6, 1, 8, 2, 3, 5, 7, 4]

L1 = [6, 1, 8, 2]
L2 = [3, 5, 7, 4]
```

&ensp;재귀 Recur<br/>
&ensp;두 리스트를 각각 다시 합병 정렬한다.<br/>
* mergeSort(L1)
* mergeSort(L2) 

```
[6 1 8 2]
→ [6 1] [8 2]
→ [6] [1] [8] [2]
```

&ensp;처럼 계속 나누어진다.<br/>

&ensp;통치 Conquer<br/>
&ensp;정렬된 두 리스트를 하나의 정렬된 리스트로 합친다.<br/>
&ensp;예<br/>
* L1 = [1, 6]
* L2 = [2, 8]

&ensp;이라면 `[1, 2, 6, 8]` 로 합친다.<br/>

&ensp;mergeSort 전체 실행 흐름<br/>
```
mergeSort(L)
      │
      ├─ 리스트 크기 > 1 ?
      │
      ├─ L1, L2로 분할
      │
      ├─ mergeSort(L1)
      │      └─ 계속 분할
      │
      ├─ mergeSort(L2)
      │      └─ 계속 분할
      │
      └─ merge(L1, L2)
```

> 먼저 완전히 나누고, 재귀 호출이 돌아오면서 합친다.

&ensp;merge 함수의 시간복잡도<br/>
&ensp;각각 n/2개의 원소를 가지는 두 정렬 리스트를 합병하는 데 `O(n)` 시간이 걸린다. 왜냐하면 합병 과정에서 각 원소는 결국 한 번씩 결과 리스트로 이동하기 때문이다. <br/>
* L1 원소 수 = n/2
* L2 원소 수 = n/2

&ensp;전체 원소: n/2 + n/2 = n<br/>
&ensp;**merge = O(n)** <br/>

# 합병 정렬 시간복잡도 분석

&ensp;트리의 높이<br/>
&ensp;매번 리스트를 절반으로 나눈다.<br/>
```
n
↓
n/2
↓
n/4
↓
n/8
↓
...
↓
1
```

&ensp;따라서 합병 정렬 트리의 높이는 `O(log n)` 이다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/3주차/3-14.png" width="600"></p>

&ensp;각 레벨의 작업량<br/>
&ensp;트리의 한 레벨 전체에서 처리되는 원소의 개수를 생각하면 항상 n개다.<br/>

&ensp;전체 시간복잡도<br/>
&ensp;한 레벨의 비용: O(n)<br/>
&ensp;레벨 수: O(log n)<br/>
&ensp;따라서 `O(n) × O(log n)` <br/>
&ensp;=> `O(n log n)` <br/>

&ensp;점화식을 이용한 분석<br/>
* T(n) = c                  (n < 2)
* T(n) = 2T(n/2) + O(n)     (n ≥ 2)

&ensp;2T(n/2)<br/>
&ensp;리스트를 절반씩 두 개로 나누기 때문에 L1 → T(n/2), L2 → T(n/2). => 2T(n/2)가 된다.<br/>

&ensp;O(n)<br/>
&ensp;두 정렬 리스트를 합치는 merge() 단계의 비용이다.<br/>
&ensp;`T(n) = 2T(n/2) + O(n)` <br/>
