# 분할통치법 Divide-and-Conquer

&ensp;**분할통치법(divide-and-conquer)**은 일반적인 **알고리즘 설계 기법(algorithm design paradigm)** 중 하나이다.<br/>
&ensp;문제를 한 번에 해결하는 것이 아니라, 큰 문제를 작은 문제로 나누고 각각 해결한 뒤 결과를 합치는 방식이다.<br/>

&ensp;분할통치법의 3단계<br/>
&ensp;분할 Divide: 입력 데이터 L을 둘 이상의 서로 분리된 부분집합 $L_1, L_2, ...$ 으로  나눈다.<br/>
&ensp;재귀 Recur: 나누어진 각각의 부분문제 $L_1, L_2, ....$ 를 **재귀적으로 해결** 한다.<br/>
&ensp;통치 Conquer: 부분문제들의 해결 결과를 합쳐서 원래 문제 L을 해결한다.<br/>

> 큰 문제 → 작은 문제들로 분할 → 각각 해결 → 결과를 다시 결합

&ensp;베이스 케이스<br/>
&ensp;재귀적으로 계속 문제를 나누다 보면 더 이상 나눌 필요가 없는 작은 문제가 나온다. 이를 **재귀의 베이스 케이스(base case)**라고 한다. 상수 크기의 부분문제가 베이스 케이스이다. 합병 정렬에서는 실제로 리스트의 원소 개수가 1개가 되었을 때 재귀 분할이 끝난다.<br>

&ensp;분할통치법을 사용하는 알고리즘<br/>
* 합병 정렬 `merge-sort`
* 퀵 정렬 `quick-sort`   

# 합병 정렬 Merge Sort

&ensp;**합병 정렬(merge-sort)**은 **분할통치법에 기초한 정렬 알고리즘** 이다.<br/>
&ensp;힙 정렬과 마찬가지로 비교에 기초한 정렬이고 실행시간은 $O(n \log n)$ 이다.<br/>

&ensp;힙 정렬과의 차이<br/>
&ensp;합병 정렬은 힙 정렬과 달리<br/>
* 외부의 우선순위 큐를 사용하지 않는다.
* 데이터를 순차적인 방식으로 접근한다.
* 따라서 디스크의 데이터를 정렬하기에 적당하다.

---

&ensp;합병 정렬의 3단계<br/>
&ensp;n개의 원소를 가진 입력 리스트 L이 있다고 하자. 합병 정렬은 세 단계로 수행된다.<br/>

&ensp;1. 분할 Divide<br/>
&ensp;무순 리스트 L을 L1, L2 두 개의 부리스트로 나눈다.<br/>
&ensp;각각 대략 n/2 개의 원소를 가진다.<br/>

&ensp;2. 재귀 Recur<br/>
&ensp;L1, L2를 각각 재귀적으로 합병 정렬한다.<br/>
* mergeSort(L1)
* mergeSort(L2)

&ensp;3. 통치 Conquer<br/>
&ensp;정렬이 완료된 L1, L2를 하나의 정렬된 리스트로 합친다.<br/>
&ensp;`L ← merge(L1, L2)` <br/>

&ensp;합병 정렬의 핵심 흐름은<br/>
```
분할
   ↓
왼쪽 정렬
   ↓
오른쪽 정렬
   ↓
합병
```

&ensp;mergeSort 의사코드<br/>
```alg
Alg mergeSort(L)

input list L with n elements
output sorted list L

1. if (L.size() > 1)   // 리스트 원소 개수는 1보다 클 때만 분할
       L1, L2 ← partition(L, n/2)   // 현재 리스트를 절반씩 두 리스트로 나눈다.
       mergeSort(L1)   // 왼쪽 리스트를 다시 합병 정렬
       mergeSort(L2)   // 오른쪽 리스트를 다시 합병 정렬
       L ← merge(L1, L2)  // 정렬된 두 리스트를 하나의 정렬된 리스트로 합친다.

2. return
```

&ensp;합병 정렬은 **분할할 때 정렬하는 것이 아니다.** 계속 나누어서 크기 1까지 내려간 뒤 **위로 올라오면서 합볍할 때 정렬된다.** <br/>

---

&ensp;두 정렬 리스트 합병 Merge<br/>
&ensp;합병 정렬에서 통치 단계에 해당하는 부분이다. 이미 정렬되어 있는 두 리스트 L1, L2를 하나의 정렬된 리스트 L로 만든다. 각각 n/2개의 원소를 가진 이중연결리스트 두 개를 합병할 때 O(n) 시간이 걸린다.<br/>

```alg
Alg merge(L1, L2)

input sorted list L1 and L2 with n/2 elements each
output sorted list of L1 ∪ L2

1. L ← empty list

2. while (!L1.isEmpty() & !L2.isEmpty())
       if (L1.get(1) ≤ L2.get(1))   // 두 리스트의 첫 번째 원소를 비교
           L.addLast(L1.removeFirst())   // 작은 값을 결과 리스트 L로 옮긴다.
       else
           L.addLast(L2.removeFirst())

3. while (!L1.isEmpty())
       L.addLast(L1.removeFirst())

4. while (!L2.isEmpty())
       L.addLast(L2.removeFirst())

5. return L
```

# 합병 정렬 시간복잡도

&ensp;1. 트리의 높이<br/>
&ensp;매번 리스트를 절반으로 나눈다.<br/>
&ensp;합병 정렬 트리의 높이는 $O(\log n)$ 이다.<br/>

&ensp;2. 각 레벨의 작업량<br/>
* 리스트 개수: $2^i$
* 각 리스트 크기: $\frac{n}{2^i}$

&ensp;따라서 한 레벨의 전체 작업량은 $2^i \times \frac{n}{2^i}$ <br/>
&ensp;즉 n이다.<br/>
&ensp;따라서 각 레벨에서 $O(n)$ 의 작업을 한다.<br/>

&ensp;전체 시간복잡도<br/>
* 레벨 수: $O(\log n)$
* 각 레벨의 작업량: $O(n)$

&ensp;따라서 $O(n) \times O(\log n)$ <br/>

&ensp;즉 $O(n \log n)$ 이다.<br/>

&ensp;점화식<br/>
&ensp;합병 정렬은 점화식으로도 표현할 수 있다.<br/>
&ensp;n < 2<br/>
&ensp;`T(n) = c` <br/>
&ensp;즉 원소가 1개면 상수 시간.<br/>

&ensp;n ≥ 2<br/>
&ensp;`T(n) = 2T(n/2) + O(n)` <br/>

&ensp;왜냐하면 `2T(n/2)` 는 mergeSort(L1), mergeSort(L2) 두 번의 재귀호출이고 O(n)은 두 정렬 리스트를 합병하는 데 드는 시간이다.<br/>
&ensp;따라서 $T(n)=O(n\log n)$ 이다.<br/>
