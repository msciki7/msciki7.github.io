# 퀵 정렬

&ensp;퀵 정렬은 **분할통치법(Divide and Conquer)**을 사용하는 정렬 알고리즘이다. 하나의 기준원소 pivot을 선택한 뒤, 원소들을 pivot보다 작은 것, 같은 것, 큰 것으로 분리하고 작은 부분과 큰 부분을 다시 재귀적으로 정렬한다.<br/>
> pivot 선택 → 분할 → LT와 GT 재귀 정렬 → LT + EQ + GT 결합

* LT : pivot보다 작은 원소
* EQ : pivot과 같은 원소
* GT : pivot보다 큰 원소

&ensp;일반 퀵 정렬 의사코드<br/>

```alg
Alg quickSort(L)
 input list L with n elements
 output sorted list L

1. if (L.size() > 1)
       k ← a position in L
       LT, EQ, GT ← partition(L, k)
       quickSort(LT)
       quickSort(GT)
       L ← merge(LT, EQ, GT)

2. return
```

&ensp;줄별 의미<br/>
&ensp;`if (L.size() > 1)`<br/>
&ensp;리스트의 원소가 2개 이상일 때만 정렬한다.<br/>
&ensp;원소가 0개, 1개 라면 이미 정렬된 것으로 본다. 즉 이것이 재귀의 베이스 케이스다.<br/>

&ensp;`k ← a position in L` <br/>
&ensp;리스트에서 pivot으로 사용할 원소의 위치 k를 결정한다.<br/>

&ensp;LT, EQ, GT ← partition(L, k)<br/>
&ensp;pivot을 기준으로 리스트를 세 부분으로 나눈다.<br/>
* LT : pivot보다 작은 값
* EQ : pivot과 같은 값
* GT : pivot보다 큰 값

&ensp;예를 들어<br/>
```
L = [6, 1, 8, 2, 3, 5, 7, 4]
pivot = 7
```

&ensp;이면<br/>
* LT = [6, 1, 2, 3, 5, 4]
* EQ = [7]
* GT = [8]

&ensp;`quickSort(LT)`: pivot보다 작은 값들에 대해 다시 퀵 정렬한다.<br/>
&ensp;`quickSort(GT)`: pivot보다 큰 값들에 대해서도 다시 퀵 정렬한다. 여기서 중요한 점은 EQ는 다시 정렬하지 않는다. pivot과 같은 값들은 이미 pivot 위치에 들어가기 때문이다.<br/>

&ensp;`L ← merge(LT, EQ, GT)` <br/>
&ensp;정렬이 끝난 세 리스트를 `LT + EQ + GT` 순으로 합친다. 그래서 최종 정렬 결과가 만들어진다.<br/>

---

&ensp;리스트 분할 partition<br/>

```alg
Alg partition(L, k)

1. p ← L.get(k)

2. LT, EQ, GT ← empty list

3. while (!L.isEmpty())
       e ← L.removeFirst()

       if (e < p)
           LT.addLast(e)

       elseif (e = p)
           EQ.addLast(e)

       else
           GT.addLast(e)

4. return LT, EQ, GT
```

&ensp;실행 과정<br/>
&ensp;예<br/>
```
L = [6, 1, 8, 2, 3, 5, 7, 4]
pivot = 7
```

&ensp;처음에는<br/>
* LT = []
* EQ = []
* GT = []

&ensp;하나씩 꺼내면서 비교한다.<br/>

| 꺼낸 값 | pivot=7과 비교 | 결과 |
|---|---|---|
| 6 | 6 < 7 | LT |
| 1 | 1 < 7 | LT |
| 8 | 8 > 7 | GT |
| 2 | 2 < 7 | LT |
| 3 | 3 < 7 | LT |
| 5 | 5 < 7 | LT |
| 7 | 7 = 7 | EQ |
| 4 | 4 < 7 | LT |

&ensp;결과는<br/>
* LT = [6,1,2,3,5,4]
* EQ = [7]
* GT = [8]

---

&ensp;partition의 시간복잡도<br/>
&ensp;partition에서는 리스트의 모든 원소를 한 번씩 확인한다. 그리고 리스트 앞에서 삭제하거나 뒤에 삽입하는 작업은 O(1)이다. 따라서 전체 원소 n개를 처리하면 `O(n)` 이다.<br/>

> 퀵 정렬 전체가 항상 O(n)은 아니다.

&ensp;partition 한 번만 O(n)이다.<br/>
&ensp;재귀 호출이 반복되기 때문에 전체 수행 시간은 이후에 별도로 계산해야 한다.<br/>

---

&ensp;Pivot 선택<br/>
&ensp;퀵 정렬에서는 어떤 값을 pivot으로 고르느냐가 매우 중요하다.<br/>

&ensp;결정적이며 쉬운 방법<br/>
* 맨 앞 원소
* 맨 뒤 원소
* 중간 원중

&ensp;결정적이며 조금 복잡한 방법<br/>
&ensp;여러 원소 중 중앙값을 선택한다.<br/>
&ensp;예: 맨 앞 / 중간 / 맨 뒤의 중앙값<br/>

&ensp;또는 0/4, 1/4, 2/4, 3/4, 4/4 위치 원소의 중앙값 등이 있다.<br/>

&ensp;무작위 방법<br/>
&ensp;`리스트에서 임의의 원소 선택` 이다.<br/>

&ensp;Pivot 선택이 중요한 이유<br/>
&ensp;pivot 선택은 두 가지에 영향을 준다.<br/>
```
분할 결과
↓
퀵 정렬 수행 성능
```

&ensp;좋은 pivot을 선택하면 리스트가 비슷한 크기로 나뉘고, 좋지 않은 pivot을 선택하면 한쪽에 원소가 몰린다.<br/>

# 퀵 정렬 최악 실행시간

&ensp;퀵 정렬의 최악의 경우는 pivot이 계속 최소값 또는 최대값으로 선택되는 경우다. 예를 들어 이미 정렬된 배열에서 계속 마지막 값을 pivot으로 잡는 상황을 생각할 수 있다.<br/>
&ensp;분할 결과가 매번 `크기 n-1 / pivot / 크기 0` 이 된다.<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/4주차/4-8.png" width="600"></p>

&ensp;전체 수행량은 `n + (n-1) + (n-2) + ... + 2 + 1` 이고 이는 `n(n+1)/2` 에 비례한다. 따라서 `O(n²)` 이다.<br/>

> pivot이 계속 최소/최대 → 한쪽만 계속 커짐 → 트리가 한쪽으로 치우침 → O(n²)

&ensp;기대 실행시간<br/>

&ensp;좋은 호출<br/>
&ensp;크기 s의 리스트에서<br/>
* LT의 크기 < (3/4)s
* GT의 크기 < (3/4)s

&ensp;둘 다 만족하는 경우<br/>
&ensp;한쪽으로 원소가 너무 몰리지 않은 분할이다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/4주차/4-9.png" width="600"></p>

&ensp;나쁜 호출<br/>
&ensp;LT와 GT 중 하나의 크기가 (3/4)s보다 큰 경우이다. 즉 한 쪽으로 많은 원소가 몰리는 분할이다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/4주차/4-10.png" width="600"></p>

# 무작위 퀵 정렬

&ensp;일반적인 결정적 퀵 정렬에서는 특정 위치의 원소, 예를 들어 마지막 원소를 pivot으로 선택했다. 무작위 퀵 정렬에서는 **입력 리스트의 무작위 원소를 pivot으로 선택한다.** <br/>

&ensp;핵심 차이는 pivot 선택 방식뿐이다.<br/>
* 일반 퀵 정렬 → 정해진 위치의 pivot
* 무작위 퀵 정렬 → random pivot

&ensp;무작위 퀵 정렬 기대 실행시간<br/>
* 좋은 호출이 나올 확률 = 1/2

&ensp;좋은 호출이 반복되면 리스트의 크기가 n → (3/4)n → (3/4)²n → ... 식으로 줄어든다.<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/4주차/4-11.png" width="600"></p>

&ensp;따라서 퀵 정렬 트리의 기대 높이는 `O(log n)`이 된다. 그리고 한 깊이에서 처리하는 전체 원소 수는 `O(n)` 이다. 그래서 **한 레벨의 작업량 × 트리 높이** 로 계산하면 **O(n) × O(log n) 이므로 O(n log n)** 이다.<br/>

* 최악 실행시간       O(n²)
* 기대 실행시간       O(n log n)

# 제자리 퀵 정렬 In-Place Quick Sort 

&ensp;제자리 퀵 정렬에서는 별도의 리스트를 만드는 대신 원래 배열 안에서 원소 위치를 바꾼다. 즉 `replace`, 실제로는 **원소 교환(swap)**을 사용한다.<br/>

&ensp;제자리 퀵 정렬 의사코드<br/>
```alg
Alg inPlaceQuickSort(L, l, r)

1. if (l ≥ r)
       return

2. k ← a position between l and r

3. a, b ← inPlacePartition(L, l, r, k)

4. inPlaceQuickSort(L, l, a-1)

5. inPlaceQuickSort(L, b+1, r)
```

&ensp;의미<br/>
* `l`: 현재 정렬 구간의 시작
* `r`: 현재 정렬 구간의 끝

&ensp;`if (l ≥ r)`<br/>
&ensp;정렬할 원소가 0개 또는 1개이므로 종료한다.<br/>

&ensp;`k ← a position between l and r`<br/>
&ensp;l ~ r 사이에서 pivot 위치를 선택한다.<br/>

&ensp;`inPlacePartition`<br/>
&ensp;현재 배열 안에서 직접 원소를 움직여 LT | EQ | GT 형태로 만든다.<br/>

&ensp;재귀 호출<br/>
&ensp;pivot보다 작은 영역 l ~ a-1 과 큰 영역 b+1 ~ r 만 다시 정렬한다.<br/>

# 제자리 분할 inPlacePartition

```alg
Alg inPlacePartition(A, l, r, k)

1. p ← A[k]

2. A[k] ↔ A[r]

3. i ← l

4. j ← r - 1

5. while (i ≤ j)

       while (i ≤ j & A[i] ≤ p)
           i ← i + 1

       while (j ≥ i & A[j] ≥ p)
           j ← j - 1

       if (i < j)
           A[i] ↔ A[j]

6. A[i] ↔ A[r]

7. return i
```

&ensp;배열의 모든 원소가 서로 다르다고 가정한다.<br/>

&ensp;의미<br/>
&ensp;`p ← A[k]` <br/>
&ensp;pivot 값을 저장한다.<br/>

&ensp;`A[k] ↔ A[r]`<br/>
&ensp;pivot을 배열의 맨 오른쪽으로 잠시 이동시킨다.<br/>

&ensp;`i ← l` <br/>
&ensp;왼쪽에서 오른쪽으로 검사할 포인터<br/>

&ensp;`j ← r - 1` <br/>
&ensp;오른쪽에서 왼쪽으로 검사할 포인터. r에는 pivot이 숨어 있으므로 r-1 부터 시작한다.<br/>

&ensp;i의 역할<br/>
```
while (i ≤ j & A[i] ≤ p)
    i ← i + 1
```

&ensp;pivot보다 작은 값들은 그대로 둔다. i는 **왼쪽에 있으면 안 되는 큰 값을 찾는다.** <br/>

&ensp;j의 역할<br/>
```
while (j ≥ i & A[j] ≥ p)
    j ← j - 1
```

&ensp;pivot보다 큰 값들은 그대로 둔다. j는 **오른쪽에 있으면 안 되는 작은 값을 찾는다.** <br/>

&ensp;잘못 위치한 두 원소 교환<br/>
```
if (i < j)
    A[i] ↔ A[j]
```

&ensp;`왼쪽에서 발견한 큰 값 ↔ 오른쪽에서 발견한 작은 값` 을 서로 바꾼다.<br/>

&ensp;i와 j가 만난 이후<br/>
&ensp;반복하다가 i > j 가 되면 partition이 거의 완료된 것이다. 마지막으로 A[i] ↔ A[r] 을 한다. A[r]에 숨겨둔 pivot을 현재 i 위치로 이동시킨다. 그래서 최종적으로 `LT | pivot | GT` 가 된다. 그리고 `return i` 를 통해 pivot의 최종 위치를 반환한다.<br/>

&ensp;제자리 분할 실행 예제<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/4주차/4-12.png" width="600"></p>

<p align="center"><img src="/assets/img/알고리즘 및 실습/4주차/4-13.png" width="600"></p>

&ensp;**i와 j가 움직이며 잘못 배치된 원소를 교환하는 과정이다.** <br/>

* i : 왼쪽 → 오른쪽(pivot보다 큰 값 탐색)
* j : 오른쪽 → 왼쪽(pivot보다 작은 값 탐색)

&ensp;찾으면 A[i] ↔ A[j]. 그리고 포인터가 교차하면 pivot ↔ A[i] 이다.<br/>

# 합병 정렬 vs 퀵 정렬

<p align="center"><img src="/assets/img/알고리즘 및 실습/4주차/4-14.png" width="600"></p>

&ensp;합병 정렬<br/>
* 분할이 쉽고 합병이 어렵다.
* 재귀적으로 가장 작은 문제까지 내려간 뒤 합치면서 결과를 만든다. (= 작은 것 → 큰 것)

&ensp;퀵 정렬<br/>
* 분할이 어렵고 합병이 쉽다.
* 처음부터 큰 배열을 pivot 기준으로 계속 작게 나눈다.(= 큰 것 → 작은 것)
