# 1. 우선순위 큐 (Priority Queue)

&ensp;1-1. 우선순위 큐란?<br/>
&ensp;일반적인 Queue는 먼저 들어온 원소가 먼저 나가는 FIFO 구조지만 Priority Queue는 삽입 순서가 아니라 key의 우선순위에 따라 원소가 나온다. 각 원소는 (key, element) 형태의 쌍으로 생각할 수 있다. <br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/1주차/1-1.png" width="600"></p>

&ensp;강의자료에서는 작은 key가 더 높은 우선순위를 갖는 minimum-oriented priority queue를 사용한다.<br/>

&ensp;예를 들어<br/>

```
(5, A)
(2, B)
(8, C)
```

&ensp;가 들어 있다면 removeMin()의 결과는 `(2, B)` 이다. <br/>

> Priority Queue = 가장 작은 key를 빠르게 찾아내기 위한 ADT

# 2. Priority Queue ADT

&ensp;핵심 연산<br/>
&ensp;`insertItem(k, e)` <br/>
&ensp;key가 `k` 이고 element가 `e` 인 항목을 삽입한다.<br/>
&ensp;`insertItem(3, A)` 라면 `(3, A)` 라는 entry가 우선순위 큐에 들어간다.<br/>

&ensp;`removeMin()` <br/>
&ensp;Priority Queue에서 가장 작은 key를 가진 원소를 삭제하면서 반환한다.<br/>
&ensp;예<br/>
&ensp;`[(5,A), (2,B), (7,C)]` 에서 `removeMin()` 을 호출하면 (2, B) 가 반환되고 큐에는 `[(5,A), (7,C)]` 가 남는다.<br/>

## 접근(accessor) 연산

&ensp;`minElement()` <br/>
&ensp;최소 key를 가진 원소의 element를 반환한다.<br/>

&ensp;`minKey()` <br/>
&ensp;최소 key 자체를 반환한다.<br/>
&ensp;중요한 점은 둘 다 보통 삭제하지 않는다는 것이다.<br/>

## 일반 연산
&ensp;`size()` <br/>
&ensp;현재 우선순위 큐 안에 있는 항목 개수<br/>

&ensp;`isEmpty()` <br/>
&ensp;큐가 비었는지 확인<br/>

## 예외

&ensp;`emptyQueueException`<br/>
&ensp;비어 있는 큐에 대해 삭제나 원소 접근을 시도할 경우 발령<br/>

&ensp;`fullQueueException()` <br/>
&ensp;만원 큐에 대해 삽입을 시도할 경우 발령<br/>

# 3. Priority Queue를 이용한 정렬
&ensp;어떤 리스트 L 이 있을 때 Priority Queue를 이용하면 간단하게 정렬할 수 있다. 강의 자료의 PQ-Sort 흐름은 다음과 같다.<br/>

1. 빈 Priority Queue P 생성
2. L의 모든 원소를 P에 삽입
3. P가 빌 때까지 `removeMin()` 결과를 다시 L 뒤쪽에 넣기

&ensp;pseudocode<br/>
```
Alg PQ-Sort(L)
    intput list L
    output sorted list L

    1. P <- empty priority queue
    2. while(!L.isEmpty())
        e <- L.removeFirst()
        P.insertItem(e)
    3. while(!P.isEmpty())
        e <- P.removeMin()
        L.addLast(e)
    4. return
```

&ensp;`L = [7, 2, 5, 1]` 이라면 먼저 `P = {7,2,5,1}` 을 만든다. 그 다음 계속 `removeMin()`을 한다.<br/>

```
1
2
5
7
```

&ensp;따라서 최종적으로 `L = [1,2,5,7]` 이 된다.<br/>

> 최소값을 계속 하나씩 꺼내면 자연스럽게 정렬된다.

&ensp;그런데 여기서 진짜 알고리즘 문제가 생긴다. -> **Priority Queue를 어떻게 구현할 것인가?** <br/>

# 4. Priority Queue 구현 ① 무순리스트(Unsorted List)

&ensp;첫 번째 방법은 원소를 정렬하지 않고 그냥 리스트에 저장하는 것이다.<br/>
&ensp;예: `[7, 2, 5, 1]` <br/>

&ensp;`insertItem()` <br/>
&ensp;정렬할 필요가 없기 때문에 아무 위치에나 넣으면 된다.<br/>
&ensp;따라서 **O(1)** <br/>

&ensp;`removeMin()` <br/>
&ensp;문제는 최소값을 찾을 때다. `[7, 2, 5, 1]` 에서 최소값 1 을 찾으려면 전체를 확인해야 한다.<br/>
&ensp;따라서 **O(n)** <br/>

&ensp;정리<br/>

| 연산                  |    무순리스트 |
| ------------------- | -------: |
| insertItem          | \(O(1)\) |
| removeMin           | \(O(n)\) |
| minKey / minElement | \(O(n)\) |

> 삽입은 빠르지만 최소값 찾기가 느리다.

# 5. 무순리스트 Priority Queue → Selection Sort

&ensp;이 구조로 PQ-Sort를 수행하면 Selection Sort가 된다. -> Why? Selection Sort 핵심은 "남은 원소 중 최소값을 찾아 하나씩 정렬 위치에 배치" 하는 것이다. 무순리스트 Priority Queue에서도 `removeMin()` 을 할 때마다 리스트 전체에서 최소값을 찾아야 한다. 그래서 사실상 같은 동작을 한다.<br/>

&ensp;시간복잡도<br/>
&ensp;삽입 단계<br/>
&ensp;`insertItem()`은 **O(1)** 이고 이를 n 번 한다. -> **O(n)**<br/>

&ensp;삭제 단계<br/>
* 첫 번째 removeMin: O(n) <br/>
* 두 번째: O(n−1)<br/>
* 세 번째: O(n−2)

&ensp;....<br/>
&ensp;따라서 n + (n−1) + (n−2) + ⋯ + 1 이고 $\frac{n(n-1)}{2}$ 이므로 $O(n^2)$ 이다. <br/>
&ensp;따라서 Selection Sort 전체 시간복잡도는 $O(n^2)$ 이다.<br/>

# 6. Priority Queue 구현 ② 순서리스트(Sorted List)

&ensp;이번에는 Priority Queue 내부를 항상 정렬된 상태로 유지한다.<br/>
&ensp;예: `[1, 2, 5, 7]` <br/>

&ensp;`insertItem()`<br/>
&ensp;새로운 원소를 넣을 때 올바른 위치를 찾아야 한다. 예를 들어 `[1, 3, 7, 10]` 에 5를 넣으면 `[1, 3, 5, 7, 10]` 이 되어야 한다. 즉 삽입 위치 탐색 + 원소 이동이 필요한다. 따라서 **O(n)** <br/>

&ensp;`removeMin()` <br/>
&ensp;최소값이 항상 리스트의 처음에 있다. 따라서 바로 가져오면 된다. 따라서 바로 가져오면 된다. -> **O(1)** <br/>

&ensp;정리<br/>

| 연산                  |    순서리스트 |
| ------------------- | -------: |
| insertItem          | \(O(n)\) |
| removeMin           | \(O(1)\) |
| minKey / minElement | \(O(1)\) |

> 삽입은 느리지만 최소값 접근은 빠르다.

# 7. 순서리스트 Priority Queue → Insertion Sort

&ensp;순서리스트를 사용하여 PQ-Sort를 구현하면 Insertion Sort가 된다. Insertion Sort의 핵심은 **새로운 원소를 이미 정렬된 부분의 적절한 위치에 삽입** 하는 것이다.<br/>

&ensp;예: `5` <br/>
* 정렬된 상태: `[5]`
* 다음 `2` 삽입: `[2,5]`
* 다음 `7` 삽입: `[2,5,7]`
* 다음 `3` 삽입: `[2,3,5,7]`

&ensp;Priority Queue의 insertItem()이 정확히 이 일을 하고 있다.<br/>

# 7. Insertion Sort 시간복잡도

&ensp;각 삽입마다 최악의 경우 이미 들어 있는 모든 원소를 이동해야 한다.<br/>
* 첫 번째 원소: `O(1)`
* 두 번째: `O(1)`
* 세 번째: `O(2)``

&ensp;...<br/>

&ensp;따라서 1 + 2 + 3 + ⋯ + (n−1) 이고, $O(n^2)$ 이다. 따라서 일반적인 최악의 경우 $O(n^2)$ <br/>

# 8. Selection Sort와 Insertion Sort의 차이

&ensp;여기가 이번 주차에서 특히 중요하다.<br/>
&ensp;둘 다 $O(n^2)$ 이라고 해서 성능이 항상 똑같은 것은 아니다.<br/>

&ensp;Selection Sort<br/>
&ensp;매 반복마다 **남은 부분에서 최소값을 찾는다.** <br/>
&ensp;예: `[5, 3, 4, 1, 2]` <br/>
* 첫 번째 pass: 최솟값 1 탐색
    - 그리고 첫 번째 위치와 swap
* 두 번째 pass: 나머지에서 최솟값 탐색

&ensp;이를 반복한다.<br/>

&ensp;Insertion Sort<br/>
&ensp;반대로 앞부분을 항상 정렬된 상태로 유지한다.<br/>

&ensp;`[5 | 3 4 1 2] -> [3 5 | 4 1 2] -> [3 4 5 | 1 2] -> [1 3 4 5 | 2] -> [1 2 3 4 5]` 이런 구조다.<br/>

## 중요한 차이 — 거의 정렬된 리스트

&ensp;Insertion Sort는 이미 거의 정렬된 입력에서 빠르다.<br/>
&ensp;예: `[1,2,3,4,6,5,7,8]` <br/>
&ensp;각 원소가 거의 자기 자리에 있기 때문에 이동이 별로 없다. 따라서 내부 반복 횟수가 상당히 작아질 수 있다. 하지만 Selection Sort는 이미 정렬되어 있어도 매 pass마다 `최소값 어디 있지?` 하면서 남은 전체 구간을 계속 탐색한다. 따라서 입력 상태에 관계없이 기본적으로 $O(n^2)$ 수준의 비교를  수행한다.<br/>

## swap 관점에서도 차이가 있음

&ensp;Selection Sort는 한 pass에서 최소값을 찾은 뒤 보통 한 번 swap한다. 따라서 swap 횟수는 대략 **O(n)** 이다. 반면 Insertion Sort를 swap 방식으로 구현하면 원소를 한 칸씩 이동시키기 때문에 최악에는 $O(n^2)$ 번 가까운 swap이 발생할 수 있다. 그래서 강의자료에서는 swap 자체가 비싼 상황에서는 Selection Sort가 더 유리할 수 있다고 설명한다.<br/>

## 제자리 정렬(In-place Sorting)

&ensp;기존 PQ-Sort는<br/>
* 입력 리스트 L
* Priority Queue P

&ensp;처럼 별도의 자료구조를 사용한다. 그러면 추가 공간이 필요하다.<br/>

&ensp;In-place 알고리즘<br/>
&ensp;추가적인 큰 자료구조를 만들지 않고, O(1) 정도의 추가 메모리만 사용하여 원래 배열 자체를 변경해서 정렬하는 것을 말한다.<br/>
&ensp;즉 `[5,3,2,4,1]` 이라는 배열이 있다면 별도 배열을 만들지 않고 이 배열 안에서 원소를 교환하여 `[1,2,3,4,5]` 로 만드는 것이다.<br/>

## In-place Selection Sort

&ensp;Selection Sort에서는 배열을 두 부분으로 생각하면 편하다.<br/>
&ensp;`[ 정렬된 부분 | 정렬되지 않은 부분 ]` <br/>
* 처음: `[ | 5 3 1 4 2 ]`
* 최솟값 1 선택 → 앞과 swap: `[ 1 | 3 5 4 2 ]`
* 다시 최소값 2: `[ 1 2 | 5 4 3 ]``

&ensp;...<br/>
&ensp;이렇게 진행한다.<br/>
&ensp;강의자료에서는 별도의 Priority Queue를 만들지 않고 입력 리스트의 일부를 Priority Queue처럼 사용하는 관점으로 설명한다.<br/>

&ensp;In-place Insertion Sort<br/>
&ensp;Insertion Sort 역시 `[ 정렬된 부분 | 미정렬 부분 ]` 으로 나눈다.<br/>
&ensp;예: `[5 | 3 4 1 2]` <br/>
&ensp;3을 정렬된 부분에 삽입: `[3 5 | 4 1 2]`<br/>
&ensp;다음 4: `[3 4 5 | 1 2]` <br/>

&ensp;즉 별도의 Priority Queue 대신 **배열 앞부분 자체를 sorted priority queue처럼 사용하는 것** 이라고 볼 수 있다.<br/>

&ensp;제자리 정렬 알고리즘<br/>
&ensp;1. 제자리 선택 정렬 (In-place Selection Sort)<br/>
```
Alg inPlaceSelectionSort(A)
input array A of n keys
output sorted array A

1. for pass ← 0 to n - 2
       minLoc ← pass

       for j ← pass + 1 to n - 1
           if A[j] < A[minLoc]
               minLoc ← j

       A[pass] ↔ A[minLoc]

2. return
```

&ensp;2. 제자리 삽입 정렬 (In-place Insertion Sort)<br/>
```
Alg inPlaceInsertionSort(A)
input array A of n keys
output sorted array A

1. for pass ← 1 to n - 1
       save ← A[pass]
       j ← pass

       while (j ≥ 1) & (A[j - 1] > save)
           A[j] ← A[j - 1]
           j ← j - 1

       A[j] ← save

2. return
```

# 정리

| 구조    | insertItem | removeMin | 결과 정렬          |
| ----- | ---------: | --------: | -------------- |
| 무순리스트 |   \(O(1)\) |  \(O(n)\) | Selection Sort |
| 순서리스트 |   \(O(n)\) |  \(O(1)\) | Insertion Sort |

&ensp;그리고 두 정렬 모두 일반적으로 $O(n^2)$ 이지만<br/>

|           | Selection Sort | Insertion Sort |
| --------- | -------------- | -------------- |
| 기본 아이디어   | 최소값 선택         | 올바른 위치에 삽입     |
| 거의 정렬된 입력 | 별 이득 없음        | 빠름             |
| swap 횟수   | 적음 \(O(n)\)    | 많을 수 있음        |
| 최악 시간     | \(O(n^2)\)     | \(O(n^2)\)     |
| 추가 공간     | \(O(1)\) 가능    | \(O(1)\) 가능    |

```
Priority Queue
        ↓
어떤 자료구조로 구현할 것인가?
        ↓
┌─────────────────┬─────────────────┐
│ Unsorted List   │ Sorted List     │
│ insert O(1)     │ insert O(n)     │
│ removeMin O(n)  │ removeMin O(1)  │
└────────┬────────┴────────┬────────┘
         ↓                 ↓
 Selection Sort       Insertion Sort
         ↓                 ↓
       O(n²)             O(n²)
```
