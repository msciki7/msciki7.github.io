# 비교정렬의 하한

&ensp;비교정렬(comparison-based sorting)은 **두 원소를 서로 비교하면서 정렬하는 방식** 이다.<br/>
&ensp;예를 들어 다음 정렬들이 모두 비교정렬이다.<br/>
* 버블 정렬
* 선택 정렬
* 삽입 정렬
* 힙 정렬
* 합병 정렬
* 퀵 정렬

&ensp;`A[i] < A[j] ?, A[i] > A[j] ?` 같이 원소끼리 비교한 결과를 이용해서 정렬 순서를 결정한다.<br/>

> 비교정렬 알고리즘은 아무리 잘 만들어도 얼마나 빨라질 수 있을까?

&ensp;$\Omega (n\log n)$ <br/>

----

&ensp;비교정렬 하한 유도<br/>
&ensp;유도 단계 1 — 가능한 입력 순서의 개수<br/>
&ensp;서로 다른 n개의 키가 있다.<br/>
&ensp;$k_1, k_2, ... , k_n$ <br/>
&ensp;이 n개의 원소를 배열하는 경우의 수는 $n!$ 이다.<br/>

&ensp;예: n=3<br/>

<p align="center"><img src="/assets/img/알고리즘 및 실습/5주차/5-1.png" width="600"></p>

&ensp;가능한 순서는 총 3! = 6 개이다.<br/>
* K B S
* K S B
* B K S
* B S K
* S K B
* S B K

&ensp;그런데 오름차순 정렬을 기준으로 하면 이 중 정답이 되는 정렬 순서는 단 하나이다.<br/>

> n개의 서로 다른 원소가 있으면 가능한 입력 순열은 n!개이다.

&ensp;유도 단계 2 — 결정트리<br/>
&ensp;이제 비교 횟수를 생각한다. 비교정렬에서는 어떤 두 원소를 비교하면 결과가 두 가지 중 하나로 나뉜다.<br/>
&ensp;예를 들면 `A < B ?` 라면 Yes, No 두 경우로 나뉠 수 있다. 따라서 정렬 알고리즘의 전체 비교 과정을 결정트리(decision tree)로 표현할 수 있다.<br/>

```tree
             비교
            /    \
         결과1   결과2
         /          \
      비교          비교
     /   \          /   \
   ...
```

&ensp;형태가 된다.<br/>

&ensp;결정트리에서 의미하는 것<br/>
&ensp;내부노드: 하나의 비교 연산(예: ki < kj ?)<br/>
&ensp;가지: 비교 결과 ki < kj 또는 ki > kj.<br/>
&ensp;루트 → 잎 경로: 하나의 입력에 대해 알고리즘이 수행하는 전체 비교 과정<br/>

&ensp;유도 단계 3 — 결정트리의 높이<br/>
&ensp;서로 다른 입력 순열은 서로 다른 결과를 가져야 한다. 앞에서 입력 순열이 총 n!개라고 했다. 따라서 결정트리에는 최소한 n! 개의 잎이 필요하다.<br/>

&ensp;이진트리의 높이<br/>
&ensp;비교 한 번마다 결과가 두 갈래로 나뉘므로 결정트리는 이진트리이다. 높이가 h인 이진트리는 최대 $2^h$ 개의 잎을 가질 수 있다. 그런데 우리는 n!개의 잎이 필요하다. 따라서 $2^h \ge  n!$ . 양변에 로그를 취하면 $h \ge \log(n!)$ . 따라서 결정트리의 최소 높이는 $\log{(n!)}$ 이다.<br/>


<p align="center"><img src="/assets/img/알고리즘 및 실습/5주차/5-2.png" width="600"></p>

&ensp;결정트리 높이가 시간복잡도인 이유<br/>
&ensp;비교정렬에서는 **트리에서 한 단계 내려가는 것 = 비교 1번** 이다.<br/>
&ensp;예를 들어 어떤 입력을 정렬하기 위해 루트에서 잎까지 5단계 내려갔다면, 총 5번의 비교가 필요했다는 뜻이다. 따라서 트리의 높이가 곧 **최악의 경우 필요한 비교 횟수** 가 된다.<br/>

&ensp;유도 단계 4 — $\Omega(n\log n)$ <br/>
&ensp;앞에서 비교정렬은 최소 $\log (n!)$ 번 정도의 비교가 필요하다. 이제 이것을 $n \log n$ 형태로 바꾸면 된다.<br/>

$$\log (n!) \ge \log ((\frac{n}{2})^{\frac{n}{2}})$$

&ensp;그리고 로그 성질을 이용하면 $= \frac{n}{2} \log \frac{n}{2}$ 가 된다. 그런데 $\frac{n}{2}\log \frac{n}{2}$ 는 점근적으로 $n \log n$ 과 같은 성장룰을 가진다.<br/>

$$\log (n!) = \Omega (n \log n)$$

&ensp;**모든 비교정렬 알고리즘의 하한은 $\Omega (n \log n)$ 이다.** <br/>

&ensp;$\Omega(n\log n)$ 이라는 것은 **모든 정렬 알고리즘이 무조건 $n \log n$ 이라는 뜻이 아니다. 정확히 비교를 기반으로 정렬하는 알고리즘은 일반적으로 그보다 더 좋은 하한을 가질 수 없다라는 뜻이다.<br/>
&ensp;그래서 우리가 지금까지 본 알고리즘 중<br/>
* 힙 정렬       O(n log n)
* 합병 정렬     O(n log n)
* 퀵 정렬       O(n log n) 

&ensp;기대시간은 비교정렬 관점에서 매우 효율적인 알고리즘이라고 볼 수 있다.<br/>

&ensp;반면<br/>
* 선택 정렬     O(n²)
* 삽입 정렬     O(n²)

&ensp;은 이 하한보다 느리다.<br/>

---

&ensp;하한 유도 전체 흐름<br/>
1. n개의 서로 다른 원소 → n!개의 가능한 순열
2. 비교정렬의 수행 과정 → 결정트리로 표현 가능
3. 서로 다른 입력 순열마다 서로 다른 잎 필요 → 최소 n!개의 잎
4. n!개의 잎을 가지는 이진트리의 최소 높이 → log(n!)
5. log(n!) = Ω(n log n)

&ensp;∴ 비교정렬의 하한 = Ω(n log n)<br/>

# 정렬의 안정성

&ensp;정렬할 데이터가 단순히 숫자 하나만 있는 것이 아니라 (key, element) 형태라고 생각한다.<br/>

$$L=((k_0,e_0),\dots,(k_{n-1},e_{n-1}))$$

&ensp;안정 정렬의 정의<br/>
&ensp;두 원소가 있다고 하자. $(k_i, e_i)$, $(k_j, e_j)$ 그리고 두 원소의 키가 같다. $k_i = k_j$ . 정렬 전에는 $(k_i,e_i)$ 가 먼저 있다고 하자. 즉 i < j 이다. 이때 정렬한 뒤에도 $(k_i, e_i)$ 가 $(k_j, e_j)$ 보다 앞에 있다면 이 정렬 알고리즘을 안정적(stable) 이라고 한다. <br/>

&ensp;안정성이 중요한 이유는 **동일한 키를 가진 원소들의 기존 순서를 유지해야 하는 응용이 많기 때문** 이다. 특히 여러 기준으로 연속해서 정렬할 때 중요하다. 예를 들어 먼저 이름순으로 정렬한 뒤 점수순으로 안정 정렬하면, 같은 점수 안에서는 기존 이름순이 유지될 수 있다.<br/>
> stable sort = 같은 키의 상대적인 순서를 유지

# 비교정렬 알고리즘 비교

| 알고리즘 | 시간 | 주요 전략 | 특징 |
|---|----|---|---|
| 선택 정렬 | $O(n^2)$ | 우선순위 큐 — 무순 리스트 | 제자리, 느림, 소규모 |
| 삽입 정렬 | $O(n^2)$ | 우선순위 큐 — 순서 리스트 | 제자리, 느림, 소규모 |
| 힙 정렬 | $O(n\log n)$ | 우선순위 큐 — 힙 | 제자리, 빠름, 대규모 |
| 합병 정렬 | $O(n\log n)$ | 분할통치 | 순차 데이터 접근, 빠름, 초대규모 |
| 퀵 정렬 | $O(n\log n)$  | 분할통치 | 제자리, 무작위, 가장 빠름, 대규모 |

&ensp;합병 / 퀵의 공통점<br/>
&ensp;둘 다 분할통치이다.<br/>
&ensp;합병 정렬<br/>
* 먼저 반으로 나눔 → 각각 정렬 → 합병

&ensp;퀵 정렬<br/>
* pivot 기준으로 분할 → 각 부분을 다시 정렬

# 사전(Dictionary) ADT

&ensp;사전 ADT는 탐색 가능한 형태의 (key,\ element) 쌍들의 모음을 모델링한다. 예를 들어 학생 정보를 생각하면 (학번, 학생정보)처럼 저장할 수 있다.<br/>
* key : 데이터를 찾기 위한 기준
* element : 실제 저장된 데이터

&ensp;사전의 주요 작업<br/>
&ensp;사전에서는 크게 세 가지 작업이 중요하다.<br/>
* 탐색(searching)
* 삽입(inserting)
* 삭제(deleting)

&ensp;즉, key를 이용해서 찾고 새 데이터를 넣고 기존 데이터를 삭제하는 자료구조라고 보면 된다.<br/>
&ensp;사전을 두 종류로 구분할 수 있다.<br/>
* 무순사전 ADT
* 순서사전 ADT

# 사전 ADT 메쏘드

&ensp;1. 일반 메쏘드<br/>
&ensp;`integer size()`<br/>
&ensp;사전에 저장되어 있는 항목의 개수를 반환한다.<br/>

&ensp;`boolean isEmpty()` <br/>
&ensp;사전이 비어 있는지 확인한다.<br/>
* 항목 없음 → true
* 항목 있음 → false

&ensp;2. 접근 메쏘드<br/>
&ensp;`element findElement(k)` <br/>
&ensp;키 k를 가진 항목을 찾는다.<br/>
* 존재한다면 해당 element 반환
* 존재하지 않는다면 NoSuchKey 반환

&ensp;3. 갱신 메쏘드<br/>
&ensp;`insertItem(k, e)` <br/>
&ensp;사전에 (k, e) 항목을 삽입한다.<br/>

&ensp;`element removeElement(k)` <br/>
* 키 k를 가진 항목이 있다면 항목 삭제 + element 반환
* 존재하지 않으면 NoSuchKey를 반환

| 메소드 | 역할 |
|---|---|
| `size()` | 항목 개수 반환 |
| `isEmpty()` | 사전이 비어 있는지 확인 |
| `findElement(k)` | 키 k의 원소 탐색 |
| `insertItem(k,e)` | `(k,e)` 삽입 |
| `removeElement(k)` | 키 k 항목 삭제 후 원소 반환 |

---

&ensp;사전의 응용<br/>
&ensp;직접 응용<br/>
* 연락처 목록
* 신용카드 사용승인
* 인터넷주소 매핑

&ensp;간접 응용<br/>
* 알고리즘 수행을 위한 보조 데이터구조
* 다른 데이터구조를 구성하는 요소

# 탐색(Search)

&ensp;탐색은 간단하게 말하면 **데이터 집단에서 특정 정보를 찾는 것** 이다.<br/>

> 사전으로 구현된 데이터 집단에서 지정된 키와 연관된 데이터 원소를 반환하는 것

&ensp;유일 키와 중복 키<br/>
&ensp;유일 키(unique key): 하나의 키에 하나의 데이터만 존재한다.<br/>
&ensp;예: 학번, 은행 계좌, login ID<br/>
&ensp;`하나의 key → 하나의 element`<br/>

&ensp;중복 키(duplicate key): 하나의 키에 여러 데이터 항목이 존재할 수 있다.<br/>
&ensp;예: 이름, 나이, 계좌개설일자<br/>
&ensp;`하나의 key → 여러 element 가능` <br/>

# 무순사전 ADT — 기록파일

&ensp;기록파일(log file)은 **무순리스트를 이용하여 구현한 사전** 이다.<br/>
&ensp;즉, 항목들을 정렬하지 않고 임의의 순서로 저장한다.<br/>
&ensp;구현 방시으로는 **이중연결리스트, 원형배열** 을 사용할 수 있다.<br/>

---

&ensp;기록파일 연산 시간복잡도<br/>
&ensp;`insertItem` <br/>
&ensp;새 항목을 리스트의 맨 앞 또는 맨 뒤에 넣으면 된다.<br/>
&ensp;따라서 O(1) 이다.<br/>

&ensp;`findElement` <br/>
&ensp;정렬되어 있지 않으므로 처음부터 하나씩 찾아야 한다.<br/>
&ensp;최악의 경우<br/>
&ensp;찾으려는 원소가 맨 마지막 또는 아예 존재하지 않음 이면 전체 리스트를 순회해야 한다.<br/>
&ensp;따라서 O(n) 이다.<br/>

&ensp;`removeElement` <br/>
&ensp;삭제하려면 먼저 해당 항목을 찾아야 하므로 최악의 경우 **O(n)** 이다.<br/>

---

&ensp;기록파일이 유리한 경우<br/>
* 소규모 사전
* 삽입은 자주 하지만 탐색과 삭제는 드문 경우

&ensp;이유: 삽입 O(1) 이 매우 빠르기 때문이다.<br/>

## 무순사전에서의 선형탐색

```alg
Alg findElement(k)

input list L, key k
output element with key k

1. L.initialize(i)

2. while (L.isValid(i))
       if (L.key(i) = k)
           return L.element(i)
       else
           L.advance(i)

3. return NoSuchKey
```

&ensp;선형탐색 의사코드 줄별 의미<br/>
&ensp;`L.initialize(i)` <br/>
&ensp;탐색 위치 i를 리스트의 처음으로 설정한다.<br/>
&ensp;i -> 첫 번째 항목<br/>

&ensp;`while (L.isValid(i))` <br/>
&ensp;현재 위치 i가 유효한 동안 계속 반복한다.<br/>
&ensp;즉 리스트 끝까지 탐색한다는 뜻이다.<br/>

&ensp;비교<br/>
&ensp;`if (L.key(i) = k)` <br/>
&ensp;현재 항목의 키와 찾으려는 키 k를 비교한다. 같으면 `return L.element(i)` 즉시 해당 원소를 반환한다. 다르면 `L.advance(i)` 다음 항목으로 이동한다. 끝까지 못 찾았다면 `return NoSuchKey` 를 반환한다. <br/>

---

&ensp;선형탐색 시간복잡도<br/>
&ensp;최악의 경우는 **찾는 키가 맨 마지막 또는 찾는 키가 없음** 이다.<br/>
&ensp;이 경우 모든 원소를 봐야 한다. 따라서 **O(n)** 시간이 걸린다.<br/>
&ensp;그리고 입력 데이터구조를 읽기만 하므로 추가 공간은 **O(n)** 이다.<br/>

# 순서사전 ADT — 일람표

&ensp;일람표(lookup table)는 **순서리스트를 사용하여 구현한 사전** 이다.<br/>
&ensp;기록파일과 가장 큰 차이는 **항목이 키를 기준으로 정렬되어 있다.** 는 것이다.<br/>

---

&ensp;일람표의 연산 시간복잡도<br/>
&ensp;`findElement` <br/>
&ensp;정렬되어 있기 때문에 이진탐색을 사용할 수 있다.<br/>
&ensp;따라서 **$O(\log n)$** <br/>

&ensp;`insertItem` <br/>
&ensp;새로운 항목을 넣으려면 공간을 만들어야 한다.<br/>
&ensp;예를 들어 1 3 5 7 9 에 4를 넣으면 1 3 _ 5 7 9를 만들기 위해 뒤쪽 원소들을 이동해야 한다. 최악의 경우 n개의 항목 이동. 따라서 **O(n)** 이다.<br/>

&ensp;`removeElement` <br/>
&ensp;삭제하면 빈 공간을 메우기 위해 뒤쪽 항목들을 이동해야 한다.<br/>
&ensp;따라서 **O(n)** 이다.<br/>

&ensp;일람표가 효과적인 경우<br/>
* 소규모 사전
* 탐색은 빈번하지만 삽입과 삭제는 드문 사전

&ensp;왜냐하면 탐색 = O(log n) 으로 빠르기 때문이다.<br/>

---

&ensp;기록파일 vs 일람표<br/>

| 연산 | 기록파일(무순) | 일람표(순서) |
|---|---:|---:|
| 탐색 | $O(n)$ | $O(\log n)$ |
| 삽입 | $O(1)$ | $O(n)$ |
| 삭제 | $O(n)$ | $O(n)$ |

## 정렬된 리스트에서의 선형탐색

&ensp;순서사전이라도 선형탐색은 가능하다. 하지만 정렬되어 있으므로 한 가지 개선을 할 수 있다.<br/>

```alg
Alg findElement(k)

1. L.initialize(i)

2. while (L.isValid(i))
       if (L.key(i) = k)
           return L.element(i)

       elseif (L.key(i) > k)
           return NoSuchKey

       else
           L.advance(i)

3. return NoSuchKey
```

&ensp;정렬된 리스트의 선형탐색도 O(n)인 이유<br/>
&ensp;실패가 예정된 경우 평균적으로 입력의 절반 정도를 탐색하고 끝날 수 있다고 한다. 하지만 n/2 도 Big-O에서는 O(n) 이다. 따라서 **O(n)** 이다.<br/>

# 이진탐색(Binary Search)

&ensp;이진탐색은 **키로 정렬된 배열 기반 리스트에서 탐색 범위를 절반씩 줄여가며 원하는 키를 찾는 방법** 이다.<br/>
&ensp;핵심은 정렬 + 절반씩 제거 이다.<br/>

&ensp;이진탐색 의사코드<br/>
<p align="center"><img src="/assets/img/알고리즘 및 실습/5주차/5-4.png" width="600"></p>

&ensp;변수 의미<br/>
* l = left
* r = right
* mid = middle

&ensp;즉 현재 탐색 범위가 l ---------------- r 이고 그 가운데가 mid이다.<br/>

&ensp;이진탐색 줄별 설명<br/>
&ensp;Driver<br/>
&ensp;`return rFE(k, 0, n-1)` <br/>
&ensp;처음에는 전체 배열을 탐색한다.<br/>
* l = 0
* r = n - 1

&ensp;종료 조건<br/>
&ensp;`if (l > r) return NoSuchKey`  <br/>
&ensp;탐색 범위가 사라졌다. 즉 찾는 키가 없다.<br/>

&ensp;중앙값 결정<br/>
&ensp;`mid ← (l + r) / 2` <br/>
&ensp;현재 탐색 범위의 가운데 인덱스를 구한다.<br/>

&ensp;찾은 경우<br/>
&ensp;`if (k = key(A[mid]))` <br/>
&ensp;중앙 원소가 찾는 값이면 종료.<br/>

&ensp;찾는 값이 더 작은 경우<br/>
&ensp;`k < key(A[mid])` 이면 오른쪽 절반은 볼 필요가 없다.따라서 l ~ mid-1 만 탐색한다.<br/>

&ensp;찾는 값이 더 큰 경우<br/>
&ensp;`k > key(A[mid])` 이면 왼쪽 절반을 버리고 mid+1 ~ r 만 탐색한다.<br/>

&ensp;이진탐색 시간복잡도<br/>
* 이진탐색 + 배열 → O(log n)
* 이진탐색 + 연결리스트 → O(n)

&ensp;분할통치 vs 이진탐색<br/>
&ensp;분할통치: 나눈 두 범위를 둘 다 고려<br/>
&ensp;이진탐색: 나눈 두 범위 중 한쪽만 고려<br/>

&ensp;예를 들어 합병정렬은 왼쪽 절반 정렬 + 오른쪽 절반 정렬 둘 다 처리한다. 반면 이진탐색은 둘 중 하나만 선택한다.<br/>
