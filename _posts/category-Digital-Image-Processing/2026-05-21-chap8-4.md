# Fourier Series와 Fourier Transform의 차이

&ensp;복잡한 신호도 여러 개의 사인파/코사인파를 섞어서 표현할 수 있다.<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-1.png" width="600"></p>

&ensp;위 그림을 보면 위에 작은 파형들이 여러 개 있고, 아래에 복잡한 파형이 있지? 이 말은 아래의 복잡한 신호가 사실은 위쪽의 여러 단순한 파형을 더해서 만들어질 수 있다는 뜻이다.<br/>

&ensp;복잡한 신호 = 저주파 성분 + 고주파 성분 + ... <br/>
&ensp;이미지는 2D 신호니까, 이미지도 여러 주파수 성분의 조합으로 표현할 수 있다.<br/>

&ensp;Fourier Series<br/>
&ensp;Fourier Series는 주기적인 신호를 다룰 때 사용<br/>
&ensp;반복되는 신호는 여러 주파수의 사인파/코사인파 합으로 표현할 수 있다.<br/>

&ensp;수식<br/>
$$f(x) = \sum_{k = -\infty }^{\infty }F[k]e^{jkw_{0}x}$$

&ensp;또는 시간 신호에서는<br/>

$$x(t) = \sum_{k = -\infty }^{\infty }X[k]e^{jkw_{0}t}$$

&ensp;Fourier Transform<br/>
&ensp;Fourier Transform은 비주기 신호를 다룰 때 사용한다.<br/>
&ensp;비주기 신호는 반복 주기가 없기 때문에, 주파수 성분이 연속적으로 퍼져 있다고 본다.<br/>

&ensp;수식<br/>
$$f(x) = \int_{-\infty }^{\infty }F(u)e^{j2\pi ux}du$$

&ensp;여기서 F(u)는 주파수 u 성분이 얼마나 들어 있는지를 나타내는 가중치이다.<br/>

&ensp;시험용 차이 정리<br/>

| 구분    | Fourier Series | Fourier Transform |
| ----- | -------------- | ----------------- |
| 대상    | 주기 신호          | 비주기 신호            |
| 표현 방식 | 사인/코사인의 합      | 사인/코사인의 적분        |
| 주파수   | 이산적            | 연속적               |
| 수식 핵심 | $\sum$         | $\int$            |
| 계수    | $F[k]$, $X[k]$ | $F(u)$            |

&ensp;이게 이미지 처리에서 중요한 이유<br/>
&ensp;이미지는 픽셀값으로 되어 있다. 예를 들어 이미지 블록이 있으면 공간 영역에서는 f(x, y)로 보인다.(x, y 는 위치)<br/>
&ensp;그런데 푸리에 변환이나 DCT를 하면 이미지를 주파수 영역으로 바꿀 수 있다.<br/>
$$f(x, y) -> F(u, v)$$

&ensp;u, v는 주파수 위치<br/>
&ensp;공간 영역에서는 "어느 위치의 픽셀값이 얼마인가?"를 보지만, 주파수 영역에서는 "밝기가 얼마나 천천히 또는 빠르게 변하는가?"를 본다.<br/>

&ensp;예를 들어 부드러운 하늘 사진은 대부분 저주파 성분이 많는다.<br/>
&ensp;부드러운 영역 -> 저주파 성분 많음<br/>

&ensp;반대로 글자, 경계선, 머리카락 같은 부분은 고주파 성분이 많다.<br/>
&ensp;급격한 변화/경계 -> 고주파 성분 많음<br/>

&ensp;압축에서는 이 성질을 이용한다. 사람 눈은 보통 고주파의 세밀한 변화에 상대적으로 덜 민감하니까, 고주파 계수를 더 많이 양자화하거나 버린다. 이게 JPEG에서 DCT를 쓰는 이유와 이어진다.<br/>

&ensp;Linear Independence와 Span<br/>
&ensp;선형결합<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-2.png" width="600"></p>

&ensp;벡터 여러 개가 있다.<br/>

$$v_{1}, v_{2}, ..., v_{n}$$

&ensp;이 벡터들에 어떤 숫자 $a_{1}, a_{2}, ..., a_{n}$ 을 곱해서 더하는 걸 선형결합이라고 한다.<br/>

$$a_{1}v_{1} + a_{2}v_{2} + ... + a_{n}v_{n}$$

&ensp;선형독립<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-3.png" width="600"></p>

&ensp;어떤 벡터도 다른 벡터들의 조합으로 만들 수 없는 상태<br/>
&ensp;수식으로는 $a_{1}v_{1} + a_{2}v_{2} + ... + a_{n}v_{n} = 0$ 을 만족하는 방법이 $a_{1} = a_{2} = ... = a_{n} = 0$ 뿐이면 선형독립이다.<br/>

&ensp;서로 중복되지 않는 방향들이라는 뜻<br/>

&ensp;예를 들어 2차원 평면에서 [1, 0], [0, 1]은 선형독립이다. 왜냐하면 x축 방향과 y축 방향은 서로 다른 방향이고, 하나로 다른 하나를 만들 수 없다.<br/>
&ensp;반대로 [1, 0],[2, 0]은 선형종속이다. 둘 다 x축 방향이기 때문에 하나는 다른 하나의 배수이다.<br/>

&ensp;Span<br/>
&ensp;Span은 어떤 벡터들의 선형결합으로 만들 수 있는 전체 공간이다. 예를 들어 [1, 0], [0, 1]이 두 벡터가 있으면 2차원 평면의 모든 벡터를 만들 수 있다. <br/>
&ensp;[3, 5] = 3[1, 0] + 5[0, 1]<br/>
&ensp;그래서 이 두 벡터는 2차원 공간을 span한다고 말한다.<br/>

&ensp;DFT에서 basis vector의 의미<br/>
&ensp;DFT도 같은 원리<br/>
&ensp;길이가 N인 신호가 있다고 해보자. $x = [x_{0}, x_{1}, ..., x_{N-1}]$ <br/>
&ensp;DFT는 이 신호를 N개의 basis vector 조합으로 표현한다. 각 basis vector는 서로 다른 주파수의 복소 지수파이다. <br/>
$$원래 신호 = 저주파 기저 × 계수 + 고주파 기저×  계수+⋯$$

&ensp;Video Compression Standard<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-4.png" width="600"></p>

&ensp;영상 압축은 예측으로 만든 차이 블록(residual block)을 DCT하고, 양자화하고, 엔트로피 코딩한다.<br/>

&ensp;전체 흐름<br/>
1. 현재 블록을 예측한다.
2. 실제 블록과 예측 블록의 차이인 residual block을 만든다.
3. residual block에 DCT를 한다.
4. DCT 계수를 양자화한다.
5. 가변 길이 부호화로 더 압축한다.
6. encoded block을 만든다.

&ensp;VVC/H.266 Standard<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-5.png" width="600"></p>

&ensp;H.266, 즉 VVC는 HEVC/H.265 다음 세대의 영상 압축 표준이다.<br/>
&ensp;흐름: 예측 → 잔차 계산 → 변환 → 양자화 → 엔트로피 코딩<br/>
&ensp;디코더 흐름: 역양자화 → 역변환 → 복원 → 필터 → 다음 예측에 사용<br/>

# Transform Coding

&ensp;원래 픽셀값 -> 변환 -> 변환 계수 압축<br/>

&ensp;즉 압축을 **공간 영영(spatial domain)** 에서 직접 하는 게 아니라 일단 변환 영역(transform domain)으로 옮긴 다음 거기서 압축하는 것이다.<br/>

&ensp;변환해서 압축하는 이유<br/>
&ensp;이유 1) 사람 눈(HVS)은 주파수마다 민감도가 다르다<br/>
&ensp;HVS는 Human Visual System, 즉 인간 시각 시스템이다. 사람 눈은 모든 주파수 성분에 똑같이 민감하지 않다.<br/>
* 저주파 성분: 전체적인 밝기 변화, 큰 모양 → 사람 눈이 민감함
* 고주파 성분: 미세한 디테일, 아주 급격한 변화 → 상대적으로 덜 민감한 경우 많음

&ensp;그래서 transform을 하면, 이미지 -> 저주파 계수 + 고주파 계수 처럼 나눌 수 있고, 그 다음 고주파는 더 세게 양자화하고 저주파는 덜 세게 양자화할 수 있다.<br/>
&ensp;**사람이 덜 민감한 정보는 더 많이 버리고, 사람이 민감한 정보는 덜 버리는 방식**<br/>

&ensp;이유 2) 픽셀 간 중복(correlation, redundancy)을 줄일 수 있다.<br/>
&ensp;이미지에서 이웃 픽셀들은 보통 값이 비슷하다. 예를 들어 하늘 사진에서는 근처 픽셀들이 거의 비슷한 파란색이다. 즉 픽셀들끼리 선형 의존성(linear dependence), **상관관계(correlation)**가 있다. 이런 신호를 그대로 압축하는 것보다 transform을 해서 중복을 몰아주고(decorrelation) 나면 훨씬 압축하기 좋아진다.<br/>

&ensp;transform의 종류<br/>
* KLT (Karhunen-Loève Transform)
* DFT (Discrete Fourier Transform)
* DCT (Discrete Cosine Transform)
* DST (Discrete Sine Transform)
* WHT (Walsh-Hadamard Transform)

&ensp;효율적인 transform<br/>
&ensp;같은 비트 수(bit rate)로 더 적은 왜곡(distortion)을 내는 transform<br/>
&ensp;같은 비트 수 -> 왜곡이 더 작다 면 더 좋은 transform<br/>
&ensp;반대로 같은 화질 -> 비트 수가 더 적다. 여도 좋은 transform<br/>

&ensp;Signal Representation<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-6.png" width="600"></p>

&ensp;1단계. 원본 이미지 $f(n_{1}, n_{2})$ <br/>
&ensp;공간 영역의 원본 이미지<br/>

&ensp;2단계. Transform A<br/>
&ensp;원본 이미지를 변환해서 transform coefficient로 바뀐다. AX = F처럼 생각하면 된다.<br/>
* X: 원본 픽셀 벡터
* A: transform matrix
* F: transform된 계수 벡터

<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-7.png" width="600"></p>

&ensp;3단계. Encoder<br/>
&ensp;transform 계수 F를 보고 sample selector, quantize 같은 처리를 해서 압축한다. 보통 이 단계에서 손실이 생긴다.<br/>

&ensp;4단계. Decoder<br/>
&ensp;양자화된 값을 복원해서 $\hat{F}$ 를 만든다.<br/>

&ensp;5단계. Transform B<br/>
&ensp;복원된 transform 계수를 다시 역변환해서 $\hat{f} (n_1, n_2)$ 를 만든다.<br/>

&ensp;transform을 쓰면 좋은 점<br/>
&ensp;픽셀 간 상관관계(선형 의존성)를 선형 변환으로 제거할 수 있다.<br/>
&ensp;원래 픽셀들은 서로 비슷해서 정보가 중복돼있다. 예를 들어 [100, 102, 101, 103] 같은 값들이 있으면 서로 강하게 연관돼 있다.<br/>

&ensp;그런데 적절한 transform을 하면 이런 중복된 정보가 어떤 계수에는 크게 몰리고 어떤 계수는 거의 0이 되게 만들 수 있다.<br/>

&ensp;많은 정보 -> 소수의 중요한 계수에 집중 되도록 만들 수 있다. => enery compaction(에너지 집중)<br/>

&ensp;distortion 식의 의미<br/>
$ D = E\{(f - \hat{f})^{T}(f - \hat{f})\}$

&ensp;이건 복원 오차의 평균 제곱값, 즉 distortion이다. (= 원본과 복원본이 얼마나 다른지 측정하는 값)<br/>
* 이 값이 작을수록 복원이 잘 된 것

&ensp;Transform A로 바꿨으면, 복원할 때는 그걸 원래대로 되돌리는 inverse transform을 써야 한다. $B = A{-1}$ <br/>

&ensp;가장 좋은 transform matrix A는 원본 신호의 covariance matrix의 eigenvector들로 만든다. <= KLT = KL Transform<br/>

## KLT

&ensp;KL Transform: 입력 신호의 공분산 행렬(covariance matrix)을 구하고, 그 행렬의 고유벡터(eigenvector)를 기저로 사용하는 transform<br/>

&ensp;공분산 행렬<br/>

$$COV_{x} = E[(x - m_{x})(x - m_{x})^{T}]$$

&ensp;또는 샘플 평균으로 쓰면:<br/>

$$COV_{x} = \frac{1}{M}\sum_{i=1}^{M}(x_{i} - m_{x})(x_{i} - m_{x})^{T}$$

* $x_{i}$ : i번째 샘플 이미지(또는 벡터화한 블록)
* $m_{x}$ : 평균 벡터
* M: 샘플 개수

&ensp;평균 벡터<br/>

$$m_{x} = E[x] = \frac{1}{M}\sum_{i=1}^{M}x_{i}$$ 

&ensp;데이터들의 평균을 구하는 것<br/>

&ensp;공분산 행렬의 의미<br/>
&ensp;공분산 행렬은 각 성분들이 서로 얼마나 같이 움직이는지를 보여준다.<br/>
&ensp;예를 들어 2차원 데이터라면<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-8.png" width="600"></p>

* 대각성분: 각 성분의 분산
* 비대각성분: 서로의 상관관계

&ensp;분산 행렬은 데이터가 어느 방향으로 퍼져 있고, 어떤 축끼리 연관돼 있는지 알려준다.<br/>

&ensp;고유값과 고유벡터<br/>
$$C_{\phi } = \lambda _{\phi }$$

* C: covariance matrix
* λ: eigenvalue
* ϕ: eigenvector

&ensp;고유벡터는 데이터가 퍼져 있는 “중요한 방향”이라고 생각하면 된다. 고유값은 그 방향으로 데이터가 얼마나 많이 퍼져 있는지를 나타난다.<br/>
* 큰 eigenvalue → 그 방향에 정보/분산이 많음
* 작은 eigenvalue → 그 방향은 덜 중요함

&ensp;이게 압축에 좋은 이유<br/>
&ensp;KLT는 이 eigenvector 방향으로 좌표계를 돌려버린다. 그러면 데이터가 가장 많이 퍼진 방향이 첫 번째 축에 오고, 그 다음 중요한 방향이 두 번째 축에 온다. 그 결과 transform 후 계수들은 서로 상관관계가 줄어들고 에너지가 몇 개의 중요한 축에 집중되기 쉽다.<br/>
&ensp;중요한 정보 ≈ 앞쪽 몇 개의 계수<br/>
&ensp;그러면 뒤쪽 덜 중요한 계수는 강하게 양자화하거나 버려도 된다.<br/>

<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-9.jpg" width="600"></p>

&ensp;KLT의 장점과 한계<br/>
&ensp;장점<br/>
1. 이론적으로 최적에 가깝다
* fixed bitrate에서 distortion 최소화
2. decorrelation 효과가 좋다
* 성분 간 상관관계 감소
3. energy compaction이 좋다
* 중요한 정보가 소수 계수에 몰림

&ensp;한계<br/>
1. 입력 데이터의 통계 특성에 따라 transform이 달라진다
* 공분산 행렬을 매번 알아야 함
2. 계산이 복잡하다
* eigenvalue/eigenvector 계산 필요
3. 실제 시스템에선 범용성이 떨어질 수 있다

&ensp;그래서 실제 이미지/영상 압축에서는 KLT가 이론적으로는 훌륭하지만, 실제로는 DCT 같은 고정 transform을 많이 사용한다.<br/>

&ensp;왜냐하면 DCT는:<br/>
* 계산이 단순하고
* 구현이 쉽고
* KLT와 비슷하게 에너지 집중 성능도 좋기 때문

&ensp;1-D KLT<br/>
&ensp;KLT를에서는 고유벡터들을 모아서 행렬을 만든다.<br/>

$$ \Phi = [\phi _{0}, \phi _{1}, \phi _{2}, ...., ,\phi _{N-1}]$$

&ensp;그리고 고유값은 큰 순서대로 정렬한다.<br/>

$$\lambda _{0} \geq \lambda _{1} \geq .... \geq \lambda _{N-1}$$

&ensp;첫 번째 고유벡터 $\phi _{0}$ 방향에 데이터 에너지가 가장 많고 두 번째 고유벡터 $\phi _{1}$ 방향에 그 다음으로 에너지가 많다.<br/>

&ensp;Forward transform: $F = \Phi ^{T}X$ <br/>
&ensp;이게 KLT 변환식<br/>

| 기호       | 의미              |
| -------- | --------------- |
| (X)      | 원래 신호 또는 픽셀 벡터  |
| $\Phi$   | 고유벡터들을 모아 만든 행렬 |
| $\Phi^T$ | 고유벡터 행렬의 전치     |
| (F)      | KLT 변환 후 계수     |

&ensp;원래 데이터 X를 고유벡터 축으로 바라본 결과가 F이다.<br/>

&ensp;Inverse transform: $X = \Phi F$ <br/>
&ensp;KLT에서 $\Phi$ 는 직교행렬이기 때문이다.<br/>

&ensp;직교행렬은 역행렬이 전치행렬과 같다.<br/>

$$\Phi ^{-1} = \Phi ^{T}$$

&ensp;앞에서 forward transform이 $F = \Phi ^{T}X$ 였다. 양변에 $\Phi$ 를 곱하면 $\Phi F = \Phi \Phi ^{T}X$ <br/>
&ensp;직교행렬에서는 $\Phi \Phi ^{T} = I$ 이니까 $\Phi F = X$ <br/>
&ensp;따라서 $X = \Phi F$ 가 된다.<br/>

&ensp;A와 B의 의미<br/>

$$A = \Phi ^{T} ,\ B = A^{-1}$$


* A: forward transform kernel
* B: inverse transform kernel

<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-10.png" width="600"></p>

&ensp;KLT 후 계수의 분산은 고유값 λ<br/>
&ensp;F(0)은 분산이 $λ_{0}$ , F(1)은 분산이 $λ_{1}$ 이런 식이다.<br/>

&ensp;$\lambda _{0} \geq \lambda _{1} \geq ..$ 로 정렬했으니까 F(0), F(1), F(2), ... 순서대로 중요한 계수라고 볼 수 있다.<br/>

&ensp;Parseval’s theorem 의미<br/>

<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-11.png" width="600"></p>

&ensp;원래 신호의 전체 에너지와 변환 후 계수들의 전체 에너지는 같다.<br/>
&ensp;KLT는 에너지를 없애는 게 아니다. 공간 영역에 흩어져 있던 에너지를 변환 영역으로 옮기는 것이다. 그런데 KLT의 장점은 전체 에너지는 같지만, 그 에너지를 앞쪽 몇 개 계수에 몰아준다. 이다. -> energy compaction<br/>

&ensp;압축 관점에서 왜 λ 큰 순서로 고르는가?<br/>
&ensp;압축할 때는 고유값이 큰 순서대로 고유벡터를 선택한다는 뜻이다.<br/>
&ensp;왜냐하면 고유값 λ 는 그 축 방향의 분산, 즉 에너지 크기를 의미하기 때문이다.<br/>
* λ 큼 ⇒ 중요한 정보 많음
* λ 작음 ⇒ 버려도 영향 적음

&ensp;그래서 압축할 때는 $\phi _{0}, \phi _{1}, \phi _{2}, ...$ 순서대로 선택한다.<br/>

&ensp;예를 들어 전체 계수가 8개인데 3개만 저장해야 한다면, F(0), F(1), F(2) 만 저장하고 나머지는 버린다.<br/>

&ensp;KLT가 실제로 어려운 이유<br/>
&ensp;KLT의 고유벡터와 고유값은 이미지마다 달라진다. 왜냐하면 KLT는 이미지의 공분산 행렬을 기반으로 만들기 때문이다. 이미지가 바뀌면 픽셀 분포도 바뀌고, 공분산도 바뀌고, 고유벡터도 바뀐다. 그래서 최적 KLT를 쓰려면 각 N × N 블록마다 ϕ 와 λ를 새로 구해야 한다.-> 실제 압축에서는 최적 KLT를 그대로 쓰기 어렵다. 그래서 대신 쓰는게 DCT, DST, Hadamard, DFT 같은 sub-optimum transform이다.<br/>

&ensp;Graphical Interpretation of KLT<br/>
&ensp;데이터를 가장 잘 설명하는 새 좌표축을 찾고, 그 축으로 데이터를 표현한다.<br/>

&ensp;Zonal Coding<br/>

&ensp;분산이 기준인 이유<br/>

* f(x, y): 공간 영역 이미지

&ensp;DFT는 이미지를 복소 지수 함수들의 합으로 표현<br/>

&ensp;3-2. DFT의 의미<br/>
&ensp;이미지 안에 어떤 주파수 패턴이 얼마나 들어 있는지 계산한다.<br/>
* 낮은 주파수: 부드러운 변화
* 높은 주파수: 급격한 변화, 에지, 세부 무늬

&ensp;그래서 DFT를 하면 이미지의 내용을 “위치 정보”가 아니라 “주파수 성분” 관점으로 보게된다.<br/>

&ensp;4. DFT의 성질<br/>
&ensp;4-1. DFT is separable<br/>
&ensp;DFT도 행-열 분리 가능하다.<br/>
&ensp;그래서 2D DFT를 계산할 때<br/>
1. 각 행에 1D DFT
2. 각 행에 1D DFT

&ensp;4-2. F(u,v) is periodic with N x N<br/>
&ensp;DFT 결과는 주기성을 가진다.<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-22.png" width="600"></p>

&ensp;주파수 영역도 N 주기로 반복된다.<br/>

&ensp;4-3. conjugate symmetry<br/>
&ensp;$F^{*}(u, v) = F(-u, -v)$ <br/>

&ensp;실수 입력 f(x,y)일 때는 이런 켤레대칭이 생긴다.<br/>
&ensp;원본 이미지가 실수값이면 DFT 결과는 완전히 독립적인 복소수들이 아니라 대칭 구조를 가진다.<br/>

&ensp;4-4. sampled values of Fourier transform<br/>
&ensp;DFT는 연속 Fourier transform을 특정 주파수 점에서 샘플링한 것이라고 볼 수 있다.<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-23.png" width="600"></p>

&ensp;에서 연속 FT 값을 찍어온 것과 비슷한 개념이다.<br/>

&ensp;5. DFT는 왜 이미지 압축에서 메인이 아닐까?<br/>
&ensp;DFT는 좋은 변환이지만<br/>
1. 결과가 복소수
2. 경계 처리 문제
3. 압축용 에너지 집중 측면에서 DCT가 더 실용적

&ensp;이라서 이미지 압축의 대표 변환은 보통 DCT가 된다.<br/>

&ensp;DCT 식<br/>

&ensp;inverse<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-25.png" width="600"></p>

&ensp;정규화 계수<br/>

&ensp;DCT는<br/>
* cosine basis를 쓴다
* 실수값만 쓴다
* separable이다
* orthogonal transform이다

&ensp;DFT보다 계산과 구현이 이미지 압축에 더 편하다.<br/>

&ensp;7. DCT is separable<br/>
&ensp;DCT도 행과 열로 나눠서 계산 가능하다.<br/>
1. 각 행에 1D DCT
2. 각 열에 1D DCT

&ensp;이렇게 하면 되기 때문에 계산 효울이 좋다.<br/>

&ensp;8. Orthogonal matrix / Unitary matrix<br/>
* Orthogonal Matrix: $A^{-1} = A^{T}$
* Unitary Matrix: $A^{-1} = A^{*T}$

&ensp;Orthogonal<br/>
&ensp;실수 행렬일 때 역행렬 = 전치행렬<br/>

&ensp;Unitary<br/>
&ensp;복소수 행렬일 때 역행렬 = 켤레전치행렬<br/>

&ensp;DCT는 실수 cosine basis를 쓰니까 보통 orthogonal transform으로 본다.<br/>
&ensp;반면 DFT는 복소 지수 함수를 쓰므로 unitary 쪽 개념이 연결된다.<br/>

&ensp;9. DCT가 압축에 좋은 이유<br/>
&ensp;DCT는 이미지처럼 인접 픽셀이 비슷한 데이터에서 에너지를 소수의 계수로 잘 몰아준다.<br/>

&ensp;예를 들어 8 × 8 블록 DCT를 하면 왼쪽 위 몇 개 계수에 대부분 에너지가 몰리ㄹ고 오른쪽 아래 고주파 계수들은 작아지는 경우가 많다.<br/>
* 저주파 계수: 큼
* 고주파 계수: 작음

&ensp;그러면 압축할 때:<br/>
* 중요한 저주파는 잘 남기고
* 중요도 낮은 고주파는 세게 양자화하거나 0으로 만들면 된다.

&ensp;이게 JPEG 핵심 원리<br/>

&ensp;DCT is not the real part of the unitary DFT.<br/>
&ensp;겉으로 보면 DCT는 cosine만 쓰니까 “DFT의 실수 부분만 뽑은 거 아닌가?”라고 생각할 수 있다.<br/>
&ensp;DCT는 단순히 DFT의 real part가 아니라, 원래 신호를 대칭 확장(symmetrical extension) 한 다음 그 확장 신호에 대해 2N-point DFT를 한 것과 관련 있다.<br/>
&ensp;이건 경계 조건이 다르기 때문이다.<br/>

&ensp;중요한 이유<br/>
&ensp;DCT는 신호를 양 끝에서 대칭적인 신호처럼 다뤄서 DFT보다 경계 불연속이 덜하고 그래서 에너지가 더 잘 몰리는 경우가 많다. 즉 이미지 압축에서 DCT가 DFT보다 더 유리한 이유 중 하나이다.<br/>

&ensp;11. DCT는 KLT와도 가깝다.<br/>
&ensp;픽셀들이 서로 강하게 correlated된 일반적인 이미지 모델에서는 DCT가 KLT와 매우 비슷하게 동작한다.<br/>

&ensp;KLT는:<br/>
* 이미지마다 basis가 달라지고
* 계산이 복잡하고
* 실전 사용이 어렵다

&ensp;그래서 실제로는 못 쓰기 쉽다.<br/>

&ensp;DCT는:<br/>
* 고정된 basis
* 계산 쉬움
* separable
* 에너지 집중 좋음
* KLT와 비슷한 성능

&ensp;이니까 실전 선택지가 된다.<br/>

# Markov Processes

&ensp;이미지 픽셀들이 서로 얼마나 연관되어 있는지 모델링하려고 Markov 모델을 쓴다.<br/>
&ensp;이미지는 보통 인접 픽셀끼리 비슷하다.<br/>
&ensp;예를 들어 한 줄의 픽셀값이 있다고 해보자.<br/>
$$100, 102, 103, 101, 104$$

&ensp;이런 식으로 옆 픽셀과 값이 크게 다르지 않다. 즉 현재 픽셀은 과거 픽셀, 특히 바로 이전 픽셀과 관계가 크다. 이걸 수학적으로 모델링한 게 Markov process<br/>

&ensp;1. p차 Markov란?<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-27.png" width="600"></p>

&ensp;현재 값 u(n)은 전체 과거를 다 볼 필요 없이, 바로 앞의 p개 값만 알면 충분하다고 가정한다.<br/>
&ensp;예를 들어 1차 Markov면 현재 값은 바로 이전 값만 보면 된다.<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-28.png" width="600"></p>

&ensp;현재 픽셀은 주로 바로 이전 픽셀과 관련이 있다고 보는 모델<br/>

&ensp;2. Stationary sequence와 covariance<br/>
&ensp;covariance function<br/>
$$ r(n) = Cov[u[n], u[0]]$$

&ensp;그리고 stationary sequence에서는<br/>
$$ r(n) = Cov[u[n' + n], u[n']]$$

&ensp;두 픽셀 사이의 관계는 절대 위치가 아니라, 둘 사이의 거리 n에만 의존한다.<br/>
&ensp;예를 들어 1번 픽셀과 2번 픽셀의 관계, 10번 픽셀과 11번 픽셀의 관계가 비슷하다고 보는 것이다.<br/>
&ensp;이미지 한 줄에서 “이웃 픽셀끼리는 비슷하다”는 성질이 위치와 관계없이 유지된다고 보는 가정한다.<br/>

&ensp;3. 1차 stationary Markov covariance<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-29.png" width="600"></p>

&ensp;여기서 ρ는 correlation coefficient, 상관계수.<br/>
&ensp;보통 이미지에서는 ρ가 1에 가까운 양수라고 생각하면 된다.<br/>
&ensp;예를 들어 ρ=0.95이면 인접 픽셀끼리 매우 비슷하다는 뜻이다.<br/>

&ensp;$r(0) = \rho ^{0} = 1$ <br/>
&ensp;자기 자신과의 상관은 1이다.<br/>

&ensp;$r(1) = \rho $ <br/>
&ensp;한 칸 떨어진 픽셀과의 상관은 ρ<br/>

&ensp;$r(2) = \rho ^{2}$ <br/>
&ensp;두 칸 떨어진 픽셀과의 상관은 $\rho ^{2}$ <br/>
&ensp;거리가 멀어질수록 상관관계가 줄어들다.<br/>
$1, \rho , \rho ^{2} , \rho ^{3}$

&ensp;4. Covariance matrix R<br/>
&ensp;R = {r(m - n)}<br/>
&ensp;행렬의 각 원소는 두 위치 m,n 사이의 거리 차이에 따라 결정된다.<br/>
&ensp;예를 들어 N=4라고 하면 covariance matrix는 이런 느낌이다.<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-30.png" width="600"></p>

* 같은 위치끼리 거리 0 → r(0)=1
* 한 칸 차이 → r(1) = ρ
* 두 칸 차이 → r(2) = $\rho ^{2}$
* 세 칸 차이 → r(3) = $\rho ^{3}$

&ensp;이게 DCT랑 관련 있는 이유<br/>
&ensp;앞에서 KLT는 공분산 행렬의 eignvector 를 basis로 쓴다고 했다.<br/>
$$R_{\phi } = \lambda _{\phi }$$

&ensp;이미지 한 줄을 1차 Markov 모델로 보면 covariance matrix가 위와 같은 형태가 된다.<br/>
&ensp;이때 ρ가 1에 가까우면, 이 공분산 행렬의 eigenvector들이 DCT basis와 매우 비슷해진다.<br/>

> 이미지 픽셀은 Markov처럼 이웃끼리 강하게 correlated되어 있고, 그런 데이터에서는 DCT가 KLT와 비슷하게 최적에 가까운 transform이 된다.

&ensp;5. Symmetrical Extension: DCT2-related to DFT<br/>
&ensp;DCT는 DFT의 real part가 아니다.<br/>
&ensp;DCT는 원래 신호를 대칭 확장한 뒤, 그 2N-point DFT와 관련 있다.<br/>

&ensp;5-1. 대칭 확장<br/>
&ensp;원래 N-point 신호가 있다고 하자.<br/>
$$x(0), x(1), ... , x(N-1)$$

&ensp;이걸 2N-point 신호 y(n)으로 확장한다.<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-31.png" width="600"></p>

&ensp;원래 신호 뒤에 거울처럼 뒤집힌 신호가 붙어 있다.<br/>
&ensp;예를 들어 원래 신호가 x = [4, 3, 2, 1] 이라면 대칭 확장하면 대략 이런 느낌이다. y[4, 3, 2, 1, 1, 2, 3, 4]<br/>
&ensp;원래 신호를 뒤집어서 이어 붙이는 것이다.<br/>
&ensp;-> symmetrical extension<br/>

&ensp;5-2. 왜 대칭 확장을 할까?<br/>
&ensp;DFT는 기본적으로 신호가 주기적으로 반복된다고 가정<br/>
&ensp;그런데 원래 신호를 그냥 DFT하면 경계에서 갑자기 점프가 생길 수 있다.<br/>

&ensp;예를 들어 신호가 [4, 3, 2, 1] 인데 주기적으로 반복된다고 보면 .., 4, 3, 2, 1, 4, 3, 2, 1, ... 이렇게 이어진다.<br/>

&ensp;여기서 1 -> 4 로 갑자기 점프한다.<br/>
&ensp;이런 경계 불연속은 고주파 성분을 많이 만든다. 그러면 에너지가 고주파로 퍼져서 압축에 불리해진다.<br/>
&ensp;반면 대칭 확장하면: 4, 3, 2, 1, 1, 2, 3, 4<br/>
&ensp;처럼 이어지니까 경계가 더 자연스러워진다.<br/>
&ensp;그래서 DCT는 DFT보다 이미지 압축에 유리한 경우가 많다.<br/>

&ensp;5-3. 식의 의미<br/>
&ensp;$Y(k) = 2N - DFT[y(n)]$ <br/>
&ensp;라고 되어있다.<br/>

&ensp;대칭 확장한 y(n)에 대해 2N-point DFT를 한다.<br/>

&ensp;DCT 행렬 A<br/>

&ensp;각 행이 하나의 basis vector이다. 입력 x와 각 basis vector를 내적하면 그 basis가 원본 신호 안에 얼마나 들어 있는지 계수 $F_i$ 가 나온다.<br/>
&ensp;DCT는 입력 신호 x가 각 cosine basis vector와 얼마나 닮았는지 내적해서 계수로 나타내는 것이다.<br/>

&ensp;Orthonormal basis vectors<br/>
&ensp;$ v_{i}\cdot v_{j} = \delta (i - j)$ <br/>

&ensp;orthonormality 정규직교성을 의미한다.<br/>

&ensp;$\delta (i - j)$ <br/>
&ensp;는 delta 함수이다.<br/>

&ensp;$i = j => v_{i} \cdot v_{j} = 1 $ <br/>
&ensp;$i \neq j => v_{i} \cdot v_{j} = 0$ <br/>

&ensp;같은 basis vector끼리 내적하면 1이고 서로 다른 basis vector끼리 내적하면 0이다.<br/>

&ensp;이게 왜 중요할까?<br/>
&ensp;정규직교 basis를 쓰면 좋은 점이 있다.<br/>
&ensp;1. 각 basis가 서로 겹치지 않는다. 즉 $F_{1}$ 성분과 $F_{2}$ 성분이 서로 독립적인 방향처럼 작동한다.<br/>
&ensp;2. 역변환이 쉬워진다.<br/>
&ensp;DCT 행렬 A가 orthonormal이면 $A^{-1} = A^{T}$ 이 된다.<br/>
&ensp;그래서 forward transform은 F = Ax 이고 inverse transform은 $x = A^{T}F$ 로 복원할 수 있다.<br/>

# Discrete Sine Transform, DST

&ensp;1. DCT와 DST의 가장 큰 차이<br/>
* DCT는 cosine basis를 씀
* DST는 sine basis를 씀

&ensp;둘 다 transform basis를 이용해 신호를 표현하지만, 사용하는 기본 파형이 다르다.<br/>

| 변환  | 사용하는 basis |
| --- | ---------- |
| DCT | cosine     |
| DST | sine       |

&ensp;2. DST-I 식의 의미<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-50.png" width="600"></p>

&ensp;입력 이미지 f(x, y)를 여러 sine basis와 비교해서 각 sine 패턴이 얼마나 들어 있는지 F(u, v)로 표현한다.<br/>
&ensp;DCT와 마찬가지로 2D DST도 x방향 sine, y방향 sine을 곱해서 2D basis를 만든다.<br/>

&ensp;3. DST는 anti-symmetric extension한 신호의 (2N+2)-point DFT와 관련 있다.<br/>

&ensp;DCT는 대칭 확장, DST는 반대칭 확장<br/>
&ensp;DCT는 신호를 대칭 확장한 것과 관련 있다.<br/>
&ensp;예를 들어 원래 신호가 [1, 2, 3]이면 대칭 확장은 느낌상 [1. 2, 3, 3, 2, 1] 처럼 거울처럼 붙이는 것이다.<br/>

&ensp;반면 DST는 반대칭 확장(anti-symmetric extension)과 관련 있다.<br/>
&ensp;느낌상 원래 신호 뒤에 부호가 반대인 뒤집힌 신호가 붙는 식이다.<br/>
&ensp;[1, 2, 3, -3, -2, -1]<br/>

| 변환  | DFT와의 관계                                    |
| --- | ------------------------------------------- |
| DCT | symmetrically extended signal의 DFT와 관련      |
| DST | anti-symmetrically extended signal의 DFT와 관련 |

&ensp;4. HEVC에서의 DST type 7<br/>
&ensp;실제 비디오 코덱인 HEVC/H.265에서 DST 계열 변환이 사용된다.<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-51.png" width="600"></p>

> DST-7은 sine basis를 사용하는 transform이고, HEVC/VVC 같은 영상 압축 표준에서 특정 residual block에 대해 사용될 수 있다.

# Hadamard Transform

&ensp;1. Hadamard Transform의 특징<br/>
&ensp;1) Real<br/>
&ensp;복소수가 아니라 실수만 사용한다.<br/>

&ensp;2) Symmetric<br/>
&ensp;변환 행렬이 대칭 구조를 가진다.<br/>

&ensp;3) Orthogonal<br/>
&ensp;기저들이 서로 직교한다.<br/>

&ensp;4) No multipliers<br/>
&ensp;Hadamard transform은 basis 값이 사실상 +1, −1로 이루어져 있다. 그래서 곱셈이 필요 없다. 그래서 하드웨어 구현이나 빠른 계산에 유리하다.<br/>

&ensp;2. Hadamard Transform 식 해석<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-52.png" width="600"></p>

&ensp;역변환도 비슷한 구조이다.<br/>
&ensp;α가 짝수면: $(-1)^{\alpha } = +1$ <br/>
&ensp;α가 홀수면: $(-1)^{\alpha } = -1$ <br/> 

&ensp;3. α(n,k) 의미<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-53.png" width="600"></p>

&ensp;여기서 n(i), k(i)는 각각 n, k를 이진수로 표현했을 때 i번째 bit이다. 즉 α(n,k)는 두 숫자의 비트끼리 곱해서 더한 값이다.<br/>

&ensp;4. Hadamard는 DCT보다 좋을까?<br/>

| 변환       | 장점                    | 단점                        |
| -------- | --------------------- | ------------------------- |
| DCT      | 에너지 집중 좋음, 이미지 압축에 강함 | cosine 계산 필요              |
| Hadamard | 곱셈 없이 빠름              | DCT만큼 자연 이미지에 최적은 아닐 수 있음 |

# Motion Compensation

&ensp;이미지는 한 장짜리 데이터지만, 영상은 여러 프레임이 시간 순서대로 이어진다.<br/>
&ensp;영상에서는 연속된 프레임이 대부분 비슷하다. 현재 프레임을 보면 이전 프레임과 완전히 다른 게 아니라 대부분은 비슷하고 일부 물체 위치만 바뀐다. -> temporal redundancy, 시간적 중복<br/>

&ensp;Motion Estimation과 Motion Compensation 차이<br/>
&ensp;Motion Estimation<br/>
&ensp;현재 블록과 가장 비슷한 블록을 이전 프레임이나 다음 프레임에서 찾는 과정이다.<br/>
&ensp;이때 찾은 이동량이 motion vector<br/>

&ensp;Motion Compensation<br/>
&ensp;찾은 motion vector를 이용해서 현재 블록을 예측하는 과정<br/>
&ensp;전 프레임의 해당 위치 블록을 가져와서 현재 블록의 예측값으로 사용한다.<br/>
&ensp;$Prediction block = F_{k-1}(x + m_{x}, y + m_{y})$ <br/>
&ensp;그리고 실제 현재 블록과 예측 블록의 차이를 구한다.<br/>
&ensp;Residual = Current block − Prediction block<br/>

&ensp;SAD 식<br/>
<p align="center"><img src="/assets/img/Digital Image Processing/chap8-4/8-60.png" width="600"></p>

&ensp;현재 프레임 $F_{k}$ 의 현재 블록과 이전 프레임 $F_{k-1}$ 에서 $(m_{x}, m_{y})$ 만큼 이동한 후보 블록의 픽셀 차이 절댓값을 모두 더한 것<br/>

| 기호           | 의미               |
| ------------ | ---------------- |
| $F_k$        | 현재 프레임           |
| $F_{k-1}$    | 이전 프레임           |
| $M \times N$ | 블록 크기            |
| $(m_x,m_y)$  | 후보 motion vector |
| SAD          | 절댓값 차이의 합        |

&ensp;SAD가 작다는 건 현재 블록과 후보 블록이 매우 비슷하다는 뜻이다.<br/>
&ensp;그래서 motion estimation은 보통 여러 후보 $(m_x, m_y)$ 를 검사해서 SAD가 가장 작은 위치를 찾는다.

&ensp;실제 motion estimation에서는 계산량 때문에 SAD가 많이 쓰이는 편이다.
제곱보다 절댓값이 계산이 간단한다.<br/>

&ensp;motion compensation 후에도 예측이 완벽하지는 않다. 현재 블록과 예측 블록 사이에 차이가 남는다. 그 차이를 residual signal이라고 한다. $Residual = Current − Prediction$ <br/>
&ensp;디코더는 motion vector로 예측 블록을 만들고, residual을 더해서 복원한다.<br/>
$$Reconstructed = Prediction + Residual$$

&ensp;residual을 보내는 게 유리한 이유<br/>
&ensp;현재 블록 자체는 값이 크고 복잡할 수 있다. 하지만 예측이 잘 되면 residual은 대부분 0 근처에 몰린다. 예를 들어 현재 블록과 예측 블록이 거의 같다면 Residual ≈ 0.<br/>
&ensp;그러면 residual은 DCT 후에도 많은 계수가 작아지고, 양자화와 entropy coding이 잘 먹힌다. <br/>
&ensp;영상 압축의 전체 흐름: Motion Estimation→Motion Compensation→Residual→Transform→Quantization→Entropy Coding<br/>
