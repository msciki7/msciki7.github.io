# 큐 ADT

&ensp;큐(Queue) = 먼저 들어온 것이 먼저 나가는 선형 자료구조 = FIFO (First-In First-Out)<br/>

<p align="center"><img src="/assets/img/data structure/10주차/10-1.png" width="600"></p>

* rear : 새 원소가 들어오는 쪽
    - 넣을 때는 rear
* front : 가장 먼저 들어온 원소가 나가는 쪽
    - 뺄 때는 front


&ensp;1. 큐 ADT는 임의의 개체들을 저장한다.<br/>
&ensp;2. 삽입과 삭제는 선입선출(FIFO) 순서를 따른다.<br/>
&ensp;3. 삽입은 rear, 삭제는 front에서 수행된다.<br/>

<p align="center"><img src="/assets/img/data structure/10주차/10-2.png" width="600"></p>

# 큐 ADT 메쏘드

&ensp;1. 주요 큐 메서드<br/>
* `enqueue(e)`
* `dequeue()`

&ensp;(1) enqueue(e)<br/>
&ensp;큐의 뒤에 원소를 삽입<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-4.png" width="600"></p>

* 새로운 원소는 rear 쪽으로 들어간다
* 기존 순서를 깨지 않고 뒤에 붙는다

&ensp;(2) dequeue()<br/>
&ensp;큐의 앞에서 원소를 삭제하여 반환<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-5.png" width="600"></p>

* 삭제 위치는 front
* 삭제와 동시에 그 원소를 돌려준다(return)

&ensp;즉 dequeue()는 그냥 없애기만 하는 게 아니라 보통 “앞 원소를 꺼내서 반환” 한다.<br/>

&ensp;2. 보조 큐 메서드<br/>
* `front()`
* `size()`
* `isEmpty()`
* `elements()`

&ensp;(1) front()<br/>
&ensp;큐의 앞에 있는 원소를 (삭제하지 않고) 반환<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-6.png" width="600"></p>

&ensp;dequeue()와 front()의 차이<br/>
* dequeue() : 앞 원소를 꺼내고 삭제함
* front()   : 앞 원소를 보기만 하고 삭제하지 않음

&ensp;(2) size()<br/>
&ensp;큐에 저장된 원소의 수를 반환<br/>

&ensp;(3) isEmpty()<br/>
&ensp;큐가 비어 있는지 여부를 반환<br/>
&ensp;큐 안에 아무 원소도 없으면 true, 하나라도 있으면 false<br/>

&ensp;(4) elements()<br/>
&ensp;큐 원소 전체를 반환<br/>
&ensp;즉 큐 안에 들어있는 원소들을 전체적으로 확인하는 기능<br/>
&ensp;큐는 순서가 중요하기 때문에 원소 전체를 볼 때도 그 순서를 유지해서 보여준다.<br/>

&ensp;3. 예외<br/>
* `emptyQueueException()`
* `fullQueueException()`

&ensp;(1) emptyQueueException()<br/>
&ensp;비어 있는 큐에 대해 삭제 또는 front를 수행 시도할 경우 발령<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-7.png" width="600"></p>

&ensp;빈 큐에서는 dequeue() 불가, front() 불가 <br/>

&ensp;(2) fullQueueException()<br/>
&ensp;만원 큐에 대해 삽입을 수행 시도할 경우 발령<br/>
&ensp;이건 큐의 크기가 제한된 경우에 등장한다.<br/>

&ensp;큐 응용<br/>
&ensp;1. 직접 응용<br/>
* 대기열, 관료적 체제
* 공유자원에 대한 접근, 예를 들어 프린터
* 멀티프로그래밍

&ensp;**“먼저 요청한 것이 먼저 처리되는 구조”** <br/>

&ensp;2. 공유자원 접근<br/>
&ensp;예를 들어 슬라이드에 프린터가 적혀 있는데, 핵심은 “자원이 하나인데 요청은 여러 개”인 상황<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-8.png" width="600"></p>

&ensp;즉 큐는 충돌 없이 순서대로 처리하기 위한 정렬 장치 역할을 한다.<br/>

&ensp;3. 멀티프로그래밍<br/>
&ensp;여러 작업(프로세스, 작업 요청 등)이 존재할 때 CPU나 어떤 자원에게 처리 대기 순서를 부여하는 구조로 큐가 쓰인다.<br/>

&ensp;4. 간접 응용<br/>
* 알고리즘 수행을 위한 보조 데이터구조
* 다른 데이터구조를 구성하는 요소

&ensp;간접 응용의 의미<br/>
&ensp;`처리할 항목들을 순서대로 저장 → 먼저 들어온 항목부터 하나씩 꺼내 처리 → 처리 중 새 항목이 생기면 뒤에 추가` <br/>
&ensp;이 구조가 필요한 알고리즘은 내부에서 큐를 사용한다.<br/>
&ensp;즉 겉으로는 “탐색 알고리즘”, “시뮬레이션”, “데이터 처리 과정”처럼 보이지만 속을 열어보면 큐가 보조 자료구조로 들어가 있다.<br/>

&ensp;5. 다른 데이터구조를 구성하는 요소<br/>
&ensp;큐가 단독으로만 존재하는 게 아니라 어떤 더 큰 구조나 시스템 안의 한 부품으로 쓰일 수도 있다는 뜻이다.<br/>
&ensp;즉 큐는 하나의 독립 자료구조이면서 동시에 다른 구조를 만드는 재료가 되기도 한다는 의미<br/>

# 배열에 기초한 큐

&ensp;배열에 기초한 큐의 기본 구조<br/>
&ensp;큐를 원형 배열 Q로 만든다.<br/>
&ensp;`Q[0], Q[1], Q[2], ..., Q[N-1]` <br/>
&ensp;크기가 N인 배열<br/>
&ensp;큐에서는 두 개의 위치 변수<br/>
* f : front 위치 = front 원소가 저장된 위치
* r : rear 위치 = rear 원소가 저장된 위치

&ensp;큐는 FIFO 구조니까 삭제는 f에서 하고, 삽입은 r 다음 위치에 한다.<br/>

&ensp;원형 배열을 쓰는 이유<br/>
&ensp;일반 배열로 큐를 만들면 문제가 생긴다.<br/>
&ensp;예를 들어 배열 크기가 N = 8있다고 하면<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-9.png" width="600"></p>

&ensp;여기서 dequeue()를 세 번 하면 앞의 원소들이 빠진다.<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-10.png" width="600"></p>

&ensp;앞쪽 0, 1, 2는 비었는데, 만약 계속 뒤쪽으로만 삽입하면 r이 배열 끝에 도달한다.<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-11.png" width="600"></p>

&ensp;이 상태에서 새 원소 I를 넣고 싶은데, 배열 뒤에는 자리가 없다. 하지만 앞쪽 0, 1, 2는 비어 있다. 7 다음은 0이다. `즉 (r + 1) % N` 을 사용해서 다음 위치를 계산한다.<br/>

&ensp;중요: 빈 칸 하나를 일부러 남긴다<br/>
&ensp;배열 칸을 전부 다 쓰지 않는다.<br/>
&ensp;크기가 N인 배열이라면 실제로 저장할 수 있는 원소 개수는 최대 N - 1개이다. 왜냐하면 빈 큐와 만원 큐를 구분하기 위해서<br/>

&ensp;1. 빈 큐 vs. 만원 큐<br/>
&ensp;빈 큐 상태<br/>
&ensp;빈 큐 조건: `(r + 1) % N = f`<br/>
&ensp;초기화할 때 설정<br/>
* f ← 0
* r ← N - 1

&ensp;만원 큐 상태<br/>
&ensp;만원 큐 조건: `(r + 2) % N = f` <br/>
&ensp;왜 r + 1이 아니라 r + 2냐면, r + 1 위치는 항상 비워두기로 약속했기 때문이다.<br/>

* 빈 큐  : rear 다음 칸이 front
    - 빈 큐  : rear 다음 칸이 front
* 만원 큐: rear 다음 다음 칸이 front
    - isFull()  : return (r + 2) % N = f

&ensp;enqueue(e)의 역할<br/>
&ensp;enqueue(e)는 원소 e를 큐의 뒤쪽, 즉 rear에 삽입하는 연산<br/>
1. 큐가 가득 찼는지 확인
2. rear를 한 칸 이동
3. 이동한 위치에 e 저장

&ensp;dequeue()의 역할<br/>
&ensp;dequeue()는 큐의 앞쪽 원소를 삭제하고 반환하는 연산<br/>
1. 큐가 비어 있는지 확인
2. front 위치의 원소를 e에 저장
3. front를 한 칸 이동
4. e를 반환

&ensp;4. size<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-19.png" width="600"></p>

&ensp;큐 원소들이 배열 안에서 두 가지 상태로 존재할 수 있다.<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-20.png" width="600"></p>

&ensp;경우 1. 원소들이 안 돌아간 상태<br/>
&ensp;예를 들어: `f = 3, r = 7` <br/>
&ensp;그러면 원소는 3, 4, 5, 6, 7에 들어있다.<br/>
&ensp;개수: `r - f + 1 = 7 - 3 + 1 = 5` <br/>

&ensp;경우 2. 원소들이 돌아간 상태<br/>
&ensp;예를 들어: `f = 6, r = 2, N = 8` <br/>
&ensp;이건 원소가 배열 끝을 지나 0번으로 돌아간 상태<br/>
&ensp;원소 위치: `6, 7, 0, 1, 2` <br/>

&ensp;그런데 단순히 r - f + 1을 하면: `2 - 6 + 1 = -3` -> 이상한 값<br/>

&ensp;그래서 원형 배열에서는 다음 식을 사용: `(N - f + r + 1) % N` <br/>
&ensp;계산해보면: `(8 - 6 + 2 + 1) % 8 = 5 % 8 = 5` <br/>

&ensp;5. front<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-21.png" width="600"></p>

&ensp;front()의 역할<br/>
&ensp;front()는 큐의 맨 앞 원소를 확인만 하는 함수(삭제하지는 않는다.)<br/>

&ensp;6. 성능과 제약<br/>
&ensp;성능<br/>
&ensp;큐의 원소 개수를 n이라 하면<br/>
* 기억장소 사용: O(n)
* 각 작업의 실행시간: O(1)

&ensp;제약<br/>
* 큐의 최대 크기를 예측할 수 있어야 하며 이 값은 실행 중 변경할 수 없다.(예외: 동적 할당)
* 만원 큐에 새로운 원소를 enqueue 시도할 경우 구현상의 오류를 일으킨다.

&ensp;크기 기억 방식<br/>
&ensp;위 의사코드들은 빈 큐와 만원 큐를 구분하기 위해 빈 칸 하나를 예비했다. 그런데 그러면 배열 크기가 N이어도 실제로는 N - 1개밖에 못 저장했다.<br/>
&ensp;대안: `원소 개수 n을 따로 저장하자.` <br/>

&ensp;기존 방식<br/>
* f, r만 사용
* 빈 칸 하나 남김
* 최대 저장 개수 = N - 1

&ensp;대안 방식<br/>
* f, r, n 사용
* n = 현재 큐에 저장된 원소 개수
* 빈 칸을 남길 필요 없음
* 최대 저장 개수 = N

&ensp;을 직접 관리하면 빈 큐와 만원 큐를 쉽게 구분할 수 있다.<br/>
* isEmpty() : n = 0
* isFull()  : n = N
* size()    : return n

&ensp;이 경우 필요한 코드 변경<br/>
* size()
* isEmpty()
* isFull()
* initQueue()
* enqueue()
* dequeue()

| 구분       | 빈 칸 하나 남기는 방식         | 원소 개수 n 관리 방식  |
| -------- | --------------------- | -------------- |
| 사용하는 변수  | `f`, `r`              | `f`, `r`, `n`  |
| 빈 큐 조건   | `(r + 1) % N = f`     | `n = 0`        |
| 만원 큐 조건  | `(r + 2) % N = f`     | `n = N`        |
| size     | `(N - f + r + 1) % N` | `n`            |
| 최대 저장 개수 | `N - 1`개              | `N`개           |
| 장점       | 변수 하나 덜 사용            | 배열 공간을 전부 사용   |
| 단점       | 한 칸 낭비                | `n`을 계속 갱신해야 함 |

# 연결리스트 기반 큐

&ensp;연결리스트에 기초한 큐의 구조<br/>
* 단일연결리스트로 큐를 구현한다.
* front 원소는 첫 노드에 저장한다.
* rear 원소는 끝 노드에 저장한다.
* f는 첫 노드를 가리킨다.
* r은 끝 노드를 가리킨다.

<p align="center"><img src="/assets/img/data structure/10주차/10-22.png" width="600"></p>

```css
f
↓
[A | next] → [B | next] → [C | NULL]
                              ↑
                              r
```

&ensp;왜 단일연결리스트만으로 충분한가?<br/>
&ensp;삽입과 삭제가 특정 위치에서만 수행되므로, 역방향 링크는 불필요<br/>
* 삽입: rear 뒤에 새 노드 추가
* 삭제: front 노드 제거

&ensp;즉, 중간 노드를 삭제하거나 뒤에서 앞으로 거슬러 올라갈 일이 없다. 그래서 이중연결리스트처럼 prev가 필요 없다.<br/>

&ensp;배열 기반 큐와 연결리스트 기반 큐 비교<br/>
&ensp;배열 기반 큐는 크기가 정해져 있다.<br/>
&ensp;그래서 N이 있고, 큐가 꽉 차면 fullQueueException이 발생했다.<br/>
&ensp;하지만 연결리스트 기반 큐는 필요할 때마다 새 노드를 만들 수 있다.<br/>
* enqueue 할 때마다 새 노드 생성
* dequeue 할 때마다 노드 반환 또는 삭제

&ensp;그래서 일반적으로 큐가 가득 찼는지 검사하는 isFull()이 필요 없다.<br/>

&ensp;성능<br/>
* 기억장소 사용: O(n)
* 큐 ADT의 각 작업: O(1)

&ensp;n은 큐에 들어 있는 원소 개수<br/>

&ensp;1. 초기화<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-23.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/10주차/10-24.png" width="600"></p>

&ensp;초기에는 큐에 아무 노드도 없다.<br/>
* f = ∅
* r = ∅

&ensp;큐가 비어 있으면 첫 노드도 없고 끝 노드도 없다.<br/>

&ensp;2. isEmpty<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-25.png" width="600"></p>

&ensp;큐가 비어 있는지는 f가 비어 있는지만 보면 된다.<br/>
* f = ∅ 이면 빈 큐
* f ≠ ∅ 이면 원소가 있음

&ensp;왜냐하면 f는 첫 노드를 가리키는 포인터. 첫 노드가 없다는 것은 큐에 원소가 하나도 없다는 뜻이다.<br/>

&ensp;3. 삽입<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-26.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/10주차/10-27.png" width="600"></p>

&ensp;빈 큐일 때와 비어 있을 때 처리가 다르다.<br/>
&ensp;enqueue(e)는 큐의 뒤에 새 원소를 넣는 연산이다. 연결리스트에서는 새 원소를 넣으려면 먼저 새 노드를 만들어야 한다.<br/>
1. 새 노드 p를 만든다.
2. p 안에 e를 저장한다.
3. p.next를 ∅로 둔다.
4. 큐가 비었으면 f와 r이 모두 p를 가리키게 한다.
5. 큐가 비어 있지 않으면 기존 rear 뒤에 p를 붙이고 r을 p로 옮긴다.

&ensp;빈 큐인 경우<br/>
```python
if (isEmpty())
    f, r ← p
```

&ensp;큐가 비어 있으면 현재 노드가 하나도 없다.<br/>
* f = ∅
* r = ∅

&ensp;여기에 새 노드 p를 넣으면, 이 노드는 동시에첫 노드, 끝 노드가 된다.<br/>
```css
f
↓
[X | ∅]
↑
r
```

&ensp;빈 큐가 아닌 경우<br/>
```python
else
    r.next ← p
    r ← p
```

&ensp;예를 들어 현재 큐가:<br/>
```css
f
↓
[A] → [B] → ∅
       ↑
       r
```

&ensp;여기서 enqueue(X)를 하면 새 노드 p를 만든다.<br/>
```css
p → [X | ∅]
```

&ensp;이 노드를 기존 rear 뒤에 붙여야 한다. 현재 r은 B를 가리키고 있다.<br/>
```css
r.next ← p
```

&ensp;이걸하면 `[A] → [B] → [X] → ∅` 이 된다.<br/>
&ensp;그런데 아직 r은 B를 가리키고 있으니 r를 마지막 노드 X로 옮겨야 한다.<br/>
```css
f
↓
[A] → [B] → [X] → ∅
              ↑
              r
```

&ensp;마지막 원소를 삭제한 경우 r ← ∅ 처리<br/>
&ensp;dequeue()는 큐의 앞 원소를 삭제하고 반환하는 연산<br/>
&ensp;연결리스트 큐에서는 front가 첫 노드이므로 첫 노드를 제거하면 된다.<br/>
1. 큐가 비었는지 검사한다.
2. front 노드의 원소를 e에 저장한다.
3. 삭제할 노드를 p에 저장한다.
4. f를 다음 노드로 이동한다.
5. 이동 후 큐가 비었으면 r도 ∅로 만든다.
6. 삭제한 노드 p를 메모리에서 반환한다.
7. e를 반환한다.

&ensp;enqueue와 dequeue 비교<br/>

| 연산           | 핵심 위치  | 포인터 변화                | 반환         |
| ------------ | ------ | --------------------- | ---------- |
| `enqueue(e)` | rear 뒤 | `r.next ← p`, `r ← p` | 없음         |
| `dequeue()`  | front  | `p ← f`, `f ← f.next` | 삭제한 원소 `e` |

# 데크(Deque) ADT

```css
데크 Deque

rear            front
 ↓               ↓
[ A ][ B ][ C ][ D ]

front 쪽에서도 삽입/삭제 가능
rear 쪽에서도 삽입/삭제 가능
```

&ensp;앞에서도 넣고 뺄 수 있고, 뒤에서도 넣고 뺄 수 있는 자료구조<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-30.png" width="600"></p>

&ensp;데크 ADT는 임의의 객체들을 저장한다.<br/>
&ensp;데크는 double-ended queue, 즉 양쪽 끝 큐이다.<br/>
&ensp;삽입과 삭제가 front와 rear 양쪽에서 모두 가능하다.<br/>

&ensp;왜 “스택과 큐의 합체”라고 하는가?<br/>
&ensp;스택은 한쪽 끝에서만 삽입과 삭제<br/>
```css
스택 Stack

top
 ↓
[ C ]
[ B ]
[ A ]

push  : top에 삽입
pop   : top에서 삭제
```

&ensp;큐는 한쪽에서 넣고, 반대쪽에서 뺀다.<br/>
```css
큐 Queue

rear       front
 ↓          ↓
[ A ][ B ][ C ]

enqueue : rear에서 삽입
dequeue : front에서 삭제
```

&ensp;데크는 이 둘을 모두 포함<br/>
```css
데크 Deque

rear       front
 ↓          ↓
[ A ][ B ][ C ]

front에서도 삽입/삭제 가능
rear에서도 삽입/삭제 가능
```

&ensp;데크는 사용 방식에 따라 스택처럼도 쓸 수 있고, 큐처럼도 쓸 수 있다.<br/>

&ensp;데크 ADT 메서드<br/>
* push(e)   : front 위치에 원소 삽입
* pop()     : front 위치의 원소 삭제 후 반환
* inject(e) : rear 위치에 원소 삽입
* eject()   : rear 위치의 원소 삭제 후 반환

&ensp;push(e)<br/>
&ensp;예를 들어 현재 데크가<br/>
```css
front      rear
 ↓          ↓
[ A ][ B ][ C ]
```

&ensp;여기서 push(X)를 하면 X가 front 쪽에 들어간다.<br/>
```css
front           rear
 ↓               ↓
[ X ][ A ][ B ][ C ]
```

&ensp;`push(e) = 앞쪽에 넣기` <br/>

&ensp;pop()<br/>
```css
front           rear
 ↓               ↓
[ X ][ A ][ B ][ C ]

pop() 실행
반환값: X
```

&ensp;결과<br/>
```css
front      rear
 ↓          ↓
[ A ][ B ][ C ]
```

&ensp;`pop() = 앞쪽에서 빼기` <br/>

&ensp;inject(e)<br/>
&ensp;inject는 데크의 rear 쪽에 새 원소를 넣는 연산<br/>
```css
front      rear
 ↓          ↓
[ A ][ B ][ C ]

inject(X)
```

&ensp;결과:<br/>
```css
front           rear
 ↓               ↓
[ A ][ B ][ C ][ X ]
```

&ensp;eject()<br/>
&ensp;eject는 rear 쪽에서 삭제하는 연산<br/>
```css
front           rear
 ↓               ↓
[ A ][ B ][ C ][ X ]

eject() 실행
반환값: X
```

&ensp;결과:<br/>
```css
front      rear
 ↓          ↓
[ A ][ B ][ C ]
```

&ensp;배열에 기초한 데크<br/>
&ensp;앞에서 큐를 배열로 구현할 때와 거의 같은 방식<br/>
* 크기 N의 배열을 원형으로 사용한다.
* front와 rear 위치를 f, r로 관리한다.
* 빈 데크와 만원 데크를 구분하기 위해 한 칸을 비워둔다.

&ensp;배열 기반 큐와 배열 기반 데크의 차이<br/>
&ensp;배열 기반 큐에서는 삽입 : rear 쪽만, 삭제 : front 쪽만<br/>
&ensp;그래서 의사코드도 주로 r은 삽입 때만 움직이고, f는 삭제 때만 움직였다.<br/>
&ensp;하지만 데크에서는 양쪽에서 모두 삽입/삭제가 가능<br/>
* push(e)   : front 쪽 삽입 → f가 움직임
* pop()     : front 쪽 삭제 → f가 움직임
* inject(e) : rear 쪽 삽입 → r이 움직임
* eject()   : rear 쪽 삭제 → r이 움직임

&ensp;배열을 원형으로 쓰는 이유<br/>
&ensp;일반 배열을 그대로 쓰면 한쪽 끝에 도달했을 때 앞쪽 빈 공간을 활용하기 어렵다. 그래서 큐와 마찬가지로 데크도 배열을 원형으로 사용한다.<br/>
&ensp;`0, 1, 2, ..., N-1 다음은 다시 0` <br/>
&ensp;이때 다음 칸 이동은: `(i + 1) % N` <br/>
&ensp;이전 칸 이동은: `(i - 1 + N) % N` <br/>
&ensp;큐에서는 주로 한 방향 이동만 많이 봤지만, 데크에서는 앞쪽으로도 삽입해야 하니까 이전 칸 이동도 필요<br/>

&ensp;빈 칸 하나를 예비하는 이유<br/>
&ensp;배열 크기가 N이어도 실제 최대 저장 개수는 N - 1개<br/>
&ensp;왜냐하면 f와 r만으로 빈 상태와 가득 찬 상태를 구분해야 하기 때문이다.<br/>
&ensp;배열 기반 큐에서 봤던 것처럼 빈 상태와 만원 상태가 포인터 모양만 보면 헷갈릴 수 있다. 그래서 한 칸을 일부러 비워서 구분한다.<br/>

&ensp;데크 연산 방향 정리<br/>

| 연산          | 위치    | 동작         | 포인터 이동      |
| ----------- | ----- | ---------- | ----------- |
| `push(e)`   | front | front에 삽입  | `f`를 이전 칸으로 |
| `pop()`     | front | front에서 삭제 | `f`를 다음 칸으로 |
| `inject(e)` | rear  | rear에 삽입   | `r`을 다음 칸으로 |
| `eject()`   | rear  | rear에서 삭제  | `r`을 이전 칸으로 |

&ensp;연결리스트에 기초한 데크<br/>
&ensp;큐와 달리 이중연결리스트를 사용한다.<br/>

&ensp;이중연결리스트 기반 데크 구조<br/>
<p align="center"><img src="/assets/img/data structure/10주차/10-31.png" width="600"></p>

&ensp;삽입과 삭제가 특정 위치에서만 수행되므로, 특별노드는 불필요<br/>
&ensp;데크에서는 삽입/삭제 위치가 항상 양 끝이다.<br/>
&ensp;중간에 끼워 넣거나 중간에서 삭제하는 일반 리스트 연산보다 단순하다. 그래서 반드시 헤더/트레일러 더미 노드를 둘 필요는 없다는 뜻이다.<br/>

&ensp;연결리스트 기반 데크의 성능<br/>
* 기억장소 사용은 O(n)
* 데크 ADT의 각 작업은 O(1)

&ensp;큐와 데크 비교<br/>


| 구분       | 큐                    | 데크                               |
| -------- | -------------------- | -------------------------------- |
| 의미       | 한쪽 삽입, 반대쪽 삭제        | 양쪽 삽입, 양쪽 삭제                     |
| 삽입       | rear에서만              | front, rear 둘 다                  |
| 삭제       | front에서만             | front, rear 둘 다                  |
| 주요 연산    | `enqueue`, `dequeue` | `push`, `pop`, `inject`, `eject` |
| 배열 구현    | 원형 배열                | 원형 배열                            |
| 연결리스트 구현 | 단일연결리스트 가능           | 이중연결리스트 필요                       |
| 이유       | rear 삭제가 없기 때문       | rear 삭제 시 이전 노드 필요               |

# 응용 문제

&ensp;1. 두 개의 스택을 이용해서 큐 ADT를 구현하라.<br/>

&ensp;큐는 FIFO<br/>
```css
큐 Queue:
먼저 들어온 원소가 먼저 나간다.

enqueue A
enqueue B
enqueue C

dequeue → A
dequeue → B
dequeue → C
```

&ensp;그런데 스택은 LIFO.<br/>
```css
스택 Stack:
나중에 들어온 원소가 먼저 나간다.

push A
push B
push C

pop → C
pop → B
pop → A
```

&ensp;즉 큐와 스택은 꺼내는 순서가 반대이다. 그래서 스택 하나만으로는 큐를 만들기 어렵고 스택 두 개를 이용해서 순서를 한 번 뒤집어야 한다.<br/>

&ensp;2. 사용할 스택 두 개<br/>
* S1 : enqueue 작업에 사용 = 입력용 스택
* S2 : dequeue 작업에 사용 = 출력용 스택

&ensp;enqueue(e) 할 때: 무조건 S1에 push<br/>
&ensp;dequeue() 할 때: S2에서 pop<br/>
&ensp;단, S2가 비어 있으면 S1의 원소를 전부 S2로 옮긴 후 pop<br/>

&ensp;왜 S1에서 S2로 옮기면 큐 순서가 되는가?<br/>
&ensp;예를 들어 큐에 A, B, C를 차례로 넣는다고 해보자.<br/>
* enqueue A
* enqueue B
* enqueue C

&ensp;이때 enqueue는 전부 S1.push()로 처리한다. 그러면 S1은 이렇게 되어 있다.<br/>
```css
S1 top
 ↓
 C
 B
 A
```

&ensp;스택이니까 가장 위에는 마지막에 들어온 C가 있다. 그런데 큐라면 먼저 나가야 하는 건 A이다. 그래서 이 상태에서 바로 S1.pop()을 하면 안 된다. C가 먼저 나오니까 큐가 아니라 스택이 된다. 그래서 S1의 원소를 전부 S2로 옮긴다.<br/>
&ensp;`S1.pop() → S2.push()` <br/>
```css
S1에서 C pop → S2에 C push
S1에서 B pop → S2에 B push
S1에서 A pop → S2에 A push
```

&ensp;그러면 S2는 이렇게 된다.<br/>
```css
S2 top
 ↓
 A
 B
 C
```

&ensp;이제 S2.pop()을 하면 A가 나온다. 스택을 한 번 옮기면서 순서가 뒤집히기 때문에 큐의 FIFO 순서가 만들어진다.<br/>

&ensp;문제 조건<br/>
&ensp;두 개의 일반 스택을 이용하여 큐 ADT를 구현하라.<br/>
&ensp;전제: 주어진 스택들은 isEmpty, top, push, pop 등의 기본 메서드를 상수시간에 수행한다. 단, size 메서드는 지원하지 않는다.<br/>
&ensp;스택에 원소가 몇 개인지 직접 물어볼 수 없다.<br/>

&ensp;그래서 반복문을 돌릴 때도 `while (!S1.isEmpty())` 이렇게 써야 한다.<br/>

&ensp;주의: 큐 ADT에는 중복 원소 저장 가능<br/>
&ensp;`큐 ADT에는 중복 원소들의 저장이 가능 = 큐가 집합이 아니라는 뜻` <br/>
&ensp;집합은 보통 같은 원소를 중복 저장하지 않는다. 하지만 큐는 순서가 있는 저장 구조라서 같은 값이 여러 번 들어갈 수 있다.<br/>
```css
enqueue A
enqueue A
enqueue B

큐 상태: A, A, B
```

&ensp;따라서 enqueue(e) 할 때 “이미 있는 원소인지” 검사하면 안 된다.<br/>

&ensp;해결 방법: 합동스택<br/>
&ensp;각각의 스택을 S1 및 S2라고 하면, S1을 enqueue 작업에, S2를 dequeue 작업에 사용한다.<br/>
```css
enqueue(e):
S1.push(e)

dequeue():
S2가 비어 있지 않으면 S2.pop()
S2가 비어 있으면 S1의 모든 원소를 S2로 옮긴 뒤 S2.pop()
```

&ensp;enqueue 의사코드<br/>
```python
Alg enqueue(e)
input element e, stack S1, stack S2
output none

1. S1.push(e)
2. return
```

&ensp;새로 들어오는 원소는 일단 전부 S1에 쌓는다.<br/>
```css
S1 top
 ↓
 C
 B
 A

S2 empty
```

&ensp;dequeue 의사코드<br/>
```python
Alg dequeue()
input stack S1, stack S2
output element

1. if (S2.isEmpty())
       if (S1.isEmpty())
           emptyQueueException()
       while (!S1.isEmpty())
           S2.push(S1.pop())
2. return S2.pop()
```

&ensp;왜 S2가 비었을 때만 옮기는가?<br/>
&ensp;dequeue() 할 때마다 매번 S1을 S2로 옮기면 안 된다. 왜냐하면 S2에 아직 먼저 나가야 할 원소들이 남아 있기 때문이다.<br/>

&ensp;성능 분석<br/>
* enqueue: O(1)
* dequeue: O(1) 상각실행시간

&ensp;dequeue는 왜 항상 O(1)은 아닌가?<br/>
&ensp;경우 1. S2가 비어 있지 않음<br/>
&ensp;`return S2.pop()` -> `O(1)` <br/>
&ensp;경우 2. S2가 비어 있음<br/>
&ensp;이때는 S1의 원소를 전부 S2로 옮겨야 한다.<br/>
&ensp;만약 S1에 원소가 k개 있다면:<br/>
```python
while (!S1.isEmpty())
    S2.push(S1.pop())
```

&ensp;이 반복이 k번 수행된다. 그래서 이 순간만 보면: `O(k)` <br/>

&ensp;상각실행시간이란?<br/>
&ensp;`가끔 오래 걸리는 작업이 있어도, 여러 번 연산 전체를 평균 내면 한 번당 O(1)로 볼 수 있다.` <br/>
&ensp;원소 하나를 생각해보면<br/>
1. enqueue 때 S1에 한 번 push됨
2. 어느 순간 S1에서 한 번 pop됨
3. S2에 한 번 push됨
4. dequeue 때 S2에서 한 번 pop됨

&ensp;즉 원소 하나가 스택 연산을 당하는 횟수는 많아야 몇 번으로 정해져 있다. (원소 하나당 이동 횟수는 상수 번) 그래서 연산을 많이 수행했을 때 전체 비용을 평균 내면 dequeue도 한 번당 O(1)로 볼 수 있다.<br/>

&ensp;2. 두 개의 일반 큐를 이용하여 스택 ADT를 구현하라.<br/>

&ensp;큐와 스택의 성질 차이<br/>

&ensp;Queue: First-In First-Out(먼저 들어온 것이 먼저 나간다.)<br/>
&ensp;예를 들어 큐에 A, B, C를 넣으면:<br/>
```css
enqueue A
enqueue B
enqueue C

dequeue → A
dequeue → B
dequeue → C
```

&ensp;Stack: Last-In First-Out(나중에 들어온 것이 먼저 나간다.)<br/>
&ensp;스택에 A, B, C를 넣으면:<br/>
```css
push A
push B
push C

pop → C
pop → B
pop → A
```

&ensp;그러니까 큐 2개로 스택을 만들려면, pop()할 때 가장 마지막에 들어온 원소만 앞쪽으로 빼낼 수 있게 만들어야 한다.<br/>

&ensp;문제 조건<br/>
&ensp;전제: 주어진 큐들은 isEmpty, front, enqueue, dequeue 등의 기본 메서드들을 상수시간에 수행한다. size 메서드는 지원하지 않는다.<br/>

&ensp;해결 전략: 합동큐<br/>
&ensp;`각각의 큐를 Q1 및 Q2라고 하면, Q1을 push 작업에, Q2를 pop 작업에 사용` <br/>
&ensp;실행시간<br/>
* push: O(1)
* pop: O(n)

&ensp;핵심 아이디어<br/>
```css
push(e):
    Q1에 enqueue(e)

pop():
    Q1에서 마지막 원소 하나만 남을 때까지
    앞 원소들을 dequeue해서 Q2에 enqueue한다.
    마지막으로 남은 원소를 dequeue해서 반환한다.
    Q1과 Q2의 역할을 바꾼다.
```

&ensp;큐 Q1에 A, B, C를 순서대로 넣으면 상태<br/>
&ensp;`Q1 front → A B C ← rear` <br/>
&ensp;큐에서 그냥 dequeue()하면 A가 나온다. 하지만 스택의 pop()은 C가 나와야 한다. 그래서 A와 B를 잠시 Q2로 옮기고 마지막 원소 C만 꺼낸다.<br/>
```css
Q1: A B C

A를 Q2로 이동
Q1: B C
Q2: A

B를 Q2로 이동
Q1: C
Q2: A B

이제 Q1에 마지막 원소 C만 남음
C를 dequeue해서 반환
```

&ensp;그 다음 남은 원소들은 Q2에 있으니까, 이제 Q2를 새 주 큐로 사용하면 된다.<br/>

&ensp;그런데 size 메서드가 없는데 “마지막 하나만 남을 때까지”를 어떻게 아나?<br/>
&ensp;문제 조건에서 큐는 size()를 지원하지 않는다고 했다. 그러면 pop()에서 원소 개수를 알아야 하니까, 스택 구현체가 별도의 변수 n을 가지고 있어야 한다.<br/>
&ensp;`n = 현재 스택에 저장된 원소 개수` <br/>
* push(e) 할 때 n ← n + 1
* pop() 할 때 n ← n - 1

&ensp;push 의사코드<br/>
```python
Alg push(e)
input queue Q1, queue Q2, integer n, element e
output none

1. Q1.enqueue(e)
2. n ← n + 1
3. return
```

&ensp;새 원소는 그냥 Q1 뒤에 넣는다.<br/>
```css
push A
push B
push C
```

&ensp;를 하면:<br/>
```css
Q1: A B C
Q2: empty
n = 3
```

&ensp;이 된다.<br/>
&ensp;push는 큐의 enqueue 한 번만 수행하니까 O(1)<br/>

&ensp;pop 의사코드<br/>
```python
Alg pop()
input queue Q1, queue Q2, integer n
output element

1. if (n = 0)
       emptyStackException()
2. for i ← 1 to n - 1
       Q2.enqueue(Q1.dequeue())
3. e ← Q1.dequeue()
4. n ← n - 1
5. while (!Q2.isEmpty())
       Q1.enqueue(Q2.dequeue())
6. return e
```

&ensp;두 개의 스택으로 큐 만들기 vs 두 개의 큐로 스택 만들기<br/>

| 문제           | 입력 연산           | 출력 연산                    | 핵심 아이디어                  | 시간                            |
| ------------ | --------------- | ------------------------ | ------------------------ | ----------------------------- |
| 두 스택으로 큐 만들기 | `S1.push(e)`    | `S2.pop()`               | 필요할 때 S1을 S2로 옮겨 순서 뒤집기  | enqueue O(1), dequeue 상각 O(1) |

#include <stdio.h>
#include <stdlib.h>

int q;
int front;
int rear;

void init(int *arr) {
    front = 0;
    rear = 0;

    for (int i = 0; i < q; i++) {
        arr[i] = 0;
    }
}

void printQueue(int *arr) {
    for (int i = 0; i < q; i++) {
        printf(" %d", arr[i]);
    }
    printf("\n");
}

int insert(int *arr, int value) {

    if ((rear + 1) % q == front) {
        printf("overflow");
        printQueue(arr);
        return 0;
    }

    rear = (rear + 1) % q;
    arr[rear] = value;

    return 1;
}

int deleteQueue(int *arr) {
    // 공백 상태: front와 rear가 같으면 삭제할 원소 없음
    if (front == rear) {
        printf("underflow\n");
        return 0;
    }

    front = (front + 1) % q;
    arr[front] = 0;

    return 1;
}

int main() {
    int n;
    scanf("%d", &q);
    scanf("%d", &n);

    int *arr = (int *)malloc(q * sizeof(int));

    init(arr);

    char op;
    int value;

    for (int i = 0; i < n; i++) {
        scanf(" %c", &op);

        if (op == 'I') {
            scanf("%d", &value);

            if (insert(arr, value) == 0) {
                free(arr);
                return 0;
            }
        }
        else if (op == 'D') {
            if (deleteQueue(arr) == 0) {
                free(arr);
                return 0;
            }
        }
        else if (op == 'P') {
            printQueue(arr);
        }
    }

    free(arr);

    return 0;
}

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct Node {
    int data;
    struct Node* prev;
    struct Node* next;
} Node;

Node* front = NULL;
Node* rear = NULL;

Node* createNode(int data) {
    Node* newNode = (Node*)malloc(sizeof(Node));
    newNode->data = data;
    newNode->prev = NULL;
    newNode->next = NULL;
    return newNode;
}

void add_front(int data) {
    Node* newNode = createNode(data);

    if (front == NULL) {
        front = newNode;
        rear = newNode;
        return;
    }

    newNode->next = front;
    front->prev = newNode;
    front = newNode;
}

void add_rear(int data) {
    Node* newNode = createNode(data);

    if (rear == NULL) {
        front = newNode;
        rear = newNode;
        return;
    }

    newNode->prev = rear;
    rear->next = newNode;
    rear = newNode;
}

void delete_front() {
    if (front == NULL) {
        printf("underflow");
        exit(0);
    }

    Node* temp = front;

    if (front == rear) {
        front = NULL;
        rear = NULL;
    } else {
        front = front->next;
        front->prev = NULL;
    }

    free(temp);
}

void delete_rear() {
    if (rear == NULL) {
        printf("underflow");
        exit(0);
    }

    Node* temp = rear;

    if (front == rear) {
        front = NULL;
        rear = NULL;
    } else {
        rear = rear->prev;
        rear->next = NULL;
    }

    free(temp);
}

void printDeque() {
    Node* p = front;

    while (p != NULL) {
        printf(" %d", p->data);
        p = p->next;
    }

    printf("\n");
}

    for (int i = 0; i < n; i++) {
        char op[3];

        if (strcmp(op, "AF") == 0) {

            add_front(x);
        } else if (strcmp(op, "AR") == 0) {
            scanf("%d", &x);
            add_rear(x);
        } else if (strcmp(op, "DF") == 0) {
