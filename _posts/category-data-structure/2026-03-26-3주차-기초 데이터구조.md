# 1. 기초 데이터구조 개념

&ensp;데이터구조는 건물의 재료와 구조물이고, 알고리즘은 그 위에서 동작하는 시스템이라고 볼 수 있다. 이때 배열과 연결리스트는 이후에 배우게 될 스택, 큐, 트리 같은 고급 자료구조를 만드는 가장 기본 재료다.<br/>

&ensp;핵심 포인트<br/>
* 배열과 연결리스트는 가장 기본적인 저장 구조이다.
* 추상적인 개념보다 실제로 메모리에 어떻게 저장되는가에 가깝다.
* 이후 고급 자료구조를 이해하려면 먼저 이 둘의 차이를 알아야 한다.



# 2. 배열(Array)

&ensp;1. 배열의 개념<br/>
&ensp;배열은 같은 자료형의 데이터들을 연속되니 메모리 공간에 저장하는 구조이다.<br/>

&ensp;배열의 주요 용어<br/>
* 배열명(array name): 배열 전체를 가리키는 이름
* 배열크기(array size): 저장할 수 있는 원소 개수
* 배열첨자(index): 각 원소의 위치 번호
* 배열원소(element): 실제 저장된 값

&ensp;예를 들어 `V[0..7]` 이라면
* 시작 인덱스는 0
* 끝 인덱스는 7
* 총 8개의 원소를 저장할 수 있다.

<p align="center"><img src="/assets/img/data structure/3주차/3-1.png" width="600"></p>


&ensp;배열의 특징<br/>
* 같은 타입의 값만 저장 가능
* 인덱스를 이용해서 빠르게 접근 가능
* 메모리가 연속적으로 배치됨

&ensp;즉 배열의 가장 큰 장점은 접근 속도다. `V[4]` 처럼 위치를 알면 바로 갈 수 있다.<br/>

&ensp;2. 배열의 메모리 할당<br/>
&ensp;배열은 컴파일 시점에 연속된 공간이 확보된다. 배열의 첫 번째 원소가 저장된 위치를 base라고 하고 어떤 원소가 base에서 얼마나 떨어져 있는지를 offset이라 한다.<br/>

&ensp;base<br/>
* 배열의 첫 번째 원소가 저장된 시작 주소
* 배열 전체의 출발점

&ensp;offset<br/>
* base로부터 몇 칸 떨어져 있는가
* 원하는 원소까지의 상대적인 거리

&ensp;offset 계산<br/>
* `V[LB..UB]` 에서 `V[k]` 의 offset = `k - LB`

&ensp;예를 들어<br/>
* 배열이 `V[3...10]`
* 찾고 싶은 위치가 `V[7]`

&ensp;이면<br/>
* offset = `7 - 3 = 4`

<p align="center"><img src="/assets/img/data structure/3주차/3-2.png" width="600"></p>

&ensp;`V[7]` 은 base로부터 4칸 떨어진 위치에 저장된다. 이 개념이 중요한 이유는 **배열 원소 접근이 수식으로 바로 계산 가능하기 때문**이다.<br/>

&ensp;중요한 이유<br/>
&ensp;배열은 중간에 있는 값을 찾을 때<br/>
* 앞에서부터 하나씩 찾는 게 아니라
* 계산으로 바로 위치를 알아낼 수 있다.

&ensp;그래서 배열은 접근 속도(access speed)가 빠른 구조<br/>

&ensp;왜 배열 접근이 빠를까?<br/>
&ensp;배열은 각 칸이 붙어 있으므로<br/>
* 시작 주소(base)를 알고
* 몇 칸 떨어졌는지(offset)를 계산하면
* 즉시 원하는 위치를 찾을 수 있다.

&ensp;그래서 배열은 랜덤 접근(random access)이 매우 빠르다.<br/>



# 3. 다차원 배열

&ensp;1. 다차원 배열<br/>
&ensp;다차원 배열은 말 그대로 차원이 2개 이상인 배열이다.<br/>
&ensp;예<br/>
* 1차원 배열: 한 줄
* 2차원 배열: 표
* 3차원 배열: 표가 여러 장 쌓인 형태
* 4차원 배열: 3차우너 구조가 시간이나 연도 축까지 포함된 형태

&ensp;1차원 배열과의 차이<br/>
&ensp;1차원 배열은 한 줄로 생각하면 됨<br/>
&ensp;예<br/>
* V[0]
* V[1]
* V[2]

&ensp;그런데 다차원 배열은<br/>
* 2차원: 표(table)
* 3차원: 표 여러 장
* 4차원: 3차원 구조가 시간축까지 포함된 형태

&ensp;다차원 배열에서는 배열의 방들이 `n > 1` 차원에 할당된다.<br/>
* 2차원 배열: 행과 열
* 3차원 배열: 층 + 행 + 열
* n차원 배열: 여러 기준으로 데이터를 구분

&ensp;배열 크기<br/>
&ensp;다차원 배열 전체 크기는 **각 차원의 크기를 곱한 값**<br/>
* 3 × 8 배열이면 총 24
* 4 × 3 × 8 배열이면 총 96

&ensp;개의 원소가 있다.<br/>

&ensp;1-2. 다차원 배열의 메모리 할당<br/>
&ensp;다차원 배열도 겉보기만 여러 차원이지 실제로 메모리에는 1차원처럼 차례대로 저장된다.<br/>

&ensp;행우선 순서(row-major order)<br/>
&ensp;행우선 순서 또는 저차원우선 순서라고 표현한다.<br/>

* 먼저 앞쪽 차원의 원소들을 모두 저장하고
* 그 다음 뒤쪽 차원의 원소들을 저장한다.

&ensp;2차원 배열로 보면<br/>
* 0행 전체 저장
* 1행 전체 저장
* 2행 전체 저장

&ensp;중요한 이유<br/>
&ensp;배열이 2차원, 3차원이어도 결국 메모리에 저장될 때는 한 줄로 퍼진다<br/>
* 2차원 배열 offset 공식
* 3차원 배열 offset 공식 

&ensp;2. 2차원 배열<br/>
&ensp;2차원 배열은 행(row)과 열(column)로 이루어진다.<br/>
&ensp;예<br/>
* V[3×8]
* 또는 V[0..2, 0..7]

&ensp;이 뜻은<br/>
* 행이 3개
* 열이 8개
* 총 24개의 원소가 있다.

&ensp;2차원 배열의 메모리 배치<br/>
&ensp;실제로 메모리에는 2차원 배열도 1줄처럼 저장된다.<br/>
* 0행의 원소들을 먼저 저장
* 그 다음 1행
* 그 다음 2행

<p align="center"><img src="/assets/img/data structure/3주차/3-3.png" width="600"></p>

&ensp;순서로 배치된다.<br/>

&ensp;2차원 배열 offset공식<br/>
* [(k1 - LB1)(UB2 - LB2 + 1)] + (k2 - LB2)

1. 앞에 있는 행들이 몇 칸 차지하는지 계산
2. 현재 행 안에서 몇 번째 열인지 더함

&ensp;예시<br/>
&ensp;V[4..6, -2..1]에서 V[5,0]의 offset 계산 결과는 6이다.<br/>

* 행 하나의 길이를 먼저 계산하고
* 현재 행까지 건너뛴 뒤
* 해당 열 위치를 더하는 것

<p align="center"><img src="/assets/img/data structure/3주차/3-4.png" width="600"></p>

&ensp;3. 3차원 배열<br/>
&ensp;3차원 배열은 행과 열 개념에 하나의 축이 더 추가된 구조이다.<br/>

&ensp;2차원 배열이 표라면 3차원 배열은 표 여러 장이 쌓인 구조<br/>

&ensp;메모리 배치<br/>
&ensp;3차원 배열도 실제 메모리에는 1차원처럼 순서대로 저장된다.<br/>
&ensp;따라서 offset 계산은<br/>
* 앞 차원 전체 크기
* 중간 차원 전체 크기
* 마지막 차원의 위치

&ensp;를 모두 반영해야 한다.<br/>

&ensp;중요한 점<br/>
&ensp;차원이 높아져도 본질은 같다.<br/>
* 시작 주소(base)가 있고 
* 거기서 얼마나 떨어졌는지(offset)만 계산하면 된다.

&ensp;다차원 배열도 결국은 1차원 메모리 공간에 저장된 것<br/>

<p align="center"><img src="/assets/img/data structure/3주차/3-5.png" width="600"></p>

# 4. 연결리스트(Linked List)

&ensp;리스트 표현 2가지<br/>
1. 순차 표현: 배열 사용
2. 연결된 표현: 연결리스트 사용

<p align="center"><img src="/assets/img/data structure/3주차/3-6.png" width="600"></p>

&ensp;연결리스트는 데이터를 메모리에 연속으로 두지 않고 각 노드가 다음 노드의 주소를 저장하면서 연결되는 구조이다.<br/>
* 연결리스트 명(linked list name), L: 연결리스트의 시작 위치 즉 첫 노드의 주소
* 연결리스트 크기(linked list size), n: 연결리스트 내 노드 수

&ensp;연결된 표현<br/>
* 리스트의 항목들을 노드(node)라고 하는 곳에 분산하여 저장
* 다음 항목을 가리키는 주소도 같이 저장
* 노드(node): <항목, 주소>쌍
* 노드는 데이터 필드와 링크 필드로 구성
  - 데이터 필드 - 리스트의 원소, 즉 데이터 값을 저장하는 곳
  - 링크 필드 - 다른 노드의 주소값을 저장하는 장소(포인터)
* 메모리안에서의 노드의 물리적 순서가 리스트의 논리적 순서와 일치할 필요 없음

<p align="center"><img src="/assets/img/data structure/3주차/3-7.png" width="600"></p>

&ensp;노드(node)의 구성<br/>
* 데이터 필드(data field): 실제 값 저장
* 링크 필드(link field): 다음 노드의 주소 저장

<p align="center"><img src="/assets/img/data structure/3주차/3-8.png" width="600"></p>

&ensp;헤드 포인터(head pointer): 리스트의 첫 번째 노드를 가리키는 변수<br/>

<p align="center"><img src="/assets/img/data structure/3주차/3-9.png" width="600"></p>

&ensp;노드의 생성: 필요할 때마다 동적 메모리 생성 이용하여 노드를 생성<br/>

<p align="center"><img src="/assets/img/data structure/3주차/3-10.png" width="600"></p>

&ensp;연결리스트는 값만 저장하는 것이 아니라 다음으로 어디 가야 하는지까지 같이 저장한다.<br/>

&ensp;연결리스트의 특징<br/>
&ensp;**메모리상의 물리적 순서와 논리적 순서는 다를 수 있다.**<br/>
&ensp;배열은 메모리상에서도 붙어 있어야 한다. 하지만 연결리스트는<br/>
* A 노드
* B 노드
* C 노드

&ensp;가 메모리 여기저기에 흩어져 있어도 링크가 이어져 있으면 논리적으로 하나의 리스트가 된다.<br/>

&ensp;장점<br/>
* 삽입, 삭제가 유리함
* 연속 공간이 필요 없음
* 크기가 동적으로 늘리고 줄일 수 있음

&ensp;단점<br/>
* 원하는 위치에 바로 접근 불가
* 링크 저장 공간이 추가로 필요
* 구현이 배열보다 복잡함
 
# 5. 연결리스트의 종류

&ensp;1. 단일 연결리스트<br/>
&ensp;가장 기본 형태<br/>
<p align="center"><img src="/assets/img/data structure/3주차/3-11.png" width="600"></p>

* 각 노드가 다음 노드 주소만 저장
* 마지막 노드는 `NULL`

<p align="center"><img src="/assets/img/data structure/3주차/3-15.png" width="600"></p>

&ensp;노드 저장내용<br/>
* 원소(element): 데이터원소
* 링크(link): 다음 노드의 주소 - 다음 노드가 없는 경우 널링크를 저장

&ensp;구조<br/>
* `data`
* `link`

&ensp;접근점<br/>
* 첫 노드, 즉 헤드노드(head node)의 주소

<p align="center"><img src="/assets/img/data structure/3주차/3-16.png" width="600"></p>

&ensp;연속 노드로 구성된 가장 단순한 연결 데이터구조<br/>



&ensp;2. 이중 연결리스트<br/>
&ensp;노드가 두 방향 링크를 가진다.<br/>
<p align="center"><img src="/assets/img/data structure/3주차/3-12.png" width="600"></p>

* 이전 노드 주소
* 다음 노드 주소

&ensp;장점<br/>
* 앞뒤 이동 가능
* 삭제가 더 편리한 경우가 많음

&ensp;단점<br/>
* 링크 필드가 하나 더 필요
* 구현이 더 복잡함

&ensp;3. 원형연결리스트<br/>
&ensp;마지막 노드가 NULL을 가리키는 대신 다시 첫 번째 노드를 가리킨다.<br/>
&ensp;리스트의 끝과 시작이 연결되어 있다.<br/>

<p align="center"><img src="/assets/img/data structure/3주차/3-13.png" width="600"></p>

&ensp;4. 헤더/트레일러 연결리스트<br/>
&ensp;실제 데이터가 아닌 더미 노드(dummy node)를 맨 앞이나 뒤에 두는 구조<br/>

&ensp;쓰는 이유<br/>
* 맨 앞 삽입
* 맨 앞 삭제

&ensp;같은 예외 처리를 줄이기 위해서<br/>
&ensp;구현을 더 깔끔하게 만들기 위한 장치<br/>

# 노드에 대한 메모리 할당

&ensp;노드(node): 한 개의 데이터원소를 저장하기 위해 동적 메모리(dynamic memory)에 할당된 메모리<br/>
&ensp;노드를 위한 메모리의 동적 할당(allocation)과 해제(deallocation)는 실행시간에 system call에 의해 처리된다.<br/>
* getnode(): 노드를 할당하고 그 노드의 주소를 반환(동적 메모리가 고갈된 시점이면 널포인터를 반환)
* putnode(i): 주소 i의 노드에 할당되었던 메모리의 사용을 해제하고 이를 동적 메모리에 반환(메모리 재활용을 위함)

<p align="center"><img src="/assets/img/data structure/3주차/3-14.png" width="600"></p>

# 단일연결리스트 구현

&ensp;1. 구조체 정의<br/>
```cpp
typedef int element;
typedef struct ListNode {
    element data;
    struct ListNode *link;
} ListNode;
```

* element는 int의 별명
* ListNode는 연결리스트의 노드 구조체
* data에는 실제 정수값 저장
* link에는 다음 노드의 주소 저장

&ensp;노드 하나는 정수 1개 + 다음 노드 주소 1개를 가진다.<br/>

&ensp;2. 노드 생성 함수<br/>
```cpp
ListNode *create_node(element data, ListNode *link) {
    ListNode *new_node;
    new_node = (ListNode *)malloc(sizeof(ListNode));
    new_node->data = data;
    new_node->link = link;
    return (new_node);
}
```

&ensp;역할<br/>
&ensp;새로운 노드를 동적 메모리로 생성하는 함수<br/>

* malloc(sizeof(ListNode))
	- 노드 1개 크기만큼 메모리 할당
* new_node->data = data
	- 데이터 값 저장
* new_node->link = link
	- 다음 노드 주소 저장
* return new_node
	- 만들어진 노드 주소 반환

&ensp;필요한 이유<br/>
&ensp;연결리스트는 크기가 고정이 아니기 때문에 필요할 때마다 노드를 만들어야 한다. 그래서 malloc을 사용한다.<br/>

&ensp;3. 삽입 함수<br/>
```cpp
void insert_node(ListNode **phead, ListNode *p, ListNode *new_node) {
    
    if (*phead == NULL) {
        new_node->link = NULL;
        *phead = new_node;
    }
    else if (p==NULL) {
        new_node->link = *phead;
        *phead = new_node;
    }
    else {
        new_node->link = p->link;
        p->link = new_node;
    }
}
```

&ensp;이 함수는 연결리스트에 새 노드를 삽입한다.<br/>

&ensp;매개변수 의미<br/>
* ListNode **phead
	- head 포인터 자체를 바꿀 수 있어야 하므로 이중 포인터 사용
* ListNode *p
	- 삽입 위치의 선행 노드
* ListNode *new_node
	- 새로 삽입할 노드

&ensp;경우 1. 공백 리스트에 삽입<br/>
```cpp
if (*phead == NULL) {
    new_node->link = NULL;
    *phead = new_node;
}
```

&ensp;리스트가 비어 있다면 새 노드가 첫 노드가 된다.<br/>
&ensp;동작<br/>
* 새 노드의 링크를 NULL
* head가 새 노드를 가리키게 함

&ensp;빈 리스트에 첫 원소를 넣는 상황<br/>

&ensp;경우 2. 맨 앞에 삽입<br/>
```cpp
else if (p==NULL) {
    new_node->link = *phead;
    *phead = new_node;
}
```

&ensp;`p = NULL` 이면 선행 노드가 없다는 뜻이다.<br/>
&ensp;즉 맨 앞 삽입이다.<br/>

&ensp;동작<br/>
1. 새 노드가 기존 첫 노드를 가리키게 함
2. head를 새 노드로 바꿈

&ensp;예를 들어<br/>
* 기존: 10 -> 20 -> 30
* 새 노드: 5

&ensp;이면 결과:<br/>
* 5 -> 10 -> 20 -> 30

&ensp;경우 3. 중간 삽입<br/>
```cpp
else {
    new_node->link = p->link;
    p->link = new_node;
}
```

&ensp;순서가 중요한 이유<br/>
* new_node->link = p->link

&ensp;를 해서 선행 노드가 새 노드를 가리키게 해야 한다.<br/>

&ensp;4. 삭제 함수<br/>
```cpp
void remove_node(ListNode **phead, ListNode *p, ListNode *removed) {

    if (p==NULL)
        *phead = (*phead)->link;
    else
        p->link = removed->link;
    free(removed);
}
```

&ensp;매개변수 의미<br/>
* phead: head를 바꾸기 위해 필요
* p: 삭제할 노드의 선행 노드
* removed: 실제 삭제할 노드

&ensp;경우 1. 맨 앞 노드 삭제<br/>
```cpp
if (p==NULL)
    *phead = (*phead)->link;
```

&ensp;맨 앞을 삭제하면 head가 다음 노드를 가리키도록 바꿔야 한다.<br/>

&ensp;예<br/>
* 기존: 50 -> 40 -> 30
* 삭제 후: 40 -> 30

&ensp;경우 2. 중간 노드 삭제<br/>
```cpp
else
    p->link = removed->link;
```

&ensp;삭제할 노드를 건너뛰도록 선행 노드의 링크를 수정한다.<br/>

&ensp;예<br/>
* 기존: 10 -> 20 -> 30
* 20 삭제 시
* 10의 link를 30으로 연결

&ensp;결과<br/>
* 10 -> 30

&ensp;마지막 free의 의미<br/>
```cpp
free(removed);
```

&ensp;노드를 리스트에서 끊는 것만으로는 충분하지 않다. 동적으로 할당한 메모리를 운영체제에 반환해야 한다.<br/>

* 링크 수정: 리스트 구조상 삭제
* free: 메모리까지 삭제

&ensp;이 둘이 합쳐져야 진짜 삭제<br/>

&ensp;5. 출력 함수<br/>
```cpp
void display(ListNode *head) {

    ListNode *p=head;
    while (p!=NULL) {
        printf("%d ", p->data);
        p = p->link;
    }
    printf("\n");
}
```

&ensp;역할<br/>
&ensp;리스트 전체를 앞에서부터 끝까지 출력한다.<br/>

&ensp;동작 원리<br/>
* p = head로 시작
* p != NULL인 동안 반복
* 현재 노드 데이터 출력
* 다음 노드로 이동

&ensp;연결리스트의 가장 기본적인 순회(traversal) 함수이다.<br/>

&ensp;6. 길이 구하기 함수<br/>
```cpp
int length(ListNode *head) {

    int count = 0;
    ListNode *tmp = head;
    while (tmp != NULL) {
        count++;
        tmp = tmp->link;
    }
    return count;
}
```

&ensp;역할<br/>
&ensp;연결리스트에 현재 몇 개의 노드가 있는지 센다.<br/>

&ensp;핵심<br/>
&ensp;배열은 크기를 쉽게 알 수 있지만 연결리스트는 노드들이 흩어져 있으므로 직접 세어야 한다.<br/>

&ensp;처음부터 끝까지 순회하면서 개수를 증가시킨다.<br/>

&ensp;7. 탐색 함수<br/>
```cpp
ListNode *search(ListNode *head, int x) {
    
    ListNode *p;
    p = head;
    while (p!=NULL) {

        if (p->data == x) return p;
        p = p->link;
    }
    return p;
}
```

&ensp;역할<br/>
&ensp;리스트 안에서 값 x를 갖는 노드를 찾는다.<br/>

&ensp;동작<br/>
* 첫 노드부터 시작
* 현재 노드의 데이터가 x와 같은지 검사
* 같으면 그 노드 주소 반환
* 끝까지 못 찾으면 NULL 반환

&ensp;배열은 인덱스로 접근 가능하지만 연결리스트는 중간 노드로 바로 갈 수 없기 때문에 앞에서부터 차례대로 찾아야 한다.<br/>

#include <stdio.h>

int main() {
    int N, M;
    scanf("%d %d", &N, &M);

    int arr[100][100] = {0};
    
    // 방향: 우, 하, 좌, 상
    int dr[] = {0, 1, 0, -1};
    int dc[] = {1, 0, -1, 0};
    
    int r = 0, c = 0, dir = 0;  // 시작 위치 (0, 0), 방향 '우'
    
    for (int num = 1; num <= N * M; num++) {
        arr[r][c] = num;
        
        int nr = r + dr[dir];  // 다음 행
        int nc = c + dc[dir];  // 다음 열
        
        // 범위를 벗어나거나 이미 채워진 경우 방향 전환
        if (nr < 0 || nr >= N || nc < 0 || nc >= M || arr[nr][nc] != 0) {
            dir = (dir + 1) % 4;
            nr = r + dr[dir];
            nc = c + dc[dir];
        }
        
        r = nr;
        c = nc;
    }
    
    // 출력
    for (int i = 0; i < N; i++) {
        for (int j = 0; j < M; j++) {
            if (j > 0) printf(" ");
            printf("%d", arr[i][j]);
        }
        printf("\n");
    }
    
    return 0;
}
