# 추상자료형(ADT)

* 쇼핑상품제조사별묶기
* ADT(Abstract Data Type)는 "이 자료구조가 무엇을 저장하고 어떤 연산을 제공하고 어떤 오류가 날 수 있는지"를 추상적으로 정의한 것이다.<br/>
* 어떻게 구현하는지는 아직 모름
* 무슨 기능을 해야 하는지만 먼저 정함

## 리스트 ADT

&ensp;리스트 ADT는 연속적인 임의 개체들을 모델링하고 각 원소는 순위(rank)로 접근한다.<br/>
&ensp;여기서 rank는 쉽게 말하면:<br/>
* 몇 번째 원소인가
* 또는 앞에 몇 개가 있는가

### 리스트 ADT에서 꼭 알아야 할 연산

&ensp;1. 상태 확인 메서드<br/>

&ensp;`isEmpty()`<br/>
&ensp;리스트가 비어 있는지 확인<br/>

&ensp;`size()`<br/>
&ensp;현재 저장된 원소 개수 반환<br/>

&ensp;2. 접근 메서드<br/>
&ensp;`get(r)`<br/>
&ensp;r번째 원소를 읽음<br/>
&ensp;이건 조회만 하는 것<br/>

&ensp;3. 갱신 메서드<br/>
&ensp;`set(r, e)`<br/>
&ensp;r번째 원소 값을 e로 바꿈<br/>

&ensp;`add(r, e)`<br/>
&ensp;r번째 위치에 e 삽입<br/>

&ensp;`addFirst(e)`<br/>
&ensp;맨 앞에 삽입<br/>

&ensp;`addLast(e)`<br/>
&ensp;맨 뒤에 삽입<br/>

&ensp;`remove(r)`<br/>
&ensp;맨 앞 삭제<br/>

&ensp;`removeFirst()`<br/>
&ensp;맨 앞 삭제<br/>

&ensp;`removeLast()`<br/>
&ensp;맨 뒤 삭제<br/>

# 배열 기반 리스트 구현

&ensp;배열 V와 현재 원소 수 n을 사용해서 리스트를 구현<br/>
&ensp;배열의 전체 크기는 N, 실제 저장 개수는 n이다.<br/>
* N = 배열 총 칸 수
* n = 현재 사용 중인 칸 수
* 유효한 원소는 V[0] ~ V[n-1]
* get(r) 또는 set(r, e)는 O(1) 시간에 V[r]을 각각 변환 또는 저장하도록 구현
  - r < 0  또는 r > n-1 인 경우 예외처리 필요

&ensp;배열 리스트의 핵심 그림<br/>
```cpp
V: [ ?, ?, ?, ?, ?, ?, ?, ? ]   // 총 크기 N
n = 0                            // 현재 원소 수
```

&ensp;원소를 넣으면 앞에서부터 차곡차곡 채워짐<br/>

```cpp
V: [10, 20, 30, ?, ?, ?, ?, ?]
n = 3
```

&ensp;즉 배열은 물리적으로 연속된 메모리라는 점이 핵심<br/>

&ensp;1. 초기화 `initialize()` <br/>
&ensp;초기에는 아무 원소도 없으므로 그냥 `n = 0` 해주면 끝. 시간복잡도는 O(1)이다.<br/>
&ensp;코드 감각<br/>
```cpp
n = 0;
```

&ensp;배열 전체를 0으로 채우는 게 핵심이 아님 "현재 아무 원소도 없다"는 상태를 n으로 관리하는 게 핵심<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-1.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-3.png" width="600"></p>

&ensp;2. 순회 `traverse()`<br/>
&ensp;배열 리스트의 모든 원소를 방문하는 연산이다.<br/>
&ensp;0부터 n-1까지 돌면 된다. 시간 복잡도는 `O(n)`<br/>

&ensp;코드<br/>
```cpp
for (int r = 0; r < n; r++) {
    visit(V[r]);
}
```

<p align="center"><img src="/assets/img/data structure/4주차/4-2.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-4.png" width="600"></p>

&ensp;문제에서<br/>
* 출력
* 합계 계산
* 최댓값 찾기
* 특정 조건 개수 세기

&ensp;이런 건 전부 순회 문제일 가능성이 큼<br/>

&ensp;3. 접근 `get(r)`, 수정 `set(r, e)`<br/>
&ensp;배열은 인덱스로 바로 접근 가능하니까 V[r] 읽기/쓰기가 가능하다. 그래서 둘다 O(1)이다.<br/>

&ensp;코드<br/>
```cpp
if (r < 0 || r >= n) error;
return V[r];
```

```cpp
if (r < 0 || r >= n) error;
V[r] = e;
```

&ensp;배열 리스트의 최대 장점은 "읽기/수정이 빠르다."<br/>

&ensp;4. 삽입 `add(r, e)`<br/>

&ensp;배열은 중간 칸에 그냥 넣을 수 없다. 삽입 위치 r부터 뒤에 있는 원소들을 한 칸씩 뒤로 밀어야 한다.(shift forward)<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-5.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-6.png" width="600"></p>

&ensp;뒤에서 미는 이유<br/>
&ensp;예를 들어<br/>
```cpp
[10, 20, 30, 40]
```

&ensp;여기서 r = 1 위치에 99 삽입:<br/>
&ensp;20, 30, 40을 뒤로 밀어야 함.<br/>
```
[10, 20, 30, 40, _]
-> [10, 20, 30, 40, 40]
-> [10, 20, 30, 30, 40]
-> [10, 20, 20, 30, 40]
-> [10, 99, 20, 30, 40]
```

&ensp;뒤에서부터 옮겨야 값이 안 덮어써짐<br/>

&ensp;코드<br/>
```cpp
for (int i = n - 1; i >= r; i--) {
    V[i + 1] = V[i];
}
V[r] = e;
n++;
```

&ensp;삽입 전에 검사<br/>
1. 배열이 꽉 찼는가
2. r이 유효한가 (0 <= r <= n)

&ensp;시간복잡도<br/>
&ensp;최악의 경우 맨 앞 삽입이라 O(n)<br/>

&ensp;5. 삭제 `remove(r)` <br/>
&ensp;삭제하면 그 자리가 빈다. 그 빈칸을 메우려고 뒤 원소들을 한 칸씩 앞으로 당겨야 한다. (shift backward)<br/>

&ensp;예시<br/>
```cpp
[10, 20, 30, 40, 50]
```

&ensp;r = 2 삭제하면 30 제거 후:<br/>
```cpp
[10, 20, _, 40, 50]
-> [10, 20, 40, 40, 50]
-> [10, 20, 40, 50, 50]
```

&ensp;유효 원소는 이제 앞의 4개만 보면 됨<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-7.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-8.png" width="600"></p>

&ensp;코드<br/>
```cpp
e = V[r];
for (int i = r + 1; i < n; i++) {
    V[i - 1] = V[i];
}
n--;
return e;
```

&ensp;삭제 전에 검사<br/>
* r이 유효한가 (0 <= r < n)

&ensp;시간복잡도<br/>
&ensp;최악의 경우 역시 맨 앞 삭제라 O(n)<br/>

## 배열 리스트의 시간복잡도

&ensp;배열 리스트<br/>
* `size`, `isEmpty` -> `O(1)`
* `get`, `set` -> `O(1)`
* `add`, `remove` -> `O(n)`
* `addFirst`, `removeFist` -> `O(n)`
* `addLast`, `removeLast` -> `O(1)`

&ensp;이런 차이가 나는 이유<br/>
&ensp;맨 뒤는 빠름<br/>
&ensp;맨 뒤 삽입은 그냥 `V[n] = e; n++;` 하면 끝이라 빠름<br/>

&ensp;맨 앞은 느림<br/>
&ensp;맨 앞 삽입/삭제는 모든 원소를 밀거나 당겨야 해서 느림<br/>

# 연결리스트 기반 리스트 구현

&ensp;단일 연결리스트 vs 이중 연결리스트<br/>
&ensp;단일 연결리스트<br/>
&ensp;노드마다<br/>
* 데이터
* 다음 노드 주소

<p align="center"><img src="/assets/img/data structure/4주차/4-10.png" width="600"></p>

&ensp;만 있음<br/>

&ensp;이중 연결리스트<br/>
&ensp;노드마다<br/>
* 데이터
* 이전 노드 주소 `prev`
* 다음 노드 주소 `next`

<p align="center"><img src="/assets/img/data structure/4주차/4-11.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-12.png" width="600"></p>


&ensp;가 있음

&ensp;header / trailer를 두는 이유<br/>
&ensp;리스트가 비어 있어도 구조를 이렇게 유지할 수 있다.<br/>
&ensp;`H <-> T` <br/>

&ensp;원소가 있으면<br/>
`H <-> A <-> B <-> C <-> T` <br/>

&ensp;장점<br/>
* 맨 앞/맨 뒤 처리 통일 가능
* null 체크가 줄어듦
* 삽입/삭제 코드가 깔끔해짐

&ensp;연결리스트에서 접근이 느린 이유<br/>
&ensp;배열은 V[r]로 바로 접근 가능했다. 하지만 연결리스트는 r번째까지 하나씩 따라가야 한다.<br/>
&ensp;get(r), set(r, e)를 위해 헤더에서 시작해서 r번 이동한다. 그래서 O(n)이다.<br/>

&ensp;코드<br/>
```cpp
p = H;
for (i = 1; i <= r; i++) {
    p = p->next;
}
return p->elem;
```

<p align="center"><img src="/assets/img/data structure/4주차/4-13.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-14.png" width="600"></p>

&ensp;1. 초기화<br/>
&ensp;비어 있는 이중연결리스트는<br/>
```cpp
H.next = T
T.prev = H
n = 0
```

&ensp;로 시작한다. 시작복잡도 O(1)<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-15.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-16.png" width="600"></p>


&ensp;2. 순회<br/>
&ensp;헤더 다음 노드부터 시작해서 트레일러 전까지 순회하면 됨<br/>
&ensp;시간복잡도 O(n)<br/>

&ensp;코드<br/>
```cpp
p = H->next;
while (p != T) {
    visit(p->elem);
    p = p->next;
}
```

<p align="center"><img src="/assets/img/data structure/4주차/4-17.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-18.png" width="600"></p>


&ensp;3. 삽입 `add(r, e)`<br/>
&ensp;연결리스트느느 삽입 자체만 보면 유리. 왜냐하면 노드 몇 개의 링크만 바꾸면 되기 때문이다.<br/>
&ensp;먼저 r번째 위치의 기준 노드 p를 찾고 그 앞에 새 노드 q를 끼워 넣는 `addNodeBefore(p, e)`를 사용한다.<br/>

&ensp;핵심 링크 변경<br/>
```cpp
q->prev = p->prev;
q->next = p;
p->prev->next = q;
p->prev = q;
```

&ensp;중요한 포인트<br/>
* 삽입 위치를 찾는 데는 O(n)
* 실제로 끼워 넣는 건 O(1)

&ensp;전체 `add(r, e)` 는 O(n)이지만 맨 앞/맨 뒤는 위치를 바로 알 수 있어서 빠르게 할 수 있다.<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-19.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-20.png" width="600"></p>


&ensp;4. 삭제 `remove(r)`<br/>
&ensp;삭제할 노드 p를 찾은 뒤 양 옆 노드를 바로 연결하면 된다.<br/>

&ensp;핵심 링크 변경<br/>
```cpp
p->prev->next = p->next;
p->next->prev = p->prev;
```

&ensp;포인트<br/>
* 노드 찾기: O(n)
* 실제 제거: O(1)

<p align="center"><img src="/assets/img/data structure/4주차/4-21.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-22.png" width="600"></p>

&ensp;연결리스트의 시간복잡도 정리<br/>
* size, isEmpty -> O(1)
* get, set -> O(n)
* add, remove -> O(n)
* addFirst, removeFirst -> O(1)
* addLast, removeLast -> O(1)

# 배열 vs 연결리스트

&ensp;배열이 유리한 경우<br/>
* 특정 위치 접근이 많다.
* get, set이 많다.
* 인덱스 기반 계산이 중요하다.

&ensp;예<br/>
* k번째 값 자주 조회
* 랜덤 접근 필요
* 원형배열 문제

&ensp;연결리스트가 유리한 경우<br/>
* 맨 앞/맨 뒤 삽입 삭제가 많다.
* 중간 삽입/삭제에서 "노드 위치만 알면" 빠르게 처리 가능
* 원소 간 연결 자체가 중요하다.

&ensp;예<br/>
* 큐/덱 구조
* 원형연결리스트 시뮬레이션
* 다항식 연결 저장

# 리스트 확장: 그룹(group)

&ensp;여러 그룹이 데이터를 어떻게 저장할까?를 다룬다.<br/>
&ensp;예<br/>
* 쇼핑몰 상품을 제조사별로 묶기
* 교수별 강의 목록
* 다항식 항을 차수별로 보기

&ensp;핵심 질문: 그룹별 데이터를 어떻게 저장하면 될까?<br/>

## 설계 방식A: 레코드의 리스트

&ensp;각 원소가 `(elem, group)` 형태를 가진다.<br/>
&ensp;예를 들어 `("z1", "Z")` , `("x1", "X")`<br/>

&ensp;장점<br/>
* 단순함

&ensp;단점<br/>
* 특정 그룹만 보려면 전체를 다 뒤져야 함
* 즉 그룹 관련 작업이 `O(n)`

<p align="center"><img src="/assets/img/data structure/4주차/4-28.png" width="600"></p>


### 레코드의 리스트 구현1: 배열 이용

&ensp;리스트를 elem 및 group 필드로 구성된 레코드의 1D 배열을 이용하여 구현<br/>
&ensp;장점: 기억장소 낭비 없음<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-29.png" width="600"></p>

&ensp;즉 배열의 간 칸이 단순한 int 하나가 아니라 구조체 느낌으로 생각하면 된다.<br/>
```cpp
typedef struct {
    char elem[20];
    char group;
} Record;

Record V[MAX];
int n = 0;
```

* `V[i].elem` : 실제 데이터
* `V[i].group` : 어느 그룹 소속인지
* `n` : 현재 저장된 레코드 수

&ensp;1. 초기화 `initGroup()`<br/>
* 초기에는 아무 레코드도 없음
* 그래서 n = 0으로 시작

&ensp;왜 이렇게 끝?<br/>
&ensp;배열 전체를 비울 필요가 없음 어차피 유효한 데이터는 0 ~ n-1까지만 보기 때문<br/>

&ensp;코드<br/>
```cpp
void initGroup(Record V[], int *n) {
    *n = 0;
}
```

<p align="center"><img src="/assets/img/data structure/4주차/4-30.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-31.png" width="600"></p>

&ensp;초기화 문제에서 배열 전체를 초기화하려고 하지 말고 **현재 개수만 0으로 둔다**<br/>

&ensp;2. 순회 `traverseGroup(g)` 배열 버전<br/>
&ensp;지정된 그룹의 멤버들만 방문하는 연산<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-32.png" width="600"></p>

1. 처음부터 끝까지 순회
2. `V[i].group == g` 인 경우만 방문

&ensp;그룹별로 따로 묶어 저장하지 않았고 그냥 (원소, 그룹) 레코드가 한 줄로 섞여 있는 구조니까 찾을 때는 전부 검사해야 한다.<br/>

&ensp;코드<br/>
```cpp
void traverseGroup(Record V[], int n, char g) {
    for (int i = 0; i < n; i++) {
        if (V[i].group == g) {
            printf("%s ", V[i].elem);
        }
    }
}
```

&ensp;시간복잡도: O(n)<br/>

&ensp;문제에서 바로 연결<br/>
* “Z 그룹 원소를 모두 출력”
* “특정 제조사 상품만 나열”
* “특정 교수의 강의만 보여라”

&ensp;3. 삭제 `removeGroup(g)` 배열 버전<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-33.png" width="600"></p>

1. `i = 0` 부터 시작
2. 현재 `V[i]` 가 그룹 g면 `remove(i)` 수행
3. 아니면 i++

&ensp;왜 for가 아니라 while을 쓰는 이유<br/>
&ensp;예를 들어 배열이<br/>
```css
0: (a, Z)
1: (b, Z)
2: (c, X)
```

&ensp;여기서 `remove(0)` 하면 배열이 당겨져서<br/>
```css
0: (b, Z)
1: (c, X)
```

&ensp;가 된다.<br/>

&ensp;이때 무조건 i++ 해버리먄 새로 0번으로 온 (b, Z)를 놓치게 된다.<br/>

&ensp;그래서<br/>
* 삭제했으면 i 를 그대로 둬야 하고
* 삭제 안 했을 때만 i++

&ensp;코드<br/>
```cpp
void removeAt(Record V[], int *n, int r) {
    for (int i = r + 1; i < *n; i++) {
        V[i - 1] = V[i];
    }
    (*n)--;
}

void removeGroup(Record V[], int *n, char g) {
    int i = 0;
    while (i < *n) {
        if (V[i].group == g) {
            removeAt(V, n, i);   // 삭제 후 i 그대로
        } else {
            i++;
        }
    }
}
```

&ensp;배열에서 여러 개 삭제할 때는 삭제 후 인덱스 이동을 조심해야 한다.<br/>

### 레코드의 리스트 구현2: 연결리스트

&ensp;각 노드에<br/>
* elem
* group
* prev
* next

&ensp;를 넣는 구조<br/>

```cpp
typedef struct Node {
    char elem[20];
    char group;
    struct Node* prev;
    struct Node* next;
} Node;
```

&ensp;그리고 전체 리스트는 이전 리스트 파트와 마찬가지로 header /trailer를 두면 편하다.<br/>
&ensp;`H <-> (z1, Z) <-> (x1, X) <-> (z2, Z) <-> T` <br/>

&ensp;1. `initGroup()` 연결리스트 버전<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-34.png" width="600"></p>

* 헤더 노드 생성
* 트레일러 노드 생성
* `H.next = T`
* `T.prev = H`

&ensp;코드<br/>
```cpp
void initGroup(Node **H, Node **T, int *n) {
    *H = (Node *)malloc(sizeof(Node));
    *T = (Node *)malloc(sizeof(Node));

    (*H)->next = *T;
    (*H)->prev = NULL;

    (*T)->prev = *H;
    (*T)->next = NULL;

    *n = 0;
}
```

&ensp;실제 데이터 노드는 없지만 구조 자체는 살아 있는 상태로 시작한다.<br/>

&ensp;2. 순회 `traverseGroup(g)` 연결리스트 버전<br/>
&ensp;연결리스트 전체를 돌면서 `group == g` 인 노드만 방문하는 알고리즘<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-35.png" width="600"></p>


&ensp;코드<br/>
```cpp
void traverseGroup(Node *H, Node *T, char g) {
    Node *p = H->next;

    while (p != T) {
        if (p->group == g) {
            printf("%s ", p->elem);
        }
        p = p->next;
    }
}
```

&ensp;배열 버전과 비교<br/>
* 배열: 인덱스 이동
* 연결리스트: 포인터 이동

&ensp;3. 제거 `removeGroup(g)` 연결리스트 버전<br/>
&ensp;지정 그룹의 모든 노드를 삭제하는 알고리즘이다.<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-36.png" width="600"></p>

1. p = H.next
2. while (p != T)
3. pnext = p.next 를 미리 저장
4. 만약 p.group == g 이면 removeNode(p)
5. 그 다음 p = pnext

&ensp;pnext를 미리 저장하는 이유<br/>
&ensp;removeNode(p)를 해버리면 p는 이미 리스트에서 제거되었거나 해제될 수 있다. 그 상태에서 p = p->next를 하면 위험하다. 그래서 삭제하기 전에 미리 다음 노드를 저장해두는 것이다.<br/>

&ensp;코드<br/>
```cpp
void removeNode(Node *p) {
    p->prev->next = p->next;
    p->next->prev = p->prev;
    free(p);
}

void removeGroup(Node *H, Node *T, int *n, char g) {
    Node *p = H->next;

    while (p != T) {
        Node *pnext = p->next;   // 먼저 저장
        if (p->group == g) {
            removeNode(p);
            (*n)--;
        }
        p = pnext;
    }
}
```

&ensp;연결리스트에서 순회 중 삭제할 때는 다음 노드를 먼저 저장해야 한다.<br/>

## 설계 방식B: 부리스트들의 리스트
&ensp;각 그룹마다 자기만의 리스트를 따로 둠<br/>
&ensp;예<br/>
* X 그룹 리스트
* Y 그룹 리스트
* Z 그룹 리스트

&ensp;장점<br/>
* 특정 그룹 작업을 격리해서 처리 가능
* 그 그룹만 바로 순회 가능

&ensp;구현 예<br/>
* 2차원 배열
* 연결리스트 배열

### 부리스트들의 리스트 구현1: 2차원 배열

&ensp;각 그룹을 하나의 행(row)으로 보고 그룹 내부 원소들을 열(column)에 넣는 방식<br/
&ensp;예를 들면<br/>
```
X: x1
Y: -
Z: z1 z2
```

&ensp;를 2D 배열로 저장<br/>

&ensp;코드<br/>
```cpp
char V[M][N][20];
int n[M];
```

* M: 그룹 개수
* N: 한 그룹당 최대 원소 수
* n[g]: g그룹 현재 원소 수

&ensp;1. 초기화 `initGroup()` 2D 배열 버전<br/>
&ensp;각 그룹에 원소가 아직 없으므로 각 행의 길이를 0으로 두면 됨<br/>

&ensp;코드<br/>
```cpp
void initGroup(int n[], int M) {
    for (int i = 0; i < M; i++) {
        n[i] = 0;
    }
}
```

<p align="center"><img src="/assets/img/data structure/4주차/4-38.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-39.png" width="600"></p>

&ensp;2. 순회 `traverseGroup(g)` 2D 배열 버전<br/>
&ensp;특정 그룹 g의 길이는 n[g]가 알고 있으니까 굳이 전체 그룹을 뒤질 필요 없이 그 행만 보면 됨<br/>

&ensp;코드<br/>
```cpp
void traverseGroup(char V[][MAX_COL][20], int n[], int g) {
    for (int j = 0; j < n[g]; j++) {
        printf("%s ", V[g][j]);
    }
}
```

&ensp;핵심<br/>
&ensp;이전 방식보다 훨씬 빠르게 특정 그룹만 접근 가능<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-40.png" width="600"></p>

&ensp;3. 제거 `removeGroup(g)` 2D 배열 버전<br/>
&ensp;해당 그룹의 길이를 0으로 만들면 끝<br/>

&ensp;그룹별 데이터가 이미 따로 저장돼 있으니까 그 그룹을 비웠다는 의미로 길이만 0으로 만들면 된다.<br/>

&ensp;코드<br/>
```cpp
void removeGroup(int n[], int g) {
    n[g] = 0;
}
```

<p align="center"><img src="/assets/img/data structure/4주차/4-41.png" width="600"></p>

&ensp;포인트<br/>
&ensp;설계가 잘 되면 알고리즘도 엄청 단순해질 수 있다.<br/>

### 부리스트들의 리스트 구현2: 연결리스트의 배열 이용

&ensp;그룹마다 이중연결리스트 하나씩 갖는 방식이다.<br/>
&ensp;즉<br/>
* `H[g]`: g그룹의 헤더
* `T[g]`: g그룹의 트레일러

&ensp;를 배열로 관리<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-42.png" width="600"></p>

&ensp;1. 초기화 `initGroup()`<br/>
&ensp;각 그룹마다 빈 이중연결리스트를 하나씩 만들어야 한다.<br/>

&ensp;코드<br/>
```cpp
void initGroup(Node *H[], Node *T[], int M) {
    for (int i = 0; i < M; i++) {
        Node *h = (Node *)malloc(sizeof(Node));
        Node *t = (Node *)malloc(sizeof(Node));

        h->next = t;
        h->prev = NULL;
        t->prev = h;
        t->next = NULL;

        H[i] = h;
        T[i] = t;
    }
}
```

<p align="center"><img src="/assets/img/data structure/4주차/4-43.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/4주차/4-44.png" width="600"></p>

&ensp;2. 순회 `traverseGroup(g)`<br/>
&ensp;특정 그룹 g에 대해서만 순회하면 된다.<br/>
```cpp
void traverseGroup(Node *H[], Node *T[], int g) {
    Node *p = H[g]->next;
    while (p != T[g]) {
        printf("%s ", p->elem);
        p = p->next;
    }
}
```

<p align="center"><img src="/assets/img/data structure/4주차/4-45.png" width="600"></p>

&ensp;3. 삽입 `addGroupFirst(g, e)`<br/>
&ensp;이거 그룹 g의 맨 앞에 원소를 넣는 것<br/>
&ensp;헤더 바로 뒤에 새 노드를 넣으면 된다.<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-46.png" width="600"></p>

```cpp
void addGroupFirst(Node *H[], Node *T[], int g, char *e) {
    Node *q = (Node *)malloc(sizeof(Node));
    strcpy(q->elem, e);

    q->prev = H[g];
    q->next = H[g]->next;

    H[g]->next->prev = q;
    H[g]->next = q;
}
```

&ensp;4. 제거 `removeGroup(g)`<br/>
&ensp;그룹 g의 모든 노드를 지우는 것<br/>
&ensp;즉 그 그룹의 리스트만 비우면 됨<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-47.png" width="600"></p>

```cpp
void removeGroup(Node *H[], Node *T[], int g) {
    Node *p = H[g]->next;
    while (p != T[g]) {
        Node *tmp = p;
        p = p->next;
        free(tmp);
    }
    H[g]->next = T[g];
    T[g]->prev = H[g];
}
```

# 리스트 확장: 공유(sharing)

&ensp;한 원소가 여러 그룹과 연결되는 경우<br/>
&ensp;예를 들면<br/>
* 쇼핑몰 상품:
    - Buyer A: x1, y1
    - Buyer B: z1
    - Buyer C: y1, z1, z2
* 대학 강좌:
    - Student A: DS, OS
    - Student B: DB
    - Student C: OS, DB, MM

&ensp;즉 같은 원소를 여러 그룹이 참조한다.<br/>

&ensp;문제<br/>
&ensp;가장 단순히 생각하면 각 그룹 리스트에 원소를 그냥 복사해서 넣으면 된다.<br/>
&ensp;그런데 그렇게 하면<br/>
* 같은 데이터가 여러 번 저장됨
* 메모리 낭비
* 나중에 값이 바뀌면 모든 복사본을 수정해야 함

&ensp;그래서 관련 그룹마다 공유 원소를 복제하는 것은 시간과 기억장소 낭비이다.<br/>

&ensp;한 원소는 한 번만 저장하거나 최소한 중복을 줄이면서, 여러 그룹과의 관계를 표현하는 구조를 설계해야 한다.<br/>

&ensp;1. 공유를 위한 설계들<br/>
* A. 레코드의 리스트
* B. 포인터의 리스트
* C. 다중리스트(multilist)

## 레코드 리스트 방식

&ensp;`(elem, group)` 쌍을 계속 나열하는 방식<br/>
&ensp;공유된 원소는 그룹마다 별도 레코드로 또 등장<br/>
&ensp;예<br/>
* (x1, A)
* (y1, A)
* (z1, B)
* (y1, C)

&ensp;즉 같은 원소가 여러 번 등장할 수 있다.<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-48.png" width="600"></p>

&ensp;장점<br/>
* 단순하다
* 구현이 쉽다
* 배열이나 연결리스트에 바로 넣을 수 있다

&ensp;단점<br/>
&ensp;특정 원소 관련 작업, 특정 그룹 관련 작업 모두 전체 레코드 순회가 필요하다. -> O(n)<br/>

&ensp;코드<br/>
```cpp
typedef struct {
    char elem[20];
    char group;
} Record;
```

&ensp;이런 레코드 배열이나 리스트를 쓴다고 생각하면 된다.<br/>

### 레코드 리스트 방식 구현1 - 배열 이용

<p align="center"><img src="/assets/img/data structure/4주차/4-49.png" width="600"></p>

&ensp;배열 안에 이런 식으로 저장된다.<br/>
* x1 / A
* y1 / C
* z1 / B
* z1 / C
* z2 / C
* y1 / A

&ensp;공유 원소가 여러 번 등장해도 배열 안에서는 그냥 독립적인 레코드들로 저장한다.<br/>

&ensp;구현 의미<br/>
&ensp;배열에서는 각 칸이 레코드 하나라고 보면 된다.<br/>
```cpp
typedef struct {
    char elem[20];
    char group;
} Record;

Record V[MAX];
int n;
```

* V[i].elem : 원소 이름
* V[i].group : 그룹 이름

&ensp;기억장소 낭비 없음 -> 배열 내부에 쓸데없는 빈칸 구조가 없다는 뜻(다만 원소 중복 저장 자체는 여전히 있음)<br/>

### 레코드 리스트 방식 구현2 - 연결리스트 이용

&ensp;노드 하나가 (elem, group) 정보를 갖고 있고 이 노드들을 연결리스트로 이어 붙인다.<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-50.png" width="600"></p>

&ensp;장점<br/>
&ensp;기억장소 낭비 최소화<br/>
* 필요한 레코드 수만큼만 노드를 만들면 되고
* 배열처럼 미리 큰 공간을 잡아둘 필요가 없기 때문

&ensp;단점<br/>
&ensp;배열이든 연결리스트든 이 방식은 결국 (elem, group) 쌍들을 한 줄로 저장한 거라<br/>
* 특정 그룹 찾기 → 전체 순회
* 특정 원소 찾기 → 전체 순회

&ensp;라는 한계는 그대로<br/>
&ensp;저장 방식만 달라졌지, 논리 구조는 여전히 “관계 목록 전체를 한데 모아놓은 방식”<br/>

## 포인터의 리스트 

&ensp;공유를 표현하기 위해 원소들을 별도의 메모리에 한 번만 저장하고, 각 그룹은 그 원소를 포인터(참조) 로 가리키는 방식이다.<br/>

&ensp;핵심 아이디어<br/>
&ensp;예를 들어 원소 저장소에:<br/>
* y1
* x1
* z1
* z2

&ensp;를 각각 한 번만 저장해 둔다.<br/>
&ensp;그 다음 각 그룹의 리스트는 실제 값을 저장하는 대신 그 원소를 가리키는 포인터를 저장한다.<br/>
&ensp;예:<br/>
* A 그룹 → y1, x1을 가리킴
* B 그룹 → z1을 가리킴
* C 그룹 → y1, z1, z2를 가리킴

<p align="center"><img src="/assets/img/data structure/4주차/4-51.png" width="600"></p>

&ensp;장점<br/>
* 단순
* 기억장소 사용 최소화

&ensp;왜냐하면<br/>
* y1이 100개 그룹에 속해도 실제 데이터는 1번만 저장
* 나머지는 주소만 들고 있으면 됨

&ensp;단점<br/>
&ensp;특정 원소 관련 작업의 격리 처리 불가<br/>
&ensp;이 구조는 그룹 쪽에서 원소를 보기에는 좋다. 하지만 반대로:<br/>
&ensp;“원소 y1은 어떤 그룹들에 속해 있지?”<br/>
&ensp;이 질문에 답하려면 여러 그룹 리스트를 다 뒤져야 한다.<br/>
&ensp;즉, 그룹 → 원소 방향은 쉬운데 원소 → 그룹 방향은 불편하다.<br/>

&ensp;포인터의 리스트 두 가지 구현<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-52.png" width="600"></p>

&ensp;배열 이용 버전<br/>
&ensp;각 그룹이 배열 하나를 갖고, 배열 칸에는 실제 원소가 아니라 원소를 가리키는 포인터가 들어간다.<br/>

&ensp;예를 들면:<br/>
```cpp
char elements[][20] = {"y1", "x1", "z1", "z2"};
char *groupA[2] = {elements[0], elements[1]};
char *groupB[1] = {elements[2]};
char *groupC[3] = {elements[0], elements[2], elements[3]};
```

&ensp;연결리스트 이용 버전<br/>
&ensp;각 그룹을 연결리스트로 만들고 노드 안에는 실제 데이터 대신 포인터를 저장한다.<br/>
&ensp;즉:<br/>
* 노드 자체는 그룹의 멤버 표현
* 하지만 원소 문자열은 중앙 저장소에 하나만 존재

## 다중 리스트(multilist)

&ensp;다중리스트는 원소들의 리스트와 그룹들의 리스트가 서로 교차하는 구조이다.<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-53.png" width="600"></p>

&ensp;다중리스트의 핵심 개념<br/>
* 원소 헤더 리스트가 있음
* 그룹 헤더 리스트가 있음
* 그리고 (원소, 그룹) 관계를 나타내는 교차점 노드가 있음

&ensp;이 교차점 노드는<br/>
* 원소 방향으로도 연결되고
* 그룹 방향으로도 연결됨

&ensp;즉 하나의 노드가 두 개의 연결 축을 갖는 구조이다.<br/>

&ensp;장점<br/>
&ensp;특정 원소 및 특정 그룹 관련 작업 모두 격리 처리 가능하다.<br/>
* 그룹 C의 원소들만 순회 가능
* 원소 y1의 그룹들만 순회 가능

### 다중 리스트 구현1 - 2D 배열

&ensp;가장 단순한 멀티 구조 버전<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-54.png" width="600"></p>

&ensp;행은 원소, 열은 그룹을 뜻하는 2D 논리 배열(boolean matrix) 를 사용<br/>
&ensp;예를 들어<br/>
* 행: z2, x1, y1, z1
* 열: A, B, C

&ensp;그리고 1이면 연결 있음, 0이면 없음.<br/>
* z2는 C만 연결 → 0 0 1
* x1은 A만 연결 → 1 0 0
* y1은 A와 C 연결 → 1 0 1
* z1은 B와 C 연결 → 0 1 1

&ensp;단점<br/>
&ensp;원소-그룹 관계가 희소(sparse)하면 메모리 낭비가 크다.<br/>
&ensp;예를 들어 원소 1000개, 그룹 1000개면 백만 칸이 필요하다.<br/>
&ensp;근데 실제 연결은 2000개뿐일 수도 있다. 그럼 대부분이 0이라 낭비가 심하다.<br/>


### 다중 리스트 구현1 - 다중연결리스트

&ensp;2D 배열의 낭비를 줄이기 위한 진짜 구현법<br/>
* 실제로 존재하는 `(원소, 그룹)` 관계만 노드로 만든다
* 0인 관계는 저장하지 않는다

1. 원소 목록이 따로 있음
2. 그룹 목록이 따로 있음
3. 관계가 있을 때만 교차 노드를 만듦
4. 각 교차 노드는 같은 그룹 안에서 다음 원소를 가리키고 같은 원소 안에서 다음 그룹을 가리킴

&ensp;장점<br/>
&ensp;기억장소 낭비 최소화<br/>
* 2D 배열은 0도 저장
* 다중연결리스트는 1인 관계만 저장

<p align="center"><img src="/assets/img/data structure/4주차/4-55.png" width="600"></p>

&ensp;1. 초기화 `initShare()`<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-56.png" width="600"></p>

* 어떤 원소도 어떤 그룹과 연결되지 않음
* 즉 교차 노드가 하나도 없음

<p align="center"><img src="/assets/img/data structure/4주차/4-57.png" width="600"></p>

&ensp;1단계: 각 원소에 대해<br/>
* 헤더 노드 `H` 생성
* `H.nextgroup = H`
* `Elements[i].header = H`

&ensp;각 원소는 그룹 방향 빈 리스트를 하나 가진다.<br/>

&ensp;2단계: 각 그룹에 대해<br/>
* 헤더 노드 `H` 생성
* `H.nextelement = H`
* `Groups[i].header = H`

&ensp;각 그룹은 원소 방향 빈 리스트를 하나 가진다.<br/>

&ensp;자기 자신을 가리키는 이유<br/>
* 비어 있으면 헤더 다음이 자기 자신
* 순회하다가 다시 헤더를 만나면 종료

&ensp;이렇게 하면 NULL 체크 대신 헤더 비교로 처리할 수 있다.<br/>

&ensp;코드<br/>
```cpp
for (int i = 0; i < NE; i++) {
    header = newNode();
    header->nextgroup = header;
    Elements[i].header = header;
}

for (int i = 0; i < NG; i++) {
    header = newNode();
    header->nextelement = header;
    Groups[i].header = header;
}
```

&ensp;초기화는 원소와 그룹 각각의 “비어 있는 관계 리스트”를 준비하는 작업이다.<br/>

&ensp;2. 원소 순회 `traverseShareElements(g)`<br/>
&ensp;지정된 그룹과 관련된 모든 원소들을 방문하는 알고리즘<br/>

<p align="center"><img src="/assets/img/data structure/4주차/4-58.png" width="600"></p>

&ensp;그룹 g의 헤더에서 시작해서 그 그룹에 속한 모든 관계 노드를 따라가며 순회한다는 뜻이다.<br/>

&ensp;코드로 옮길 때 중요한 점은 visit(p)가 뭘 출력하느냐이다.<br/>
&ensp;관계 노드 자체를 출력하는 게 아니라 보통은 그 노드가 가리키는 원소 정보를 출력해야 한다.<br/>
&ensp;즉:<br/>
* p->elemIndex
* 또는 p->elemPtr

&ensp;같은 걸 이용해서 실제 원소 이름을 찾아야 한다.<br/>
&ensp;그룹 기준 순회는 group 헤더에서 시작해 element 방향 링크를 따라간다.<br/>

&ensp;3. 그룹 순회 `traverseShareGroups(e)`<br/>
&ensp;지정된 원소와 관련된 모든 그룹들을 방문<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-59.png" width="600"></p>

&ensp;원소 e에서 시작해 그 원소와 관련된 모든 그룹 체인을 따라간다는 뜻<br/>

&ensp;4. 삽입 `addShare(e, g)`<br/>
&ensp;새로운 (원소, 그룹) 관계를 추가하는 알고리즘<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-60.png" width="600"></p>

&ensp;노드 p 하나를 만들어서 그룹 리스트에도 연결, 원소 리스트에도 연결하는 것이다.<br/>

```cpp
p = newNode();
p->elem = e;
p->group = g;

// 그룹 쪽 삽입
p->nextelement = groupHeader[g]->nextelement;
groupHeader[g]->nextelement = p;

// 원소 쪽 삽입
p->nextgroup = elementHeader[e]->nextgroup;
elementHeader[e]->nextgroup = p;
```

&ensp;실제 구현에서는 노드가 어느 원소/그룹을 뜻하는지 알아야 하니까 다음 중 하나가 필요하다.<br/>
* elemIndex, groupIndex 저장
* 혹은 원소 헤더/그룹 헤더를 직접 가리키는 포인터 저장

# 응용문제 - 다항식

&ensp;다항식(polynomial)을 리스트로 표현하는 문제<br/>
* 여러 개의 다항식을 저장하는 데이터구조를 설계하라
* 각 다항식은 하나의 헤더 단일연결리스트로 표현
*  예시 다항식:
    - a = 3x^4 + 8x
    - b = 11x^3 - 8x + 4
    - c = -6x^2

&ensp;수학식도 자료구조 관점에선 결국 레코드의 순서 있는 리스트로 볼 수 있다.<br/>

## 다항식 덧셈/뺄셈 문제

&ensp;문제:<br/>
* addPoly(x, y) : 다항식 덧셈
* subPoly(x, y) : 다항식 뺄셈

&ensp;둘 다 호출하는 보조 알고리즘 appendTerm(k, c, e)를 먼저 작성<br/>

&ensp;해답<br/>
&ensp;각 다항식에 대해 헤더 단일 연결리스트를 사용하고 각 노드는 두 필드를 저장한다.<br/>
* coef
* exp

<p align="center"><img src="/assets/img/data structure/4주차/4-64.png" width="600"></p>

&ensp;`appendTerm(k, c, e)`<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-65.png" width="600"></p>

&ensp;의미: 현재 마지막 항이 k일 때 그 뒤에 새 항 (c, e)를 붙이고 새 마지막을 갱신하는 과정이다.<br/>

&ensp;다항식 연산은 결과를 앞에서부터 차례대로 만들어 가기 때문에 항 하나를 안전하게 뒤에 붙이는 함수가 있어야 구현이 깔끔하다.<br/>

&ensp;`addPoly(x, y)`<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-66.png" width="600"></p>

&ensp;전체 구조<br/>
1. 결과 헤더 생성
2. i, j를 각각 x, y의 첫 항으로 둠
3. 둘 다 NULL이 아닐 동안 반복
4. 차수를 비교하며 결과에 붙임
5. 남은 항들 처리
6. 결과 반환

&ensp;`subPoly(x, y)`<br/>
&ensp;전체 구조는 addPoly와 거의 동일한데 계수 계산만 다르다.<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-67.png" width="600"></p>

&ensp;차이<br/>
* 경우 1: i.exp > j.exp
    - x에만 있는 높은 차수 항 → 그대로 결과에 추가
* 경우 2: i.exp < j.exp
    - y에만 있는 높은 차수 항 → 0 - y항 이므로 음수 부호 붙여서 결과에 추가
* 경우 3: i.exp == j.exp
    - 같은 차수 → diff = i.coef - j.coef

# 응용문제 - 생일케이크

&ensp;상황:<br/>
* 원형으로 놓인 n개의 양초
* 첫 번째 양초부터 시작
* k개를 건너뛴 다음 나타나는 양초를 제거
* 다음 양초부터 다시 반복
* 마지막 하나가 남을 때까지 반복

&ensp;그리고 마지막까지 남는 위치를 알고 싶다는 문제<br/>

## 구현1 - 배열

&ensp;구조<br/>
* 원형배열 A[0:n-1]
* 각 배열 원소는 양초를 표현
* 초기화 시 각 칸에 1 ~ n 저장

&ensp;양초 번호 자체를 배열 값으로 저장하는 것<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-68.png" width="600"></p>

&ensp;배열 시뮬레이션 두 버전<br/>
&ensp;버전 1: 삭제 대신 0으로 표시<br/>
* 양초를 실제로 배열에서 없애지 않음
* 꺼진 양초는 0으로 표시
* 다음 탐색에서 0은 건너뜀

&ensp;장점<br/>
* 배열 당기기가 필요 없음

&ensp;단점<br/>
* 살아 있는 양초를 찾기 위해 0을 계속 건너뛰어야 함
* 총 실행시간이 Ω(kn)

&ensp;버전 2: 실제 삭제<br/>
* 양초를 제거할 때 배열에서 실제 삭제
* 이후 원소들을 당겨옴

&ensp;장점<br/>
* 배열에는 항상 살아 있는 양초만 남음

&ensp;단점<br/>
* 삭제 한 번이 O(n)
* 전체는 O(n^2)가 될 수 있다

&ensp;배열 버전 알고리즘<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-69.png" width="600"></p>

&ensp;`runSimulation(A, n, k) {ver.1}`<br/>
1. r ← 0
2. 양초가 1개 남을 때까지 반복
3. i < k 동안
* r ← (r + 1) % N
* A[r] != 0 이면 카운트 증가
4. 도달한 양초를 0으로 표시
5. 남은 개수 n--
6. 다음 시작점으로 살아 있는 양초를 찾음
7. 마지막에 A[r] 반환

&ensp;`runSimulation(A, n, k) {ver.2}`<br/>
1. r ← 0
2. while n > 1
3. r ← (r + k) % n
4. remove(r)
5. 마지막 A[0] 반환

&ensp;`candle(n, k)` 와 `buildList(A, n)`<br/>
&ensp;buildList는 단순히 A[r] = r+1 채우기.<br/>
&ensp;candle은 생성 후 시뮬레이션 호출.<br/>

## 구현2 - 원형연결리스트

&ensp;데이터구조<br/>
* 크기 n의 원형 연결리스트 L
* 각 노드는 양초 하나
* 각 노드의 값은 양초 위치 번호 1 ~ n

<p align="center"><img src="/assets/img/data structure/4주차/4-70.png" width="600"></p>

&ensp;시간복잡도<br/>
* 양초 하나 제거에 k회의 연산 필요
* 총 n-1개 제거
* 전체 O(kn)

&ensp;원형연결리스트 알고리즘<br/>
<p align="center"><img src="/assets/img/data structure/4주차/4-71.png" width="600"></p>

&ensp;`runSimulation(L, n, k)`<br/>
1. p ← L
2. while (p != p.next)
* 노드가 하나 남으면 자기 자신을 가리키므로 종료 조건이 됨
3. for i ← 1 to k-1
*  p ← p.next
4. pnext ← p.next
5. p.next ← (p.next).next
6. putnode(pnext)
7. p ← p.next
8. 마지막에 p.elem 반환

&ensp;`buildList(n)`<br/>
1. 첫 노드 생성, elem = 1
2. 2부터 n까지 차례로 새 노드 연결
3. 마지막에 p.next = L
4. return L

&ensp;`candle(n, k)`<br/>
* L ← buildList(n)
* return runSimulation(L, n, k)

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

// 노드 구조체
typedef struct Node {
    char elem;
    struct Node* prev;
    struct Node* next;
} Node;

// 이중연결리스트 구조체 (헤더 + 트레일러)
typedef struct {
    Node* header;
    Node* trailer;
    int size;
} DoublyLinkedList;

// 새 노드 생성
Node* createNode(char elem) {
    Node* node = (Node*)malloc(sizeof(Node));
    node->elem = elem;
    node->prev = NULL;
    node->next = NULL;
    return node;
}

// 리스트 초기화
void initList(DoublyLinkedList* list) {
    list->header = createNode('\0');
    list->trailer = createNode('\0');
    list->header->next = list->trailer;
    list->trailer->prev = list->header;
    list->size = 0;
}

// 특정 순위의 노드 포인터 반환 (1-based)
// 유효 범위: add는 1~size+1, delete/get은 1~size
Node* getNodeAt(DoublyLinkedList* list, int rank) {
    Node* cur = list->header->next;
    for (int i = 1; i < rank; i++) {
        cur = cur->next;
    }
    return cur;
}

// add(list, r, e): 순위 r에 원소 e 삽입
void add(DoublyLinkedList* list, int r, char e) {
    // 유효 순위: 1 ~ size+1
    if (r < 1 || r > list->size + 1) {
        printf("invalid position\n");
        return;
    }
    Node* newNode = createNode(e);
    // 순위 r의 현재 노드(삽입 위치의 오른쪽)
    Node* next = getNodeAt(list, r);
    Node* prev = next->prev;

    prev->next = newNode;
    newNode->prev = prev;
    newNode->next = next;
    next->prev = newNode;
    list->size++;
}

// delete(list, r): 순위 r의 원소 삭제
void deleteAt(DoublyLinkedList* list, int r) {
    // 유효 순위: 1 ~ size
    if (r < 1 || r > list->size) {
        printf("invalid position\n");
        return;
    }
    Node* target = getNodeAt(list, r);
    target->prev->next = target->next;
    target->next->prev = target->prev;
    free(target);
    list->size--;
}

// get(list, r): 순위 r의 원소 출력
void get(DoublyLinkedList* list, int r) {
    // 유효 순위: 1 ~ size
    if (r < 1 || r > list->size) {
        printf("invalid position\n");
        return;
    }
    Node* target = getNodeAt(list, r);
    printf("%c\n", target->elem);
}

// print(list): 모든 원소 출력
void printList(DoublyLinkedList* list) {
    Node* cur = list->header->next;
    while (cur != list->trailer) {
        printf("%c", cur->elem);
        cur = cur->next;
    }
    printf("\n");
}

// 리스트 메모리 해제
void freeList(DoublyLinkedList* list) {
    Node* cur = list->header;
    while (cur != NULL) {
        Node* next = cur->next;
        free(cur);
        cur = next;
    }
}

int main() {
    DoublyLinkedList list;
    initList(&list);

    int n;
    scanf("%d", &n);

    for (int i = 0; i < n; i++) {
        char op[10];
        scanf("%s", op);

        if (op[0] == 'A') {
            int r;
            char e;
            scanf("%d %c", &r, &e);
            add(&list, r, e);
        } else if (op[0] == 'D') {
            int r;
            scanf("%d", &r);
            deleteAt(&list, r);
        } else if (op[0] == 'G') {
            int r;
            scanf("%d", &r);
            get(&list, r);
        } else if (op[0] == 'P') {
            printList(&list);
        }
    }

    freeList(&list);
    return 0;
}

    Node *newNode = (Node *)malloc(sizeof(Node));
    newNode->next = NULL;

Node * readPoly(int n) {
    Node* head = getNode();
    Node* rear = head;

    for (int i =0;i < n; i++) {
        int coef, exp;
        scanf("%d %d", &coef, &exp);

        if (coef != 0) {
            appendTerm(&rear, coef, exp);
        }
    }
    return head;
}

void appendTerm(Node **k, int c, int e) {
    Node * t = getNode();
    t->coef = c;
    t->exp = e;
    t->next = NULL;

    (*k)->next = t;
    *k = t;
}

Node* addPoly(Node* x, Node* y) {
    Node *t = getNode();
    t->next = NULL;
    Node *i = x->next;
    Node *j = y->next;
    Node *k = t;
    while ((i != NULL) && (j != NULL)) {
        if (i->exp > j->exp) {
            appendTerm(&k, i->coef, i->exp);
            i = i->next;
        }else if (i->exp < j->exp) {
            appendTerm(&k, j->coef, j->exp);
            j = j->next;
        }else {
            int sum = i->coef + j->coef;
            if (sum != 0) {
                appendTerm(&k, sum, i->exp);
            }
            i = i->next;
            j = j->next;
        }
    }
    while (i != NULL) {
        appendTerm(&k, i->coef, i->exp);
        i = i->next;
    }
    while (j != NULL) {
        appendTerm(&k, j->coef, j->exp);
        j = j->next;
    }

    return t;
}

    while (p != NULL) {

        p = p->next;

    printf("\n");
}
