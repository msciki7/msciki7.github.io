# 분리집합 ADT

&ensp;1. 분리집합이란?<br/>
&ensp;분리집합은 말 그대로 서로 겹치지 않는 여러 집합을 관리하는 자료구조이다.<br/>
&ensp;예를 들어 전체 원소가 이렇게 있다고 해보자.<br/>
&ensp;`{1}, {2}, {3}, {4}, {5}, {6}` <br/>
&ensp;처음에는 모든 원소가 각각 따로 떨어져 있다. 여기서 `union(1, 2)`를 하면 1과 2가 같은 집합이 된다.<br/>
&ensp;`{1, 2}, {3}, {4}, {5}, {6}` <br/>
&ensp;또 `union(3, 4)`를 하면<br/>
&ensp;`{1, 2}, {3, 4}, {5}, {6}` <br/>
&ensp;그리고 `union(2, 3)`을 하면 2가 속한 집합과 3이 속한 집합이 합친다.<br/>
&ensp;`{1, 2, 3, 4}, {5}, {6}` <br/>
&ensp;`{1, 2, 3, 4}, {5}, {6}` <br/>
&ensp;분리집합은 원소들이 어느 집합에 속하는지 관리하고, 두 집합을 합치는 자료구조이다.<br/>

&ensp;2. 왜 “분리”집합이라고 부를까?<br/>
&ensp;분리집합에서는 각 집합들이 서로 겹치면 안 된다.<br/>
&ensp;예를 들어 이런 건 가능<br/>
```css
A = {1, 2, 3}
B = {4, 5}
C = {6}
```

&ensp;각 원소는 딱 하나의 집합에만 속한다.<br/>

&ensp;그런데 이런 건 분리집합이 아니다.<br/>
```css
A = {1, 2, 3}
B = {3, 4, 5}
```

&ensp;원소 3이 A에도 있고 B에도 있으니까 두 집합이 겹친다. 분리집합은 이런 교집합이 있는 상태를 허용하지 않는다.<br/>

&ensp;3. 분리집합 ADT<br/>
* makeSet(x)
* find(x): 원소 e가 속한 집합을 찾아주는 연산
* union(x, y): 원소 x가 속한 집합과 원소 y가 속한 집합을 합치는 연산
* size(S): 집합 S에 들어 있는 원소 개수를 반환하는 보조 메소드

# 분리집합 구현

&ensp;분리집합 구현 방식 전체 비교<br/>
&ensp;리스트에 기초한 구현<br/>
* find는 빠르고 union은 느리다
* 배열 또는 연결리스트 사용

&ensp;리스트 기반 구현에서는 각 원소가 자기가 어느 집합에 속하는지 바로 알 수 있게 만든다. 그래서 `find(e)` 는 빠르다. 예를 들어 원소 4가 집합 A에 속한다고 저장되어 있으면 `find(4) = A` 를 바로 알 수 있다.<br/>
&ensp;하지만 `union(A, B)` 를 할 때는 문제가 생긴다. 두 집합을 합치려면 한 집합에 속합 원소들의 소속 정보를 전부 바꿔야 한다.<br/>
&ensp;예를 들어<br/>
* A = {1, 4, 7}
* B = {2, 3, 6, 9}

&ensp;에서 `union(A, B)`를 하면 A원소들을 B로 옮기거나 B원소들을 A로 옮겨야 한다.<br/>
&ensp;원소 여러 개의 소속 집합 정보를 수정해야 하니까 `union`이 느려진다.<br/>

----

&ensp;트리에 기초한 구현<br/>
* find는 느리고 union은 빠르다
* find 성능 개선 가능

&ensp;트리 기반은 경로 압축(path compression) 같은 방법으로 find 성능을 개선할 수 있다.<br/>

----

&ensp;리스트에 기초한 구현<br/>

<p align="center"><img src="/assets/img/data structure/14주차/14-1.png" width="600"></p>

&ensp;리스트 기반 구현에서는 집합 하나당 리스트 하나를 사용한다. 그래서 A 집합은 A 리스트로, B 집합은 B 리스트로, C 집합은 C 리스트로 표현한다.<br/>

```css
A → 4 → 1 → 7
B → 9 → 3 → 6 → 2
C → 5 → 11 → 0 → 10 → 8
```

&ensp;여기서 각 원소 노드는 자신이 속한 집합을 가리키는 참조를 가진다.<br/>
&ensp;원소 4, 1, 7은 모두 A를 가리킨다.<br/>
* 4.set = A
* 1.set = A
* 7.set = A

&ensp;그래서 `find(4)`를 하면 4가 가진 set 포인터를 보고 바로 A를 알 수 있다.<br/>

&ensp;리스트 기반에서 find(e)<br/>
* find(e): e가 소속된 집합을 반환
* 실행시간: O(1)

&ensp;리스트 기반에서 union(x, y)<br/>
* union(x, y): x, y 중 작은 집합의 원소들을 큰 집합으로 이동
* 실행시간: O(min(|A|, |B|))

&ensp;예를 들어<br/>

```css
A = {1, 4, 7}          크기 3
B = {2, 3, 6, 9}       크기 4
```

&ensp;union(A, B)를 한다고 해보면<br/>
&ensp;A가 더 작고 B가 더 크니까, A를 B에 붙이는 게 좋다.<br/>
&ensp;그러면 A에 있던 원소 1, 4, 7의 소속 집합 정보를 B로 바꿔야 한다.<br/>
* 1.set = B
* 4.set = B
* 7.set = B

&ensp;그리고 A 리스트를 B 리스트 뒤에 연결하면 된다.<br/>
&ensp;결과는 이렇게 된다.<br/>
* B = {2, 3, 6, 9, 1, 4, 7}
* A = empty

&ensp;이때 바꿔야 하는 원소 수는 A의 크기인 3개이다.<br/>
&ensp;그래서 실행시간은 `O(min(|A|, |B|))` <br/>

## 배열을 사용할 경우

<p align="center"><img src="/assets/img/data structure/14주차/14-2.png" width="600"></p>

```css
A = {1, 4, 7}
B = {2, 3, 6, 9}
C = {0, 5, 8, 10, 11}
```

&ensp;배열 S를 사용해서 각 원소가 어느 집합에 속하는지 저장한다.<br/>

&ensp;배열 기반 find와 union 의사코드<br/>
<p align="center"><img src="/assets/img/data structure/14주차/14-3.png" width="600"></p>

&ensp;find(e): 원소 e의 소속 집합은 S[e]에 저장되어 있으므로 바로 반환한다.<br/>
&ensp;-> 총 실행시간: **O(1)**<br/>

&ensp;union(x, y): `S[i] == y` 인 칸을 찾고 그 칸을 전부 `S[i] = x` 로 바꾼다.<br/>
&ensp;-> 총 실행시간: **O(n)**<br/>

## 연결리스트를 사용할 경우

&ensp;연결리스트 방식의 구조<br/>
&ensp;각 집합에는 레코드가 있다.<br/>
* size: 집합 원소 수
* head: 첫 번째 원소 노드 주소
* tail: 마지막 원소 노드 주소

&ensp;각 원소 노드에는 세 가지 정보가 있다.<br/>
* elem: 원소 값
* set: 이 원소가 속한 집합 레코드를 가리키는 포인터
* next: 다음 원소 노드를 가리키는 포인터

<p align="center"><img src="/assets/img/data structure/14주차/14-4.png" width="600"></p>

* A = {4, 1, 7}
* B = {9, 3, 6, 2}
* C = {5, 11, 0, 10, 8}

&ensp;각 집합은 하나의 연결리스트이다.<br/>
* A: 4 → 1 → 7 → Ø
* B: 9 → 3 → 6 → 2 → Ø
* C: 5 → 11 → 0 → 10 → 8 → Ø

&ensp;각 행에는 이런 정보가 들어 있다.<br/>
&ensp;`size | head | tail` <br/>
&ensp;예를 들어 A 집합은 원소가 3개니까<br/>
* size = 3
* head = 4번 노드
* tail = 7번 노드

&ensp;B 집합은<br/>
* size = 4
* head = 9번 노드
* tail = 2번 노드

&ensp;C 집합은<br/>
* size = 5
* head = 5번 노드
* tail = 8번 노드

&ensp;그리고 각 원소 노드 안에는 set 포인터가 있어서 자신이 속한 집합 레코드를 가리킨다.<br/>
&ensp;예를 들어 4, 1, 7 노드는 모두 A 집합 레코드를 가리킨다.<br/>
* 4.set = A
* 1.set = A
* 7.set = A

&ensp;그래서 find(1)은 1번 노드의 set을 보고 A를 반환할 수 있다.<br/>

&ensp;연결리스트 기반 find와 union 의사코트<br/>

<p align="center"><img src="/assets/img/data structure/14주차/14-5.png" width="600"></p>

&ensp;find(e): 원소 e의 노드를 찾고, 그 노드가 가리키는 set 정보를 보고, 그 집합의 식별자를 반환한다.<br/>
&ensp;`find(e) = e 노드의 set 포인터가 가리키는 집합` <br/>

&ensp;union(A, B): A, B 중 작은 집합을 큰 집합에 병합<br/>
* 실행시간: O(min(|A|, |B|))
* 상각실행시간: O(log n)

&ensp;연결리스트 union 의사코드 흐름<br/>
&ensp;1단계: 작은 집합과 큰 집합 결정<br/>
```cpp
if S[A].size < S[B].size
    smallerSet, largerSet ← A, B
else
    smallerSet, largerSet ← B, A
```

&ensp;A와 B 중 크기가 작은 쪽을 smallerSet, 큰 쪽을 largerSet으로 정한다.<br/>

&ensp;2단계: 작은 집합의 head, tail 저장<br/>
```cpp
headS, tailS ← S[smallerSet].head, S[smallerSet].tail
```

&ensp;작은 집합의 시작 노드와 마지막 노드를 기억한다.<br/>

&ensp;3단계: 큰 집합의 head, tail 저장<br/>
```cpp
headL, tailL ← S[largerSet].head, S[largerSet].tail
```

&ensp;큰 집합의 시작 노드와 마지막 노드를 기억한다.<br/>

&ensp;4단계: 작은 집합 원소들의 set 포인터 변경<br/>
```cpp
p ← headS

while p ≠ Ø
    p.set ← headL
    p ← p.next
```

&ensp;작은 집합 원소들이 이제 큰 집합에 속하도록 set 정보를 바꾼다.<br/>
&ensp;A의 원소들이 B를 가리키도록 바꾼다.<br/>
&ensp;이 반복문은 작은 집합의 원소 개수만큼 돈다.<br/>
&ensp;-> **O(min(|A|, |B|))** <br/>

&ensp;5단계: 두 리스트 연결<br/>
```cpp
tailL.next ← headS
```

&ensp;큰 집합의 마지막 노드 뒤에 작은 집합의 첫 노드를 붙인다.<br/>

&ensp;6단계: 큰 집합의 tail과 size 수정<br/>
```cpp
S[largerSet].tail ← tailS
S[largerSet].size ← S[A].size + S[B].size
```

&ensp;이제 큰 집합의 마지막 노드는 원래 작은 집합의 마지막 노드가 된다.<br/>
&ensp;크기는 두 집합 크기의 합으로 바꾼다.<br/>

&ensp;7단계: 작은 집합 비우기<br/>
```cpp
S[smallerSet].head, S[smallerSet].tail ← Ø
S[smallerSet].size ← 0
```

&ensp;작은 집합은 큰 집합에 흡수되었으니까 비운다.<br/>

## 배열 방식과 연결리스트 방식 비교

| 구현 방식    | find |  union | 특징                              |
| -------- | ---: | -----: | ------------------------------- |
| 배열 방식    | O(1) |   O(n) | find는 매우 간단하지만 union 때 배열 전체 검사 |
| 연결리스트 방식 | O(1) | O(min(\|A\|, \|B\|)) | 작은 집합만 수정해서 union 개선 |

## 트리에 기반한 구현

&ensp;분리집합 하나를 트리 하나로 표현한다.<br/>
&ensp;예를 들어 집합이 3개 있다고 하자.<br/>
* A = {1, 4, 7}
* B = {2, 3, 6, 9}
* C = {0, 5, 8, 10, 11}

&ensp;트리 기반 구현에서는 각각을 이렇게 표현한다.<br/>
* A 집합 → 하나의 트리
* B 집합 → 하나의 트리
* C 집합 → 하나의 트리

&ensp;그리고 각 집합은 트리의 루트(root) 로 식별된다.<br/>
&ensp;예를 들어 A 집합의 루트가 1이면,<br/>
* find(4) = 1
* find(7) = 1

---

&ensp;**연결트리와 가상트리**<br/>
&ensp;연결트리<br/>
* 각 노드는 원소 및 부모를 가리키는 포인터를 저장
* 단, 루트는 자신을 부모로 하는 포인터를 저장

&ensp;가상트리: 가상트리는 실제로 트리 노드를 따로 만들지 않고, 배열 하나로 트리처럼 표현하는 방식<br/>

---

&ensp;Parent 배열 읽는 법<br/>

<p align="center"><img src="/assets/img/data structure/14주차/14-6.png" width="600"></p>

* Parent[0] = 11  → 0의 부모는 11
* Parent[1] = 1   → 1은 루트
* Parent[2] = 2   → 2는 루트
* Parent[3] = 2   → 3의 부모는 2
* Parent[4] = 1   → 4의 부모는 1
* Parent[5] = 5   → 5는 루트
* Parent[6] = 2   → 6의 부모는 2
* Parent[7] = 1   → 7의 부모는 1
* Parent[8] = 5   → 8의 부모는 5
* Parent[9] = 6   → 9의 부모는 6
* Parent[10] = 5  → 10의 부모는 5
* Parent[11] = 8  → 11의 부모는 8

&ensp;루트는 자기 자신을 부모로 가지고 있다.<br/>
* Parent[1] = 1  → A 집합의 루트
* Parent[2] = 2  → B 집합의 루트
* Parent[5] = 5  → C 집합의 루트

&ensp;그래서 세 집합의 대표는 각각 1, 2, 5이다.<br/>
* A = {1, 4, 7}          대표 1
* B = {2, 3, 6, 9}       대표 2
* C = {0, 5, 8, 10, 11}  대표 5

<p align="center"><img src="/assets/img/data structure/14주차/14-7.png" width="600"></p>

&ensp;트리 기반 find(e)<br/>
&ensp;트리 기반에서 find(e)는 부모 포인터를 따라 루트까지 올라가는 연산이다.<br/>

&ensp;예를 들어 find(0)을 해보자.<br/>
&ensp;Parent 배열에서<br/>
* Parent[0] = 11
* Parent[11] = 8
* Parent[8] = 5
* Parent[5] = 5

&ensp;따라서 경로는 `0 → 11 → 8 → 5` 이다.<br/>
&ensp;5는 자기 자신을 부모로 가지니까 루트이다.<br/>
&ensp;`find(0) = 5` <br/>

&ensp;-> 실행시간: **O(n)** <br/>

&ensp;트리 기반 union(x, y)<br/>
&ensp;union(x, y): 트리 x, y 중 하나를 다른 트리의 루트 밑에 붙인다.<br/>

&ensp;예를 들어 B 집합의 루트는 2, C 집합의 루트는 5이다.<br/>
* B의 루트 = 2
* C의 루트 = 5

&ensp;union(B, C)를 할 때 C를 B 밑에 붙인다고 하면, `Parent[5] = 2` 로 바꾸면 된다.<br/>
&ensp;기존에는 C의 루트 5가 자기 자신을 가리켰다.<br/>
&ensp;`Parent[5] = 5` <br/>
&ensp;그런데 union 후에는 5의 부모가 2가 된다.<br/>
&ensp;그러면 C 트리 전체가 B 트리 밑으로 들어간다.<br/>
* C 집합의 모든 원소 Parent를 바꾸는 게 아니다.
* C의 루트 Parent만 바꾼다.

&ensp;-> 실행시간: **O(1)** <br/>

&ensp;기본 트리 기반 구현의 문제점<br/>
&ensp;트리 기반은 union이 빠르지만, find가 느려질 수 있다.<br/>
&ensp;왜냐하면 트리가 한쪽으로 길게 늘어질 수 있기 때문이다.<br/>

---

&ensp;성능 개선 전략 1: 크기에 의한 union<br/>
&ensp;**union-by-size** <br/>
&ensp;`크기에 의한 union = 작은 트리를 큰 트리의 루트 밑에 붙이는 방법` <br/>

&ensp;Size 배열<br/>
&ensp;union-by-size를 하려면 각 트리의 크기를 알아야 한다.<br/>
&ensp;그래서 Parent 배열과 함께 Size 배열을 사용한다.<br/>

<p align="center"><img src="/assets/img/data structure/14주차/14-9.png" width="600"></p>

&ensp;union-by-size 예시<br/>
&ensp;예를 들어 union(B, C)를 한다고 하자.<br/>
&ensp;B의 루트는 2, 크기는 4이다.<br/>
* rootB = 2
* Size[2] = 4

&ensp;C의 루트는 5, 크기는 5이다.<br/>
* rootC = 5
* Size[5] = 5

&ensp;작은 트리는 B, 큰 트리는 C이다.<br/>
&ensp;따라서 B를 C 밑에 붙여야 한다.<br/>
&ensp;`Parent[2] = 5` <br/>
&ensp;그리고 C의 크기를 갱신한다.<br/>
```css
Size[5] = Size[5] + Size[2]
        = 5 + 4
        = 9
```

----

&ensp;성능 개선 전략 2: 경로 압축<br/>
&ensp;경로 압축은 `find`를 수행할 때, 루트까지 가는 경로에 있는 노드들의 부모를 전부 루트로 바꿔버리는 방법이다.<br/>

&ensp;예시: find(0)<br/>
&ensp;처음 0에서 루트 2까지 가는 경로: `0 → 11 → 8 → 5 → 2` <br/>
&ensp; 기본 find는 그냥 루트 2를 찾고 끝난다.<br/>
&ensp;그런데 경로 압축 find는 루트를 찾은 뒤, 지나간 노드들의 부모를 전부 2로 바꾼다.<br/>
* Parent[0] = 2
* Parent[11] = 2
* Parent[8] = 2
* Parent[5] = 2

&ensp;그러면 구조가 이렇게 납작해진다.<br/>
* 0  → 2
* 11 → 2
* 8  → 2
* 5  → 2

&ensp;이후에 다시 find(0)을 하면 바로 2로 갈 수 있다.<br/>

&ensp;경로 압축 find 의사코드<br/>

<p align="center"><img src="/assets/img/data structure/14주차/14-11.png" width="600"></p>

&ensp;기본 find와의 차이: 루트를 찾은 결과를 Parent[e]에 저장한다.<br/>

&ensp;예를 들어 find(0)을 호출하면 내부적으로 이렇게 된다.<br/>
```css
find(0)
    Parent[0] = find(11)

find(11)
    Parent[11] = find(8)

find(8)
    Parent[8] = find(5)

find(5)
    Parent[5] = find(2)

find(2)
    return 2
```

&ensp;개선된 union 의사코드<br/>
<p align="center"><img src="/assets/img/data structure/14주차/14-12.png" width="600"></p>

* x 집합이 y 집합보다 작으면 x를 y 밑에 붙인다.
* y 집합이 x 집합보다 작거나 같으면 y를 x 밑에 붙인다.

# 시간복잡도 정리

&ensp;기본 트리 기반<br/>
* find(e): O(n)
* union(x, y): O(1)

&ensp;union-by-size 사용<br/>
* union(x, y): O(1)

&ensp;path compression 사용<br/>
* O(log* n)

&ensp;log* n은 중첩 log n을 의미<br/>
&ensp;즉, log* n = log log log ... n ≈ 1<br/>
&ensp;쉽게 말하면 log* n은 로그를 몇 번 취해야 1 이하가 되는지를 나타낸다.<br/>

| 구현 방식            |  find | union | 특징                         |
| ---------------- | ----: | ----: | -------------------------- |
| 기본 트리 기반         |  O(n) |  O(1) | union은 빠르지만 find가 느려질 수 있음 |
| union-by-size    |   개선됨 |  O(1) | 작은 트리를 큰 트리 밑에 붙임          |
| path compression | 매우 개선 |  O(1) | find 중 지나간 노드를 루트에 직접 연결   |
