# 트리

&ensp;트리의 핵심 정의: 트리(Tree) 는 데이터를 계층적으로 저장하는 자료구조<br/>

&ensp;배열이나 리스트는 데이터가 일렬로 놓여 있다.<br/>
```txt
배열 / 리스트
A - B - C - D
```

&ensp;그런데 트리는 데이터가 위에서 아래로 뻗어나간다.<br/>
```txt
트리
        A
      / | \
     B  C  D
    / \    |
   E   F   G
```

&ensp;트리는 **부모-자식 관계** 를 가진 자료 구조라고 보면 된다.<br/>

## 트리 ADT

&ensp;트리 ADT의 정의<br/>
1. 데이터 원소들이 계층적으로 저장된다.
2. 가장 위의 원소를 제외한 모든 원소는 부모(parent)를 가진다.
3. 각 원소는 0개 이상의 자식(children)을 가질 수 있다.
4. 트리는 비어 있을 수 있다.

<p align="center"><img src="/assets/img/data structure/11주차/11-1.png" width="600"></p>

&ensp;여기서 `(주)포도컴퓨터`는 가장 위에 있으니까 부모가 없다. 그래서 이 노드가 **루트(root)** 이다.<br/>
&ensp;`판매`, `제조`, `연구`는 (주)포도컴퓨터의 자식<br/>
* `국내`, `해외`는 `판매`의 자식이고,
* `아시아`, `미국`, `유럽`은 `해외`의 자식

&ensp;트리는 알고리즘을 단순화한다.<br/>
&ensp;일반적인 트리 ADT에서는 **빈 트리도 허용** 할 수 있다. 하지만 어떤 알고리즘을 설명할 때는 이렇게 가정한다.<br/>
&ensp;`트리가 비어 있지 않다고 가정한다.` <br/>
&ensp;왜냐하면 루트가 있다고 가정하면 알고리즘이 단순해지기 때문이다.<br/>
&ensp;예를 들어 트리의 모든 노드를 출력한다고 해보면<br/>
* 빈 트리일 수도 있음 → 루트가 있는지 먼저 검사해야 함
* 비어 있지 않다고 가정 → root()부터 바로 시작 가능

> 트리 ADT 자체는 빈 트리를 허용할 수 있지만, 알고리즘 설명에서는 루트가 존재한다고 가정하면 의사코드가 단순해진다.

## 트리 용어 정리

<p align="center"><img src="/assets/img/data structure/11주차/11-2.png" width="600"></p>

&ensp;1. 루트 root<br/>
&ensp;루트(root)는 부모가 없는 노드이다.<br/>
&ensp;위 트리에서는 A가 루트<br/>

&ensp;2. 내부 노드 internal node<br/>
&ensp;내부 노드(internal node) 는 자식이 하나 이상 있는 노드<br/>
&ensp;`A, B, C, F` <br/>
* A의 자식: B, C, D
* B의 자식: E, F
* C의 자식: G, H
* F의 자식: I, J, K

&ensp;3. 외부 노드 external node / 리프 leaf<br/>
&ensp;외부 노드(external node) 또는 리프(leaf) 는 자식이 없는 노드<br/>
&ensp;`D, E, G, H, I, J, K` <br/>
&ensp;트리의 끝에 있는 노드들이다.<br/>

&ensp;4. 형제 siblings<br/>
&ensp;형제 노드(siblings) 는 같은 부모를 가진 노드들<br/>
&ensp;예를 들어 `A의 자식: B, C, D` -> B, C, D는 서로 형제<br/>

&ensp;5. 조상 ancestor<br/>
&ensp;조상(ancestor) 은 어떤 노드에서 위로 올라갔을 때 만나는 노드들<br/>
&ensp;예를 들어 J의 조상은<br/>
```css
            A
           /
          B
           \
            F
             \
              J
```

* J의 부모는 F
* J의 조부모는 B
* J의 증조부모는 A

&ensp;따라서 J의 조상은 `F, B, A` <br/>

&ensp;6. 자손 descendant<br/>
&ensp;자손(descendant) 은 어떤 노드에서 아래로 내려갔을 때 만나는 노드들<br/>
&ensp;예를 들어 B의 자손은?<br/>
```css
      B
     / \
    E   F
       /|\
      I J K
```

&ensp;따라서 B의 자손은 `E, F, I, J, K` <br/>

&ensp;7. 부트리 subtree<br/>
&ensp;부트리(subtree) 는 어떤 노드와 그 노드의 모든 자손으로 이루어진 트리<br/>
&ensp;예를 들어 C를 루트로 하는 부트리로 표시<br/>
```css
      C
     / \
    G   H
```

&ensp;큰 트리 안에 들어 있는 작은 트리<br/>

## 경로 path

&ensp;경로(path) 는 조상 또는 자손 관계를 따라 이어진 노드들의 순서<br/>
&ensp;예를 들어 A에서 F까지 가는 경로는 `A → B → F` <br/>

&ensp;경로 길이 path length<br/>
&ensp;**경로 길이(path length)** 는 경로에 포함된 **간선(edge)의 개수** <br/>
&ensp;노드는 3개지만, 간선은 2개<br/>
```txt
A - B : 간선 1개
B - F : 간선 1개
```

&ensp;따라서 경로 ABF의 길이는 2<br/>

## 깊이 depth

&ensp;노드의 깊이(depth) 는 루트에서 그 노드까지 가는 유일한 경로의 길이<br/>
&ensp;`depth(v) = root에서 v까지의 간선 수` <br/>
* A의 깊이 = 0
* B, C, D의 깊이 = 1
* E, F, G, H의 깊이 = 2
* I, J, K의 깊이 = 3

## 높이 height

&ensp;1. 노드의 높이 height<br/>
&ensp;노드의 높이(height) 는 그 노드에서 외부 노드, 즉 리프까지 내려가는 가장 긴 경로의 길이<br/>

&ensp;`height(v) = v에서 가장 멀리 있는 리프까지의 간선 수` <br/>
&ensp;예를 들어 F의 높이를 보면<br/>
```txt
      F
    / | \
   I  J  K
```

&ensp;F에서 리프까지 가장 긴 경로는<br/>
* F → I
* F → J
* F → K

&ensp;전부 간선 1개 -> height(F) = 1<br/>

&ensp;B의 높이는?<br/>
```txt
      B
     / \
    E   F
       /|\
      I J K
```

* B → E       길이 1
* B → F → I   길이 2
* B → F → J   길이 2
* B → F → K   길이 2

&ensp;가장 긴 길이는 2개 -> height(B) = 2<br/>

&ensp;2. 트리의 높이 height of a tree<br/>
&ensp;트리의 높이는 루트의 높이<br/>
&ensp;`height(T) = height(root)` <br/>

&ensp;위 트리에서 루트 A에서 가장 멀리 있는 리프는 I, J, K<br/>
&ensp;`A → B → F → I` <br/>
&ensp;간선 수는 3개 -> `height(T) = 3` <br/>

&ensp;깊이와 높이 비교<br/>
&ensp;깊이 depth<br/>
&ensp;`루트에서 해당 노드까지` <br/>
* depth(A) = 0
* depth(B) = 1
* depth(F) = 2
* depth(I) = 3

&ensp;높이 height<br/>
&ensp;`해당 노드에서 가장 먼 리프까지` <br/>
* height(I) = 0
* height(F) = 1
* height(B) = 2
* height(A) = 3

| 노드 | 깊이 depth | 높이 height |
| -- | -------: | --------: |
| A  |        0 |         3 |
| B  |        1 |         2 |
| C  |        1 |         1 |
| D  |        1 |         0 |
| E  |        2 |         0 |
| F  |        2 |         1 |
| G  |        2 |         0 |
| H  |        2 |         0 |
| I  |        3 |         0 |
| J  |        3 |         0 |
| K  |        3 |         0 |

* 깊이 = 루트에서 내려오는 거리
* 높이 = 리프까지 내려갈 수 있는 거리

## 순서트리 ordered tree

&ensp;순서트리(ordered tree) 는 각 노드의 자식들 사이에 순서가 정해져 있는 트리<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-3.png" width="600"></p>

&ensp;예를 들어 책의 목차를 생각하면 된다.<br/>
```tree
책 A
├─ 서론
├─ Ch.1
├─ Ch.2
└─ 참고문헌
```

&ensp;여기서 서론, Ch.1, Ch.2, 참고문헌은 그냥 아무 순서로 있는 게 아니다.<br/>
&ensp;책에서는 반드시 순서가 중요하다. `서론 → Ch.1 → Ch.2 → 참고문헌` <br/>

&ensp;이 순서가 바뀌면 책의 구조가 이상해진다. 그래서 책의 목차 구조는 순서트리이다.<br/>

# 트리 ADT 메소드

&ensp;1. 일반 메소드<br/>

&ensp;**isEmpty()** <br/>
&ensp;`boolean isEmpty()` <br/>
&ensp;트리가 비어 있는지 확인하는 메소드<br/>
* 트리에 노드가 없으면 true
* 트리에 노드가 하나라도 있으면 false

&ensp;**size()** <br/>
&ensp;`integer size()` <br/>
&ensp;트리에 들어 있는 전체 노드 수를 반환한다.<br/>
&ensp;예를 들어 이 트리에서<br/>
```tree
            A
         /  |  \
        B   C   D
       / \ / \
      E  F G  H
        /|\
       I J K
```

&ensp;노드는 총 11개이다.<br/>
&ensp;`A, B, C, D, E, F, G, H, I, J, K` <br/>
&ensp;-> T.size() = 11<br/>

&ensp;2. 접근 메소드<br/>
&ensp;접근 메소드는 특정 노드에 접근하거나, 노드의 정보를 가져오는 메소드<br/>

&ensp;**root()**<br/>
&ensp;`node root()` <br/>
&ensp;트리의 루트 노드를 반환<br/>

&ensp;**parent(v)**<br/>
&ensp;`node parent(v)` <br/>
&ensp;노드 v의 부모 노드를 반환<br/>

&ensp;**children(v)** <br/>
&ensp;`node children(v)` <br/>
&ensp;노드 v의 자식들을 반환<br/>

&ensp;엄밀히는 자식이 여러 개일 수 있으니까, 반환값은 하나의 노드가 아니라 자식 노드들의 집합/리스트라고 이해<br/>

&ensp;**element(v)** <br/>
&ensp;`element element(v)` <br/>
&ensp;노드 v에 저장된 원소를 반환<br/>
&ensp;트리에서 노드와 원소를 구분해야 한다.<br/>
* 노드(node): 저장 공간 자체
* 원소(element): 그 노드 안에 들어 있는 데이터

&ensp;3. 질의 메소드<br/>
&ensp;질의 메소드는 특정 노드의 상태를 물어보는 메소드<br/>

&ensp;**isInternal(v)** <br/>
&ensp;`boolean isInternal(v)` <br/>
&ensp;노드 v가 내부 노드인지 확인한다.<br/>
&ensp;자식이 하나 이상 있으면 true이다.<br/>
* isInternal(A) = true
* isInternal(B) = true
* isInternal(F) = true
* isInternal(I) = false

&ensp;**isExternal(v)** <br/>
&ensp;`boolean isExternal(v)` <br/>
&ensp;노드 v가 외부 노드, 즉 리프인지 확인한다.<br/>
&ensp;자식이 없으면 true이다.<br/>
* isExternal(I) = true
* isExternal(D) = true
* isExternal(A) = false

&ensp;**isRoot(v)** <br/>
&ensp;`boolean isRoot(v)` <br/>
&ensp;노드 v가 루트인지 확인한다.<br/>
* isRoot(A) = true
* isRoot(B) = false

&ensp;4. 갱신 메소드<br/>
&ensp;갱신 메소드는 트리의 내용을 변경하는 메소드이다.<br/>

&ensp;**swapElements(v, w)** <br/>
&ensp;`swapElements(v, w)` <br/>
&ensp;노드 v와 노드 w에 저장된 원소를 서로 교환한다.<br/>
&ensp;**노드 위치를 바꾸는 게 아니라 노드 안의 데이터만 바꾸는 것** <br/>
&ensp;예를 들어,<br/>
```tree
      A
     / \
    B   C
```

&ensp;swapElements(B, C) 하면 구조는 그대로이지만 왼쪽 자식 노드와 오른쪽 자식 노드의 element 값을 교환한다.<br/>

```tree
      A
     / \
    C   B
```

&ensp;**setElement(v, e)** <br/>
&ensp;`element setElement(v, e)` <br/>
&ensp;노드 v에 저장된 원소를 새로운 원소 e로 바꾼다.<br/>

&ensp;예를 들어 setElement(B, "판매부") 를 하면 그러면 노드 B의 데이터가 "판매부"로 바뀐다.<br/>
&ensp;보통 기존 원소를 반환하기도 한다. (= oldElement = setElement(v, e)) <br/>

&ensp;4. 예외 **invalidNodeException()**<br/>
&ensp;`invalidNodeException()` <br/>
&ensp;잘못된 노드에 접근했을 때 발생하는 예외<br/>

## 트리 응용

&ensp;1. 직접 응용<br/>

&ensp;1) 조직 구성도<br/>
&ensp;조직도는 대표적인 트리 구조<br/>
```tree
회사
├─ 부
│  ├─ 과
│  └─ 팀
└─ 직원
```

* 내부노드: 부, 과, 팀 등
* 외부노드: 직원

&ensp;2) 파일 시스템<br/>
```tree
/
├─ home
│  ├─ user
│  │  ├─ a.txt
│  │  └─ b.txt
├─ var
└─ etc
```

* 내부노드: 폴더 또는 디렉토리
* 외부노드: 파일

&ensp;3) 프로그래밍 환경<br/>
```tree
프로그램
├─ 함수
│  ├─ if문
│  ├─ for문
│  └─ 변수 선언
└─ 클래스
```

* 내부노드: 프로그램 구조물
* 외부노드: 어휘, 상수, 심볼

&ensp;2. 간접 응용<br/>
&ensp;간접 응용은 현실 구조를 그대로 나타내는 것보다는, 알고리즘을 도와주는 보조 자료구조로 트리를 쓰는 경우<br/>
* 정렬 알고리즘
* 탐색 알고리즘
* 우선순위 큐
* 힙
* 이진 탐색 트리
* 파싱 트리

## 깊이 depth

&ensp;노드 v의 깊이(depth):  루트에서 v까지 가는 경로의 길이<br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-4.png" width="600"></p>

&ensp;이 의사코드는 재귀<br/>

```cpp
Alg depth(v)
1. if (isRoot(v))   // 현재 노드 v가 루트인지 검사
       return 0
   else
       return 1 + depth(parent(v))
```

&ensp;실행시간: `O(n)`<br/>
&ensp;n은 트리의 전체 노드 수<br/>

&ensp;depth 알고리즘의 특징<br/>
* depth(v)의 트리는 일반 트리이다. 즉, 트리의 상세 구현과 독립적이다.

&ensp;이 알고리즘은 트리가 배열로 구현되었는지 연결리스트로 구현되었는지 몰라도 된다.<br/>

## 높이 height

&ensp;노드 v의 높이(height): v에서 외부 노드, 즉 리프까지 가는 가장 긴 경로의 길이<br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-5.png" width="600"></p>

```cpp
Alg height(v)
1. if (isExternal(v))   // 현재 노드 v가 외부 노드인지 확인
       return 0
   else
       h ← 0
       for each w ∈ children(v)   // 현재 노드 v의 모든 자식 w에 대해 반복
           h ← max(h, height(w))
       return 1 + h   // v의 높이 = 가장 높은 자식의 높이 + 1
```

&ensp;실행시간: `O(n)`<br/>

## 선위순회 preorder traversal

&ensp;순회 traversal: 순회는 트리의 노드들을 체계적인 방식으로 모두 방문하는 것이다. 리스트는 앞에서 뒤로 가면 되지만 트리는 가지가 여러 개라서 방문 순서를 정해야 한다.<br/>

&ensp;선위순회: 노드를 그 자손들보다 앞서 방문한다.(= 현재 노드를 먼저 방문하고, 그 다음 자식들을 방문)<br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-6.png" width="600"></p>

```cpp
Alg preOrder(v) 
1. visit(v)  // 현재 노드 v에 방문
2. for each w ∈ children(v)   // 현재 노드의 자식들을 왼쪽부터, 또는 정해진 순서대로 하나씩 가져온다.
       preOrder(w)   // 각 자식 w에 대해 다시 선위순회를 수행
```

&ensp;실행시간: `O(n)` <br/>

&ensp;선위순회의 응용<br/>
1. 구조적 문서를 인쇄
2. 계층적 파일 시스템의 모든 폴더를 나열

&ensp;예: 구조적 문서를 인쇄<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-8.png" width="600"></p>

&ensp;의사 코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-7.png" width="600"></p>

```cpp
Alg printTableOfContents(v)
1. rPrint(v, 0)   // v는 출력할 문서 트리의 루트이다. 
2. return

Alg rPrint(v, d)   // v: 현재 출력할 노드, d: 현재 노드의 깊이
1. for i ← 1 to d
       write(Tab)   // 들여쓰기
2. write(element(v))
3. for each w ∈ children(v)
       rPrint(w, d + 1)  
4. return
```

## 후위순회 postorder traversal

&ensp;후위순회: 노드를 그의 자손들보다 나중에 방문한다.<br/>
&ensp;현재 노드를 바로 방문하지 않고, 먼저 자식들을 전부 방문한 뒤 마지막에 현재 노드를 방문<br/>
&ensp;후위순회 방식<br/>
1. 첫 번째 자식 부트리 방문
2. 두 번째 자식 부트리 방문
3. 세 번째 자식 부트리 방문
4. ...
5. 현재 노드 방문

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-9.png" width="600"></p>

```cpp
Alg postOrder(v)  
1. for each w ∈ children(v)   // 현재 노드 v는 아직 방문하지 않았다.
       postOrder(w)    // 먼저 자식에게 내려간다.
2. visit(v)         // 자식들의 처리가 모두 끝난 후 현재 노드 v를 방문
```

&ensp;실행시간: `O(n)` <br/>

&ensp;: 디스크 사용량 계산<br/>
&ensp;후위순회는 특히 자식들의 결과를 먼저 알아야 부모를 계산할 수 있는 문제에 많이 쓰인다.<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-10.png" width="600"></p>

&ensp;폴더 총 사용량 = 폴더 자체의 사용량 + 폴더 안의 파일 사용량 + 자식 폴더들의 사용량<br/>
&ensp;부모 폴더의 크기를 알기 위해서는 먼저 자식 폴더들의 크기를 알아야 한다.<br/>

&ensp;diskUsage(v) 의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-11.png" width="600"></p>

```cpp
Alg diskUsage(v)
1. sum ← 0   // 총 사용량 0
2. for each w ∈ children(v)
       sum ← sum + diskUsage(w)   // 현재 노드 v의 모든 자식 w에 대해 디스크 사용량 계산
3. return sum + space(v)  // 현재 노드 자체의 사용량 space(v)를 더해서 반환
```

## 레벨순회 levelorder traversal

&ensp;레벨: 트리에서 깊이 d에 존재하는 모든 노드들의 집합<br/>
&ensp;레벨순회: 깊이 d의 모든 노드들을 깊이 d+1의 노드들보다 앞서 방문한다.(= 위층부터 아래층으로 방문한다.)<br/>

&ensp;레벨순회는 큐 사용<br/>
&ensp;레벨순회는 먼저 발견한 노드를 먼저 방문해야 한다. -> FIFO 구조 -> 큐는 FIFO 구조<br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-12.png" width="600"></p>

```cpp
Alg levelOrder(v)
1. Q ← empty queue   // 빈 큐
2. Q.enqueue(v)      // 시작 노드 v를 큐에 넣는다복
3. while (!Q.isEmpty())  // 큐가 빌 때까지 반복
       v ← Q.dequeue()   // 큐에서 가장 앞에 있는 노드를 꺼낸다. 
       visit(v)     // 꺼낸 노드 방문
       for each w ∈ children(v)
           Q.enqueue(w)    // 현재 노드의 자식들의 큐의 뒤쪽으로 넣는다. 
4. return
```

&ensp;실행시간: `O(n)` <br/>

&ensp;예: 계층구조 인쇄<br/>
&ensp;레벨순회를 이용해서 회사 계층구조를 출력하는 예시<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-13.png" width="600"></p>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-14.png" width="600"></p>

```cpp
Alg printHierarchy(v)
1. Q ← empty queue
2. Q.enqueue(v)
3. while (!Q.isEmpty())
       v ← Q.dequeue()
       write(depth(v), element(v))   // 노드 이름, 노드 깊이 출력
       for each w ∈ children(v)
           Q.enqueue(w)
4. return
```

&ensp;선위순회, 후위순회, 레벨순회 비교<br/>

| 순회   | 방문 순서             | 자료구조  | 의사코드 핵심              | 대표 응용      |
| ---- | ----------------- | ----- | -------------------- | ---------- |
| 선위순회 | 부모 먼저, 자식 나중      | 재귀/스택 | `visit(v)` 후 자식 방문   | 목차 출력      |
| 후위순회 | 자식 먼저, 부모 나중      | 재귀/스택 | 자식 방문 후 `visit(v)`   | 디스크 사용량 계산 |
| 레벨순회 | 위 레벨 먼저, 아래 레벨 나중 | 큐     | dequeue 후 자식 enqueue | 계층구조 출력    |
