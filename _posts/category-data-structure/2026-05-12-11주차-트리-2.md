# 이진트리

&ensp;이진트리(binary tree) 는 각 노드가 최대 두 개의 자식을 가지는 트리<br/>
&ensp;`각 노드의 자식 수 ≤ 2` <br/>
* 왼쪽 자식 left child
* 오른쪽 자식 right child

<p align="center"><img src="/assets/img/data structure/11주차/11-15.png" width="600"></p>

&ensp;일반 트리와 이진트리 차이<br/>
* 일반 트리에서는 자식이 여러 개 가능
* 이진 트리에서는 한 노드가 자식을 최대 2개까지만 가능

&ensp;이진트리의 외부 노드와 내부 노드<br/>
* n : 전체 노드 수
* e : 외부 노드 수
* i : 내부 노드 수
* h : 트리의 높이

&ensp;외부 노드는 자식이 없는 노드(리프), 내부 노드는 자식이 있는 노드이다.<br/>

&ensp;이진트리의 성질<br/>
* e = i + 1
* n = i + e = 2e - 1
* h ≤ i
* h ≤ (n - 1) / 2
* e ≤ 2^h
* h ≥ log₂e
* h ≥ log₂(n + 1) - 1

# 이진트리 ADT 메소드

&ensp;앞에서 배운 트리 ADT 메소드를 그대로 상속한다.<br/>
* isEmpty()
* size()
* root()
* parent(v)
* children(v)
* element(v)
* isInternal(v)
* isExternal(v)
* isRoot(v)
* swapElements(v, w)
* setElement(v, e)

&ensp;추가 메소드 1: leftChild(v)<br/>
&ensp;`node leftChild(v)` <br/>
&ensp;노드 v의 왼쪽 자식을 반환한다.<br/>

&ensp;추가 메소드 2: rightChild(v)<br/>
&ensp;`node rightChild(v)` <br/>
&ensp;노드 v의 오른족 자식을 반환한다.<br/>

&ensp;추가 메소드 3: sibling(v)<br/>
&ensp;`node sibling(v)` <br/>
&ensp;노드 v의 형제 노드를 반환<br/>

&ensp;이진트리 ADT의 전제<br/>
&ensp;**적정 이진트리** <br/>
&ensp;적정 이진트리(proper binary tree) 는 내부 노드가 항상 자식을 정확히 2개 가지는 이진트리<br/>
* 내부 노드의 자식 수 = 2
* 외부 노드의 자식 수 = 0

&ensp;이 둘만 허용한다.<br/>

```cpp
Alg height(v)
1. if (isExternal(v))
       return 0
   else
       h ← max(height(leftChild(v)),
               height(rightChild(v)))    // 현재 노드가 내부 노드라면 왼쪽 자식과 오른쪽 자식의 높이를 각각 구해서 큰 값 저장
       return 1 + h
```

## 이진트리 예시: 수식 평가 expression evaluation

&ensp;수식 트리는 연산자와 피연산자를 트리로 표현한다.<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-20.png" width="600"></p>

&ensp; = (2 × (7 - 1)) / (3 + 1)<br/>

&ensp;연산자 노드의 값을 계산하려면 먼저 왼쪽 값과 오른쪽 값을 알아야 한다.<br/>
&ensp;예를 들어 루트 / 를 계산하려면<br/> 
* 왼쪽 부트리 값 = 2 × (7 - 1)
* 오른쪽 부트리 값 = 3 + 1

&ensp;이 구 값을 먼저 알아야 한다. 즉 부모 연산자를 계산하기 전에 자식 부트리 값을 먼저 계산해야 한다. 그래서 수식 평가는 후위순회 방식이다.<br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-21.png" width="600"></p>

&ensp;여기서 ◇는 연산자를 의미<br/>

```cpp
Alg evalExpr(v)
1. if (isExternal(v))   // 현재 노드가 외부노드라면 숫자
       return element(v)
   else
       x ← evalExpr(leftChild(v))
       y ← evalExpr(rightChild(v))
       ◇ ← element(v)   // 현재 노드에 저장된 연산자
       return x ◇ y
```

## 중위순회 Inorder Traversal

&ensp;중위순회(inorder traversal) 는 이진트리에서만 자연스럽게 정의되는 순회 방식<br/>
&ensp;방문 순서: `왼쪽 부트리 방문 → 현재 노드 방문 → 오른쪽 부트리 방문` <br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-22.png" width="600"></p>

```cpp
Alg inOrder(v)
1. if (isInternal(v))    // 현재 노드 v가 내부 노드라면 왼쪽 자식이 있으니까 먼저 왼쪽 부트리를 중위순회
       inOrder(leftChild(v))
2. visit(v)
3. if (isInternal(v))   
       inOrder(rightChild(v))    // 오른쪽 부트리를 중위순회
```

&ensp;실행시간: `O(n)` <br/>

&ensp;예: 이진트리 그리기<br/>
&ensp;이진트리의 노드들을 xy 평면에 그리고자 하자.<br/>
&ensp;규칙<br/>
* $x_v$ = v의 중위순회 순위
       - x좌표 = 중위순회에서 몇 번째로 방문되는가
* $y_v$ = v의 깊이
       - y좌표 = 루트에서 얼마나 아래에 있는가

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-23.png" width="600"></p>

```cpp
Alg drawBinaryTree(v)
1. rDBT(v, 0)   // 초기 rank는 0

Alg rDBT(v, rank이
1. if (isInternal(v))  
       rDBT(leftChild(v), rank)  // 중위순회-> 왼쪽 부트리 먼저 처리
2. rank ← rank + 1      // 현재 노드를 방문할 차례 -> 방문 순위 + 1
3. drawNodeXY(v, rank, depth(v))   // x좌표: 중위순회 순위, y 좌표: 깊이
4. if (isInternal(v))
       rDBT(rightChild(v), rank)
```

&ensp;예: 수식 인쇄<br/>
&ensp;수식 트리에서 괄호가 있는 수식을 출력하는 방법<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-24.png" width="600"></p>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-25.png" width="600"></p>

```cpp
Alg printExpr(v)
1. if (isInternal(v))   // 현재 노드가 내부 노드 즉 연산자라면 여는 괄호 출력
       write('(')
       printExpr(leftChild(v))  // 왼쪽 부트리 출력
2. write(element(v))
3. if (isInternal(v))   // 현재 노드가 내부 노드라면 오른쪽 부트리를 출력한 뒤 닫는 괄호 )를 출력
       printExpr(rightChild(v))
       write(')')
```

## 오일러 투어 순회 Euler Tour

&ensp;이진트리에 대한 일반순회 generic traversal<br/>
&ensp;쉽게 말하면 트리의 바깥 테두리를 띠라 한 바퀴 도는 순회이다. 출발은 루트의 왼쪽 방향에서 시작한다.<br/>

&ensp;오일러 투어의 핵심: 한 노드를 세 번 방문한다<br/>
1. 왼쪽에서 만남  → L
2. 아래에서 만남  → B
3. 오른쪽에서 만남 → R

&ensp;이 세 위치가 각각 순회와 연결된다.<br/>
* visitLeft(v)  = preorder 위치
* visitBelow(v) = inorder 위치
* visitRight(v) = postorder 위치

<p align="center"><img src="/assets/img/data structure/11주차/11-26.png" width="600"></p>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-27.png" width="600"></p>

&ensp;오일러 투어가 세 순회를 포함하는 이유<br/>
* visitLeft(v)   → Root, Left, Right에서 Root 위치 → preorder
* visitBelow(v)  → Left, Root, Right에서 Root 위치 → inorder
* visitRight(v)  → Left, Right, Root에서 Root 위치 → postorder

&ensp;예: 부트리 크기 계산<br/>
&ensp;오일러 투어를 이용해서 각 노드를 루트로 하는 부트리의 크기를 계산하는 예시<br/>
&ensp;부트리의 크기: 해당 노드와 그 노드의 모든 자손 노드의 수<br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-28.png" width="600"></p>

```cpp
Alg findSizeOfSubtrees(v)
1. k ← 0   // k = 각 노드를 왼쪽에서 방문했을 때의 카운터 값
2. eulerTour(v)

Alg visitLeft(v)
1. k ← k + 1
2. v.kleft ← k   // v.kleft = 노드 v를 왼쪽에서 처음 방문했을 때의 k 값

Alg visitBelow(v)
1. return

Alg visitRight(v)
1. v.size ← k - v.kleft + 1  // v.size = v를 루트로 하는 부트리의 크기
```

&ensp;작동 원리<br/>
&ensp;k는 왼쪽에서 방문했을 때의 누적 번호<br/>
* 왼쪽에서 방문하면 → k 증가 → 그 노드의 kleft 저장
* 오른쪽에서 방문하면 → 현재 k - kleft + 1 계산 → 그 노드의 부트리 크기 저장

<p align="center"><img src="/assets/img/data structure/11주차/11-29.png" width="600"></p>

&ensp;왜 오일러 투어로 부트리 크기를 구할 수 있을까?<br/>
&ensp;부트리 크기는 그 노드 아래에 몇 개의 노드가 있는지 알아야 한다. 일반적인 후위순회로도 이렇게 구할 수 있다. `size(v) = 1 + size(leftChild(v)) + size(rightChild(v))` <br/>
&ensp;그런데 오일러 투어 방식은 방문 시작 번호와 방문 종료 시점의 번호를 이용해서 한 번의 순회로 구하는 방식이다.<br/>
* v의 부트리를 들어갈 때 번호 저장
* v의 부트리를 다 빠져나올 때 현재 번호와 비교

# 배열에 기초한 이진트리

&ensp;1D 배열로 이진트리 표현<br/>
&ensp;이진트리는 배열 하나로 표현할 수 있다.<br/>
&ensp;`T[i] = 순위 i에 해당하는 노드의 원소` <br/>
&ensp;다만 여기서는 0번 칸은 사용하지 않고, 루트를 1번에 저장한다.<br/>
&ensp;0번은 부모/자식 인덱스 계산을 쉽게 하기 위해서이다.<br/>

<p align="center"><img src="/assets/img/data structure/11주차/11-30.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/11주차/11-31.png" width="600"></p>

&ensp;배열 인덱스 규칙<br/>
* 왼쪽 자식 위치  = 2i
* 오른쪽 자식 위치 = 2i + 1
* 부모 위치      = i / 2

&ensp;예를 들어 B가 2번 위치에 있으면,<br/>
* B의 왼쪽 자식 = 2 × 2 = 4번
* B의 오른쪽 자식 = 2 × 2 + 1 = 5번
* B의 부모 = 2 / 2 = 1번 

&ensp;n과 N의 의미<br/>
* n = 실제 노드 수
* N = 배열의 크기 또는 사용할 수 있는 최대 순위 범위

&ensp;최선과 최악의 경우<br/>

&ensp;`실제 노드 수 n = 배열에서 필요한 최대 위치 N` <br/>

# 연결 이진트리

&ensp;연결 이진트리는 각 노드를 객체 또는 구조체로 만들고 각 노드 안에 필요한 정보를 저장하는 방식이다.<br/>

&ensp;노드 저장 내용<br/>
1. 원소 elem
2. 부모 노드 parent
3. 왼쪽 자식 노드 left
4. 오른쪽 자식 노드 right

&ensp;노드 하나가 이렇게 생겼다고 생각하면 된다.<br/>
```css
┌───────────────┐
│ parent pointer│
├───────────────┤
│ elem          │
├───────────────┤
│ left pointer  │
├───────────────┤
│ right pointer │
└───────────────┘
```

&ensp;예시 구조<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-45.png" width="600"></p>

* root → B
* n = 5

&ensp;노드 B: 루트<br/>
* B.parent = NULL
* B.left = A
* B.right = D

&ensp;노드 A: 리프<br/>
* A.parent = B
* A.left = NULL
* A.right = NULL

&ensp;노드 D: 자식 둘<br/>
* D.parent = B
* D.left = C
* D.right = E

&ensp;노드 C, E: 리프<br/>
* C.parent = D
* C.left = NULL
* C.right = NULL
* E.parent = D
* E.left = NULL
* E.right = NULL

&ensp;연결 이진트리의 root와 n<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-46.png" width="600"></p>

* root : 루트 노드를 가리키는 포인터
* n    : 전체 노드 수

&ensp;트리 전체 구조는 보통 이런 정보를 가진다.<br/>
```cpp
typedef struct BinaryTree {
    Node* root;
    int n;
} BinaryTree;
```

&ensp;root는 루트 노드의 주소를 저장하고, n은 트리 안에 있는 전체 노드 수를 저장한다. 그래서 size() 를 호출하면 전체 노드를 세지 않고 바로 n을 반환할 수 있다.<br/>

# 연결트리

&ensp;일반 트리를 연결 구조로 구현하는 방법<br/>
&ensp;일반 트리는 자식이 몇 개일지 모른다. 그래서 이진트리처럼 `left`, `right` 만으로는 부족하다.<br/>

&ensp;연결트리 Ver.1: 자식 리스트 방식<br/>

&ensp;노드 저장 내용<br/>
1. 원소 elem
2. 부모 노드 parent
3. 자식 노드들의 리스트

&ensp;각 노드가 자기 자식들을 리스트로 가지고 있다.<br/>
```cpp
B.children = [A, D, F]
D.children = [C, E]
A.children = []
C.children = []
E.children = []
F.children = []
```

<p align="center"><img src="/assets/img/data structure/11주차/11-49.png" width="600"></p>

&ensp;Ver.1의 특징<br/>
&ensp;자식이 몇 명이든 리스트에 저장된다. -> 그래서 일반 트리를 표현하기 편하다.<br/>
* 자식이 0명 → 빈 리스트
* 자식이 2명 → 자식 2개짜리 리스트
* 자식이 5명 → 자식 5개짜리 리스트

&ensp;연결트리 Ver.2<br/>
&ensp;Ver.2는 자식 리스트를 통째로 저장하지 않고 첫 번째 자식과 바로 아래 동생 노드를 저장하는 방식이다. 이 방식은 흔히 `first child / next sibling representation` 이라고 생각하면 된다.<br/>

&ensp;노드 저장 내용<br/>
1. 원소 elem
2. 부모 노드 parent
3. 첫째 자식 노드 first
4. 바로 아래 동생 노드(같은 부모를 가진 형재들 중에서 다음 형제 노드) next

<p align="center"><img src="/assets/img/data structure/11주차/11-50.png" width="600"></p>

&ensp;B의 자식들<br/>
* B의 첫째 자식 = A
       - B.first = A
* A의 다음 형제 = D
       - A.next = D
* D의 다음 형제 = F
       - D.next = F
* F의 다음 형제 = NULL
       - F.next = NULL

&ensp;리프 노드: A, C, E, F<br/>
* A.first = NULL
* C.first = NULL
* E.first = NULL
* F.first = NULL

&ensp;children(v) 의사코드<br/>
&ensp;`children(v)`는 노드 `v`의 모든 자식을 모아서 반환하는 함수이다. 그런데 Ver.2에서는 `v`가 모든 자식 리스트를 직접 들고 있지 않는다. 대신 첫째 자식만 알고 있다. (`v.first`) 그리고 나머지 자식들은 첫째 자식의 `next`, 그 다음의 `next` 를 따라가야 한다.<br/>

```cpp
Alg children(v)
1. C ← ∅   // 자식들을 담을 빈 집합 또는 리스트 C를 만든다.
2. c ← v.first   // 현재 확인할 자식 후보 c를 v의 첫째 자식으로 둔다.
3. while (c ≠ ∅)   // 현재 자식 후보 c가 NULL이 아닐 동안 반복.
       C ← C ∪ {c}  // 현재 자식 c를 결과 리스트 C에 추가.
       c ← c.next   // 다음 형제로 이동.
4. return C
```

&ensp;Ver.1과 Ver.2 비교<br/>

&ensp;Ver.1: 자식 리스트 방식<br/>
&ensp;각 노드가 자식들의 리스트를 직접 저장한다.<br/>
&ensp;장점<br/>
* children(v)를 바로 얻기 쉽다.
* 자식 수가 많은 일반 트리에 자연스럽다.

&ensp;단점<br/>
* 각 노드마다 리스트 구조를 관리해야 한다.
* 자식 삽입/삭제 시 리스트 관리가 필요하다.

&ensp;Ver.2: first-child next-sibling 방식<br/>
&ensp;각 노드가 첫째 자식과 다음 형제만 저장한다.<br/>
&ensp;장점<br/>
* 노드마다 고정된 포인터 수만 가진다.
* 자식 수가 달라도 같은 구조로 표현 가능하다.

&ensp;단점<br/>
* children(v)를 구하려면 first부터 next를 따라가야 한다. -> 따라서 자식 수만큼 시간이 걸린다.
