# 이진트리

&ensp;이진트리(binary tree) 는 각 노드가 최대 두 개의 자식을 가지는 트리<br/>
&ensp;`각 노드의 자식 수 ≤ 2` <br/>
* 왼쪽 자식 left child
* 오른쪽 자식 right child

<p align="center"><img src="/assets/img/data structure/11주차/11-15.png" width="600"></p>

&ensp;일반 트리와 이진트리 차이<br/>
* 일반 트리에서는 자식이 여러 개 가능
* 이진 트리에서는 한 노드가 자식을 최대 2개까지만 가능

&ensp;이진트리의 외부 노드와 내부 노드<br/>
* n : 전체 노드 수
* e : 외부 노드 수
* i : 내부 노드 수
* h : 트리의 높이

&ensp;외부 노드는 자식이 없는 노드(리프), 내부 노드는 자식이 있는 노드이다.<br/>

&ensp;이진트리의 성질<br/>
* e = i + 1
* n = i + e = 2e - 1
* h ≤ i
* h ≤ (n - 1) / 2
* e ≤ 2^h
* h ≥ log₂e
* h ≥ log₂(n + 1) - 1

# 이진트리 ADT 메소드

&ensp;앞에서 배운 트리 ADT 메소드를 그대로 상속한다.<br/>
* isEmpty()
* size()
* root()
* parent(v)
* children(v)
* element(v)
* isInternal(v)
* isExternal(v)
* isRoot(v)
* swapElements(v, w)
* setElement(v, e)

&ensp;추가 메소드 1: leftChild(v)<br/>
&ensp;`node leftChild(v)` <br/>
&ensp;노드 v의 왼쪽 자식을 반환한다.<br/>

&ensp;추가 메소드 2: rightChild(v)<br/>
&ensp;`node rightChild(v)` <br/>
&ensp;노드 v의 오른족 자식을 반환한다.<br/>

&ensp;추가 메소드 3: sibling(v)<br/>
&ensp;`node sibling(v)` <br/>
&ensp;노드 v의 형제 노드를 반환<br/>

&ensp;이진트리 ADT의 전제<br/>
&ensp;**적정 이진트리** <br/>
&ensp;적정 이진트리(proper binary tree) 는 내부 노드가 항상 자식을 정확히 2개 가지는 이진트리<br/>
* 내부 노드의 자식 수 = 2
* 외부 노드의 자식 수 = 0

&ensp;이 둘만 허용한다.<br/>

```cpp
Alg height(v)
1. if (isExternal(v))
       return 0
   else
       h ← max(height(leftChild(v)),
               height(rightChild(v)))    // 현재 노드가 내부 노드라면 왼쪽 자식과 오른쪽 자식의 높이를 각각 구해서 큰 값 저장
       return 1 + h
```

## 이진트리 예시: 수식 평가 expression evaluation

&ensp;수식 트리는 연산자와 피연산자를 트리로 표현한다.<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-20.png" width="600"></p>

&ensp; = (2 × (7 - 1)) / (3 + 1)<br/>

&ensp;연산자 노드의 값을 계산하려면 먼저 왼쪽 값과 오른쪽 값을 알아야 한다.<br/>
&ensp;예를 들어 루트 / 를 계산하려면<br/> 
* 왼쪽 부트리 값 = 2 × (7 - 1)
* 오른쪽 부트리 값 = 3 + 1

&ensp;이 구 값을 먼저 알아야 한다. 즉 부모 연산자를 계산하기 전에 자식 부트리 값을 먼저 계산해야 한다. 그래서 수식 평가는 후위순회 방식이다.<br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-21.png" width="600"></p>

&ensp;여기서 ◇는 연산자를 의미<br/>

```cpp
Alg evalExpr(v)
1. if (isExternal(v))   // 현재 노드가 외부노드라면 숫자
       return element(v)
   else
       x ← evalExpr(leftChild(v))
       y ← evalExpr(rightChild(v))
       ◇ ← element(v)   // 현재 노드에 저장된 연산자
       return x ◇ y
```

## 중위순회 Inorder Traversal

&ensp;중위순회(inorder traversal) 는 이진트리에서만 자연스럽게 정의되는 순회 방식<br/>
&ensp;방문 순서: `왼쪽 부트리 방문 → 현재 노드 방문 → 오른쪽 부트리 방문` <br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-22.png" width="600"></p>

```cpp
Alg inOrder(v)
1. if (isInternal(v))    // 현재 노드 v가 내부 노드라면 왼쪽 자식이 있으니까 먼저 왼쪽 부트리를 중위순회
       inOrder(leftChild(v))
2. visit(v)
3. if (isInternal(v))   
       inOrder(rightChild(v))    // 오른쪽 부트리를 중위순회
```

&ensp;실행시간: `O(n)` <br/>

&ensp;예: 이진트리 그리기<br/>
&ensp;이진트리의 노드들을 xy 평면에 그리고자 하자.<br/>
&ensp;규칙<br/>
* $x_v$ = v의 중위순회 순위
       - x좌표 = 중위순회에서 몇 번째로 방문되는가
* $y_v$ = v의 깊이
       - y좌표 = 루트에서 얼마나 아래에 있는가

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-23.png" width="600"></p>

```cpp
Alg drawBinaryTree(v)
1. rDBT(v, 0)   // 초기 rank는 0

Alg rDBT(v, rank이
1. if (isInternal(v))  
       rDBT(leftChild(v), rank)  // 중위순회-> 왼쪽 부트리 먼저 처리
2. rank ← rank + 1      // 현재 노드를 방문할 차례 -> 방문 순위 + 1
3. drawNodeXY(v, rank, depth(v))   // x좌표: 중위순회 순위, y 좌표: 깊이
4. if (isInternal(v))
       rDBT(rightChild(v), rank)
```

&ensp;예: 수식 인쇄<br/>
&ensp;수식 트리에서 괄호가 있는 수식을 출력하는 방법<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-24.png" width="600"></p>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-25.png" width="600"></p>

```cpp
Alg printExpr(v)
1. if (isInternal(v))   // 현재 노드가 내부 노드 즉 연산자라면 여는 괄호 출력
       write('(')
       printExpr(leftChild(v))  // 왼쪽 부트리 출력
2. write(element(v))
3. if (isInternal(v))   // 현재 노드가 내부 노드라면 오른쪽 부트리를 출력한 뒤 닫는 괄호 )를 출력
       printExpr(rightChild(v))
       write(')')
```

## 오일러 투어 순회 Euler Tour

&ensp;이진트리에 대한 일반순회 generic traversal<br/>
&ensp;쉽게 말하면 트리의 바깥 테두리를 띠라 한 바퀴 도는 순회이다. 출발은 루트의 왼쪽 방향에서 시작한다.<br/>

&ensp;오일러 투어의 핵심: 한 노드를 세 번 방문한다<br/>
1. 왼쪽에서 만남  → L
2. 아래에서 만남  → B
3. 오른쪽에서 만남 → R

&ensp;이 세 위치가 각각 순회와 연결된다.<br/>
* visitLeft(v)  = preorder 위치
* visitBelow(v) = inorder 위치
* visitRight(v) = postorder 위치

<p align="center"><img src="/assets/img/data structure/11주차/11-26.png" width="600"></p>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-27.png" width="600"></p>

&ensp;오일러 투어가 세 순회를 포함하는 이유<br/>
* visitLeft(v)   → Root, Left, Right에서 Root 위치 → preorder
* visitBelow(v)  → Left, Root, Right에서 Root 위치 → inorder
* visitRight(v)  → Left, Right, Root에서 Root 위치 → postorder

&ensp;예: 부트리 크기 계산<br/>
&ensp;오일러 투어를 이용해서 각 노드를 루트로 하는 부트리의 크기를 계산하는 예시<br/>
&ensp;부트리의 크기: 해당 노드와 그 노드의 모든 자손 노드의 수<br/>

&ensp;의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-28.png" width="600"></p>

```cpp
Alg findSizeOfSubtrees(v)
1. k ← 0   // k = 각 노드를 왼쪽에서 방문했을 때의 카운터 값
2. eulerTour(v)

Alg visitLeft(v)
1. k ← k + 1
2. v.kleft ← k   // v.kleft = 노드 v를 왼쪽에서 처음 방문했을 때의 k 값

Alg visitBelow(v)
1. return

Alg visitRight(v)
1. v.size ← k - v.kleft + 1  // v.size = v를 루트로 하는 부트리의 크기
```

&ensp;작동 원리<br/>
&ensp;k는 왼쪽에서 방문했을 때의 누적 번호<br/>
* 왼쪽에서 방문하면 → k 증가 → 그 노드의 kleft 저장
* 오른쪽에서 방문하면 → 현재 k - kleft + 1 계산 → 그 노드의 부트리 크기 저장

<p align="center"><img src="/assets/img/data structure/11주차/11-29.png" width="600"></p>

&ensp;왜 오일러 투어로 부트리 크기를 구할 수 있을까?<br/>
&ensp;부트리 크기는 그 노드 아래에 몇 개의 노드가 있는지 알아야 한다. 일반적인 후위순회로도 이렇게 구할 수 있다. `size(v) = 1 + size(leftChild(v)) + size(rightChild(v))` <br/>
&ensp;그런데 오일러 투어 방식은 방문 시작 번호와 방문 종료 시점의 번호를 이용해서 한 번의 순회로 구하는 방식이다.<br/>
* v의 부트리를 들어갈 때 번호 저장
* v의 부트리를 다 빠져나올 때 현재 번호와 비교

# 배열에 기초한 이진트리

&ensp;1D 배열로 이진트리 표현<br/>
&ensp;이진트리는 배열 하나로 표현할 수 있다.<br/>
&ensp;`T[i] = 순위 i에 해당하는 노드의 원소` <br/>
&ensp;다만 여기서는 0번 칸은 사용하지 않고, 루트를 1번에 저장한다.<br/>
&ensp;0번은 부모/자식 인덱스 계산을 쉽게 하기 위해서이다.<br/>

<p align="center"><img src="/assets/img/data structure/11주차/11-30.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/11주차/11-31.png" width="600"></p>

&ensp;배열 인덱스 규칙<br/>
* 왼쪽 자식 위치  = 2i
* 오른쪽 자식 위치 = 2i + 1
* 부모 위치      = i / 2

&ensp;예를 들어 B가 2번 위치에 있으면,<br/>
* B의 왼쪽 자식 = 2 × 2 = 4번
* B의 오른쪽 자식 = 2 × 2 + 1 = 5번
* B의 부모 = 2 / 2 = 1번 

&ensp;n과 N의 의미<br/>
* n = 실제 노드 수
* N = 배열의 크기 또는 사용할 수 있는 최대 순위 범위

&ensp;최선과 최악의 경우<br/>

&ensp;`실제 노드 수 n = 배열에서 필요한 최대 위치 N` <br/>

# 연결 이진트리

&ensp;연결 이진트리는 각 노드를 객체 또는 구조체로 만들고 각 노드 안에 필요한 정보를 저장하는 방식이다.<br/>

&ensp;노드 저장 내용<br/>
1. 원소 elem
2. 부모 노드 parent
3. 왼쪽 자식 노드 left
4. 오른쪽 자식 노드 right

&ensp;노드 하나가 이렇게 생겼다고 생각하면 된다.<br/>
```css
┌───────────────┐
│ parent pointer│
├───────────────┤
│ elem          │
├───────────────┤
│ left pointer  │
├───────────────┤
│ right pointer │
└───────────────┘
```

&ensp;예시 구조<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-45.png" width="600"></p>

* root → B
* n = 5

&ensp;노드 B: 루트<br/>
* B.parent = NULL
* B.left = A
* B.right = D

&ensp;노드 A: 리프<br/>
* A.parent = B
* A.left = NULL
* A.right = NULL

&ensp;노드 D: 자식 둘<br/>
* D.parent = B
* D.left = C
* D.right = E

&ensp;노드 C, E: 리프<br/>
* C.parent = D
* C.left = NULL
* C.right = NULL
* E.parent = D
* E.left = NULL
* E.right = NULL

&ensp;연결 이진트리의 root와 n<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-46.png" width="600"></p>

* root : 루트 노드를 가리키는 포인터
* n    : 전체 노드 수

&ensp;트리 전체 구조는 보통 이런 정보를 가진다.<br/>
```cpp
typedef struct BinaryTree {
    Node* root;
    int n;
} BinaryTree;
```

&ensp;root는 루트 노드의 주소를 저장하고, n은 트리 안에 있는 전체 노드 수를 저장한다. 그래서 size() 를 호출하면 전체 노드를 세지 않고 바로 n을 반환할 수 있다.<br/>

# 연결트리

&ensp;일반 트리를 연결 구조로 구현하는 방법<br/>
&ensp;일반 트리는 자식이 몇 개일지 모른다. 그래서 이진트리처럼 `left`, `right` 만으로는 부족하다.<br/>

&ensp;연결트리 Ver.1: 자식 리스트 방식<br/>

&ensp;노드 저장 내용<br/>
1. 원소 elem
2. 부모 노드 parent
3. 자식 노드들의 리스트

&ensp;각 노드가 자기 자식들을 리스트로 가지고 있다.<br/>
```cpp
B.children = [A, D, F]
D.children = [C, E]
A.children = []
C.children = []
E.children = []
F.children = []
```

&ensp;예시<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-48.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/11주차/11-49.png" width="600"></p>

&ensp;Ver.1의 특징<br/>
&ensp;자식이 몇 명이든 리스트에 저장된다. -> 그래서 일반 트리를 표현하기 편하다.<br/>
* 자식이 0명 → 빈 리스트
* 자식이 2명 → 자식 2개짜리 리스트
* 자식이 5명 → 자식 5개짜리 리스트

&ensp;연결트리 Ver.2<br/>
&ensp;Ver.2는 자식 리스트를 통째로 저장하지 않고 첫 번째 자식과 바로 아래 동생 노드를 저장하는 방식이다. 이 방식은 흔히 `first child / next sibling representation` 이라고 생각하면 된다.<br/>

&ensp;노드 저장 내용<br/>
1. 원소 elem
2. 부모 노드 parent
3. 첫째 자식 노드 first
4. 바로 아래 동생 노드(같은 부모를 가진 형재들 중에서 다음 형제 노드) next

<p align="center"><img src="/assets/img/data structure/11주차/11-48.png" width="600"></p>
<p align="center"><img src="/assets/img/data structure/11주차/11-50.png" width="600"></p>

&ensp;B의 자식들<br/>
* B의 첫째 자식 = A
       - B.first = A
* A의 다음 형제 = D
       - A.next = D
* D의 다음 형제 = F
       - D.next = F
* F의 다음 형제 = NULL
       - F.next = NULL

&ensp;리프 노드: A, C, E, F<br/>
* A.first = NULL
* C.first = NULL
* E.first = NULL
* F.first = NULL

&ensp;연결트리 Ver.2 메소드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-51.png" width="600"></p>

&ensp;children(v) 의사코드<br/>
&ensp;`children(v)`는 노드 `v`의 모든 자식을 모아서 반환하는 함수이다. 그런데 Ver.2에서는 `v`가 모든 자식 리스트를 직접 들고 있지 않는다. 대신 첫째 자식만 알고 있다. (`v.first`) 그리고 나머지 자식들은 첫째 자식의 `next`, 그 다음의 `next` 를 따라가야 한다.<br/>

```cpp
Alg children(v)
1. C ← ∅   // 자식들을 담을 빈 집합 또는 리스트 C를 만든다.
2. c ← v.first   // 현재 확인할 자식 후보 c를 v의 첫째 자식으로 둔다.
3. while (c ≠ ∅)   // 현재 자식 후보 c가 NULL이 아닐 동안 반복.
       C ← C ∪ {c}  // 현재 자식 c를 결과 리스트 C에 추가.
       c ← c.next   // 다음 형제로 이동.
4. return C
```

&ensp;Ver.1과 Ver.2 비교<br/>

&ensp;Ver.1: 자식 리스트 방식<br/>
&ensp;각 노드가 자식들의 리스트를 직접 저장한다.<br/>
&ensp;장점<br/>
* children(v)를 바로 얻기 쉽다.
* 자식 수가 많은 일반 트리에 자연스럽다.

&ensp;단점<br/>
* 각 노드마다 리스트 구조를 관리해야 한다.
* 자식 삽입/삭제 시 리스트 관리가 필요하다.

&ensp;Ver.2: first-child next-sibling 방식<br/>
&ensp;각 노드가 첫째 자식과 다음 형제만 저장한다.<br/>
&ensp;장점<br/>
* 노드마다 고정된 포인터 수만 가진다.
* 자식 수가 달라도 같은 구조로 표현 가능하다.

&ensp;단점<br/>
* children(v)를 구하려면 first부터 next를 따라가야 한다. -> 따라서 자식 수만큼 시간이 걸린다.

## 계승자

&ensp;이진트리 T의 노드 v에 대한 아래의 일반 알고리즘을 작성하라<br/>
* preOrderSucc(v): 선위순회 계승자(즉, T를 노드 v 직후에 방문되는 노드)를 반환
* inOrderSucc(v): 중위순회 계승자(즉, T를 중위순회할 경우 노드 v 직후에 방문되는 노드)를 반환
* postOrderSucc(v): 후위순회 계승자(즉, T를 후위순회할 경우 노드 v 직후에 방문되는 노드)를 반환

&ensp;주의: 계승자 노드가 존재하지 않을 경우 invalidNodeException을 발령해야 한다.<br/>

&ensp;계승자: 어떤 순회 결과에서 현재 노드 바로 다음 노드<br/>

&ensp;세 가지 계승자<br/>
&ensp;1. preOrderSucc(v)<br/>
&ensp;`preOrderSucc(v) = 트리를 전위순회할 때 노드 v 직후에 방문되는 노드` <br/>
&ensp;전위순회: Root → Left → Right<br/>

&ensp;2. inOrderSucc(v)<br/>
&ensp;`inOrderSucc(v) = 트리를 중위순회할 때 노드 v 직후에 방문되는 노드` <br/>
&ensp;중위순회: `Left → Root → Right` <br/>

&ensp;3. postOrderSucc(v)<br/>
&ensp;`postOrderSucc(v) = 트리를 후위순회할 때 노드 v 직후에 방문되는 노드` <br/>
&ensp;후위순회: `Left → Right → Root` <br/>

| `postOrderSucc(v)` | Left → Right → Root | 단순히 내부 여부보다 부모와의 관계가 중요 | 오른쪽 자식이면 부모, 왼쪽 자식이면 오른쪽 부트리의 첫 후위 노드 |


## 로만노드(roman node)

&ensp;T는 n개의 노드로 구성된 이진트리<br/>
&ensp;로만노드(roman node) = 어떤 노드 v에서 왼쪽 부트리 크기와 오른쪽 부트리 크기의 차이가 5 이하인 노드<br/>

&ensp;부트리 크기: v 자신 + v의 모든 자손 노드 수<br/>

&ensp;로만노드의 조건<br/>
&ensp;노드 v<br/>
```tree
        v
      /   \
   left   right
```

&ensp;왼쪽 부트리 크기를 l, 오른쪽 부트리 크기를 r이라고 하면,<br/>
* l = size(leftChild(v))
* r = size(rightChild(v))

&ensp;로만노드 조건: `|l - r| ≤ 5` <br/>

&ensp;주어진 노드 v와 v의 모든 자손들이 로만인 경우 v를 루트로 하는 부트리의 크기를, 그렇지 않으면 0을 반환하는 선형시간의 일반 알고리즘 romanSize(v)를 작성하라. <br/>

&ensp;반환값의 의미<br/>
&ensp;romanSize(v)의 반환값은 두 가지<br/>
1. v와 v의 모든 후손이 로만이면 → v를 루트로 하는 부트리의 크기 반환
2. 하나라도 로만이 아니면 → 0 반환

&ensp;romanSize(v) 의사코드<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-56.png" width="600"></p>

&ensp;이 알고리즘은 후위순회 방식이다.<br/>
&ensp;왜냐하면 부모 v가 로만인지 판단하려면, 먼저 왼쪽 부트리 크기와 오른쪽 부트리 크기를 알아야 하기 때문이다.<br/>

&ensp;어느 노드도 한 번 이상 방문하지 않으므로 `O(n)` 시간에 실행<br/>

&ensp;이 알고리즘은 반환값 하나에 두 정보를 담는다.<br/>
* 0이면 실패
       - romanSize(v) = 0 → v의 부트리 안에 로만이 아닌 노드가 있다.
* 양수이면 성공 + 부트리 크기
       - romanSize(v) = k > 0 → v의 부트리 전체가 로만이고, 크기는 k이다.

## 양자택일식 문답시스템(결정트리)

&ensp;결정트리(decision tree) = 질문을 따라 내려가면서 최종 결정을 얻는 이진트리<br/>
&ensp;예: 식사결정<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-57.png" width="600"></p>

&ensp;양자택일식 문답시스템: 예 / 아니오로 답할 수 있는 질문들을 차례로 던져서 최종 결정을 내리는 시스템<br/>

&ensp;예를 들면:<br/>
* 스무고개
* 고장 진단 시스템(troubleshooter)
* 분류기(classifier)
* 추천기(recommender)

&ensp;왜 이게 이진트리인가?<br/>
&ensp;질문 하나마다 가능한 답이 두 개뿐이다.<br/>
* yes = 왼쪽 자식
* no = 오른쪽 자식

&ensp;결정트리의 구조<br/>
```tree
질문
 ├─ yes → 다음 질문 or 최종결정
 └─ no  → 다음 질문 or 최종결정
```

&ensp;결정트리에서 노드 의미<br/>
&ensp;1) 내부노드<br/>
&ensp;질문을 저장<br/>
&ensp;예<br/>
* 빠른 식사를 원하세요?
* 양식도 좋으세요?
* 비싸도 됩니까?

&ensp;2) 외부노드(리프)<br/>
&ensp;결정을 저장<br/>
&ensp;예<br/>
* 햄버거
* 국수
* 레스토랑
* 요리해 드세요

&ensp;배열 기반 결정트리 구축<br/>

&ensp;buildDecisionTree()<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-58.png" width="600"></p>

* 루트는 순위 1에서 시작
* 루트는 질문이어야 하므로 makeInternalNode(1) 호출
* 이후 재귀적으로 전체 트리를 만들어감

&ensp;makeExternalNode(i)<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-59.png" width="600"></p>

&ensp;배열의 i번째 칸에 결정(리프 노드) 을 넣는 함수<br/>

&ensp;makeInternalNode(i)<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-60.png" width="600"></p>

&ensp;이 함수는 배열의 i번째 자리에 질문 노드를 만들고, 그 질문의 yes/no 가지를 재귀적으로 완성하는 함수<br/>

```cpp
Alg makeInternalNode(i)
1. write("Enter question: ")  // 현재 노드에 들어갈 질문을 입력하라고 함
2. T[i] ← read()   // 질문을 배열 T[i]에 저장(현재 노드가 내부노드가 됨)
3. write("Question if yes to ", T[i], "?")  // 이 질문에 yes라고 답했을 때 다음이 무엇인지 묻는 것
4. if (read() = "yes")  
      makeInternalNode(2i)   // yes 쪽 다음 노드가 또 질문이면 → 왼쪽 자식에 내부노드 생성
   else
      makeExternalNode(2i)  // yes 쪽 다음 노드가 최종 결정이면 → 왼쪽 자식에 외부노드 생성
5. write("Question if no to ", T[i], "?")  // 현재 질문에 no라고 답했을 때 다음이 무엇인지 묻음
6. if (read() = "yes")
      makeInternalNode(2i + 1)  // no 쪽 다음이 질문 → 오른쪽 자식(2i+1)에 내부노드 생성
   else
      makeExternalNode(2i + 1)  // no 쪽 다음이 최종 결정 → 오른쪽 자식에 외부노드 생성
7. return
```

&ensp;연결리스트 기반 결정트리 구축<br/>

&ensp;buildDecisionTree()<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-61.png" width="600"></p>

&ensp;루트 노드를 만들어 반환한다. 배열 기반은 makeInternalNode(1)이었고, 연결리스트는 노드를 새로 할당해서 포인터로 연결해야 하므로 makeInternalNode() 자체가 노드를 반환한다.<br/>

&ensp;makeExternalNode()<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-62.png" width="600"></p>

```cpp
Alg makeExternalNode()
1. v ← getnode()  // 새 노드 하나 동적 생성
2. write("Enter decision: ")  // 결정을 입력
3. v.elem ← read()   // 그 결정을 노드에 저장 
4. v.left, v.right ← ∅  // 리프 노드이므로 자식 포인트는 없음 
5. return v
```

&ensp;makeInternalNode()<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-63.png" width="600"></p>

1. 새 노드 생성
2. 질문 저장
3. yes 쪽 만들기 → 왼쪽 자식 연결
4. no 쪽 만들기 → 오른쪽 자식 연결
5. 완성된 현재 노드 반환

&ensp;runDecisionTree: “이미 만든 트리를 실행하는 알고리즘”<br/>
&ensp;즉 트리는 이미 만들어져 있고, 이제 사용자가 질문에 yes/no로 답해서 최종 결정을 얻는 과정이다.<br/>

&ensp;runDecisionTree(v)<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-64.png" width="600"></p>

* 사용자에게 질문에 답하라고 안내
* 루트에서부터 처리 시작

```cpp
Alg processNode(v)
1. write(element(v))  // 현재 노드의 내용을 출력 
2. if (isInternal(v))   // 현재 노드가 내부노드인지 확인(내부노드: 질문, 외부노드: 최종결정)
      if (read() = "yes")
          processNode(leftChild(v))
      else
          processNode(rightChild(v))
```

&ensp;build와 run의 차이<br/>
* build = 구조 생성
* run   = 구조 사용

&ensp;실행시간 관점<br/>
1. buildDecisionTree: O(n)
2. runDecisionTree: 트리 높이 = O(h)

# 스레드 이진 트리

&ensp;스레드가 필요한 이유<br/>
&ensp;일반적인 연결 이진트리 노드는 `leftChild | data | rightChild` 이렇게 생겼다.<br/>
&ensp;그런데 리프 노드나 자식이 하나 없는 노드들은 `leftChild`, `rightChild`가 NULL이 되는 경우가 많다.<br/>
* n개 노드 이진트리의 총 링크 수 = 2n
* 널 링크 수 = n + 1

&ensp;즉 노드가 n개 있으면 각 노드마다 왼쪽/오른쪽 링크가 있으니까 전체 링크 칸은 2n개 이다.<br/>
&ensp;그런데 실제 자식 연결에 쓰이지 않는 NULL 링크가 n+1개가 생긴다.<br/>

&ensp;예를 들어 노드가 9개라면<br/>
* 총 링크 수 = 2 × 9 = 18
* 널 링크 수 = 9 + 1 = 10

&ensp;스레드 Thread의 기본 아이디어<br/>
&ensp;스레드는 이 NULL 링크를 그냥 비워두지 않고 **다른 의미 있는 노드를 가리키게 하는 것** 이다.<br/>
* 오른쪽 자식이 NULL이면 → rightChild를 중위 후속자(inorder successor)를 가리키게 한다.
* 왼쪽 자식이 NULL이면 → leftChild를 중위 선행자(inorder predecessor)를 가리키게 한다.

&ensp;중위 선행자와 중위 후속자<br/>
&ensp;중위순회: `Left → Root → Right` <br/>
&ensp;예를 들어 중위순회 결과가 다음과 같다고 하면 `H D I B E A F C G` <br/>
* 중위 선행자 = B 바로 앞에 방문되는 노드
       - inorder predecessor(B) = I
* 중위 후속자 = B 바로 뒤에 방문되는 노드
       - inorder successor(B) = E

&ensp;스레드 이진트리는 NULL 링크를 이런 선행자/후속자로 바꿔서 순회를 쉽게 만든다.<br/>

&ensp;스레드 이진트리의 노드 구조<br/>
&ensp;스레드 이진트리 노드는 단순히 leftChild, rightChild만 가지면 안 된다. 왜냐하면 그 포인터가 진짜 자식인지, 아니면 스레드인지 구분해야 한다.<br/>
&ensp;그래서 다음 필드가 필요하다.<br/>
* leftThread
* leftChild
* data
* rightChild
* rightThread

<p align="center"><img src="/assets/img/data structure/11주차/11-65.png" width="600"></p>

&ensp;leftThread<br/>
* leftThread == false → leftChild가 진짜 왼쪽 자식 포인터
* leftThread == true → leftChild가 중위 선행자를 가리키는 스레드

&ensp;rightThread<br/>
* rightThread == false→ rightChild가 진짜 오른쪽 자식 포인터
* rightThread == true → rightChild가 중위 후속자를 가리키는 스레드

&ensp;f와 t 의미<br/>
* f = false = f이면 실제 자식 포인터
* t = true = t이면 스레드 포인터

&ensp;예를 들어 어떤 노드의 오른쪽 필드가 t라면, `rightThread = true` 이므로 rightChild는 실제 오른쪽 자식이 아니라 **중위 후속자를 가리키는 스레드** 이다.<br/>

&ensp;헤드 노드가 필요한 이유<br/>
&ensp;헤드 노드는 트리의 순회를 편하게 하기 위해 사용하는 특별한 노드이다.<br/>
&ensp;스레드 이진트리에서는 가장 앞 노드의 선행자나 가장 뒤 노드의 후속자가 애매해질 수 있다. 예를 들어 중위순회의 첫 번째 노드는 선행자가 없고, 마지막 노드는 후속자가 없다.<br/>
&ensp;이런 "끊기는 문제"를 해결하기 위해 헤드 노드를 둔다고 보면 된다.<br/>
* 헤드 노드 = 순회의 시작과 끝을 통일적으로 처리하기 위한 특수 노드

<p align="center"><img src="/assets/img/data structure/11주차/11-66.png" width="600"></p>

&ensp;스레드 이진트리의 장점<br/>
&ensp;`스택을 이용하지 않고 중위 순회 가능` <br/>
&ensp;일반 이진트리에서 중위순회를 반복문으로 하려면 보통 스택이 필요하다.<br/>
&ensp;왜냐하면 왼쪽으로 내려갔다가 대시 부모로 돌아와야 한다. 그런데 스레드 이진트리는 NULL 포인트 자리에 중위 선행자/후속자 정보가 들어 있기 때문에 스택 없어도 다음 방문 노드를 찾을 수 있다.<br/>

&ensp;중위 후속자 insucc<br/>
```cpp
threadedPointer insucc(threadedPointer tree)
{
    threadedPointer temp;
    temp = tree->rightChild;
    if (!tree->rightThread)
        while (!temp->leftThread)
            temp = temp->leftChild;
    return temp;
}
```

&ensp;이 함수는 현재 노드 tree의 중위 후속자를 반환한다.<br/>

&ensp;insucc 흐름 이해<br/>
&ensp;경우 1. rightThread가 true인 경우<br/>
```cpp
if ptr->rightChild == NULL originally
ptr->rightChild = 중위 후속자
rightThread = true
```

&ensp;오른쪽 포인터가 스레드라면 이미 중위 후속자를 가리키고 있다.<br/>
&ensp;그래서 바로 반환하면 된다.<br/>
* temp = tree->rightChild
* return temp

&ensp;경우 2. rightThread가 false인 경우<br/>
&ensp;rightThread == false라는 건 오른쪽 자식이 실제로 있다는 뜻이다.<br/>
&ensp;중위순회에서 현재 노드 다음은 **오른쪽 부트리에서 가장 왼쪽 아래 노드** <br/>

```cpp
temp = tree->rightChild;

while (!temp->leftThread)
    temp = temp->leftChild;
```

&ensp;오른쪽 자식으로 한 번 간 뒤, 왼쪽 자식 링크가 실제 자식인 동안 계속 왼쪽으로 내려간다. 그러다가 leftThread == true 가 되는 순간은 더 이상 실제 왼쪽 자식이 없다는 뜻이다. 그 노드가 바로 중위 후속자이다.<br/>

&ensp;스레드 이진트리의 중위순회 tinorder<br/>
```cpp
void tinorder(threadedPointer tree)
{
    threadedPointer temp = tree;
    for ( ; ; ) {
        temp = insucc(temp);
        if (temp = tree) break;
        printf("%3c", temp->data);
    }
}
```

&ensp;헤드 노드에서 시작 → insucc로 다음 중위 노드를 찾음 → 헤드 노드로 돌아오면 종료<br/>

&ensp;tinorder 흐름<br/>
1. temp를 헤드 노드로 둔다.
2. insucc(temp)를 호출해 첫 번째 중위순회 노드를 찾는다.
3. 그 노드를 출력한다.
4. 다시 insucc를 호출해 다음 노드를 찾는다.
5. 헤드 노드로 돌아오면 순회 종료.

&ensp;스레드 이진트리 삽입<br/>
<p align="center"><img src="/assets/img/data structure/11주차/11-67.png" width="600"></p>

&ensp;스레드 이진트리에서 노드를 삽입하는 방법<br/>
&ensp;`s의 오른쪽 자식으로 r을 삽입한다.` <br/>
&ensp;일반 이진트리라면 단순히 `s.rightChild = r` 만 하면 될 것 같은데 스레드 이진트리는 스레드까지 고쳐야 해서 더 복잡하다.<br/>

&ensp;insertRight의 의도<br/>
&ensp;삽입 전 s의 오른쪽 링크는 두 가지 경우가 가능하다.<br/>
1. s의 오른쪽 링크가 스레드였다.
2. s의 오른쪽 링크가 실제 오른쪽 자식이었다.

&ensp;새 노드 r을 s의 오른쪽 자식으로 넣으면, 기존에 있던 오른쪽 관계 또는 스레드 관계를 r 쪽으로 적절히 옮겨야 한다.<br/>
* r은 s의 오른쪽 자식이 된다.
* r의 왼쪽 스레드는 s를 가리킨다.
* r의 오른쪽 링크는 원래 s의 오른쪽 링크를 물려받는다.

&ensp;insertRight 코드 의도 정리<br/>
```cpp
void insertRight(threadedPointer s, threadedPointer r)
{
    threadedPointer temp;

    r->rightChild = s->rightChild;
    r->rightThread = s->rightThread;

    r->leftChild = s;
    r->leftThread = TRUE;

    s->rightChild = r;
    s->rightThread = FALSE;

    if (!r->rightThread) {
        temp = insucc(r);
        temp->leftChild = r;
    }
}
```

&ensp;일반 트리를 이진트리로 변환<br/>
&ensp;일반 트리에서는 한 노드가 자식을 여러 명 가질 수 있다.<br/>
```tree
        A
     /  |  \
    B   C   D
```

&ensp;이걸 이진트리로 표현하려면 다음 규칙을 사용한다.<br/>
* 왼쪽 자식 = 첫 번째 자식
* 오른쪽 자식 = 바로 다음 형제

&ensp;일반 트리 → 이진트리 변환 규칙<br/>
* 원래 트리에서 부모-첫째 자식 관계는 왼쪽 자식 링크로 표현한다.
* 원래 트리에서 형제 관계는 오른쪽 자식 링크로 표현한다.

&ensp;왼쪽 자식-오른쪽 형제 트리의 오른쪽 형제 포인터를 45˚ 회전<br/>
&ensp;일반 트리에서 형제들이 가로로 나열되어 있던 관계를 이진트리에서는 오른쪽 자식 방향으로 표현한다.<br/>

&ensp;루트 노드의 오른쪽 자식은 공백<br/>
&ensp;루트는 형제가 없다. 오른쪽 자식은 다음 형제를 의미하는데 루트에게는 형제가 없다. 따라서 변환된 이진트리에서 `root.right = NULL` 이 된다.<br/>

#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct Node {
    struct Node* left;
    int data;
    struct Node* right;
} Node;

Node* makeNode(int data) {
    Node* newNode = (Node*)malloc(sizeof(Node));
    newNode->left = NULL;
    newNode->data = data;
    newNode->right = NULL;
    return newNode;
}

Node* findNode(Node* root, int data) {
    Node* result;

    if (root == NULL) {
        return NULL;
    }

    if (root->data == data) {
        return root;
    }

    result = findNode(root->left, data);

    if (result != NULL) {
        return result;
    }

    return findNode(root->right, data);
}

void attachChildren(Node* root, int x, int y, int z) {
    Node* parent = findNode(root, x);

    if (y != 0) {
        parent->left = makeNode(y);
    }

    if (z != 0) {
        parent->right = makeNode(z);
    }
}

void searchTree(Node* root, char path[]) {
    Node* cur = root;

    printf(" %d", cur->data);

    for (int i = 0; path[i] != '\0'; i++) {
        if (path[i] == 'L') {
            cur = cur->left;
        } else if (path[i] == 'R') {
            cur = cur->right;
        }

        printf(" %d", cur->data);
    }

    printf("\n");
}

void freeTree(Node* root) {
    if (root == NULL) {
        return;
    }

    freeTree(root->left);
    freeTree(root->right);
    free(root);
}

        if (i == 0) {
            root = makeNode(x);

            if (y != 0) {
                root->left = makeNode(y);
            }

            if (z != 0) {
                root->right = makeNode(z);
            }
        } else {
            attachChildren(root, x, y, z);
        }
    }

    scanf("%d", &s);

    for (int i = 0; i < s; i++) {
        scanf("%s", path);
        searchTree(root, path);
    }

    freeTree(root);

    return 0;
}
